见实施前的 `network-numeric-blocks-phase42-source-notes-2026-09-22.md`。使用冻结源码重建 Phase39 Vite 转换，确认 profile 中 pack 入口与源位置匹配。typed Array.from 对应 136 个位置样本；这些是采样数，不是 CPU 毫秒。

## 4. 当前编译版真实五人验收

`check-compiled-multiplayer.mjs` 使用五个独立无头 Chromium 进程，1280×720，实际编译后的 LAN 页面和 Worker，无 Vite 源码导入/玩法替换。UI 创建、设置人数/规模、加入、应用配装、准备、开战；17 艘 AI 配置仅通过测试拥有的服务端 socket 注入正常验证的 host options 命令，属于场景准备，不是 UI AI 编辑测试。

通过项：
- 五人，合计 22 船；房主权威 Worker 只在房主运行。
- DOM 输入后持续推进；测量 10002ms 推进 594 tick（约 59.4 物理 Hz）。输入效果的严格确定性比较由 Phase41 覆盖，本测试不冒充同一条验证。
- 人为阻塞房主主线程 800ms，中间 450ms 服务端发布 seq 推进 24 次。
- 客机刷新后回到同一 match，服务器仍推进。
- 默认共享本地完成回执真实启用；未出现 page/worker/console 错误；所有拥有的浏览器及服务器正常关闭。

首次 `compiled-5` 只在末尾断言失败：脚本错误读取 `sample.row.hud`，而解析器实际返回 `sample.hud`，真实日志有 14 个 sharedCredit=true 房主样本。只修正字段路径，**没有取消断言**。`compiled-5-v2` 完整重跑通过。

性能边界：这不是旧/新版本配对压测，不是远程 Steam/n2n。客机1在预热后短暂为 60Hz，交火阶段约 31–46Hz；重连压力末尾约 14Hz。未刷新的页面多数显示 60FPS，刚刷新的客机仍在预热（8FPS）。**不能将功能通过、低本机 RTT 或物理接近60Hz称为完整同步稳定60Hz。** 与 Phase41 的命令保持夹具不同，不直接比较两者 Hz 宣称退步/进步。

完整结果：`phase42/compiled-5-v2/result.json`。当前下一瓶颈仍须在正常交火下拆分房主模拟、完整捕获/编码、回调追赶合并和接收端成本；不能盲目扩大信用窗口、排队全部旧帧或降低目标 Hz。
