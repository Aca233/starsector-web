# 舰船强度规范 v0.1 · 讨论稿

日期：2026-09-29。范围：Web 自定义舰船、军械、专属系统、插件与模块舰。
状态：**规范提案与静态基线核对，未获确认的目标不是现行规则；本轮不改运行数值、不迁移存档、不更新发布包。**

## 1. 统一目标，不把所有船做成一样强

建议采用“原版战术基准 + 扩展舰分层 + 整舰部署成本约束”。

- 常规舰有原版参照；跨作品巨舰保留体量、火力、防御和战场影响力，不为了单挑公平削成普通战列舰。
- 同成本应在多种合理任务中具备相近的选择价值，不要求每个对局五五开，更不要求护卫舰和巨舰单挑平等。
- 小船的价值可以是拦截、追击、侧袭、牵制和低成本部署，不能因为不能正面击毁巨舰就判废物；也不能拿这些名义掩盖它实际什么都做不好。
- 原作身份决定玩法方向；缺少可信证据的跨作品尺寸、科技倍率与“灭星”说法不能直接变成伤害倍率。显示尺度、安装档位、战术强度分开。
- 本规范是 Web 平衡设计，不冒充原版官方数值或跨作品官方战力排名。

## 2. 三个分类轴

每艘船必须明确以下三项，不用一个“舰级”包办：

1. **物理舰级**：沿用宿主护卫／驱逐／巡洋／主力，影响配装和相关规则；不为强度分级擅自改这些枚举。
2. **战术定位**：例如拦截护航、鱼雷猎杀、正面压制、火力支援、航空、区域防御。确定一个主定位，辅助定位明确成本。
3. **强度层**（仅设计标签，尚未加入引擎）：
   - 常规战术舰：以原版同类战术能力与舰队用途为锚点。
   - 强化旗舰：允许超过常规主力舰的独特能力，由部署成本和真实恢复/暴露窗口约束。
   - 战略巨舰：作为舰队核心或相当份额的战力评估，必须验证对等部署成本的混编舰队交战，不拿单艘巡洋舰当平衡靶。

层级不绑定固定伤害、DP或血量公式。不能先划一个高层标签，再以此豁免一切成本。

## 5. 整舰能力统一计账

### DP：为整艘舰的战斗能力付费

DP覆盖：舰体＋全部模块＋内置军械＋内置插件＋技能＋航空容量与默认体系＋保护/修复友军的支援能力。

- 内置0OP是“改装时不收费”，不是“平衡时免费”。
- 模块不另外部署也不能成为免费武器、免费载荷池或免费技能。
- 新增内置能力后重新评估整舰，不必机械涨DP，但必须说明由什么既有弱点或成本吸收收益。
- 默认采用稳定的整舰DP，不在本提案中引入按装配实时收费的新部署系统。
- 现有战斗部署上限必须容纳所定DP；不能只把巨舰DP抬高却让玩家在默认入口无法部署。地图尺度、舰队配额是同步审核项，不擅自扩容。

### OP：为配装选择付费

OP控制同一舰体内部的取舍，不直接等同DP。

- 固定内置军械可以0OP，但要计入舰体战力；对比配装时不能把固定火力漏掉。
- 模块先有整舰设计预算，再分配到舱段；当前局部OP上限继续由现有编译器执行，不声称已实现总池。
- 两套配装要有各自擅长场景，不能一套在火力、防护、机动、续航上全胜。
- 航空联队的OP、补充、再武装、损失与出击距离必须和母舰同账。

## 6. 六项战斗指标，拒绝只看纸面DPS

所有结果注明配装、舰长/技能、CR、AI或玩家、时间窗、目标、距离、方位和初始资源。

| 指标 | 必须记录 | 不允许的替代 |
| --- | --- | --- |
| 爆发 | 首次抵达、一次技能完整窗口、实际命中与载荷支出 | 只乘弹伤与枪数 |
| 持续火力 | 建议10／60／180秒窗口，装填、供弹、恢复、被迫停火；不适用时说明 | 满弹匣头几秒冒充长期DPS |
| 防御 | 对不同伤害类型的实际承伤、过载/破盾、恢复间隔、关键模块损失 | HP＋装甲＋盾容量相加 |
| 覆盖与命中 | 炮口距离、前/侧/后可交战火力、追转、弹速、遮挡 | 双舷全部同时计入单方向输出 |
| 机动与接战 | 获得射击位置、躲避、脱离和再次接战所需时间 | 只看最高速度 |
| 支援与续航 | 友军获保护、导弹拦截、维修、航空出勤与有限弹药消耗 | 只看本舰击杀数 |

不强制合成为一个精确“战力分”。机制不同的舰船用多项证据判定，避免看似科学的任意权重。

## 7. 四档军械规范

继续遵守 SMALL / MEDIUM / LARGE / EXTRA_LARGE 同档换装。XL是Web扩展，不是原版新增档位。

- 档位是安装与兼容契约，不是固定倍数伤害公式，也不保证任何XL武器都胜过任何L武器。
- 每件武器标注主职能：反盾、破甲、斩杀、近防、范围压制或支援；比较同职能、近似OP和实际覆盖的武器。
- 实弹、能量、导弹分别检查载荷、精度、弹速、备弹、再装填、弹体生存、可拦截性与穿透/爆破契约。
- 射程从实际炮口和交战目标边界核对；巨舰不能因为炮口远离舰心而形成虚假的高射程或贴脸才开火。
- 女王军械升档已是现行兼容变更；本规范不撤销它，也不自动追加伤害。新档位的同档可换军械与插件加成需要重新核对，避免目录标签掩盖强度问题。
- 主炮具备威力应有可见蓄能、弹道、命中、破盾/贯穿结果；不能用极大光效掩盖低伤害，也不能因“有逼格”而无条件穿过所有对象。

## 8. 系统与专属插件规范

每个能力必须写“收益／可利用窗口／限制或成本／对手的应对”。不是每个被动都必须附加负面词条，但其收益必须纳入DP/OP或整舰约束。

- 不再用“切换目标优先级”包装成强力爆发技能；此类能力可作为辅助操作，不能冒充伤害收益。
- 爆发技能验证实际射速，宿主最小间隔、弹匣、动画与载荷限制都要计入。罗西南特PDC实测15→20，不写理论22.5。
- 进攻、防御、机动都很强的舰，必须有资源竞争、互斥窗口、朝向限制或足够成本，不能叠出常驻全能态。
- 内置插件负责表达舰体固有机制；选装插件改变路线。不得把同一套虚空盾/反应堆规则拆成多个重复说明当作内容。
- 不能把正常可用性故障卖成插件优势，例如过慢的基础护盾展开若已使常规接战失效，应先核实并修正基础规则，而不是强迫付OP解锁正常体验。
- 对友军有效的护盾、维修和火控，以舰队场景评估；这类收益可能远高于本舰面板变化。

## 9. 最小校准与放行

本节是拟采用的验收方法，本轮没有启动这些战斗，也不宣称已通过。

1. 冻结一套基准环境与每艘舰两套合法预设；无额外舰长加成/一致CR，记录主机版本、配置、种子与AI。
2. 先集中完成相关规则正确性校验，避免拿漏弹、不开火、射程判定错误、错误供弹或失效技能当平衡问题。
3. 每艘先选三类代表性任务：主职能、受克制场景、对等DP的混编战斗。巨舰另包含局部失段和支援友军；小船另包含拦截/脱离，不只做单挑。
4. 使用多个种子并交换出生侧，报告样本数、任务成功率、资源消耗和关键故障；少量样本只作为调整方向，不宣布精确胜率结论。AI对AI先作可复现基线，再做玩家操控上限的独立试玩。
5. 只有一种预设全面支配另一种、低成本船跨多数场景取代高成本船、或舰体主职能反复无法完成时，标记需要调整。克制对局输掉不自动构成不合格。
6. 每轮只调整一组明确因素，记录因果：几何/命中与行为缺陷优先，随后资源循环、武器性能、整舰预算与DP；不同时修改所有参数制造无法追溯的“平衡”。
7. 规则/数值改动按工程约定集中类型检查、改动lint与相关场景；只针对失败复查，不为每个字段重跑全套。

放行级别：静态账本已核对 → 规则受控已验 → 主职能实战已验 → 混编成本已校准 → 玩家试玩反馈已复核。未到最后，不写“最终平衡”。

## 11. 建议执行顺序

1. **先以罗西南特校准常规小舰基准**：8DP是否兑现拦截、机动与有限鱼雷；检查火控高热收益与手动轴炮命中，而不是继续盲加血。
2. **烛渊与休伯利安**：分别对照巡洋与主力舰基准，检查技能资源收益和部署溢价。
3. **女王与方舟**：先统一整舰统计口径，再做180DP附近的混编对照；同价不意味着要改成同一套盾、航空或武器。
4. 规范经确认并有首轮校准结果后，再写入舰船制作skill、舰船包的设计/验收要求；不要把尚未验证的目标固化为全局硬规则。
