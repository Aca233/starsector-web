# 普通房主单次上传与去弹丸世界配对 — 2026-09-23

## 当前结论

普通玩家房主的二进制快照现在可以由共享中继派生完整／去弹丸两种版本，LAN 与默认 Steam 异步快照准备 Worker 适配器共用同一逐接收端选择逻辑。房主仍只编码、上传一份完整 SWB1；不是让房主重复编码、上传两份大世界。

这是**源码实现与无头传输验证完成**，不是新桌面安装包、发布版、全战斗画面联调或真实 Steam/WAN 验收。视觉／战斗组件保持显式实验 opt-in：

- `VITE_LAN_LAYERED_SYNC=true`：实验分层／视觉通道。
- `VITE_LAN_CRITICAL_COMBAT=true`：在上述实验模式下同时请求战斗组件。
- 默认 auto 仍只启用已协商的附加运动路线，不自动开启视觉／战斗组件，不开启历史未验收的 AI／serializer Worker 或 Native Sockets。

## 实现

1. **同一次校验中记录字节位置**：在 BinarySnapshot 的既有有界 relay projection 遍历中，可选记录根 map、world 与 projectiles 的位置和出现次数；所有忽略子树仍执行原有 tag、key、深度、长度、UTF8 和 packed number 校验。
2. **延迟派生且共享结果**：只有某位接收端满足已有的协商、加载、组件活跃、同 sync 的真实视觉消费与新鲜度条件，才把 projectiles 的原值替换为 MessagePack 空数组并追加 projectileVisuals:1。一次广播最多派生一次，其他符合条件的接收端共享这份只读结果，不额外重建／编码整个世界对象图。
3. **完整原包不变**：根 map header、projectiles 值和新增 marker 之外的字节原样复制；SWB1 match/seq、SWF2/3、舰船、光束、水雷、声音、事件及 packed 数值保持原内容。派生结果必须比原包小并保持协议大小限制。
4. **按客机而非按房间删减**：没有消费、回执过期或不可用的客机仍选择完整原包。视觉与完整世界各自的回执不能互相释放额度；bootstrap 短等待、250 ms 新鲜度、15 tick 界限、detail cadence 和失败回退策略均未修改。
5. **Steam 交给 Worker 的是选中的字节**：精简字节不会被元数据中原来的完整 frame 覆盖。既有组件失败时的准备 epoch 作废、可见性恢复后必须先消费新完整世界的机制保持不变。

## 保守回退边界

下列情况不派生，保留原本完整快照路线：

- 旧的无 SWF2/3 前缀格式、JSON 上传、需要完整对象图的旧同步 Steam 适配器／混合房间。
- 根／world 结构不满足条件，缺少 projectiles，重复 world 或 projectiles，已有任何 projectileVisuals 标记。
- UTF8 兼容路径回退到库解码器：已收集的部分位置不能用于拼包。
- 替换后没有体积收益，或根 map 无法在原计数上限内添加 marker。

回退不豁免任何校验，也未改变原解码器对其它重复键的 last-write 语义。dedicated authority 原有配对字节路径仍使用同一选择器，本轮不重复编码它。

## 验证记录

集中执行一次工程 typecheck、改动文件 oxlint、既有 codec 场景及所需 LAN/Steam 生产链路场景；仅对具体失败做定向复查，没有重跑整个工程，也没有重跑 48 舰容量基准。

- **typecheck：通过**。
- **5 个改动实现／声明／测试文件的 oxlint：退出码 0**。
- **codec：9 个相关用例最终通过**。覆盖原投影语义／随机变异／坏包与截断，新增 SWF2/3、packed 数值、数组与列式标签、offset view、完整原包不可变、重复调用共用派生结果、缺失／歧义／legacy／UTF8 回退，以及根 map 的 15→16、65535→65536 和上限回退。
- **生产连接：5 个相关用例最终通过**。包括默认能力策略、3 个真实 LAN 客户端保持完整二进制世界、默认 Steam、实验组件 Steam，以及普通 LAN 单次上传按客机配对。
- **LAN 场景**：真实本机 relay/helper 和真实编译的 LanConnection；先完整 bootstrap，两个客机真正消费视觉基线，然后暂扣一端的精确视觉回执。共享时钟推进使该端过期，同一上传序号向新鲜端发送精简版、过期端发送完整版；只在补交实际回执后释放视觉债务。之后两端过期都恢复完整世界，最终无未释放快照／视觉额度。
- **Steam 场景**：两个真实本机 relay、真实编译客户端、真实异步编码 Worker；只有 Steam SDK 包搬运被 mock。完整可靠状态暂扣期间独立组件继续；单次二进制上传的派生结果经过 Worker 后精确到达，后台恢复和组件失败重新传完整弹丸，旧排队精简提案在降级时作废。
- 视觉新鲜度时钟在场景内受控，避免等待既有 200 ms detail cadence 与 250 ms TTL 的测试调度竞态；不是调整生产门限，也不是实际网络延迟测量。

首次 codec 8/9、生产连接 4/5；两处失败都是新测试假设错误：误以为 world 属于冻结字典，以及把 ACK 的帧数当作序号（实际发送 1/2/4/5 共四帧）。仅修正测试，定向复查 2/2 通过。合并首次已通过项，共 14 个不同相关用例通过，保留首次失败日志，不冒充一次性全绿。

证据目录：`artifacts/network-bulk-pair-20260923/`；包含 source-before、typecheck.log、lint.log、codec.log、activation.log、targeted-recheck.log、lint-recheck.log、状态文件和本轮相对工作区起点的 patch。

## 性能与交付边界

- 消除了“为了配对而要求房主多编码／上传一份完整大世界”的需求；只在有合格接收端且确实更小时分配精简字节。
- 本轮未新增 CPU、FPS、真实带宽或 input-to-photon 前后基准，不能量化实际性能提升。此前 capture 平均下降约 29.93% 和 48 舰 8 秒短测结论仍只属于上一阶段证据。
- 未修改物理、AI、伤害、模拟保真度、请求快照频率、过载门限或恢复策略；未改玩法／界面／生涯；未操作桌面、使用子代理、暂存、提交、推送、打包、发布或安装新版本。
