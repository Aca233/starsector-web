# Worker整页例外路径与实测：修改前证据（2026-09-25）

继续原目标，不以可选接入代替性能验证。上一轮是实质进展：生产页面接入及真实三客户端场景通过。本轮先检查当前源码，发现JSON state每包都resetPresentationConsumption：对Worker会每包撤销UI、插值和实时坐标，不能作为可用回退。控制包还每帧重发图形设置，在Worker内重复normalize并尝试访问不存在的localStorage。

原版0.98a-RC8；本轮重新读取settings.json:8–9的vsync/60fps和CombatEntityAPI.java:16–20的位置/速度/朝向接口。只优化实现/测量，不改模拟率/精度/数量/画质/权限；无原版实机UI验证，不占用桌面。

修复仅在状态编码真正切换时撤销owner代际，保留未消费跨格式切换的安全重连；相同JSON流持续消费，解析耗时只计一次。图形偏好仅改变时同步。既有真实联机场景增加测试专用、各线程本地有界帧记录，比较同一候选源码 main/shared/messages 三个运行臂。测的是DOM事件到采用新控制的WebGL提交，不冒充物理屏幕延迟。每臂正常/固定主线程压力窗口；messages臂测量后通过真实relay JSON输出检查持续接收及返回binary。一个既有场景、一次集中静态检查，具体失败才定向复查；这是小样本先导对照，不是默认开启依据。
补充实现前复核：页面原先在“实时坐标不可读”时通过active()误判为权限失效并resetInput，会清掉已排队动作；本轮将显式权限门槛和短暂读不可用分离，并在同一messages/JSON场景中用真实背压和暂时读不可用验证动作只发送一次。测量首轮发现真实碰撞保护使预测暂停，探针不得把新按键被采样当作可见移动；最终分开报告控制采样提交与有局部预测证据的提交，并列出未预测输入及原因。
