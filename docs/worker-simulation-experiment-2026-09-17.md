# 单机模拟 Worker 实验：2026-09-17

## 结论：保留实验入口，不默认启用

已实现“主线程绘制 + 一个 Worker 权威模拟”，并提供同场景单线程对照。
**尚不是将模拟算法拆分给多个核心。** 普通战斗、设计器、联机入口均未切换到这条链路。

100 艘攻势级密集交战，2560×1440、DPR 1、Chromium/ANGLE D3D11、RTX 5060：

| 合并两次重复的指标 | 单线程实验模式 | Worker 实验模式 | 解释 |
|---|---:|---:|---|
| 浏览器 rAF 回调率 | 13.47 Hz | 31.23 Hz | +131.8%，不是总算力提升 |
| 已呈现的模拟进度 | 6.70 TPS | 5.42 TPS | **下降 19.1%** |
| 帧间隔 P95 | 166.7 ms | 83.3 ms | 主线程卡顿减少 |
| 输入发出到绘制提交 P95 | 234.3 ms | 517.6 ms | **操控链路明显变差** |
| 快照打包平均耗时 | — | 63.00 ms | Worker 额外成本 |
| 快照应用平均耗时 | — | 43.35 ms | 主线程额外成本 |
| 每次快照有效数值数据 | — | 7,871,433 字节 | 不含字符串/shape 元数据和缓冲区空余容量 |

画面更顺，但战斗推进更慢、输入延迟更大，不符合“收益很好且影响不大”的启用条件。
没有达到 100 舰 / 180 FPS，也不能把更高的回调率表述成整体模拟提速。

## 可使用的范围

本地地址参数：`?view=worker-lab&backend=worker&ships=100`。
单线程对照：`?view=worker-lab&backend=main&ships=100`。
支持 2 / 10 / 50 / 100 艘固定攻势级预设。默认暂停，手动开始；音频默认关闭，可单独打开。

提供自动/手动驾驶、开火、护盾、排能、舰船系统、武器组、缩放、暂停和数据导出。
**不支持**在这一实验入口中导入任意改装、动态增援、航母/无人机阵容、战役接管或运行中切换后端。
遇到不支持的舰船引用会显式停止，而不是忽略实体。
回退链接重新开局；绝不把不完整的渲染快照伪装成可继续模拟的存档。

## 实现约束

- 两种后端共用 `LabSimulation` 的构造及每步算法，保留 1/60 秒权威步长和原有模拟内部顺序。
- 实验调度器每个事件循环任务最多运行一个模拟步，暴露掉落的墙钟时间，不通过增大 dt 偷跳战斗。
  **这不同于普通战斗的追帧调度器**，所以不能拿本表与上一晚的普通战斗 rAF 数字相除。
- Float64 数据流保留数值精度；对象图引用去重；稳定的舰船/武器规格、系统定义及 hullStats 由相同预设构造，不每帧重发。
- 该静态模板假设仅适用于固定、不可中途改装的实验预设。没有宣称支持任意动态系统定义。
- 使用 transferable ArrayBuffer 和复用缓冲区，不要求 SharedArrayBuffer/跨源隔离部署头。
- 最多一个尚未消费的快照；回收后发送最新状态，避免旧快照无限积压；暂停后不重复发送同一 tick。
- Worker 只发模拟数据/音效事件，主线程只更新呈现镜像；不以镜像接管权威模拟。
- 仅插值已知的最后一个模拟步，不外推未知命中。短时特效可能受快照呈现频率影响；不宣称像素级或全部音效保真。
- 音效事件有有界队列；测试记录中存在溢出（包括手动快进阶段）。本轮测量两端均关闭播放，音频保真未验收。
- 后台标签页和 WebGL 上下文丢失会暂停；恢复后由用户显式继续。Worker 失败会停止并提供重新开局回退。

## 验证与测量口径

测量固定同一生产构建 `artifacts/worker-simulation-2026-09-17/build-validated`，按 main → worker → worker → main 顺序串行运行。
每次从 seed `0x51180` 的相同阵容开始，先推进 60 步，再运行 2 秒预热，随后采样约 12 秒。
共 1,075 条帧样本。初始 60 步后的呈现投影数值 SHA、字符串、对象形状、模拟 RNG、视觉 RNG 在四次运行中一致。

真实原生 rAF，无 `gl.finish`、无 CPU profiler，未并发运行本任务的构建/测试/性能采样。
回调率不是物理显示器出帧测量；TPS 根据已呈现 tick 的进度统计，Worker 端可能仍有未呈现的新步。
输入延迟从合成输入消息提交计时，到该输入对应的状态完成主线程绘制提交为止，**不包含鼠标硬件、GPU完成和显示扫描**。
两种后端的墙钟预热推进步数与测量结束 tick 不同，因此测量期战斗轨迹进度不同。

单线程两次分别为 15.08 / 11.87 Hz，7.51 / 5.90 TPS；Worker 为 31.50 / 30.96 Hz，5.36 / 5.49 TPS。
重复数量有限，环境有波动，没有置信区间或持续真实游戏帧率保证。

功能验证：
- Node/Vite SSR 下 2、10、100 舰，tick 0/1/4/12，共 12 组数据流往返一致性检查；保留 Vector2、组件原型、typed array、Map/Set 和引用。
- 浏览器 10 舰 tick 90 呈现投影与两条 RNG 相同（较早实验构建冒烟结果）。
- 已测构建 100 舰四次 tick 60 呈现投影及 RNG 一致。
- 已测构建 2 舰手动推进/横移/开火 + 护盾/系统动作，tick 45 的呈现投影一致。
- 暂停停止权威步进；上下文丢失停止步进；上下文恢复不擅自继续。
- Worker 协议失败可终止并提示；Worker 不可用时可明确重新开局至单线程。
- 页面异常和 GL error 均为零（刻意注入的 Worker 故障另行验收）。

这些检查不构成任意舰型/长局的完整权威状态等价证明。诊断脚本只在忽略的 artifacts 目录，未恢复项目测试目录或测试 runner。

工作区有并行的舰船系统等改动。测量使用固定构建，之后的源码漂移列在 summary.json 中，没有覆盖或撤销这些改动。
早期一次全量 typecheck 被其他文件 SystemArc.ts 的类型错误阻塞；最后再次运行全量 typecheck 已通过。
