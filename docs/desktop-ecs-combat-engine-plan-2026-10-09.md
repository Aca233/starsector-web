## 一、 目标与体验愿景

### 1. 核心目标
解决现有 Rust 内核与混合架构在 22+ 艘主力战舰同屏交火时出现的严重性能劣化（端到端往返耗时高达 ~160ms，频繁伴随 100~400ms 的 V8 垃圾回收卡顿），通过**底层架构的根本性升级**，实现**“极致性能”与“模组高扩展性”**的双赢：
1. **转向 ECS（实体组件系统）与面向数据设计（DOD）**：彻底打破深层嵌套的面向对象（OOP）对象树，采用连续内存（SoA，Structure of Arrays）线性存储实体，CPU L1/L2 缓存命中率拉满，利用 AVX2 向量硬件加速实现单指令多数据（SIMD）并行推进；
2. **采纳“游戏级近似计算（Game-level Approximation）”**：取消逐帧全场景深拷贝（Clone），放弃高开销的连续微积分交点求算，改用扁平空间哈希网格（Spatial Hash Grid）配合圆包围盒/定向包围盒（OBB）快速剔除；
3. **建立零对象（Zero-Object）直通 WebGL 渲染管线**：物理步完成后，Rust 直接向对齐现有 WebGL `SpriteBatcher`（16 floats/sprite）的共享连续内存填充渲染图元，前端直接通过一条 `bufferSubData` 直传显卡，**彻底抹平 68ms 的 JS 对象反序列化与 53ms 的呈现图比对开销**；
4. **与现有 `ShipPack` 舰船包体系深度融合**：使开源社区和模组玩家能够**零代码、纯数据驱动**地添加新船、新武器，并通过**“原子物理积木”**与**“轻量 TS 事件钩子”**轻松扩展前所未有的战术新机制，无需编译 Rust 底层。

### 2. 玩家与开发者体验
* **玩家体验**：
  * 大规模舰队战帧率由“PPT 级卡顿”跃升为**丝滑稳定 60~144Hz**，彻底消除战斗中的掉帧停顿；
  * 战舰转向惯性、初速射程、护盾展开与过载手感、幅能条变化与原版体感完全一致；
  * 现有改装台（`NativeRefit`）、技能树、战备目录与战术地图 HUD 100% 保持原样，交互零变化。
* **模组开发者体验**：
  * **做新船/新武器**：直接在 `ShipPack` 中配置数值与贴图，无需写代码、无需编译，开箱即用；
  * **做新机制/大招**：既可以通过拼装“引力场、时空减速、冲刺、相位穿越”等预制物理积木（零代码），也可以在 TypeScript 里写几行事件钩子实现天马行空的大招。

## 二、 本次范围与明确不做的内容

### 1. 本次开发范围
1. **Rust ECS 扁平连续内存物理内核**：
   * 基于连续数组的组件存储：`Transform`、`Velocity`、`Projectile`、`HullBounds`、`Shield`、`Flux`、`ArmorGrid`、`WeaponMounts`；
   * 全面采用 `f32` 单精度浮点，单指令并行计算 8 颗弹药的位移与衰减；
   * 移除 `step_scene` 每次物理步前的场景深拷贝（Clone）。
2. **两级空间网格碰撞检测**：
   * 256px 扁平空间哈希网格，将上万发弹药与战舰在 O(N) 复杂度内快速分桶；
   * 圆包围盒（粗筛）+ 护盾圆弧点积 / 舰体 OBB（细筛），跳过 95% 以上的无关检测。
3. **直通 WebGL 渲染桥接（Zero-Object Bridge）**：
   * 实现紧凑渲染生成器，严格对齐 `SpriteBatcher.ts` 的 16-float 实例格式；
   * 前端渲染循环直接通过指针共享内存直传显存，彻底废弃 `snapshot()` 与 `CombatPresentationEncoder`。
4. **现有 `ShipPack` 舰船包通用实体加载流水线**：
   * 开战前一次性解析 `ShipPack` 中的船体、武器与装配定义，直接“烘焙（Bake）”并展平为 ECS 组件，战斗循环中零动态解析开销。
5. **新机制双向接入架构**：
   * **TS -> Rust 指令队列（Command Queue）**：以 16~32 字节二进制指令下发突进、大招发射、状态修改；
   * **Rust -> TS 事件邮箱（Event Outbox）**：低频上报命中、摧毁、技能触发等特殊事件，供玩家 TS 钩子响应；
   * **Rust 内置原子物理积木**：径向引力/斥力场、时间膨胀倍率、碰撞图层掩码切换。

### 2. 明确不做的内容
1. **不重写 GPU 渲染器**：不碰 DirectX 12 / Vulkan / wgpu 纯原生图形重写，现有 WebGL 渲染器完全满足性能需求；
2. **不重写 React UI 面板**：现有的战舰改装台、技能树、菜单等 100% 保持在 Web 层；
3. **不改变原版数值平衡性**：伤害倍率、幅能耗散公式严格沿用原版数据；
4. **不触碰生涯模式（Campaign）及存档系统**；
5. **不操作用户可见桌面与键鼠，全程采用后台无头测试**。

## 三、 原版依据与当前差异

### 1. 原版依据
* 原版 Starsector（0.98a-RC8）中，战斗以固定 60 FPS 推进（`settings.json:9 "fps":60`）；
* 原版通过 CSV/JSON 纯文本数据驱动船体（`.ship`）、武器（`.weapon`）与装配（`.variant`）；
* 原版通过 Java 插件脚本（`ShipSystemPlugin`、`WeaponEffectPlugin`）以事件和低频更新的方式支持模组新机制。

### 2. 当前实现与差异
* **老架构弊端**：
  * 老 Rust 核心为了 100% 确定性回放，每帧做全场景深拷贝（耗时 5ms+）；
  * 每帧把状态序列化为巨大的 Float64Array，传给 TS 后在 JS 堆中 new 出几万个临时对象（耗时 68ms+），引发剧烈 GC（耗时 100~400ms）；
  * 机制被硬编码在 Rust 中，玩家无法自由扩展。
* **新架构革新**：
  * 数据线性排布，无指针跳转，L1 Cache 命中率逼近 100%；
  * 渲染数据一趟遍历直入显存，跨语言传递时间由 120ms 降至 0.2ms；
  * 新机制通过原子物理能力与通用指令队列彻底解耦，开源玩家零门槛做船。

## 四、 核心架构设计与数据流转

### 1. 架构总览
```
┌────────────────────────────────────────────────────────┐
│                   表现层 (TypeScript / Web)             │
│                                                        │
│  • React UI (改装台、技能树、战术 HUD)                  │
│  • 模组扩展 (ShipPack 声明配置 + 可选 TS 机制钩子)       │
│  • WebGL 实例化渲染器 (SpriteBatcher.ts)                │
│                                                        │
│         │ 指令队列 (16B 命令)          ▲ 渲染缓冲 (Zero-Copy)│
│         ▼                             │ (16 floats/sprite) │
├───────────────────────────────────────┴────────────────┤
│                   物理与核心 (Rust ECS 原生层)          │
│                                                        │
│  • 扁平组件池 (Transforms, Velocities, Projectiles)     │
│  • 两级空间哈希网格 (256px Spatial Hash Grid)          │
│  • 基础原子物理系统 (径向力场、时间膨胀、碰撞图层掩码)    │
│  • 零拷贝实例生成器 (Direct Render Buffer)             │
└────────────────────────────────────────────────────────┘
```

### 2. 双向通信协议
* **下行指令（TS -> Rust Command Queue）**：
  定长 16~32 字节二进制结构体：`[OpCode, EntityId, Param1, Param2, Param3...]`。
  * `APPLY_FORCE`: 施加方向冲量；
  * `SET_TIME_SCALE`: 调整实体时间流速倍率；
  * `SET_COLLISION_MASK`: 切换碰撞图层（如进入相位）；
  * `SPAWN_PROJECTILE`: 生成特殊武器弹药；
  * `RADIAL_FORCE`: 激活范围引力/斥力场。
* **上行事件（Rust -> TS Event Outbox）**：
  低频事件环形队列：`[EventType, SourceId, TargetId, PosX, PosY...]`。
  * `ON_SYSTEM_TRIGGER`: 技能触发通知；
  * `ON_CRITICAL_HIT`: 特殊弹药击中通知；
  * `ON_SHIP_OVERLOAD`: 幅能过载通知；
  * `ON_SHIP_DESTROYED`: 战舰击坠通知。

## 五、 分阶段实施顺序与交付计划

### 阶段 1 (P0)：核心 ECS 扁平物理与空间网格原型压测（核心算力突破）
* **任务**：
  1. 搭建紧凑 ECS 基础数据结构（SoA 线性存储）；
  2. 实现 256px 空间哈希网格与圆包围盒/OBB 碰撞检测；
  3. 压测场景：50 艘战舰 + 10,000 发弹幕并发混战；
  4. 验证指标：纯模拟耗时（Movement + Spatial Grid + Collision）稳定在 **1.0ms** 以内。

### 阶段 2 (P1)：直通 WebGL 渲染管线贯通（消灭反序列化与 GC）
* **任务**：
  1. Rust ECS 侧实现 `DirectRenderBatcher`，按 `SpriteBatcher.ts` 的 16-float 规格直接排布平铺内存；
  2. 前端对接零拷贝显存上传通道（`gl.bufferSubData` 直传），废弃旧的 `snapshot()` 与 `CombatPresentationEncoder`；
  3. 验证指标：数据传递与显存上传时间稳定在 **0.5ms** 以内，彻底消除 V8 GC 停顿。

### 阶段 3 (P2)：战舰系统与现有 `ShipPack` 通用实体加载适配
* **任务**：
  1. 实现开战前从 `ShipPack`（`ShipSpec`、`WeaponSpec`、`PackFit`）向 ECS 扁平组件的一次性“烘焙（Bake）”；
  2. 将通量系统、护盾圆弧、装甲网格、武器槽位作为通用组件接入；
  3. 接入现有 7 个内置舰船包（烛渊、休伯利安、荣光、亚顿之矛、折锋、罗西南特、重力），验证 100% 正常开战。

### 阶段 4 (P3)：机制原子能力扩展与全链路综合验收
* **任务**：
  1. 实现 Rust 侧三大原子物理机制：径向引力/斥力场、时间膨胀、碰撞图层掩码；
  2. 接入 Command Queue 与 Event Outbox，打通 TS 机制脚本调用通道；
  3. 完整接入战术 HUD 与现有改装台；
  4. 集中执行严格的性能 ABBA 对照测试与长效稳定性测试。

## 六、 验收标准与门禁

1. **绝对性能指标（22 艘战舰 + 10,000 弹幕高负载场景）**：
   * **纯模拟耗时（Simulation Time）**：**<= 1.5 ms**（相比老架构 88ms 提升近 60 倍）；
   * **渲染数据提交（Render Upload）**：**<= 0.5 ms**（相比老架构 53ms 提升 100 倍）；
   * **单帧往返总耗时（Roundtrip）**：**<= 2.5 ms**（稳定跑满 60~144Hz）；
   * **GC 表现**：连续运行 3000 帧（50秒）以上，V8 堆内存零尖峰，杜绝任何 10ms 以上的 GC 停顿。
2. **扩展性验收**：
   * 现有的 7 个内置舰船包全部能通过通用加载器进入战场，武器开火、战术系统正常运作；
   * 新增一个纯数据自定义舰船包，无需修改任何 Rust 代码、无需任何编译，直接可以在游戏内正常驾驶和作战。
3. **功能与手感一致性**：
   * 战舰转向惯性阻尼、护盾阻拦弹药、幅能耗散手感与原版高度一致；
   * 现有战舰改装台（`NativeRefit`）、技能树和 UI 交互完全无缝可用。

## 七、 待核实事项与风险控制

1. **碰撞精度微调**：
   * 在阶段 1 压测中，对比圆包围盒+OBB 近似与原版多边形碰撞的手感差异，确保在视觉和受击判定上玩家感觉不出偷工减料；
2. **指令队列容量预算**：
   * Command Queue 和 Event Outbox 预分配固定尺寸（如各 64KB 环形缓冲），并在越界时提供安全截断与警告保护，杜绝任何动态内存再分配。
