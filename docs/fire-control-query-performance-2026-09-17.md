# 自动火控射线与拦截预测优化（2026-09-17）

## 本轮结论

保留本轮三处源码修改。百舰生产浏览器交替对照中，模拟均值 **134.030 → 114.689 ms/步（下降 14.4%）**，完整“模拟 + 视觉更新 + 渲染 + gl.finish”轮次 **161.001 → 141.543 ms（下降 12.1%）**。

百舰模拟 P95 为 **163.1 → 145.0 ms**，完整轮次 P95 为 **194.3 → 172.2 ms**。渲染提交均值 **26.918 → 26.800 ms**，基本不变；本轮修改针对模拟侧。

**仍未达到 100 艘战列舰 / 180 FPS。** 模拟步仍远超 60 Hz 的 16.67 ms 预算，渲染提交也远超 180 Hz 的 5.56 ms 展示预算。这不是原生 requestAnimationFrame/物理显示器 FPS 验证，不能将脚本轮次耗时直接换算成实际游戏帧率。

只使用本轮同一冻结源码图内的前后对照；基线已包含上一轮威胁预测优化及此前渲染、路径缓存和拦截优化。不同报告的绝对耗时存在运行差异，不能跨报告拼接出额外加速幅度。

## 重新剖析后的选择

先冻结当前工作区，再独立对百舰第 181–300 步进行 CPU 采样，并通过 source map 映射回源码。

- 模拟 step 的采样累计约 17.90 秒。
- `ShipWeaponControlSystem.update` 累计约 6.90 秒；`AutofireController.aim` 和 `decide` 分别约 3.85 秒与 2.87 秒。它们是嵌套调用，不能与父函数时间叠加。
- `assessThreats` 仍约 5.85 秒，尚有大量剩余成本。
- `shipSegmentEntry` 约 2.01 秒，`solveWeaponAim` 约 3.08 秒，`shotObstruction` 约 2.24 秒。

因此本轮处理自动火控的射线计算与临时对象，而不是继续减少画面效果。剖析数据只用于选热点，不作为加速测量。

原始剖析及映射结果：`artifacts/fire-control-broadphase/simulation.cpuprofile`、`profile-summary.json`。

## 源码修改

### `src/engine/math/Geometry.ts`

新增 `segmentPolygonEntry`：只返回命中参数 t，不构造未使用的交点和法线。

- 保留原多边形边遍历顺序、线段相交公式、平行判定阈值、闭区间条件、相等 t 的更新规则和末端在多边形内部的回退。
- 原 `intersectSegmentWithPolygon` 保持不变；需要完整接触点/法线的物理碰撞路径没有被替换成简化判定。

### `src/engine/ai/FireControlGeometry.ts`

- 为深度冻结的 authored hull bounds 同时记录保守 extent；可变/改装 bounds 仍逐次读取，不缓存可变几何。
- 在创建并旋转局部射线端点之前，先用世界空间保守包围盒排除远处舰体。extent 来自真实多边形坐标，**不是 collisionRadius**；任意旋转的原多边形都包含在该范围中，并保留坐标尺度相关余量。
- 保留下一级局部包围盒及精确多边形判定，仅将最后的多边形查询换成只返回 t 的等价路径。
- 没有多边形时仍用原圆判定，不再执行本来就不会使用的局部坐标旋转。
- 护盾仍独立执行原偏移中心、展开弧与精确接触判定；舰体包围盒未命中不代表忽略护盾。
- 新增标量 `interceptTimeComponents`；原向量接口委托同一稳定二次方程。等速/线性分支、有效根条件和最小根选择保持不变，但不再创建根数组及 filter 结果。

### `src/engine/ai/AutofireController.ts`

- `solveWeaponAim` 直接计算相对位置、相对速度和方向分量，保留原减法、平移、加速项的运算顺序。不会代数重排为 `targetPos + v * (delay + time)`。
- 返回的 AimSolution 仍拥有独立 point；不会把临时向量泄漏给保留的目标/候选列表。
- `shotObstruction` 在单次查询内复用 start/end，舰船与小行星仍按原顺序检查，原阵营、相位、战机穿透条件和首个阻挡结果不变。
- 没有改变选靶排序、同分处理、扫描间隔、火控随机流、射程、弹速、护盾覆盖或友伤规避规则。

本轮没有修改模拟频率、预警窗口、特效数量、渲染设置或游戏时间速度。

## 完整生产浏览器对照

两个独立页面逐步交替先后顺序，不并行推进；每场 360 个固定 1/60 秒模拟步，每步进行一次渲染，前 60 步预热，统计后 300 步。构建、剖析和其他 CPU 验证未与计时对照重叠运行。

## 等价性及最终工作区验证

独立于计时运行的 **134,000 组数值/查询对照**：

- 50,000 组稳定拦截解：标量与向量入口均用 Object.is 对照旧结果，覆盖等速、线性分支、无解、±0、NaN、Infinity 及极小/极大尺度。
- 30,000 组多边形 t：对照旧完整接触结果的 t，包括凹形、反序、重复点、段首/段尾落在顶点、零长度、非有限坐标和极端尺度。
- 30,000 组舰体/护盾射线：包括旋转舰体、超出 collisionRadius 的 authored bounds、偏移护盾、不同盾弧、负/无穷半径、深冻结/浅冻结/可变几何及原地修改点坐标。
- 12,000 组完整瞄准解：对照目标标识、种类、point、delay、speed 和 range，覆盖舰船/导弹、充能/连射状态、方向与射界、炮管索引和导弹剩余寿命。
- 12,000 组舰船/小行星遮挡结果：移动射手、移动阻挡物、不同接触时间与距离，原舰船顺序及逆序场景。

另外，双隔离 SSR 引擎运行 10 Onslaught 舰 360 步、6 Odyssey/Paragon 舰 240 步、6 Doom/Onslaught 舰 240 步、100 Onslaught 舰 240 步；每 60 步完整引擎和 AI 状态摘要一致。SSR 耗时未当作浏览器性能结果。

当前源码与计时候选快照一致。`npm run typecheck`、`npm run lint`、`npm run build` 通过；构建仍有大 chunk 提示。当前 dist 的十舰运行、WebGL 上下文丢失/恢复和资源释放检查通过，无页面/GL 错误。

没有恢复已移除的项目测试套件；辅助脚本、快照和结果均在忽略的 `artifacts/fire-control-broadphase/` 中。未进行资源哈希/大小审计。

## 剩余方向

自动火控仍会扫描目标和阻挡物，威胁预测仍有逐舰全弹丸/挂点工作。当前收益减少了单个候选的计算和分配，不等于解决大规模战斗的整体复杂度。下一轮应重新复核剩余热点，并针对可明确界定生命周期的预测/火控候选索引继续优化；不能以缩短预警、跳过安全检查或降低模拟吞吐替代算法收益。
