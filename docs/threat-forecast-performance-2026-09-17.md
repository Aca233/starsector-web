# 威胁预测热点优化（2026-09-17）

## 本轮结果与限制

优化模拟侧，而非再削减特效。百舰生产浏览器交替对照中：

- 模拟 CPU 均值 **152.756 → 126.751 ms/步**，下降 **17.0%**。
- 完整脚本工作轮次 **180.261 → 153.876 ms**，下降 **14.6%**。
- 模拟 P95 **190.0 → 153.1 ms**；完整轮次 P95 **220.7 → 183.6 ms**。

这是一个明确比上一轮渲染局部优化更有用的方向，但 **100 舰 / 180 FPS 未达到**。当前模拟步仍远超 60 Hz 的 16.67 ms 预算；渲染提交仍约 27 ms，也远超 180 Hz 的 5.56 ms 展示预算。不能把脚本轮次耗时直接换算成浏览器实际 FPS。

**本报告只比较本轮同一冻结源代码图的交替运行。** 基线已包含此前增量拦截、索引尾迹和路径缓存。不同报告的绝对耗时有较大运行差异，不能拿上一轮约 205 ms 与本轮 127 ms 拼出额外加速比例。

## 先剖析，再选择修改

当前生产源代码的独立百舰剖析，在第 181–300 个模拟步采样：

- 模拟 step 的采样累计约 20.83 秒；`assessThreats` 累计约 8.81 秒，约占 42%。
- `weaponMuzzle`、Vector2 克隆/构造、自动火控也是显著热点；导弹索引重建不是这一阶段的最大占比。
- 单独加入诊断计时后，12,000 次威胁评估中：弹丸预测约 4.34 秒、敌舰武器预测约 4.06 秒、护盾扇区选择约 0.14 秒。
- 该诊断阶段检查了 7,800,000 个敌方挂点，仅 903,063 个通过原有 approach-time 下界。没有因为扇区选择存在平方复杂度，就误将它当作本场景主瓶颈。

这些剖析/插桩时间只用于选择热点，不作为优化前后加速对照。

诊断代码仅在忽略的 artifacts 构建中；没有将计时插桩写入生产源文件。

## 保留的修改

### `src/engine/ai/ThreatAssessment.ts`

- 在单次评估内复用轨迹终点、相对位移和炮口三个 Vector2，不为每个弹丸/挂点重复构造它们。没有跨舰或跨帧缓存可变预测状态，也没有依赖新的失效时机。
- 按原始浮点运算顺序计算相对运动终点，然后用带余量的运动 AABB 排除明确无交集的普通弹丸。
- 包围范围包含原碰撞半径、近炸引信范围和坐标尺度相关余量；使用半径绝对值对应原二次方程的 radius²。
- 原二次方程、ETA、威胁插入顺序、累计顺序、护盾朝向和同分决策不变。
- 追踪本舰的制导弹不能仅因当前直线轨迹不相交就被丢弃，继续计算追击 ETA。
- NaN/Infinity 几何边界按保守方式继续原计算。非有限 horizon 禁用排除：尤其旧实现会在 `horizon=Infinity` 时记录 `ETA=Infinity` 的未命中条目，不能悄悄删掉。

初版边界对照发现了上述 Infinity-horizon 语义差异，已补充回退，并重新执行全部对照后才构建计时候选。

### `src/engine/ai/FireControlGeometry.ts`

- `weaponMuzzle` 支持可选输出向量，默认调用仍返回新对象；威胁评估使用其局部临时向量。
- 去除炮口偏移的中间 Vector2，保留原旋转、平移和偏移加法顺序。
- 继续只缓存三角函数，不缓存炮口位置；舰位、挂点相对坐标、炮塔方向和当前炮管偏移仍读取实时值。
- 负数/非整数炮管索引导致 offset 为 undefined 时，保留原 Vector2 构造器的零默认值语义。

本轮没有改变模拟频率、预警/泄能时间窗、武器能力、判定半径、特效数量或图像质量设置。

## 生产浏览器完整工作负载

RTX 5060，Chromium / ANGLE D3D11，2560×1440，DPR 1。Onslaught 舰队，固定种子 `0x51180`，同布局、同相机。两独立生产页面逐步交替先后顺序；每场 360 步，预热 60 步，统计后 300 步。每步含玩家 AI、完整 fixedUpdate、视觉更新、渲染和最后的 gl.finish。

构建、剖析、计时对照与其他 CPU 验证没有重叠进行。结果是一轮配对实验，不声称统计显著性；JIT、GC 和系统负载仍可能影响墙钟测量。

## 等价性与当前工作区验证

- **3,600 组威胁评估**，每组 96 枚混合弹丸：不同阵营、无明确阵营、已经命中、诱饵、制导与非制导、引信、寿命/射程/衰减、负半径、NaN、Infinity、不同 horizon、极小至极大数值尺度；完整输出深比较一致。
- **40,000 组轨迹边界评估**：切线附近、段首、浮点边界、移动观察者、近炸半径、负半径、制导追击、2^-500 至 2^500 尺度；完整输出深比较一致。
- **20,000 组炮口计算**：实时变更舰位/朝向、挂点位置、炮塔角度、炮管索引和偏移数组，覆盖负数/非整数/NaN 索引以及 ±0、NaN、Infinity 角度。默认与复用输出路径均与旧实现坐标逐项 Object.is 一致。
- 双隔离 SSR 引擎：10 Onslaught 舰 360 步、6 艘 Odyssey/Paragon 混合舰 240 步、100 Onslaught 舰 240 步；每 60 步完整引擎与 AI 状态摘要一致。
- 上表三个浏览器完整战斗的最终引擎摘要一致。SSR 耗时未被当作浏览器加速数据。
- 当前源代码与计时候选快照一致。`npm run typecheck`、`npm run lint`、`npm run build` 通过，仍有大 chunk 提示。
- 当前 `dist` 的十舰运行、WebGL 上下文丢失/恢复和资源释放检查通过，无页面/GL 错误。
- 没有恢复被移除的测试套件；辅助脚本、冻结快照和结果仅在忽略的 `artifacts/simulation-structure/` 下。没有进行资源哈希/大小审计。

## 剩余工作

本轮仍按舰扫描弹丸和敌方挂点，只降低了每个候选的成本并排除了部分精算。距离百舰高帧率仍有明显结构性差距。下一轮应先复核优化后的热点，再决定是否给预测引入有明确生命周期的候选索引、筛除远处不可达武器，或优化自动火控/遮挡查询；不能未经失效验证就缓存可变世界状态，也不能用降低模拟吞吐或缩短预警来替代算法收益。
