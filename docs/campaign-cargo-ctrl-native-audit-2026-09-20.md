# Ctrl 快捷货舱转移 — 编码前原版对照（2026-09-20）

## 证据与范围

- 原版 0.98a-RC8，`decompiled/starfarer_obf/com/fs/starfarer/campaign/ui/trade/F.java:410-476`：无手持时 Ctrl 直接转至对侧；向货舱取入时，正剩余空间先填满；已满/超载时可整组取入。移出时若超载，先移出超额，再点击才整组转移。剩余不到1时整组转移。
- 同文件425-428：船员/陆战队用共享人员容量，燃料用油箱，普通商品用货舱占用/每件空间；除数>0后正数截断、负数向下取整。`campaign/fleet/CargoData.java:199-205` 的 freeCrew/freeFuel 先转 int（向零取整）。市场 excess/deficit 是另一分支，不纳入无费用抛弃货舱策略。
- 实机1920×1080已看到船员149/140：第一次 Ctrl 点击后货舱140、下栏9、没有手持、左侧汇总9。保存的已有截图：`artifacts/native-cargo-ctrl-overload-20260920.jpg`。第二次点击后源栈消失、左侧149、HUD0/140，但画面被开始菜单部分遮挡，不能作为完整视觉验收。
- 用户随后要求使用电脑：立即停止桌面/键鼠操作，不再激活窗口或启动可见浏览器。原版测试转移未确认、未保存，已提醒用户可按T撤销；**不声称恢复了原版库存**。向内取入、燃料/普通货物边界本轮只有源码证据，实机验证待用户允许后再做。

## 实现方案

- 当前 Web Ctrl 明确未实现。新增独立可替换 cargoGestures 规则服务，不在 React 硬编码原版容量公式，也不改变 cargo.jettison 权威确认。
- 扩展已有认证只读 cargo-preview 查询：可附带快捷转移源栈，校验世界/控制权/舰队和完整成员版本、保留库存及源栈可用量，复用锁定 fleetStats 和 cargoGestures。读查询无回执、无库存写入。
- 状态机只执行已报价的分量跨栏转移，合并或首空格放入，保留不可变/精度/64种/4096槽保护。
- 等待报价只锁短暂货舱手势，不作乐观整栈移动；Esc/T可取消读请求，晚到响应、卸载、库存/成员版本变化或权限变化不能回写草稿。等待服务器是联机差异，不冒称原版单机零延迟。
- 先做来源/模型/真实Worker与HTTP验证，再用独立无头浏览器测交互/晚回包/截图，不占用用户桌面。既有数量条/普通转移/预览回归必须保留。
