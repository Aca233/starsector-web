# 舰船改装界面（以原游戏为准）

## 基准与本次纠偏

用户明确要求不要自行设计。视觉基准为提供的原作改装截图；交互依据本地原作界面代码，不再以自创工作台代替：

- `decompiled/starfarer_obf/com/fs/starfarer/coreui/refit/Q.java`：底部武器组、装配方案、撤消、清空装配、修复、模拟战斗、下一艘按钮。
- `WeaponPickerDialog.java`：挂点旁的右侧单列武器列表、左侧详细数据、当前武器、类型筛选、悬停参数、单击换装；不够装配点的武器禁用。
- `wgd2/WeaponGroupDialogV2.java`：842px 窗口、7 组分配、自动开火行、右侧射击模式/幅能表、自动分配、确认/取消。
- `ManageVariantsDialog.java`：当前装配名称、保存当前配置、读取/重命名/删除。
- `ModPickerDialogV3.java`：覆盖左侧舰船列表的展开式插件表格，右侧参数不进入模态遮罩；四列排序、分类筛选、点击安装/移除。

已撤掉自创的左侧工具栏、挂点清单、推荐装配入口。左侧只保留实际可改装舰船，中央/右侧/底部位置继续按截图。首页只有「舰船设计」。现有战斗使用 AuthenticTacticalConsole。

## 操作

- 左侧选舰：未修改可直接切换；只有相对打开时基准或已存方案发生实际修改才询问保存/放弃。仅打开插件、查看武器、打开编组后取消，不产生修改；撤消回初始状态后也不再询问。
- 鼠标移到舰船上显示挂点；左键打开挂点右侧的武器列表，单击安装，右键卸下。顶部当前武器条目可点击拆卸；内置武器不可拆。悬停更新左侧说明，按住 Ctrl 对比当前武器和候选武器，F2 打开原作背景资料。1/2/3 切换武器类型；左键点击外侧、右键或 Esc 关闭。
- 武器说明/战术应用来自原作 descriptions.csv 与 weapon_data.csv，伤害类型图标使用原作资源。当前没有仓库/市场，所以库存来源按钮禁用并有说明，不编造“100可用”等数量。
- 右侧调整幅能和插件；A 在左侧展开插件列表，右侧保持可操作。再次 A、返回按钮或 Esc 只收起列表。展开期间舰船挂点、舰船列表和底部改装操作不接收输入。
- 插件表格按原图保留「舰船插件 / 设计类型 / 装配 / 状态 & 需求」；列标题切换排序。类型来自原作 CSV 的 uiTags，筛选计数仅统计当前已实现的六项，零项分类禁用，不填充虚构条目。
- W 打开七组武器管理：自动开火行在编号表头上方，按武器类型染色，方形勾选格、挂载点/炮塔标签与实际射界图标。Q 自动分配、W/Enter 确认、T/Esc 取消；确认才写回，取消保持原配置。
- V 打开装配方案。保存当前配置；已有配置换名保存会另存为新方案，旧方案不被覆盖。支持读取、重命名、删除。
- T 清空装配，从空舰重新配置；U 撤消。Ctrl+S 快捷保存仍可用。
- G 的按钮恢复原作“修复”，当前无 D-插件损坏，故禁用，不拿保存功能冒充修复。
- N 模拟战斗；试战使用当前真实装备、插件和编组，返回后不保留战损。

## 内容与边界

目前仅包含攻势、典范、厄运；16 种可安装武器与攻势内置 TPC；6 种可编辑插件。这不是完整原版移植：未接入市场/经济、D-插件修复、S-插件、全部原作武器或原作全部自动装配方案。模拟对手选择仍是网页的有限三舰目录，不宣称已还原原作整套部署界面。

不为了对齐截图而伪造数值或把未实现武器替换贴图冒充原武器。默认配置是当前支持装备的可用配置，不标注为原作 stock variant。原作典范“突击”方案使用尚未接入的等离子炮、重型针刺炮、PD 激光，未冒充完整实现。

四个新插件的数据与效果来自本地 CSV / `data/hullmods/*.java`，普通安装（不含 S 插）：稳定护盾维持 ×0.5；强化护盾承伤 ×0.8、穿盾概率 ×0.5；幅散管道扩容排幅 ×1.25、EMP 损伤 ×0.5；幅能配送器主力舰耗散 +150。界面和战斗共用 effectiveHullStats。护盾维持以未加耗散通道的基础耗散计算，避免重复加成。

方案库使用 `starsector-web:design-studio:v1:` + BASE_URL，最多 100 份；草稿单独缓存。旧五组草稿保留原分组并追加两组空组。保留未知版本、损坏数据、跨标签页写入保护与 WebGL 失败返回。试战是隔离 GameSession，不写原作和舰队存档。

## 切换舰船界面闪烁问题修正（2026-10-12）

- **问题现象与根因**：在舰船改装界面（`?view=design`）点击左侧舰船列表或按 `X` 切换舰船时，整屏与中央舰体舞台会明显闪烁一下。排查定位到三处叠加原因：
  1. `StudioApp.tsx` 给 `<NativeRefit key={editorKey}>` 传 `key`、`NativeRefit.tsx` 给 `<RefitEditor key={identity}>` 传 `key`，导致每次切船或载入方案都整树销毁并重建 `<main className="native-refit-app">`、左侧 `HullRoster`（含全部缩略图与滚动容器）和右侧参数面板；
  2. `ShipStage.tsx` 的 `.studio-ship` 节点绑定了 `key={spec.id}`，且 `InstalledWeaponArt.tsx` 对未显式声明 `spriteWidth`/`spriteHeight` 的原版武器在 `onLoad` 触发前以 `width: undefined, height: undefined`（配合 `.studio-weapon-image { max-width: none; height: auto }`）渲染，导致每次切船重建 `<img>` 时武器贴图先以原始像素尺寸闪现一帧，且若复用节点而不缓存自然尺寸则会在舞台宽高变化时残留旧舰体的百分比尺寸；
  3. `EngineExhaustPreview.tsx` 的 WebGL2 尾焰预览 `useEffect` 依赖 `[engineParts, parts, ...]`，每次切船（乃至同舰修改配装）都会销毁并重建 `SpriteBatcher`、`RibbonBatcher`、`WebGLTextureManager` 并异步重新 `preload`，造成尾焰断帧闪烁与反复创建 WebGL 上下文。
- **修正方式**：
  1. 移除 `<NativeRefit>` 与 `<RefitEditor>` 上的强制重挂载 `key`，改为通过 `openRevision` / `identity` 在 `RefitEditor` 内部原位重置单舰瞬态 UI 状态（当前弹窗面板、选中槽位、甲板索引、缩放与平移、编组高亮、提示与悬停浮层），保持外层框架与左侧舰船列表 DOM 常驻；去掉 `AssemblyThumbnail` 的 `loading="lazy"` 避免列表缩略图重解码闪烁；
  2. 移除 `ShipStage.tsx` 中 `.studio-ship` 的 `key={spec.id}`；在 `InstalledWeaponArt.tsx` 中按贴图 URL 缓存自然宽高（`naturalWidth`/`naturalHeight`），已缓存或已知尺寸时直接在 React `style` 中计算当前舞台百分比宽高，首次未测量完成的武器贴图在 `onLoad` 写入尺寸前保持 `visibility: hidden`，彻底消除未缩放武器贴图闪现；
  3. 将 `EngineExhaustPreview.tsx` 拆分为常驻 WebGL2 上下文/批处理器初始化与场景参数更新：复用同一个 `WebGLTextureManager` 与上下文，贴图已命中 `textureCache` 时同步重绘，首次加载新舰体贴图时先清屏再异步 `preload` 完成后绘制。
- **验收方法**：运行类型检查与改动文件 `oxlint`；使用无头浏览器在 `?view=design` 连续切换多艘舰船，核验 `.native-refit-app`、`.refit-roster-results`、`.studio-ship` DOM 引用在切船前后保持同一节点不销毁，且无未缩放武器贴图闪现与控制台错误。
