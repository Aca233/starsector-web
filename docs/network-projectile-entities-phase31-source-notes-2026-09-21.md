# Phase31 原生弹丸实体修订：实施前对照（2026-09-21）

## 证据与约束
已读原版DamagingProjectileAPI.java：source、weapon、damage、didDamage、elapsed和fading各自独立；tpc_shot.proj为BALLISTIC_AS_BEAM，尾长100、fadeTime=.3，不能删掉尾端/伤害状态。没有桌面操作许可，不新增原版实机/UI等价声明。本轮不改运动、伤害、碰撞、渲染精度、目标Hz，不碰生涯或其他任务AI改动。

现有CaptureProjectiles先captureProjectileProjection完整pack/压列，再expandSnapshotProjectiles展开，再由ProjectileEventStream进行canonical/image/digest。不能把该多重全量遍历直接启用作优化。默认LAN/Steam的快照在生产/发送/接收/呈现均可被合并跳过；上一帧增量不能直接套用。旧visual通道还受50ms间隔、默认关闭、量化/预测互斥限制，不作为本轮捷径。

## 最小实现合同
原生权威图直接生成拥有自己存储的声明式字段视图：新增实体捕获全部字段；存量深比较已捕获字段，只分配变化的子树；死亡移除；维持ID及顺序。复制当前P1省略合同，测试必须与原capture+expand逐字段等价，不能新增省略。未知类型、cycle/Ship引用等不猜测，返回fallback，不损坏已有基准。

基准包和累计create/update/remove/order包分离。每个update相对同一已确认基准，不依赖前一个update；允许跳过全部中间更新。prepare不提交，只有传输接纳后commit；reset/失败不推进基准。接收先校验全部key、类型、数量、深度、成员、顺序与epoch/anchor，再原子提交；输入/输出不得与源状态共享可变子树。缺基准返回明确错误供原有全量恢复使用，不能应用半个包。

## 验证与启用规则
- 原生22舰轨迹P1字段等价、出生/死亡/重排/字段新增删除、嵌套可变值、特殊number、随机数不变。
- 丢弃prepare、跳中间更新、未知基准、错epoch、过期/重复、损坏字段与输入别名测试。
- 捕获+编码+解码+接收应用总成本对照旧实体管线，保存负结果；局部数字不得冒充完整联机收益。
- 生产接线必须保证每个peer已拥有正确anchor（不能把主机capture/传输ACK当作客机已应用）。当前服务器并不提供该实体基准的确认合同，未完成该部分之前不把实验插入默认路径或声称联机已改善。不能为了“快速”制造基准丢失/重连循环。
## 首个纵向实验的自包含变体（编码前补充）
为避免把LAN/Steam两套ACK改造成隐含新增前提，首个纵向实验采用**自包含基准胶囊**：基准用现有压列快照编码一次、base64随帧携带；已有可靠字节增量可复制该不变片段。更新只包含相对该基准的实体新增/字段修正/删除/顺序。客户端基准缓存只是加速，清空缓存或跳任意中间帧仍能从当前帧重建。不是已经实现“基准只发一次”的最佳带宽版本；必须核对cold包、基准轮换与总wire成本，不达标不接入默认路径。
预测只作为无损编码参考，使用现有ProjectileEventStream.reference的1/60重复加减顺序，并发送全部差异纠正，不用于命中/销毁推断。默认客户端应用验证当前viewer值，静态字段被renderer/mod修改也会覆盖，不能跳过必要恢复。
预设性能门槛：完整22舰同源轨迹A/B与B/A，至少120个测量tick，3及5个离线接收副本；每副本数总CPU P50至少减少5%、P95不恶化超过10%、总压缩wire不增加；所有非弹丸语义不变。失败保留，不调小阈值。最多先做这一条，不开启旧visual量化路线。

## 实验后澄清
上文“基准分离 + prepare/commit + peer 应用确认”是最初考虑的生产合同，并未在本轮实现。实际测试的是随后列出的**自包含胶囊**变体：每包独立完整，因此捕获可立即推进私有缓存，放弃捕获不会破坏后续包；接收缓存提交仍在完整校验后。生命周期序号过滤沿用调用者，未新增 epoch/过期包拒绝承诺。最终完整管线门槛失败，未接生产，详细负结果见 `network-projectile-entities-phase31-2026-09-21.md`。
