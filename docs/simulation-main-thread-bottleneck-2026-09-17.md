# 主线程瓶颈复测：本轮没有新增可靠提速（2026-09-17）

## 结论与当前代码

**本轮未验收新的运行时优化，不能宣称“提升太小”的问题已经解决。** 数值校验影子数组、融合射线查询、额外船体平方距离索引均已撤回。此前验收的 AI 多核、导弹索引、协议优化及最近边界索引保持不变。

撤回前逐文件核对当前内容与本轮冻结候选完全一致，只从本轮冻结基线恢复自己的文件，不恢复 Git HEAD，也不覆盖其他任务修改。没有降低模拟/AI/武器频率，没有跳步、增加 dt 或改用 Float32。

## 整步对照结果：拒绝保留不稳定的小收益

所有数据均为 100 艘默认原生 Onslaught，双方四个 Workers；各轮预热 60 步、计时 180 步，同种子、dt=1/60，逐步交替两版先后，第二轮反转初始顺序。计时包含玩家 AI、打包、分发/等待、验证、合并、回退及主线程剩余模拟。构建、性能测试、诊断均串行。

| 实验与轮次 | 基线 ms/步 | 候选 ms/步 | 整步吞吐变化 | 处理 |
|---|---:|---:|---:|---|
| 私有数值影子数组 1 | 90.15619 | 89.42319 | +0.820% | 高背景负载，不作为稳定收益 |
| 私有数值影子数组 2 | 45.56283 | 45.74719 | −0.403% | 撤回 |
| 融合参数射线查询 1 | 38.61606 | 37.75639 | +2.277% | 需复测 |
| 融合参数射线查询 2 | 37.02631 | 37.76953 | −1.968% | 撤回 |
| 射线查询 + 船体平方距离索引 | 38.64533 | 39.14822 | −1.285% | 撤回 |

不同实验/轮次的绝对耗时不能作为累计优化对比。数值影子首轮存在明显主机负载干扰；其他轮次也有波动，未停止任何无关进程、未调整其优先级。**上述百分比不是上线收益，更不能相加/相乘；没有获得新的屏幕 FPS 数据。**

- 数值影子保存独立于 SharedArrayBuffer 的权威原值，不把可被 Worker 改写的共享数据当校验基准。专用诊断 3,552,060 条断言通过，包括 12 个共享线损坏案例，但收益不成立。
- 几何候选避免射线候选边数组/排序，并用独立的原始平方残差公式查询船体距离。不是用爆炸 Math.hypot 距离替代另一套算术顺序。326,743 条 Object.is 断言通过，92,956 个射线、92,956 个距离、24,057 个舰船查询组合和 9 组回调/访问器兼容案例通过，但仍不满足性能要求。
- 五次整步筛选共 110 条完整状态哈希记录一致；包含 Autofire WeakMap 中的隐含目标、扫描定时与私有 RNG 状态。
- 被拒绝的几何组合只做了上述有界检查，没有冒称完成三轮性能验收或延长到 tick 660。

## 新的主线程热点数据

单独对撤回数值影子后的基线采样：i5-13490F、16 逻辑处理器，100 舰、4 Workers，60 步预热 + 180 步采样。主线程 CPU 采样期间不执行诊断状态序列化，避免把哈希/图遍历计入游戏热点。

| 阶段 | 平均 ms/步 |
|---|---:|
| 整步 wall time | 42.878 |
| 主线程舰炮控制（ship.weapons） | 13.611 |
| 主线程弹丸系统（weaponSystem.update） | 8.473 |
| 主线程快照打包 | 3.959 |
| 主线程快照校验 | 2.792 |
| 等待 Workers | 8.318 |

这些值来自**有 CPU 采样及阶段插桩的诊断**，用于定位，不用来宣称性能提升。阶段表不是 CPU 使用率；Worker kernel/sync 包含在等待过程，不可再相加。舰炮控制亦包含在 ship.update 中，未重复列出其父阶段。

- 四个 Workers 并非未启用：每步平均接受 97.3 个 AI 结果，回退 1.7 个（共 99 个非玩家 AI）；最大 Worker kernel 平均 6.253 ms，最大同步平均 1.419 ms。
- 主线程自身的舰船运动只有约 0.201 ms/步；单独把位置积分搬去另一线程不是当前最大的机会。
- 更重的是瞄准候选筛选、友军遮挡、精确目标射线以及弹丸推进/碰撞。舰炮控制 + 弹丸阶段合计约 22.08 ms/步，占本次整步约 51.5%。
- 因此，增加现有 **AI** Worker 数量不会并行这约 22 ms 的工作。即便理想化地消除本次全部 8.318 ms 等待、其他成本不变，整步仍约 34.56 ms；这是诊断数据的理论推算，不是可实现或已测得的新优化。

## 后续工作的实际边界（尚未实现）

要突破当前收益，需要处理舰炮控制/弹丸模拟本身，而不是继续堆 AI 线程或保留没有稳定总收益的数学快路径。不能直接把完整 ship.update 平均分到多个 Workers 后宣称无损：舰船更新读取的是按顺序变化的世界，发射、组件故障、散布等还依赖同一个权威 RNG 与回调顺序。

可继续研究只读火控计算与主线程按原序提交的拆分，但其快照、依赖校验、失效回退以及 RNG 边界还需要实际原型与整步对照验证。本轮没有实现此架构，也没有将改成每舰 RNG 或快照式战斗时序偷偷作为“无损优化”上线。

**100 艘战列舰 / 180 FPS 仍未实现；本轮没有新增已验收提速。**
