# Weapon Fidelity Parameter Mapping

This file records source-to-web mappings that are confirmed enough to implement. It deliberately separates data transport from visual interpretation.

| Source concept | Web contract / renderer | Status | Notes |
| --- | --- | --- | --- |
| projectile length / width | `WeaponSpec.projLength/projWidth` -> `Projectile` -> projectile render pass | implemented | TPC and Autopulse now use per-ID visual profiles with `trailScale=1` and `glowScale=1`, so confirmed source dimensions are not enlarged a second time by the TPC family profile |
| RGBA projectile fringe/core | `fringeColor/coreColor` | implemented for source-authored projectile strips | WebGL and Canvas preserve configured alpha instead of discarding the fourth channel. A weapon-animation `.wpn glowColor` (for example TPC mount glow) is not reinterpreted as projectile glow; a projectile `.proj glowColor/glowRadius` (for example Heavy Blaster) is a separate source-authored in-flight halo contract |
| signed texture scroll | `textureScrollSpeed` | implemented for pulse, beam and source ballistic strips | WebGL and Canvas use the configured sign directly. Canvas no longer stretches one whole texture over every projectile/beam; it wraps source slices with the same signed phase convention as WebGL |

## Explicit non-mappings

- `fadeTime` is not used to keep a projectile collidable after its normal simulation lifetime.
- Visual dimensions are not assigned to damage radius or collision radius.
- Weapon animation `glowColor` is not interpreted as a per-frame projectile halo for `BALLISTIC_AS_BEAM` shots.
- No damage, range, refire, projectile speed, collision, guidance, or beam-damage-duration values were changed in this batch.
- Ballistic source `fadeTime` metadata does not extend the projectile collider or damage lifetime.
- `visualSpawnType` is renderer-only and must not be consumed by collision, damage, range, fuse, or lifecycle systems.
- Beam source chargeup/chargedown metadata does not alter fire-control cadence, damage duration, refire delay, or Beam simulation lifetime in W05.
- Render-time sustained-Beam deduplication is not simulation deduplication and must never be used to suppress damage ticks or sound events.
- Launcher smoke, missile engine dimensions/colors and missile trail parameters are visual-only fields and must not be consumed by guidance, acceleration, collision, damage, fuse, HP, or lifetime logic.
- Missile `projLength/projWidth` and trail width are display geometry; they are not aliases for collision radius, explosion radius, or damage radius.
- Missile top-level `.proj explosionRadius/explosionColor` are stored in `missileExplosionVisualSpec` and are visual-only; they are not aliases for `explosionSpec.radius/coreRadius`, proximity-fuse radius, collision radius or damage radius.
- `.proj hitGlowRadius` is never used as an explosion/fireball radius. It owns only the independent hit-glow layer.
- Target Beam `.wpn` files without `hitGlowRadius` do not receive invented per-weapon source radii; width-based endpoint-glow sizing remains a Web PROVISIONAL fallback.
- Reaper remains unguided in W06. Atropos is the guided-turn acceptance sample; Sabot's current Web two-stage behavior is observed, not silently replaced with source MIRV mechanics.
- Shield impact presentation never substitutes visual fireball size for damage/collision radius, and suppressing a shield fireball does not change absorbed damage or flux.
- Beam contact FX/audio cadence is not a damage cadence: it must never skip or combine Beam damage ticks.
- Heavy Blaster `visualSpawnType=BALLISTIC_AS_BEAM` does not convert its Web projectile collision to source `RAY` behavior.
