# 联机表现层本地化审查（2026-09-18）

## 边界

用户确认尾迹不必逐点一致，并要求检查还有哪些内容适合各客户端自己算。目标是把纯画面计算与传输从房主 Worker 移到观看端；不是把碰撞、伤害、制导或胜负交给各客户端。不得直接关闭整个 CombatFXSystem：其中 hulkFragments 的位置、朝向和边界会参与 ProjectileCollisionHandler 的遮挡与碰撞。

## 本轮已实现：连续导弹烟雾尾迹

- host.worker.ts 在创建权威世界后禁用 ContrailEngine，并以 localContrails=true 捕获快照；world 不再传 contrailEngine。
- LocalContrails.ts 在房主显示窗口及客机上，根据同一显示插值位置、本地 SnapshotPlayback.visualTime 采样。不会执行 fixedUpdate、制导、命中或消耗模拟随机数。
- 每 60Hz 显示时隙最多采样一次，高刷新率不会三倍生成尾迹；卡帧后不追补大量旧点。暂停/快照饥饿时随显示时钟冻结。
- 保留来源定义的喷口、偏移、寿命、宽度、扩散、颜色、混合模式和最小间距；显示端帧率/网络条件不同，具体烟带采样点允许不同。
- 导弹消失或失效后脱离并淡出；位置大幅跳变分成新烟带，不连成长线；失去同步、重新同步、显示时钟回退或大跳跃时清空旧烟带。
- MissileContrails.ts 只抽取原有视觉采样公式；单机默认继续启用原来的权威尾迹路径。
- 协议 22 → 23，仍保留构建号校验，不能混用新旧入口。没有修改 SnapshotPlayback / MotionPrediction 本身、物理 dt、舰数、AI/伤害规则或恢复预算。

之前尝试的逐点紧凑编码已撤回，新的 $trailPoints 格式和二进制扩展都没有交付。BinarySnapshot.mjs 未修改。相应忽略目录里的实验结果仅作历史，不代表正式实现。

## 已在本地运行，不应重复改造

- 舰船/导弹喷焰的实际几何绘制、闪烁/噪声采样：ShipEngineRenderer、MissileEngineVisuals、RenderDeterminism。推力、损坏、系统状态仍需要权威来源，不能连 engineController 一起删掉。
- 镜头跟随、缩放、HUD、渲染插值、视觉纹理等。
- 屏幕震动的随机偏移已在 WebGLCombatRenderer 本地算；同步的是强度标量，优先级远低于大批粒子。
- 音效已经由房主发有 ID 的一次性事件，各客户端本地播放和定位。

## 必须继续权威同步

舰船/弹丸/导弹的位置与存活、AI/导航、制导、碰撞、伤害、装甲、幅能、护盾判定、武器弹药/冷却、舰载机及水雷、战斗结果；还包括会挡弹的大型残骸与小行星。星云/地图等静态数据可考虑加载时一次同步，但不等于允许各端自行生成不同的影响战斗的地图。

## 实施事件式 FX 前的必要工作

1. 稳定事件 ID、权威发生 tick、样式与参数；允许视觉随机形状不同，事件本身不能被重复播放或凭空创造。
2. 当前快照链路会主动丢弃过期快照，短寿命效果不能只出现于一张可能被跳过的帧。需要有界事件保留、去重、过期策略及重连基线，而不是每粒子每帧同步。
3. 先分离纯视觉随机流与影响实体/残骸的随机流。当前 visualRandom 被 FX、舰船、舰载机、残骸等共同使用，删除粒子调用可能改变后续随机序列；不能简单把所有 spawn/update 置空。
4. 小块 debris 是视觉粒子；hulkFragments 虽存放在 FXSystem，却会移动并参与弹丸碰撞，两者必须拆开处理。
