## Expected behavior → current difference → implementation contract
- State: existing object fields are sole owners; experimental CombatKinematicsStore copies poses at stage boundaries. New core instead holds permanent numerical rows. Native Ship/Vector2/Flux/weapon property descriptors alias those rows, without per-step import or commit-copy. Identity, enumerable order, Boolean types and Vector2 methods remain unchanged. Removed/fallback entities materialize their last values before slot reuse.
- Motion: preserve exact existing command arithmetic and per-entity order. Core computes directly in owned rows; modules/stations keep parent-relative rule adapters. Unknown field accessors, motion/vector overrides and unsafe component readers retain the ordered object path, rather than overwriting custom writes.
- Fire/effects: keep the existing all-queries-before-emissions boundary and original Web resource/effect order. Rule methods write the same canonical memory through adapters. Armor, projectile, AI and system rules are NOT rewritten or claimed parallel in this slice.
- Collision: replace the full object pair scan with a numerical spatial index, queried in the original i/j order. Reindex after each candidate's response, including both complete assemblies, and requery the remaining j suffix. A static pair list is unsafe because earlier displacement can introduce later pairs. Nonfinite/oversized coordinates conservatively fall back to all candidates. Exact geometry and damage remain existing ordered rules.
- Networking: existing motion wire frame reads canonical rows directly; complete snapshots retain their current layout and use compatibility descriptors. No new client-owned authority.
- Lifecycle: generation-checked handles, buffer growth preserving aliases, removal/detach/dispose, descriptor/identity changes and custom callbacks need explicit tests. Core is engine-private, not serialized into saves/snapshots.

## Implementation boundary recorded during verification
- Native armor's own `cells` descriptor is constructor-certified in Ship's existing private reader registry. It is not mistaken for an arbitrary getter and is not migrated/modified by the core. Copied descriptors alone cannot certify a new object.
- Shared numerical accessors use a non-enumerable private Symbol view to reach canonical buffers directly. WeakMap certificates separately verify object/view/descriptor identity; numeric state and Symbol metadata do not appear in snapshots. First implementation's per-read WeakMap/Map lookup failed performance acceptance; this is a targeted bridge repair, not evidence that object-driven AI has been replaced.
- Collision admission audits only relevant native damage/shield/assembly hooks plus engine FX method identities. An unrelated AI range/forecast allowlist must not silently disable all indexed contacts. Unknown cross-entity damage/FX hooks retain the full ordered pair loop.
- Canonical schema: pose 6 scalars; history 3; hull HP and dead/retreated; ten FluxTracker numeric/Boolean fields; sixteen required numeric fields per weapon mount (angles, cooldown/burst/state clocks, cycle, ammo/recharge, recoil/glow/barrel/spread, health/disable clocks). Optional fields, string firingState, trigger flags, armor cells, system internals, AI intents and projectile state remain with existing rule owners. This is a real but partial core migration, not a completed new whole-world engine.
- Rollout is explicitly opt-in: `VITE_COMBAT_STATE_CORE=true`; unset/false keeps normal state owners. The older numeric-motion experiment and query-read comparison switches preserve their meanings. Core diagnostics report buffer bytes only, not total heap/descriptors.

## Late detach boundary
A concrete freeze reproduction showed that Object.freeze on an admitted object makes native adapter descriptors non-configurable. Replacing them with data properties is then illegal. Such surviving adapters now retain retired (never-recycled) numerical rows; normal configurable fields still materialize. This conditional retirement is a lifecycle fallback, not a new gameplay state or successful performance workaround. It passed the final seven boundary checks; complete timing was not repeated after this repair.
