# AI / 火控与离线学习底座（2026-09-18）

> 本文保留初始 v1 单挑底座的历史记录。当前已升级为 v2 舰队观测与分离的训练/验证/留出对战，见 [原 AI 上的舰队学习](ai-residual-fleet-learning-2026-09-18.md)。旧权重不兼容；旧销毁抑制选项已取消，相关早期试跑不应作为长对局证据。

## 当前状态

本轮优先建立可验证的底座，不替换已有战斗安全控制，也不宣称训练出更强的完整 AI。

- 现有规则增强：自主火控按伤害类型与迎弹面的护盾状态、残血/过载机会、弹药提示、转炮成本评分；保留目标只有有限加分。手动模式仍优先玩家选中的目标。
- PD 同等级导弹目标中，迫近撞击优先于“已经锁定”。合法性、射程、实际炮口追踪、友伤和障碍物检测仍由原控制器负责。
- 接敌距离加入低船体与局部兵力劣势的保守修正。航母站位、炮兵角色、紧急幅能储备不允许被学习动作突破。
- 学习策略默认 **关闭**：`src/engine/ai/learning/combat-policy.json` 是明确的空基线，不是假装训练完成的权重。
- 没有引入训练依赖、在线探索、后台训练、网络模型下载或存档修改。未恢复旧测试目录/测试框架；检查沿用现有独立 `scripts/check-*.mjs` 形式。

## 边界和接口

`CombatPolicy.ts` 定义可替换的策略层：

- 54 个离散观测：自身幅能 3 档 × 自身船体 2 档 × 可见敌舰的攻击窗口 3 档 × 舰体基础速度比 3 档。
- 4 个有限动作：BALANCED / PRESSURE / FINISH / CAUTIOUS，仅修改接敌距离、压盾和收割的偏好，不能直接发射武器或控制排能、护盾、转向。
- 不合法、友军、死亡或不可见目标不生成观测。
- 运行时只做确定性查表；不消耗战斗随机数。未见状态、默认动作或候选动作样本不足、收益差过小均回退 BALANCED。
- 模型加载时校验版本、特征定义、动作顺序、有限 Q 值、访问次数和阈值。不兼容模型整体回退。
- 默认动作与候选动作都至少访问 8 次，且优势至少 .03，才允许候选动作。这只是实验置信门槛，不是上线性能保证。
- 生产权重随构建打包，主线程/Worker 不在对局中独立更新模型。训练覆盖用 WeakMap 绑定隔离的模拟舰船，不支持作为联网热切换接口。

火控安全判断、舰船防御、碰撞规避、玩家指令继续由原来的模块拥有。策略只提供建议，不能绕过 `AutofireController.decide` 或玩家的航点/撤退流程。

## 训练和复现

在项目根目录执行：

```powershell
npm run ai:check
npm run ai:train -- --episodes 24 --seconds 45 --eval-pairs 12 --seed 1729
npm run ai:evaluate -- --model artifacts/ai/latest/candidate-policy.json --seconds 60 --eval-pairs 24 --output artifacts/ai/evaluation
```

需要 Node 22+（本轮使用 Node 24），无需浏览器、GPU 或 Python。通过已有 esbuild 打包真实 `CombatEngine`，模拟物理 60 Hz，每秒一个策略动作；双方都由真实 `CapitalShipAI` 操作，不是另写的简化战斗公式。

当前课程是 lasher / wolf / hammerhead 三种同型单挑、交换学习方，使用确定种子改变初始横向位置。清除地形，但不修改武器、船体、护盾或伤害参数。

- 算法：表格 Q-learning，alpha=.12，gamma=.97，epsilon 从 .35 降到 .10；终止转移不自举。
- 回报：敌我归一化船体损失差、击杀/阵亡、过载时间、小幅时间惩罚。没有“开枪次数”奖励，超时不记胜利。
- 评估：独立种子；规则基线与候选采用同一场景、种子和阵营，不更新 Q 表。
- 报告：每局结果、收益、双方剩余船体、非基线动作次数、超时、模型及模拟器打包摘要、Node 版本、训练参数。
- 输出默认在忽略版本控制的 `artifacts/ai/latest/`，**不会覆盖运行时模型**。`--model` 可继续训练已有候选；`--episodes 0` 仅评估。

## 本轮验证

- `npm run ai:check`：14 项检查通过，包括模型校验/回退、终止转移、可见性、手动所有权、武器目标匹配、航母/紧急距离限制、友伤/障碍物/幅能/弹药门禁、迫近导弹优先、指令优先和模拟确定性。
- 6 局训练，每局最多 30 秒；6 组成对评估，双方阵营各覆盖一次；完整重复运行检查模型、训练轨迹和评估结果一致。
- 短跑覆盖 10 个观测状态，评估出现 63 次非基线动作，证明训练到推理的链路实际执行。
- 6 组评估全部超时，双方胜利数均为 0；平均收益差约 +.281、归一化船体差约 +.094。样本太少且没有完成战斗，**不构成胜率提升或可上线证据**。保留默认关闭。

## 已知局限和下一步

1. 单挑课程不足以训练多目标火力分配；目前 learned fire-target 权重只是接好接口，不能声称已训练出有效多目标选择策略。需要 2v2/3v3、护航、航母、相位、混合射程和多阵营课程，以及相应团队奖励。
2. 观测未包含装甲分布、在途火力、友舰掩护、武器阵容和局部危险场；离散状态也会在阈值边缘切换。以后加入稳定的决策周期/记忆时需同步 Worker 状态和一致性验证。
3. 先增强规则基线：在途弹药/光束伤害预算防过杀、按命中时间分配 PD、错峰排能与交接火力线、候选接敌位置的射界/风险评分、可解释的决策诊断。
4. 扩展独立场景集和足够长的完成战斗，比较规则前后胜率、战损、弹药效率、己方遮挡时间、过载时间及 CPU 成本。当前检查不是对所有联网/多核路径的完整性能验证。
5. 模型只有在广泛评估和安全复核后才应写入打包 JSON 并重建；无需现在启用。后续 PPO/小型网络也应复用这些边界，而不是接管安全门禁。
