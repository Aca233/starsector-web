# 联机战斗报告（2026-09-17）

## 操作与显示

- 正常结束后显示胜利、失利或平局，由自己的参战队伍判断；不再将一艘敌舰的结构读数当成敌方整队战果。
- 按队伍展开主舰名册，包含真人、AI、未出场后备。显示在场、撤退中、已撤离、未出场、已损失，以及部署点、剩余结构、战备。
- 队伍摘要显示在场/损失/撤离/待命数量及损失舰船的DP；撤退中计入在场，舰载机不计入主舰名册。
- 不推算伤害、击杀、奖励或可回收战利品。中断没有完整结算，不冒充胜负或展示过时HUD作为最终结果。
- 返回房间不修改参战配装；房间中可再次打开“上一局战报”。报告由服务端保存到下一局开始，可在同房间重连后取回；不是跨房间/跨服务器重启的永久战绩库。
- 返回按钮不依赖连接就绪；断线时仍能离开结算面板，返回后按房间当前连接状态处理。

## 数据与权限

- 主机 Worker 在胜负终态生成独立 BattleReport。其来源是完整主舰名册及部署状态，不读取客户端HUD采样。
- 终态报告随 finish 可靠消息提交，不依赖可能被背压跳过的最后一帧渲染快照。发送失败可重试；服务端按同一对局幂等重放。
- 服务端只允许主机提交，校验队伍/席位/名单完整性、唯一ID、状态和数值范围，并与已接收快照的身份名单对照。复制投影后保存并广播同一份结果。
- 旧对局的迟到 finish 不影响新对局；正常结束后的迟到 state 不改写结果；中断不携带上一局报告。
- 主机仍是计算权威；上述校验不是独立服务端反作弊或重新模拟战斗。
- 沿用16 MiB通信安全预算，超大报告明确失败，不无限停在等待结算。
- 协议随当前变更升级。旧后台需要重启，各客户端刷新并重新建房，不能混用旧协议。

## 验收边界

未新增测试源码或测试运行器；使用 esbuild write:false、Node stdin、独立内存 VM、临时本机服务和浏览器内存页面。

- 三队八艘名册：终帧结构/CR、后备、撤退、损失、席位对应、错误名册/重复ID/非有限数值/旧帧拒绝通过。
- 实际 Worker 源在内存中执行，通过构造败方终态触发正式结束路径，输出正确胜者和完整四艘报告。
- 真实双 WebSocket：非主机拒绝；故意不发送最后渲染快照，报告仍包含最终结构；双方报告一致；重复 finish 幂等；同席位重连重放；旧对局忽略；下一局中断不混入旧结果。
- 实际战报组件：三队六艘状态展示、展开对方队伍、返回回调、中断不显示结果表通过；390px窄屏无页面横向溢出，返回按钮可见。
- 最终类型检查、lint、服务端语法和生产构建通过；构建保留既有的大分包警告。
- 上述并非两台物理电脑自然打完整局的全链路验收，也不包含长期大规模性能测试。
