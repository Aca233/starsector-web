# 局域网无损二进制快照（2026-09-18）

## 目标与选择

继续降低前台联机的传输和房主编码开销，不删舰船/特效、不降低模拟或同步频率、不量化数值。

先检查了批量记录的常量列去重：实际 8 舰样本仅减少约 1.1%，没有启用。另做了同步 gzip 原型测量，但没有把额外压缩/解压、调度和 Steam 双重压缩引入本轮。

最终采用 `@msgpack/msgpack` 3.1.3，对已有的自包含展示快照做二进制序列化。没有改变 CombatSnapshot 的字段字典、批量记录、舰船引用或恢复语义。代码已接入 LAN 路径；Steam 保留原有的 JSON + SteamPacketCodec 压缩路径。

## 实现

- `src/network/BinarySnapshot.mjs` / `.d.mts`：二进制帧、状态封装、兼容性回退与解码前边界检查。
- 房主 Worker 只编码一次，使用 transferable ArrayBuffer 交给主线程，不结构化克隆整棵世界对象树。编码器返回拥有独立存储的副本，下一次编码不会修改已发送缓冲区。
- LAN 消息使用 `SWB1` 标识、小型 JSON 对局/序号头和二进制帧。房主本地显示从同一份二进制帧解码；服务器校验后复用收到的原始字节转发。
- 浏览器 WebSocket 设置 `binaryType = "arraybuffer"`，同时继续接收普通 JSON 控制消息及 JSON 快照回退。
- 只允许已握手的 LAN 房主发送二进制状态；对局 ID、单调序号、帧 tick、舰船名单、部署和结算的已有验证继续生效。Steam 传输不接受该二进制上行。
- 继续保留上一轮的后台过滤、未加载过滤、接收者积压节流、房间验证摘要。没有修改 SnapshotPlayback、MotionPrediction、物理 dt、AI 或伤害规则。

### 精度、边界与内存

- 不启用 float32 强制转换。JavaScript 数值维持原有精度；安全整数与浮点分别按 MessagePack 的无损表示编码。
- 省略对象中的 undefined，与原 JSON 语义一致；投影中已有的 `$undefined`、`$number`、Vector2、Map、Set、typed array、Ship 引用标记照常保留。
- 单独出现的 UTF-16 代理项、原始非有限数等罕见情况回退 JSON，避免 UTF-8 替换字符或改变旧编码语义。已有显式非有限数标记仍可走二进制。
- 保持 16 MiB **整条通信消息**预算，封装头也计入；头长度最多 1024 B。
- 解码前扫描标记、剩余长度、容器声明长度与嵌套深度（最多 128 层），拒绝截断、尾随数据、短输入声明巨大数组/字符串等。单个 map 最多 65,536 项。不接受扩展、时间戳或原始 binary 类型；本协议只接受 JSON 形状的数据。
- 拒绝非字符串键与危险对象键。展示还原原有的深度、布局、数组和引用校验没有删除。
- 解码器按调用创建，避免 SDK 的最后输入缓冲区及异常时的部分对象栈长期保留旧帧；SDK 自身有界的字符串键缓存仍共享。内存仍随有效帧大小增长，这不是固定进程 RSS 保证。

协议升至 **21**。LAN/Steam 都须使用同一套更新后的服务与页面；保留 JSON 读取器不意味着旧协议客户端可以混入新房间。

## 同帧测量（最终受限实现）

输入是此前真实 8 舰交火的 tick 1804 帧。浏览器端两轮、每轮预热 40 次、150 个交替先后顺序样本；最终实现包含兼容性扫描、解码预检查和请求局部解码器。

| 项目 | 原 JSON 路径 | 二进制路径 |
| --- | ---: | ---: |
| 帧大小 | 813,043 B | 479,855 B |
| 编码均值（两轮合并） | 6.513 ms | 4.367 ms |
| 解码均值（两轮合并） | 2.827 ms | 2.860 ms |

- 该帧体积减少 **40.98%**。
- 房主编码均值减少约 **33%**。JSON 对照包含原生产路径为计算 UTF-8 通信预算而进行的 TextEncoder 编码。
- 加入边界检查后的解码基本持平，不能使用早期仅 SDK 的快速度宣称最终解码同样提速。
- 不包含采集、世界还原、物理、渲染与真实网络。不能把此结果当成游戏 FPS 提升，也不与此前不同场景收益简单相加。

证据：`artifacts/lan-binary-final-benchmark.json`。早期探索另保留 `lan-msgpack-node-probe.json`、`lan-msgpack-browser-probe.json`、`lan-binary-bounded-probe.json`；它们不是最终性能数字。

## 正确性与安全检查

使用临时 stdin / 内存模块 / Playwright，没有新增测试文件或运行器。

- 实际帧解码后逐字段相等；分别应用 JSON 与二进制帧，再采集的世界相等。
- Ship、Vector2、typed array、Map、Set 与舰船对象引用保持正确；显式 undefined、NaN、Infinity、-Infinity 标记还原一致。
- 两艘苍鹭及 **12 艘动态战机**的快照、应用后再采集结果一致。
- 固定种子生成 2000 个对象，二进制结果与 JSON 语义一致；覆盖 Unicode、整数、浮点、数组和 undefined。
- 缓冲区带非零偏移解码正确；转移旧缓冲区后再次编码正常。
- 空包、截断、尾随字节、非法标记、过深嵌套、超大声明长度、危险键拒绝。
- 服务端原样转发二进制；非房主、旧对局、旧序号和坏包不推进房间状态。
- 接收器二进制/JSON 两路径、后台过滤、后台结束消息、精确封装大小预算、Steam 文本发送通过。
- 初次世界验证探针因缺少 Vite 虚拟模块/构建常量、随后因未准备资源清单而未通过；完善探针环境后才完成动态战机验证，未把这些失败归因于游戏性能。

证据：`lan-binary-world-validation.json`、`lan-binary-boundaries.json`、`lan-binary-client.json`、`lan-binary-relay.json`。

## 实际浏览器与十连接验证

### 最终构建双端

最终生产构建 ID：`2026-09-18T00:31:07.951Z`。

- 两端视口 1600×1000，2 真人 + 每队 3 AI，共 8 艘守护者；实际导入并应用此前相同的两份配装。
- tick 3 → 3600，59,953 ms 墙钟，推进约 **0.99995×**。
- 记录 1192 个 Worker 快照，全部为二进制；0 Worker error、0 recovered、0 pageerror。
- tick 900 附近刷新客机，tick 954 时恢复同步；W 键输入恢复。
- 客机隐藏后不收二进制状态；房主隐藏时仍继续推进。两端回到前台均经过新的 syncId 恢复操控。
- 末段 HUD：约 4 ms 网络、56 FPS、17 Hz 状态、1.00× 战斗速度。这是单次运行值，不是 FPS 对照收益。
- 开战通过现有 start 协议触发，不作为房间按钮完整交互验收。
- 最终构建也包含工作区其他任务同时提交到文件系统的内容，因此不能将整体构建大小/运行差异全部归于本次编码修改。

证据：`artifacts/lan-binary-final-live.json`、`lan-binary-final-live-log.txt`。较早一次 60 秒双端结果保留在 `lan-binary-live.json`。

### 十连接、合成百舰

10 个真实 WebSocket 连接，100 舰合成状态发往 9 个接收者；刷新重连时的资源准备门槛与 controls-ready 通过。消息从 JSON 等价 **3,763,501 B** 变为二进制 **2,187,005 B**。

这是数据通路检查，不运行百舰物理，不代表十台机器或持续 20 Hz 网络性能。证据：`artifacts/lan-binary-ten-peer.json`。
