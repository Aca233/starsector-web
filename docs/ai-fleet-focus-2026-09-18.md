## 假设与唯一改动

原分配器即使目标所需火力尚未填满，也按已有投入扣分。候选只把该扣分改为超过原 `demand` 估计后才开始；保留原需求估计、斜率 2、封顶 6、自己火力的 0.25 权重、距离/压力/黏性等其他评分，以及命令、隐藏敌人、物理与火控安全规则。

```ts
// 原式
score -= Math.min(6, ((claims.get(target.id) ?? 0) + u.power * .25) / demand * 2);
// 冻结候选
score -= Math.min(6, Math.max(0, ((claims.get(target.id) ?? 0) + u.power * .25) / demand - 1) * 2);
```

这不只是“集火更多”：原式还含自己火力项，故即便没有队友认领，候选也可能改变对小型/残血目标的偏好。目标变化还会间接影响接近路径、掩护和撤退任务。不能将所有收益归因为集火，或声称任务/走位完全不会改变。

基线 SHA256：`405b2fda184450d244d4843fd4c2a2fad2819a8820436ac495c44b0ba2cabe7d`；候选：`e880f310734fe2f677ad4908d1a04161d7ec09c71ba8ac63c8719e5ed2dfcf5e`。只替换冻结 bundle 中一个表达式，分队对战不替换整套引擎。`isolation.json` 保存精确表达式与分发器哈希。

**反例保留**：5 秒后切换的轻型局由胜变超时；巡洋混编由超时变负。五舰局由负变超时；驱逐、突击、三舰双方均超时。死亡采样是每秒一次的“已观察到死亡时间”，不是精确击杀时刻。不挑正例或把更快第一杀当整局增强。
