# Vector2 构造热点优化：移除重复字段初始化

日期：2026-09-17。

## 结论与边界

保留 Vector2 构造器的单文件改动。本轮基线已包含此前保留的近炸船体粗筛、弹丸威胁索引、火控缓存和 FX 四纹理合批；本轮收益不能与那些不同基线的百分比直接相加。

密集百舰两次测量，模拟均值分别下降 **14.92% / 16.39%**，完整周期均值分别下降 **11.47% / 12.63%**。实际 rAF 诊断仍远未达到百舰 180 帧，详见下表，不以完整周期的倒数代替 FPS。

没有减少舰船、弹丸、AI 更新、物理步数或特效，没有降低分辨率/抗锯齿，也没有更改浮点几何公式。本轮不是 Worker 迁移，不声称 100 艘战列舰 / 180 FPS 已完成。

## 为什么改基础向量构造

当前生产构建的独立 CPU 采样仍显示威胁预测、近炸、射击遮挡等热点。Vector2 构造/克隆与编译产生的字段初始化 helper 横跨这些路径。采样期间的完整耗时受 profiler 影响，未用来计算本轮加速比例。

先诊断了更早的武器 ETA 下界：后 120 步、12,000 次威胁评估中，剩余角度计算 2,347,923 次，仅 48,513 次（约 2.07%）还能按该下界排除。没有为这点潜在收益修改 ThreatAssessment.ts。

源码原来的 x/y 普通类字段声明，在当前兼容构建中会产生两次 undefined 字段初始化，然后构造器再覆盖为坐标。现在把声明设为 type-only declare，构造器直接初始化最终值，避免这一层重复工作；**不是此前已拒绝的全局 ES2022 构建目标切换**。

生产修改仅 src/engine/math/Vector2.ts：

- 普通实例直接写入 x/y，坐标参数默认值、属性顺序及可写/可枚举/可配置描述符不变。
- 若继承链已有 x/y（包括 setter 或只读属性），使用 Object.defineProperties 创建自身可写数据字段，避免普通赋值触发继承 setter 或失败。
- 所有向量运算方法完全未变，没有近似计算、对象池或别名共享。
- 未要求提高浏览器支持版本，主构建与现有 host Worker 构建均来自同一候选源码。

这不覆盖任意 Proxy 原型副作用或 JavaScript 反射内建函数被猴子补丁替换的行为；没有把有限的运行验证说成任意扩展环境证明。

## 行为验证

临时诊断均位于忽略的 artifacts/dense-simulation/，没有恢复用户删除的项目测试套件或运行器。

- 20,000 组输入上的 **200,000 次向量操作对照**：set/copy/clone/add/addScaled/subScaled/sub/scale/normalize/rotate，此外逐组核对 length/lengthSq/dot/distanceTo/heading/fromAngle/lerp、返回自身语义及自身属性描述符。覆盖正常随机数、大小尺度、零/负零、NaN、Infinity、undefined 默认值与 null，使用严格数值比较而非放宽 epsilon。
- 5 项继承/属性边界：普通派生原型、继承 setter、继承只读字段、两字段组合、基础原型上新增只读字段；构造后自身字段、赋值和 setter 调用计数一致。
- 完整状态对照：10 艘 Onslaught ×360 步；6 艘 Odyssey/Paragon ×360 步；密集 100 艘 Onslaught ×180 步。每 60 步检查引擎和玩家 AI 的完整序列化状态，**15 个检查点一致**，仅忽略墙钟 kernelMs。
- 所有配对浏览器场景的最终引擎状态指纹、存活数一致，页面与 GL 错误为零。
- 最终当前源码与 290 文件候选快照一致；只有 Vector2.ts 与本轮基线不同。typecheck、lint、build、浏览器冒烟及 WebGL 上下文丢失/恢复、FX/ribbon 资源释放检查通过。dist 已更新。
- 开发中首次 typecheck 曾因 in 检查把 this 收窄为 never 失败；已改为在 object 类型上检查，最终 typecheck 和全部构建通过，初始失败日志保留。原有大 chunk 提示仍存在。

## 真实 rAF 调度诊断

原生 Chromium requestAnimationFrame 驱动现有生产调度器和 CombatSession.fixedUpdate / 插值渲染。密集百舰预推进 180 步，预热 5 回调，观察后 20 回调。前后顺序独立运行，无 gl.finish / CPU profiler。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 回调间隔窗口 | 18.316 s | 16.133 s |
| 观察到的回调频率 | 1.092 Hz | 1.240 Hz |
| 回调间隔 P50 | 916.7 ms | 833.3 ms |
| 回调间隔 P95 | 1283.4 ms | 1066.7 ms |
| 完成模拟步数 | 120 | 120 |
| 模拟推进速率 | 6.552 TPS | 7.438 TPS |

这是**一组 20 回调顺序诊断**，不证明持续游戏帧率或统计显著加速。无头环境、自动驾驶和固定相机，不包含完整输入/音频/UI，也不是物理 180 Hz 显示器验收。现有调度器的 100 ms 墙钟截断和补步规则未变；droppedSimulationSeconds=0 不等于没有墙钟截断。

本轮没有改渲染 shader；上一轮 FX 合批的稀疏 MSAA 像素差异例外仍存在，本轮通过不意味着该严格像素检查被修复。

截图复核另发现：上下文恢复首帧的云层有明显方块边缘；上一轮 artifacts/dense-render/current-restored.png 中也有相同现象，不是本轮 Vector2 修改新引入。资源/GL 冒烟通过不等于恢复首帧画面完全正确。当前 SpriteBatcher.begin 在内部混合模式已经为 NORMAL 时不会重新设置 GL blendFunc，恢复后的 GL 默认混合状态是后续需要验证的可疑点；本轮尚未修复或把它宣称为正常。
