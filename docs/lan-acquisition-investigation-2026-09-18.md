# 百舰房主计算：索敌采样与未采用的空间索引（2026-09-18）

## 当前结论

用户要求优先解决联机。此前已处理快照饥饿；本轮针对真实物理更新过载采样，没有放宽恢复保护、改物理步长、降低舰船规模或改变 AI/伤害规则。

**本轮空间索引方案没有采用。** 原型有一次约 8.6% 的收益，但补足兼容性/生命周期保护后的配对实测没有可靠收益，平均成本反而高约 6.4%。已精确撤回本轮五个源文件的变更，保留之前的优化与其他任务的既有修改；新增的实验类也已移除。当前仍不能宣称百舰联机实时通过。

## 新采样

- 冻结当前 src 脚本/JSON，固定 seed=2232494901，使用既有两真人守护者 + 98 锤头编队。

## 尝试过的实现

1. 每艘舰的瞄准阶段，缓存所有目标位置/速度/半径，用既有 outsideAcquisition 的保守界限过滤候选。保持目标顺序、精确拦截、射击安全检查与索敌频率。构建/保护成本抵消收益。
2. 减少重复资格检查并提前排除友舰的原型仍无收益，而且未完成全部扩展回调兼容，未采用。
3. 每个原生武器阶段建立空间格网；在每舰移动之后更新位置，以全场最大半径和 L1 速度上界做保守查询，按原名单序号排序候选。原型单次较快，随后补足保护。
4. 完整版对未知状态效果、改写的 Ship / weapon control / hostile / visibility / autofire 方法、自定义装甲回调、模块化舰船等回退原路径；更新前后刷新位置，finally 关闭索引，不跨帧复用。

完整实现曾写入工作区以执行 typecheck/lint，但在最终对照后已撤回。artifacts 中保留候选源码仅作证据，不能误认为现有功能。

## 正确性检查与限制

- 最终版本 27,077 项边界/门槛检查通过：2500 次包含动态移动/速度/半径变化的查询，其中 2265 次确实缩小候选；没有漏掉既有保守界限认为可能可达的目标，候选顺序稳定。
- 非有限查询、负参数、重复对象、索引关闭均回退；初次检查发现 Infinity speed 未强制回退（原界限允许该数值），随后加入显式有限性门槛并重新验证。
- 原生世界单步触发 819 次索引查询；十种自定义回调/方法/状态效果情形均回退，没有查询索引。

- 最终 typecheck/lint 曾通过；撤回后再次检查。由于候选未通过性能门槛，没有为它创建生产构建或宣称生产双端通过。
