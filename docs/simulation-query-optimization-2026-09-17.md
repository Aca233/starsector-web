## 实际修改

1. **导弹索引失效后的增量重建。** 命中、爆炸等仍令索引失效，下一查询仍遍历权威数组检查每枚导弹。复用未改变网格的条目和桶，只更新移动/半径改变所涉及的网格；删除消失的条目，刷新原数组顺序。不是跳过失效检查。重复对象仍退回原始扫描，异常坐标/大范围查询仍保守回退。
2. **弹丸数据显式编解码。** 将打包、校验、Worker 应用中的通用字符串路径解析，改为同一 22 字段、同一顺序的显式访问。保留 Float64 + 类型标签 + 字符串字典，以及 undefined/null/布尔值/特殊数值；不是 Float32 或丢字段。字段数量有编译期约束。

主对照阶段均值（已包含于整步时间，不另加）：

| 阶段 | 前 ms | 后 ms |
|---|---:|---:|
| 打包/预览 | 4.285 | 3.811 |
| 分发等待（包含 Worker 计算） | 10.588 | 9.225 |
| 主线程输入校验 | 3.276 | 2.719 |
| 最慢 Worker 的输入应用 | 2.425 | 1.531 |

前后每步均接受 97.3 个原生 AI 结果、回算 1.7 个。没有降低 AI 频率、跳过模拟步、扩大 dt 或降低碰撞精度；主线程仍负责权威运动、火控、弹丸、碰撞和伤害。这不是整艘船完整线程所有权。

- 19 项真实 CombatSession 的输入/命令/换装/部署/暂停/重启/切战斗/销毁/故障/超时/强制权威回退等定向验证通过；每版真实固定步调度器 120 步，最大在途步数 1，状态一致。

- 2 艘、50 艘独立配对状态一致。npm run typecheck、npm run lint、npm run build 通过；构建保留现有大块警告。
- 生产 preview 的真实 CombatView/RAF/WebGL2 冒烟：100 艘、实际四线程提交、暂停时钟稳定、无页面错误。软件 WebGL 只用于功能验证，不作为 FPS 数据；任务创建的服务和浏览器已关闭。
