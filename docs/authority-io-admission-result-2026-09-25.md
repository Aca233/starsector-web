# 普通房主发送前预检：结果（2026-09-25）

## 本次实际解决的问题
在普通玩家房主的 direct I/O 链路，计算 Worker 原本可能先捕获世界、编码并 transfer 到 I/O Worker，随后才因本地 WebSocket 积压收到 skipped。此次把“当前已明确无法准入”的可选共享提示提前到捕获/编码之前。

不是增大信用窗口、网络队列或积压，不以降低物理/AI/快照目标频率或实体数量换性能。没有实现/启用 GPU 计算，也没有更换安装包。

## 实现与边界
- 新增每端口独立的单 Int32 提示，仅 IO 写入；未知/禁用/撤销时维持原回退路径。
- 发送处的原 RealtimeSendGate 完整保留，真正 dispatch 必须再校验。16.67ms 同批次 motion/snapshot 限制、tick/attempt 完成日志及远端信用均不改变。
- 本地画面不被网络提示阻塞。两边均不可发布时省掉捕获/编码/transfer；显示可发布时仍正常捕获/显示，只省网络分支的额外编码或复制。
- 排空复用原 4ms timer，空闲不新增常驻轮询；覆盖 native buffered bytes 和主线程尚未交接的预约，避免 copy/post 失败回滚后提示卡死。
- 异步序列化的投递前和结果发布前同样检查提示。终局绕过提示，仍经过真正发送门，不声称终局获得保证送达。
- 声音仍为原有有界队列、实际 dispatch 时退休，预检阻止的工作不会提前消费声音。
- 明确受阻时不创建无用途的编码片段缓存；仍只保留一份同 tick world projection，排空后可复用。

## 可重复证据
### 1. 冻结旧源码的受控工作量 A/B
执行提取出的真实 snapshot()/完成处理函数，用空 DTO 世界控制本地受阻条件：显示端也无空位，共 120 次候选发布。

| 受阻期间工作 | 修改前 | 修改后 |
|---|---:|---:|
| 世界捕获 | 120 | 0 |
| 编码 | 120 | 0 |
| 跨线程快照传递 | 120 | 0 |

排空后两者都成功发送最新 tick 121，world 深度相等，成功次数和序号相同。新实现保留此前未 dispatch 的声音。此场景没有真实舰船负载；它证明无效工作被取消，不能换算为 CPU 提升百分比、FPS 或公网带宽收益。

显示端可用的独立场景：连续 10 tick 仍产生 10 份显示帧、10 次捕获、10 次编码；网络不发送、不创建投机片段缓存；同 tick 排空后复用捕获发送网络帧。

### 2. 真实无头浏览器 I/O 链路
扩展既有 socket-close 场景，保留原 8 种关闭/回退用例，另验证真实 Worker + MessagePort + WebSocket：
- 受控的 4096 字节主线程预约使提示受阻，强行递交 tick 1 仍由真正发送门拒绝，序号不前进。
- 撤销预约后不再发任何唤醒消息，原排空 timer 自动清除提示；额外端口唤醒消息数为 0。
- tick 2 实际抵达测试 WebSocket 服务器，线上序号为 7；关闭后提示撤销，队列归零。
- 全部通过，浏览器错误 0，完成清理。

这里的堵塞来自受控预约，不是公网/TCP 拥塞模拟；服务器为该既有传输测试的本地 WS，不冒充完整联机鉴权测试。

### 3. 普通双人联机短验收
既有 check-normal-multiplayer-browser：实际 LanBattle、房主 Worker、WebGL、LanConnection、DesktopLanBridge、relay；2 名玩家，0 额外 AI，seed 917，同机无头 SwiftShader。
- 5005ms 内模拟从 tick 204 前进至 504（300 tick）。
- 双方完整状态采样中位数均 60Hz，FPS 中位数均约 60.003。
- 房主日志确认 sharedAdmission=true，preflightSkips 有累计；该计数包含同 tick 重复检查与启动阶段，不能当作测量窗口内节省的唯一帧数。
- 双方 connected/loaded，workerNotes、浏览器错误及战斗失败均为空；完成清理。

这是正常路径烟测，不是性能对照，不表示修复了历史 0.2.11 的公网 4–7Hz / 高 ACK 延迟，也未验证原生 Steam 公网链路。

## 集中验证及失败历史
- npm run typecheck：通过。
- 修改文件 oxlint：通过。
- 既有 authority I/O、local completion、capture reuse、network publication 共 66 个场景：首轮 64 通过、2 失败。失败来自旧的函数提取夹具缺少当前 fail() 已依赖的 summarizeNetworkFailure；补入真实依赖后仅重跑这 2 个用例，均通过，未改生产错误处理来迎合测试。首次日志完整保留。
- 同时补齐夹具对当前 captureLanDisplayCombat facade 的映射；保留旧捕获记录器和冻结源兼容，未删减断言。
- 最后代码复查发现受阻显示帧仍可能构造投机片段缓存，增加一个条件排除该分配；只定向检查其显示/同 tick 复用场景和对应 lint，通过。浏览器运行早于这项最终分配守卫，之后没有传输、模拟或 UI 改动，未为此重跑浏览器套件。
