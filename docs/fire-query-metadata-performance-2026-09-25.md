# 火控资格元数据共享：实现与验收（2026-09-25）

## 结论与保留范围
保留一块**局部资格查询优化**：对不可变舰体配置共享原生插件白名单分类，避免每挂点重复遍历同一份插件定义。**没有证明整步模拟或交互延迟提速，未完成动态目标查询事务、火控重构或200舰60Hz目标。**

唯一生产修改为 `src/engine/extensions/HullMods.ts`：
- 注册不可变ShipSpec的私有解析名单冻结；模块自己创建的缓存数组不是插件的可变API。`installedHullMods`继续返回新的、可排序/增删的调用方数组；定义、挂点和调用方输入所有权不变。
- 原生白名单布尔分类以私有名单为WeakMap键，缓存正/负值。白名单只在模块初始化注册原生定义，外部注册不能覆盖或变成原生。
- 每次仍读取every方法，替换的方法/getter及异常走当前调用；普通/浅冻结/动态配置重新解析，不缓存外部回调结果。未知插件仍报错，后续正确注册后可重新解析。
- 可见性、相位、运动、武器角色、动态射程、目标/遮挡、射击频率、RNG与网络流程未改。不启用旧FireControlQueryRoster资格修正/范围树，不冻结可变挂点。旧ArmorGrid资格失配仍未解决。

### 废弃的初测
最初把微基准接在原型替换合同之后，得到121.039→16.150ms。恢复Array.prototype.every并不能恢复V8此前被失效的优化假设，故这组测量不代表正常运行环境，**已废弃，不作为收益证据**。保留原始qualification-benchmark.json与日志，未覆盖；有效结果为fresh-qualification-benchmark.json。基准模式已移到任何合同执行之前，避免以后重复这一测量错误。首次集中检查632断言含12批值比较；修正后的独立合同为626断言（新增动态外部射程回调验证、不再混入计时）。
