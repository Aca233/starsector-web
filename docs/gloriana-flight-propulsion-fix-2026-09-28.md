## 原版证据 → 本轮设计 → 验证

- 本机0.98a-RC8 API `loading/WeaponSlotAPI.java:12–14` 分别声明isHardpoint/isTurret/isHidden，隐藏与固定不是同义；`data/hulls/dagger.ship` 同时存在360度隐藏能量位和5度隐藏导弹位，不能以HIDDEN推导射向。
- `data/weapons/tpc.wpn:8–12` 固定炮允许不单独绘制炮壳，仍有hardpointOffsets/glow；当前Web已有hardpointUsesHullSprite能力。
- `combat/ShipEngineControllerAPI.java:33–47` 声明单喷口contribution/disabled/repair，体现有效推力与部件损伤关联；API并未定义女王号的模块分摊比例。本轮按Web自定义模块规则扩展，不改变未声明此能力的舰船。
- 画面依据：上轮实际查看三型正式航空素材及Worker画面；狂怒、雷鹰、星鹰的炮/挂架都在机体图内。无需新增素材，固定射向、炮口标定和出管方向必须跟机体。原版桌面实机仍待许可，不新增界面布局。

## 本轮规则

1. 女王号三型机载炮位采用明确HARDPOINT，武器本体使用舰体图，不重复叠炮；保留真实炮口、伤害、弹药和射界瞄准容差，独立转速为0。离膛鱼雷再按既有制导规则转向。继续用已有AI拦截/压盾/轰炸与返航链路。
2. 用显式、可校验的舰体配置声明动力依赖EP/ES，不在通用运动引擎里硬编码舰名。两舱按有效喷口贡献平均分摊；舱毁、离舰、失效或缺失不贡献推力。恢复的喷口可重新贡献，摧毁舱不凭计时复活。
3. 完整状态保持原值；单侧全失效保留65%速度、60%加速、70%转向，双侧保留30%/20%/40%应急能力；制动不变，不附加失控偏航。母舰本体原有熄火/故障规则仍优先，不能由模块绕过。
4. AI、运动预测和HUD读取真实运动参数或权威状态文本；不另起显示端推力模拟。不改四层虚空盾、48槽、三项内置、六甲板、武器伤害，也不重写用户存档。
