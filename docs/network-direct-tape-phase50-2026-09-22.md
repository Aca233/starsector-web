# Phase50：私有tape直接编码，移除辅助线程的世界对象重建

2026-09-22。**本块实现和局部成本门槛通过；整局对照未完成，不默认启用异步编码，也不宣称游戏Hz/远程延迟已改善。**

## 已实现

- 私有数值tape直接生成现有SWF2，不再重建完整世界DTO后遍历编码。沿用固定依赖的既有数值宽度和字符串写入器，网络字节不变。
- 显示/网络两条通道只差声音队列时，仅替换顶层sounds字节段，不重遍历整图。只重建小的sounds子树以保持原先“相同音效ID复用显示字节”的合同。
- 共享有界tape reader；保留非法标签/键、重复键、深度、预算、孤立代理字符的拒绝/回退。非canonical手工整数键tape回退，不能改变JS对象枚举顺序。
- 输出拥有独立存储；沿用原单任务/准确ID、取消、异常和同步回退。4MiB tape、2MiB单输出槽、网络大小限制和全部信用/超时不变。
- **默认同步路径、物理60Hz目标和serializer opt-in条件均未改。** 没有把旧Phase24方案默认打开。

## 局部完整子系统成本（不是整局加速）

使用既有22舰原生场景，3/5受控席位，tick120/360/600/1354/1800/2256的真实捕获，每点正反顺序，24个窗口，每臂30次预热、80次计时。每次显示/网络字节都与同步编码比较。

对照是旧tape重建+编码作业，候选是直接tape作业；两者均计入tape准备、辅助作业及结果mailbox复制。**这是Node内串行调用成本，不含真实线程唤醒/调度、网络、压缩、渲染，更不是RTT。**

- 辅助作业P50比值0.382–0.441，即下降55.9%–61.8%。
- 准备+作业+结果复制P50比值0.541–0.607，即下降39.3%–45.9%。
- 全24窗口通过事先声明的worker P50≤.90、总P50≤.95、总P95≤1.10门槛。
- 5席tick2256（22舰、61弹体、1beam，230158字节）：总P50正序5.095→3.039ms；反序5.048→2.826ms。准备成本未被消除，权威capture本身也仍未移走。
