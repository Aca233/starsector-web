# 分层同步第三阶段：压缩分片、房间共享节奏与生命周期（2026-09-21）

## 1. 实现及不可混淆的三种回执

`SnapshotChunkCodec.mjs` 将已经选定的 SLD1/SWB1 帧先整体 deflate(level1/mem7)，再切为 SWC1：40B 元数据 + 至多 2004B 内容。每个未掩码 server WS 分片含 WS header 至多 2048B。不可压缩时保留原内容；不将每个分片各自压缩，避免丢失跨片压缩收益。

每个 frame 使用随机 128-bit token、严格连续 offset、原/压缩长度和 CRC32。接收端只保留一个有界 partial frame，完整拼装后有界 inflate，再交回已有 SLD1/SWB1 decoder。半个世界绝不转交浏览器。原包超出 SWC1 限额时走原完整路径，不陷入永久跳过。

- **bulk-ack**：只表示 helper 收到了对应分片字节，释放该 token/offset 的传输 flight；累计回执必须是实际已发送的端点。
- **state-consumed**：仍由浏览器实际消费完整世界后发出；差分基线/渲染器 credit 不能由分片回执冒领。
- **motion-consumed**：仍要求当前 match/sync 和实际已发送 tick；其耗时不是空闲 RTT。

生产 `LanBulkScheduler` 以整个房间共用 flight 控制分片，而非每个客机再复制一份无限窗口。初值 16KiB，上限 64KiB，地板 8KiB；按实际 critical 回执相对独立原生 RTT 的队列超额调整。等待压缩的老客机也保留首次分片机会；额度不随本机 socket 排空自行返还。此处的 wireBytes 仅是分片 WS 字节，不含 IP/TCP、重传和 VPN 封装。

每客机最多一个当前世界，压缩任务数和输入计费有上限。相同不可变包的同时压缩可共享。`retainedBytes` 是受管理 raw job 的计费，不等于进程 RSS；zlib 输入/输出、副本、内部工作区和分片临时缓冲仍额外占用物理内存。取消/关闭不能提前卸下仍在压缩或等待 send callback 的 job 计费，防止连续取消造成隐藏的无限压缩积压。

## 2. 断线、重同步及旧回执

- 活连接上取消/重同步/隐藏，已写入网络的字节仍是 retired debt；不借超时伪造 ACK。
- leave 后即使 `p.room === null`，原 primary 的 `bulkReceiptOwner` 仍能接收旧房间真实分片回执。每 peer 只有一个 owner；存在旧房间 debt 时，不在另一房间再建立并行分片 credit。
- 主连接真正关闭或被新连接替代时，旧 transport epoch 不可能再完成可用世界。其未确认字节记为 **abandonedBytes/abandonedChunks**，不是 receipts/completed；清除该已失效连接的 flight，并将共享自适应窗口降回地板。新发送仍要真实 ACK，旧 token 对新任务无效。
- 这不宣称已把断线前的字节从路由器中撤回，也不保证反复连接抖动时共享物理出口绝无残余数据；它解决的是永久逻辑占额，恢复期采用小窗口。断线策略须继续接受真实 n2n 路由/丢包测试。
- terminal 与新 launch 在原有有序主通道上发送，helper 清空半帧；已取消任务不再续发。optional control lane 中途丢失，latest ACK 重放及后续分片回执退回主通道。
- 无已消费 critical stream 的 loaded room 走原完整同步；现有 partial job 可先完成。混合能力客户端仍可能通过普通完整包占用共享出口，尚不构成对任意混合房间的延迟保证。

## 3. 初测与否定结果

原录制：`artifacts/network-latency-phase5-20260920/frames22`。它仍含旧插值端点，不包含第二阶段新旧同场捕获的字段省略收益；不能把两次优化百分比相乘。

模型：真实 WS/TCP/zlib，独立 Node guest 进程，同一个按实际 WS 字节排队的共享 FIFO 下行，上行 32Mbps，无丢包。关键包没有模拟网络优先权。输入只是录制回放中采样并回显的序号，不是原生模拟处理/输入到光子的延迟。无 renderer、无 Steam SDK、无真实 n2n/WAN。

固定 8KiB flight（`layered-replay-chunks-probe.json`）虽把 5 人/4Mbps 的关键状态提高到约 56Hz，但完整世界只有约 0.43Hz，P95 年龄约 2.4–2.55 秒。**不能作为最终默认方案**。

自适应 16–64KiB 初测（`layered-replay-chunks-adaptive.json`）：

|5 人场景|关键状态|关键年龄 P95|完整世界|完整世界年龄 P95|合成输入回显 P95|
|---|---|---|---|---|---|
|4Mbps / RTT60|53.3–53.9Hz|约64ms|1.14Hz|867–898ms|112–123ms|
|32Mbps / RTT20|56.7–56.9Hz|约31ms|4.43–4.57Hz|100–116ms|约63ms|

这是关键运动/输入路径改善，但 4Mbps 下弹体、HP 等完整世界仍接近一秒旧。**“运动 50 多 Hz”不等于“完整战场 60Hz”，不能据此宣布目标完成。**

生命周期修正后的独立 3/4/5 人回放结果保存在 `layered-replay-chunks-phase3-final.json`；最终摘要见本文后续节。回放场景有稳定协商的关键通道，掉线/重连/fallback 由独立真实 relay+helper 集成测试覆盖，不把它们冒充已包含在性能表中。
