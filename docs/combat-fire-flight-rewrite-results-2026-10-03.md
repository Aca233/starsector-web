# 火控与飞行器执行路径重写结果（2026-10-03）

## 落地范围

这轮不是解除计时器限制，也没有改变步长、单位数量、决策频率或战术规则。重写的是热点查询执行结构，接入实际主机 Worker，受验证的封闭权威路径默认启用；`VITE_COMBAT_FIRE_FLIGHT_REWRITE=false` 可关闭本轮改动。普通未注册 inline / 自定义路径保留原实现。

### 火控

- 位移、护盾、组件和武器状态全部推进后，建立一次状态/敌对/友军遮挡关系平面，不再让各舰各炮重复穿透系统读取。
- 数值 acquisition BVH 按节点的位置、速度和碰撞范围做保守筛选，再交给原有精确拦截/射界/船体护盾计算。权限严格来自当前调用者的实际名单；Gloriana 限制名单不会借用整个 frame 的目标权限。
- 名单对应的数字行/排序一次编译。在已有 native 私有只读 span 中 seal 名单、编译武器角色；仍实时生成会随炮塔变化的炮口/查询输入。未 seal 的调试或通用调用继续读取可修改的武器标量，不把 refit spec 冻结。
- 每舰实际受限 aimWorld 只做一次 native 准入，逐炮/逐接触复用该阶段绑定；绑定在 query batch 关闭前移除，关闭或变更 frame/source/batch/budget 时失效。未知 getter 不在准入时调用。

### 飞行器

- 引入飞行专用关系名单，避免每架飞机都重建 `engine.ships`、重新过滤同一静态阵营/可见关系。
- 没有错误地把飞行阶段当成位置/存活状态不变：前一架飞机停靠、死亡、返航撤退后，后一架仍读取实时存活/撤退、位置和当前目标。
- 导弹相对轨迹、最近接近评分和抵达/刹车转向改成纯数值内核，去掉逐候选临时 Vector。命令优先级、评分顺序、返回对象、转向和刹车值保留。
- Gloriana 的友军+选中目标名单按原来来源顺序构建。飞行关系在无人机/舰船 state/motion/fire 阶段前关闭，不把旧权限扩展进后续推进。

## 同窗口对照

既有2玩家/20AI、seed917、三种 authored 舰体场景，176初始实体/734挂点。两个分支均启用前轮主舰+模块决策管线和数值火控获取；本轮开关 off/on 是区别。ABBA，每组150预热+120计时。

| 阶段 | 本轮关闭 | 本轮开启 | 降幅 |
|---|---:|---:|---:|
| 整个模拟步 | 48.2360 ms | 45.1031 ms | 6.49% |
| 火控查询 | 15.1455 ms | 13.2965 ms | 12.21% |
| 飞行器/机库/无人机阶段 | 5.4342 ms | 2.4661 ms | 54.62% |

原始四组整步均值：49.767874、45.937073、44.269088、46.704101 ms。**此轮基线也变动了，不能拿前一轮39.79ms直接拼接、更不能累计两轮降幅冒充结果。** 单机这次四组配对只证明当前测量窗口收益，不保证所有机器/其它场景相同。

每组270步：149,137次数值获取查询，原来源行25,310,013，树返回候选1,484,491（减少94.13%）；30,597次阶段相位读取、509,448次阶段关系读取。候选减少不是整个火控CPU或所有碰撞计算减少94%。飞行关系阶段270次、实时敌对查询26,147次、受限射击名单26,147次、数值转向25,551次、导弹查询14,807次。

## 没有隐藏失败版本

初版虽然筛掉大量候选，但每次查询重建 ordinal 数组，并继续全名单验证；第二版还把全武器字段 metadata 审计放进每步入口。火控阶段先后出现+6.60%、+2.26%的负收益；再修后仍基本持平(+0.38%)。最终改为私有 native loop 身份准入、实际只读名单入口编译和每舰一次世界绑定后，火控才出现12.21%的正收益。

四个版本分别保留在 `authority`、`authority-repair`、`authority-final`、`authority-context`。前三个是具体火控失败/修复回执，**最后一个才是本轮计时接受版本**；没有覆盖失败记录或从多个版本中只挑最好数字。默认改动及通用 binding guard 在之后完成，最终源文件另外保留于 `final-source`，没有把它冒充计时输入。

- 原有战斗规则实现保留作 oracle：数值射线1536种情况，完整获取/预瞄对照、反转/子集名单、延迟快速目标、源顺序、相位/友军遮挡和关闭回退。
- 飞行32组转向/刹车与导弹评分对照；存活、停靠、撤退、位置更新过程中，实际敌对选择和受限名单仍与旧实现一致。
- `standard` 与 `large-battle-v3` 两个 profile 的真实同步/Worker 场景通过；四组270步完整状态和随机见证相同。最终均170实体/90弹体，玩家235发/敌人243发。
