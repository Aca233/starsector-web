# 生涯模式实现进度与还原度账本 — 2026-09-19

## 结论

目标仍是**默认尽量还原原版、规则可整套替换、可独立行动也可汇合联机**。当前完成的是领域/持久化基础、遭遇生命周期骨架、有限原版后勤/移动/普通跳跃与缺油漂移，以及统一世界时钟与 Worker 在线调度，**不是完整或可玩的生涯模式**。默认未实现的玩法保持不可用，不用自创奖励、免费维修或简易殖民收入冒充原版。

设计优先级仍以 `campaign-ruleset-architecture-2026-09-19.md` 为准。原实现方案最后的“10 项 SQL 探针”是此前的概念验证；本文件记录真正的新模块和新测试，二者不要混淆。

### 可大改：不仅仅是更多配置项

- 每项服务的实现可以被明确替换，依赖不满足就拒绝装配。
- provider 可通过同一个事务计划读写 `extensions`：`{id, version, schemaVersion, data}`。
- 扩展 ID 使用 `providerId:localId`；provider ID 不能含冒号。只有该命令所属的 provider 可以写自己的命名空间，存档中的扩展必须对应已选择的 provider。
- 扩展同样有版本、回执、原子提交，不需要每添加一个研究/殖民机制就改数据库表。
- 已用**测试专用、非默认玩法**的 research provider 验证独立状态创建/更新和越界拒绝。它验证扩展数据通路，**不等于已验证整套殖民/经济大改**。
- 新增测试直接替换整个 simulation 与时钟速率（10 ticks/秒）、保留同一调度器/事务/回执通路；另测世界依赖属性规则的分批/舰队顺序一致性。测试规则不进入默认组合。
- 内核强制的是结构和提交一致性。任意改变空间、时间或根本实体关系仍可能需要显式升级内核/schema，不能承诺所有改动都只改 JSON。

## 3. 当前遭遇生命周期

```text
准备（冻结本场参战资产检查点） → 运行 → 中断、待恢复
      │                                  │
      └─ 从未开打：可取消、释放本场锁       └─ 新 attempt 重新准备，保留原检查点
```

- 命令只允许内部 `system` 身份。计算主机也是玩家，不因此成为世界系统身份。未来网关不得透传客户端自选 principal。
- 当前桥接边界为两方、最多 8 舰队/128 持久舰船，属于当前实现支持范围，不是原版规则或不可变内核限制。
- 检查点只含本场舰队、成员、配装、舰体/CR/装甲/弹药和规则/内容引用，不含整份世界。
- 重试不写回舰队/舰船状态，只更新当前遭遇和本模块状态。旧 attempt 不能启动新的执行。
- 资产在锁定期间若被其他代码改动，启动/恢复会拒绝并要求检查，不悄悄覆盖新状态。
- 未开打可取消，并默认在 30 游戏秒的准备期限后自动取消；加载时掉线不绕过期限。一旦开打，即使中断后重新进入准备也不可直接取消；重试准备超时退回 recovery-required，避免逃避待实现的战斗后果。
- 显式联机策略为锁定参战舰队暂停后勤、局外舰队继续推进，释放后不追补被暂停的时间；完整防拖延与真实结算尚未完成。
- 取消只释放本场当前舰队行的锁，不更换资产所有人、不发奖、不恢复整份世界。
- **尚无 `encounter.commit`**。有意不接受客户端任意提供金钱/奖励/新舰状态；真实结果校验、部署成本和原版战后处理完成后才接结算。
- 服务重启后的活动遭遇扫描/接管尚未实现；已测试的是新 epoch 下内部命令恢复，不是自动故障恢复。当前 epoch 已有同一 SQLite 文件的持久 fencing，新 Repository 打开时接管 authority 行，旧实例后续操作拒绝；仍不是分布式租约/选主，也不处理跨副本双主。
