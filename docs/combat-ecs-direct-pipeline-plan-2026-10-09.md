**遵循约定**：AGENTS.md《先策划，后实现》与《原版先行》准则

## 一、 目标与玩家体验

### 1. 核心目标
针对战斗场景在 22+ 艘主力战舰同屏混战时出现的严重 CPU 瓶颈与 GC 掉帧，**彻底摆脱“传统面向对象层层嵌套（OOP）”与“逐帧反序列化生成数万个 JS 垃圾对象”的沉重历史包袱**，在底层实施架构级重构：
1. **转向 ECS（实体组件系统）与面向数据设计（DOD）**：将分散在堆内存各处的战舰与海量弹药拆解为线性紧凑排列的组件流（SoA，Structure of Arrays），极大提升 CPU L1/L2 缓存命中率与 SIMD 向量化吞吐；
2. **采纳“游戏级近似计算（Game-level Approximation）”**：取消逐帧全场景原子深拷贝（Frame Clone），放弃昂贵耗时的连续几何交点微积分；改用两级空间哈希网格（Spatial Hash Grid）与圆/定向包围盒（OBB）物理快速剔除；
3. **建立零对象（Zero-Object）直通渲染管线**：Rust ECS 物理步推进完成后，直接将全场可见图元（Sprites、Beams、Shields）按现有 WebGL `SpriteBatcher` 的 16-float 格式写入连续共享二进制内存，前端通过一条 `bufferSubData` 直传显卡，**彻底抹平 68ms 的 JS 对象反序列化与 53ms 的呈现图比对开销**；
4. **单帧性能压进 1~3ms**：彻底消灭 V8 引擎垃圾回收（GC）引起的卡顿掉帧，让战斗在 60Hz 乃至 144Hz 下丝滑稳定运行。

### 2. 玩家体验
* **视觉与操作手感 100% 保持**：战舰转舵阻尼、武器射程、弹药初速、护盾展开与过载效果、幅能升降手感与原版完全一致；
* **现有 UI 零损保留**：玩家已习惯的高精战舰改装台（`NativeRefit`）、技能树、战备目录、对话、暂停菜单与战术地图 HUD 100% 保持现状；
* **感知唯一变化**：大规模交火时，从之前的“PPT 级掉帧与停顿”转变为“稳定满帧、指哪打哪”。

## 二、 本次范围与明确不做的内容

### 1. 本次开发范围
1. **紧凑 ECS 原生内核原型构建**：
   * 基于轻量、低开销的 Rust 原生 ECS 模式（基于紧凑 Archetype / SoA 存储）；
   * 建立扁平组件：`Transform2D`、`Kinematics`（速度/加速度）、`Projectile`、`SpatialCell`、`HullBounds`、`ShieldCircle`、`FluxState`、`ArmorGrid`；
   * 全面改用 `f32` 单精度浮点运算，开启 AVX2 向量硬件加速。
2. **空间网格碰撞检测与游戏级近似算法**：
   * 实现扁平 256px 空间哈希网格（Spatial Hash Grid），将弹药与战舰在 O(N) 复杂度内快速分桶；
   * 弹药与护盾：圆形弧度点积判定；
   * 弹药与舰体：圆包围盒粗筛 + 凸包/OBB 近似求交，移除耗时的连续微积分相交计算；
   * 移除 `step_scene` 每次物理步推进前的场景深拷贝（Clone）。
3. **直通 WebGL 渲染桥接（Zero-Object Bridge）**：
   * Rust 侧实现 `RenderBatchSystem`，顺序将可见战舰与弹药写入连续内存缓冲区，数据格式严格对齐 `SpriteBatcher.ts` 的实例属性定义（16 floats/sprite）；
   * 前端渲染循环直接通过指针共享的 `Float32Array` 执行显存拷贝与硬件实例化绘制（`drawArraysInstanced`）；
   * 彻底废弃原 `RustCombatCore.ts:snapshot()` 与 `CombatPresentationEncoder.ts` 的对象生成与 Diff 逻辑。
4. **轻量旗舰状态通道（HUD Mini-Channel）**：
   * 仅通过数十字节的定长二进制结构体向前端提供“玩家旗舰”状态（血量百分比、幅能、护盾角度、武器装填），供屏幕底部 HUD 刷新。

### 2. 明确不做的内容
1. **不做纯原生 GPU 图形重构**：不引入 DirectX 12 / Vulkan / wgpu 独立原生渲染器；现有 WebGL 渲染器完全满足性能需求；
2. **不重写任何 React UI 面板**：改装台、技能树、菜单面板等保留在 Web 层；
3. **不改变原版战斗平衡性数值**：武器伤害、通量耗散率、护盾阻断比严格沿用原版数据；
4. **不触碰生涯模式（Campaign）及存档系统**；
5. **不操作用户可见桌面与键鼠，全程采用无头基准与后台验证**。

## 三、 原版依据与当前差异

### 1. 原版依据
* 原版 Starsector（0.98a-RC8）中，战斗以 60 FPS 推进（`settings.json:9 "fps":60`）；
* 原版战舰实体的装甲网格分为多块小方格，武器挂点按照相对坐标跟随舰体旋转；
* 原版弹丸虽然判定精细，但在空间上具有最大射程、存活时间（lifetime），并且同样依赖分块空间格进行广相碰撞过滤。

### 2. 当前实现与差异
* **老架构弊端**：
  * 老 Rust 核心为了追求 100% 确定性回放，每帧做全场景深拷贝（耗时 5ms+）；
  * 每帧把内部状态序列化为巨大的 Float64Array，传给 TS 后在 JS 堆中 new 出几万个临时对象（耗时 68ms+），引发剧烈 GC（耗时 100~400ms）；
* **ECS 直通架构革新**：
  * 数据线性排布，无指针跳转，L1 Cache 命中率极高；
  * 弹药与战舰在物理步正向推进，无 Clone 开销；
  * 渲染数据一趟遍历直入显存，跨语言传递时间由 120ms 降至 0.2ms。

## 四、 核心架构设计与数据流转

### 1. 内存与数据流拓扑
```
┌────────────────────────────────────────────────────────┐
│                   Rust ECS 原生战斗内核                 │
│                                                        │
│  [Entity 0..N] 扁平组件池 (SoA 线性内存)                │
│   • Transforms:    [x, y, rotation]                    │
│   • Velocities:    [vx, vy, vrot]                      │
│   • Projectiles:   [lifetime, damage, type]            │
│   • SpatialGrids:  [cell_x, cell_y]                    │
│                           │                            │
│  [System 执行流]           ▼                            │
│   MovementSystem ──► SpatialGridSystem ──► CollisionSystem
│                           │                            │
│                           ▼ (一趟顺序写入)              │
│                  Direct Render Buffer                  │
│       [16 floats/sprite: x, y, scale, rot, uv, col]    │
└───────────────────────────┬────────────────────────────┘
                            │ (Zero-Copy 内存共享)
                            ▼
┌────────────────────────────────────────────────────────┐
│               前端 WebGL 渲染管线 (TypeScript)          │
│                                                        │
│   gl.bindBuffer(gl.ARRAY_BUFFER, instanceVBO)          │
│   gl.bufferSubData(..., directBuffer.subarray(...))    │
│   gl.drawArraysInstanced(gl.TRIANGLES, 0, 6, count)    │
│                                                        │
│   (全程 0 个 JS 对象创建，0 次反序列化，0 次 GC)        │
└────────────────────────────────────────────────────────┘
```

### 2. 实例数据对齐规格（直接兼容 `SpriteBatcher.ts`）
每个渲染实例正好占 16 个 `f32`（64 字节，恰好对应一条标准 CPU 缓存行 Cache Line）：
* `[0..1]`: `worldPos.xy`
* `[2..3]`: `scale.xy`
* `[4]`: `rotation`
* `[5..6]`: `pivot.xy`
* `[7..10]`: `uvRect (u0, v0, u1, v1)`
* `[11..14]`: `color (r, g, b, a)`
* `[15]`: `padding / textureSlot`

## 五、 分阶段交付与实施计划

### 阶段 1 (P0)：轻量 ECS 原型与弹药高并发压测（核心算力验证）
* **任务**：
  1. 在 `native/combat-core` 中搭建独立 ECS 模块；
  2. 实现 `Transform`、`Velocity`、`Projectile` 连续数组，配合 AVX2 向量物理积分；
  3. 实现扁平 256px 空间哈希网格与圆包围盒碰撞求交；
  4. **无头压测基准**：模拟 10,000 发高速弹幕与 50 艘战舰的碰撞，验证纯模拟耗时压进 **1.0ms** 以内。

### 阶段 2 (P1)：直通渲染缓冲区（Zero-Copy Direct Buffer）打通
* **任务**：
  1. 在 ECS 中实现 `RenderBatchSystem`，直接生成对齐 `SpriteBatcher` 16-float 规格的连续内存；
  2. 前端编写直通绘制适配层，绕过所有的 TS 对象转换与 `CombatPresentationEncoder`；
  3. 测量数据传输与 GPU 上传耗时，验证其稳定在 **0.5ms** 以内且完全零 GC 增长。

### 阶段 3 (P2)：战舰高层逻辑移植（幅能、护盾、装甲与火控）
* **任务**：
  1. 将通量系统（硬幅能/软幅能/耗散）、护盾（展开角度/圆弧判定）、装甲格（扁平位图）作为 ECS 组件接入；
  2. 接入现有的武器装填与发射逻辑；
  3. 建立 22 艘主力战舰实战混编场景测试，验证战斗体验与手感。

### 阶段 4 (P3)：全链路集成与综合验收
* **任务**：
  1. 接入现有 React 改装台与战术 HUD（Mini-Channel 数据喂养）；
  2. 集中执行严格的性能 ABBA 验证与稳定性测试；
  3. 正式报告实际性能质变结果。

## 六、 验收标准

1. **绝对性能指标**：
   * 在 22 艘主力舰 + 20 艘护卫舰 + 数千发弹药的极端混战中：
     * **纯模拟耗时（Simulation Time）**：**<= 2.0 ms**（相比目前的 88ms 提升 40 倍以上）；
     * **渲染数据提交与上传（Render Upload）**：**<= 0.5 ms**（相比目前的 53ms 提升 100 倍）；
     * **全场单帧往返（Roundtrip）**：**<= 3.5 ms**（轻松稳跑 144Hz）；
2. **内存与稳定性**：
   * 连续运行 3000 帧（50秒）以上，V8 堆内存零尖峰，杜绝任何 10ms 以上的 GC 停顿；
3. **功能与手感**：
   * 战舰运动惯性、护盾格挡弹药、幅能过载机制完全正常；
   * 现有战舰改装台（`NativeRefit`）和 UI 交互完整可用。
