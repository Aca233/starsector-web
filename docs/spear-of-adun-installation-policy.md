# 亚顿之矛 v06：内置专武与开放换装槽

日期：2026-09-27。用户明确提出「有些槽位是固定某个武器的」。本文件记录本轮设计决定与现有实现依据；不是新增运行时占位武器或已经完成的配装迁移。


## 最新决定：固定结构装炮，旋转环不设挂点

用户已认可：常规可换武器只放在固定结构，中央旋转环作为能源/聚焦与舰体能力机构，前部原生开合机构独立内置。安装锁定与炮头可动仍分别定义；不改炮来解决环的问题，不搬旧26槽。

已完成模型归属、12个固定候选位置（2大/4中/6小）及144个组合姿态的支撑采样，另记录1套前部原生机构。计数是当前Web布局候选，尚未定型炮座、炮管、射界与火力，不是新增运行武器。完整档案/可编辑绑定母版及检查见 `spear-of-adun-fixed-mounts.md`。旋转网格Object_7须沿父链识别，不能因其权重名不含Core而误归固定。

## 采用的规则

| 维度 | 内置专武位置 | 开放换装位置 |
| --- | --- | --- |
| 武器身份 | 舰体基础定义绑定一个确切武器 ID；不可普通卸装、替换 | 由配装选择，严格同档并满足武器类别/接口 |
| 外形 | 专为这处原生机构制作；无需迎合所有通用炮塔外形 | 有真实承座与适配空间，空座也需合理 |
| 运动 | 可固定、可转动或可开合；与武器锁定是独立维度 | 同样由安装结构决定，不能因为可换装就默认360°炮塔 |
| 操作 | 作为武器时仍可编组、开火和自动开火；不会因“内置”自动变成被动特效 | 保留现有武器组与配装操作 |
| 平衡 | 内置火力计入整舰预算；不能在原有26座火力外免费叠加 | 使用现有装配点和同档限制 |

舰体级太阳射线等能力不因为拥有内置武器机制就强行伪装成通用炮位。核心、装饰、发光面不自动视为武器。

## 本舰的当前分配原则

- 已确认是武器、且与原生外形紧密结合的标志性机构，优先使用内置专武。
- 仅开放确实能容纳替换武器的独立位置；不继续坚持26个全可换装炮塔。
- 本轮完成前部 Object_15 的原生机构拆装样板。它是专用机构的美术候选，不等于已证明原作炮型、枪口和射界；若为它赋予新攻击行为，应标为 Web 改编。
- 不把该物体的12个骨骼控制段注册成12个武器槽。控制段只是源网格的组成。

## 已核对的实现与原版依据

- 原版0.98a-RC8 `../starsector-core/data/hulls/onslaught.ship`：`builtInWeapons` 将 `WS 016` 和 `WS 017` 绑定为 `tpc`。内置与槽位是否旋转并不是同一概念。
- `src/engine/content/ShipSpec.ts`：有 `defaultWeaponId`、`builtIn`，另有独立的 `mountType`、`arcDeg`。
- `src/studio/DesignModel.ts` 的 `isBuiltIn()` 当前读取**基础舰体**中对应槽的 `defaultWeaponId`；它不把试玩配置里的默认装备自动视为内置。
- `SourceWeaponPicker.tsx` 对内置槽禁用卸下/替换；`DesignModel.ts` 的方案解码拒绝改变内置武器；`NativeVariantImport.ts` 保留基础舰体中的内置绑定并提示冲突。
- `WeaponInstallation.ts` / `WeaponInstallationRenderer.ts` 已支持独立固定承座及可选固定前景。前景随舰体安装朝向，不应跟着炮头瞄准旋转。
- `WeaponCompatibility.ts` 的 `BUILT_IN` 类别本身不是“锁住某个ID”的安全检查；不能只改类别或只禁用一个 UI 按钮就宣称完成锁定。

## 接入时必须同步处理

1. 确切绑定写入 v06 基础舰体槽，不只写默认配装。沿用内置机制，不另造重复的 `lockedWeaponId` 系统。
2. `SpearOfAdunPack.ts` 的 `adunShips()` 已修正：基础舰体的确切武器ID优先，内置标记沿用现有 `assembleShip()` 的规则，不再统一写 `builtIn:false`。旧v05基础舰体未新增绑定，因此当前试玩配装仍保持不变。
3. 专武若不允许在其他舰船外装，同步进入 `builtInOnly` 筛选；ID锁定、外装资格、同档兼容是不同检查。
4. 编组、清空配装、原版方案导入、自定义方案解码与联机权威校验均需验收；本轮只是代码核对，不声称这些路径已经按新绑定测试通过。
5. 原版式内置武器通常不单独消耗可分配 OP，火力代价需计入整舰 OP/部署等平衡；不能因此无限堆免费内置武器。
6. 旧存档不原地改槽位意义。正式迁移另做兼容处理，保留本轮之前的试玩舰。

## 2026-09-27 继续制作前的最小对照

- 原版证据：`onslaught.ship` 通过 `builtInWeapons` 固定 TPC；`tpc.wpn` 的 `hardpointSprite:""` 表示固定外壳已经属于舰体，另有独立 glow 与枪口。不能因此给同一内置武器画第二套通用炮座。
- 当前差异：本项目配装锁定机制存在，但 `adunShips()` 覆盖为 `builtIn:false` 并按尺寸替换全部默认武器。
- 本轮代码范围：生成默认配装时保留基础舰体的确切武器ID和内置标记，不修改现有26槽位置、数值与资源。延续项目现有 `assembleShip()` 的绑定优先级。
- 验证：在既有亚顿之矛检查脚本中覆盖固定炮/炮塔内置绑定、不可卸下/替换、导入篡改拒绝、非内置槽仍可换装；之后验证现有试玩场景不变。原版实际UI和新舰装舰仍未验证。
- 美术范围：以原生前部机构制作 Web 改编的轴向聚焦器开合。沿用既有控制骨，不添加几何；左右开合不是原模型自带动作。它的设计定位是对舰首方向的重目标蓄能打击，不是原作“三道太阳射线”能力，也不意味着12个控制段对应12次射击。
