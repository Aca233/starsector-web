# 显示定义表：实现与最终复测（2026-09-24）

## 结论与默认状态

已落地自包含的 display-v2 定义表，接入生产 LAN 捕获与接收路径，并完成本切片的无头正确性验收。**仍然默认关闭**：仅构建时显式设置 `VITE_LAN_DISPLAY_DEFINITIONS=true` 才启用；未改任何用户环境文件、没有发布。

修复挂载点对象身份问题后的最终 ABBA 复测：64 舰接收应用均值下降 **48.1%**，完整串行 CPU 流水线下降 **21.0%**，未压缩帧字节数下降 **41.9%**。但捕获均值上升 **29.6%**，权威端总 CPU 均值仅变化 **−0.4%**、P95 反而上升，因此不能当作模拟吞吐或实际操作延迟的优化成果直接默认启用。

本轮没有 ECS、AI、物理、渲染画质或 Worker 架构重写；不减少舰船/弹丸、不降低更新频率、不移除坏包/权限检查。此前模拟热路径小优化仍保留，但不与本表的收益混算。

## 实际实现的边界

1. **每帧自包含，而非跨帧定义增量。** 完整内容字符串是修订标识，同一帧重复内容只发送一次，挂载点/系统引用帧内索引。没有新 ACK、缺失基线、旧定义安装顺序或重连历史依赖。
2. **不冻结权威源对象。** 顶层普通数据属性逐次检查描述符与值；嵌套对象只有经现有 immutableCopy 登记为不可变才准入。访问器、可变子树、不支持的数据或预算超限保留旧捕获路径。定义采样延迟至原 pack 遍历位置，避免提前采样掩盖有效射程/弹速查询造成的修改。
3. **动态数据不进静态表。** displayRange/displaySpeed、系统有效费用/射速/槽位、状态计时和原本的显示字段继续按原顺序采样。仅提取原有 weaponSpec 和系统 definitionData，不缩减读集。
4. **接收器独立所有权。** 以完整内容为键的有界本地缓存；新内容先执行完整语法、深度/节点/字符、禁止键与资源 URL 校验，再创建不可变副本。只有该接收器自行生成的不可变值能跳过重复定义校验；普通字段的 assertDataField 仍在。
5. **挂载点根身份独立。** 缓存共享规范定义及其不可变子树，每个定义绑定有独立的浅冻结根对象。未变内容复用该绑定的根，内容修订创建新根；不同挂载点不可因内容相同而别名化。LanDisplayShip 的射程/弹速查询及 LocalFirePrediction 依赖这个区分。
6. **保留回退合并语义。** 从不可变定义退回普通数据时先复制为可变对象；来源删除字段或原接收记录含本地扩展时，保留旧接收器的“遗漏字段不删除”行为。现有可变记录继续检查访问器/方法遮蔽，不因为收到了已验证定义就自动变成可信记录。
7. **保留发布包所有权。** v2 的翼队 tags、rebuildQueue 也复制已知嵌套数组/行，后续模拟不会修改已捕获发布包。v1 保持既有表示。

### 明确的兼容限制

- v2 准入后的显示定义是只读的；内容修改会更换根，不能假设对显示 spec 的写操作或永久保留旧 spec 引用仍有效。现有可变回退记录的合并语义保留，不等于支持任意模组写入冻结定义。此限制也是保持显式开关的原因。
- 接收器接受 displayVersion 1 与 2；这只是数据回退能力。**房间协议已从 30 升到 31**，旧协议客户端不能加入，需服务端/主机与客户端一起更新；不是跨版本房间兼容。
- 所有预算有界：每帧表最多 1024 项、1048576 字符、200000 节点、深度 32；缓存最多 256 项、2097152 字符、400000 节点。缓存淘汰不影响自包含帧正确性；这些缓存预算不包含正在显示或被调用方保留的只读端点。
- 未增加握手特性协商。开关由构建控制；dedicated Worker 构建也显式传入该变量，缺省 false。

原版数据/API 最小对照见 `display-definitions-source-notes-2026-09-24.md`。本轮没有操作桌面，也没有声称新增视觉效果与原版实机等价。

## 最终复测，而非沿用修复前数据

- Node v24.13.1；2 艘玩家 Onslaught + 62 艘 AI Hammerhead；seed 917。
- 现有 benchmark-authority-cpu 场景，生产 LAN 捕获、packed numbers、二进制编码/解码、实际接收应用；无采样 profiler。
- 每轮预热 240 tick，再测 240 tick；固定 1/60 s 模拟步。顺序为旧 v1 → 最终 v2 → 最终 v2 → 旧 v1，两轮/臂，各 480 个测量样本。
- 使用已有冻结 before-cpu.mjs 与新冻结 final-cpu.mjs；后者包含挂载点根身份修复。四轮全部保留，未挑选快轮次。构建输入不含 campaign 模块。
- 不含 renderer、IPC、网络、计时器或调度节拍，因此数值不是 FPS、网络 Hz、主线程长任务或输入到画面延迟。

### 均值（ms/测量 tick；负百分比表示耗时下降）

| 阶段 | 原 v1 | 最终 v2 | 变化 |
| --- | ---: | ---: | ---: |
| 模拟步 | 12.29 | 12.45 | +1.3% |
| 快照捕获 | 6.37 | 8.26 | +29.6% |
| 二进制编码 | 5.19 | 3.05 | -41.2% |
| 二进制解码 | 2.89 | 1.61 | -44.3% |
| 接收应用 | 15.65 | 8.13 | -48.1% |
| 捕获 + 编码 + 解码 + 应用 | 30.10 | 21.05 | -30.1% |
| 权威端：模拟 + 捕获 + 编码 | 23.85 | 23.76 | -0.4% |
| 完整串行 CPU 流水线 | 42.39 | 33.50 | -21.0% |

- 每帧未压缩二进制字节：**666285.70 → 386849.39**（−41.94%），不是压缩后网络流量。
- 完整流水线 P50：**41.12 → 32.36 ms**；P95：**51.94 → 43.31 ms**。
- 发布与接收四段合计 P95：**34.11 → 25.49 ms**。
- 权威端三段合计 P95：**31.27 → 32.71 ms**。不能用接收端均值的大幅下降掩盖权威端尾部退步。
- 模拟步均值变化 +1.35%，不是提速；本切片本来就未改模拟计算。不同阶段可受 GC、布局、系统负载影响，不把差异直接归因为单个函数。

之前的 abba-1-before 至 abba-4-before 是根对象修复前的独立实验：接收应用 −47.4%、完整 CPU −17.6%、权威端 +4.7%、捕获 +35.2%。它们仍保留作历史，不与最终四轮混合。两批都显示接收端明显改善，但无法支持权威端稳定提速的结论。

## 正确性与验证结果

- 最终定向回归 **8/8 通过**：显示 record/direct-projectile 既有 guards 与恢复行为；v1/v2 全数据值、HUD 和贴图读集；同内容双挂载点的独立射程/弹速与跨帧稳定身份；定义修改、undefined、访问器准入、可变子树回退及重新准入；保留发布包、跳帧、冷重连、v1/v2 切换；非法语法/索引/资源/深度/字符/节点预算；binary、tape、relay、delta 路径。
- 非法定义表与引用在显示对象修改前拒绝；该断言仅覆盖新定义预检，不宣称把所有既有解码失败改造成事务回滚。
- 类型检查通过；本次改变文件的 oxlint 通过；改动范围 whitespace 检查通过。
- 真实 authority Worker：**16 舰、1200 tick、1199 帧、1184 个带 muzzleEvents 的帧**；逐帧比较快速权威摘要与完整解码摘要，v2 表非空。先前失败只是结果目录不存在，补建后本次完整执行通过；它是正确性验证，不是延迟基准。
- 最终四轮完整末态显示数据值归一化摘要一致（保留特殊数字、typed buffer、Map/Set、舰船引用与循环；忽略只读属性标记及非循环元数据共享）。归一化本身不证明对象身份等价，挂载点身份由上述独立回归验证。
- 原 v1 四轮/历史 wire 摘要保持一致；最终 v2 wire 摘要与修复前 v2 一致，说明根身份修复仅改变接收所有权，不改变报文。
- 之前单次关闭开关的 fallback 检查与冻结 v1 的 wire/完整对象图摘要一致；该单次时间数据不足以证明没有性能回归。

## 晋升门槛与后续方向

1. 本实现暂不默认启用。先定位捕获阶段新增开销，要求完整权威端均值和 P95 都有稳定收益，不能只报告接收器节省。

3. 纯模拟吞吐仍应按下一方案文档，单独推进火控候选查询/事务内共享，不把本轮报文优化说成解决 100/200 舰 60Hz。不得同时重写 Worker/AI/ECS 造成无法归因。

生涯模式的并行改动未暂存、提交、打包发布或覆盖。
