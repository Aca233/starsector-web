# Phase 17：房主模拟与画面线程解耦—实现前记录

本轮为联机扩展的线程/流控改造，不改变原版 fixedUpdate、AI、伤害、武器或界面。继续沿用 Phase16 原版证据；原版实机操作与同分辨率截图未获许可，不作等价声明。

早期探索基线（后来发现缺少 COOP/COEP，走原生 WebSocket 回退；不能当桌面默认路径对照，保留失败/探索证据）：同一台无头软件渲染机器、3 个真实 LanBattle、22 舰，房主 physics 59.886Hz，但本机完整显示约15Hz、客机约9Hz，客机输入确认 P95 436/474ms。此测量含单机软件 GPU 争用，不等于用户显卡或 Steam/n2n 性能。此前只测物理 Worker 或录制回放不能覆盖该瓶颈。

现状：host.worker 的快照/运动上传、所有远端 input/presence 都要经过 LanBattle 的主线程。其显示解码信用同时限制网络出版。因此房主主线程卡顿会拖累远端玩家，即使物理 Worker 能维持60步。

预期：在已有可信的同一 socket I/O Worker 与物理 Worker 之间建立有界 MessagePort，沿用原认证连接、原协议与安全限制。网络出版信用和房主显示信用分开；输入按同一 socket 顺序交给物理 Worker。原生 WebSocket/不支持 Worker 的环境保留旧路。连接失效停止直通，重连保留旧路径，不伪造 ACK。显示单次音效独立保留有界队列；不把取消/未发送当网络消费。

验证：单元测试顺序、scope、背压、关闭、缓慢主线程、终局和回退；真实 LanBattle 3/4/5 人并验证主线程受阻时远端输入与网络出版仍继续。LAN 与 Steam 共用本地 I/O 接线，但真实 Valve 公网/n2n 仍需真人验证。不得用本机 loopback 证明任意带宽下60Hz。

## 验证纠正（实现后补记）

初版浏览器夹具缺少跨源隔离响应头，`crossOriginIsolated=false`，未实际使用 WorkerLanSocket。加入 COOP/COEP 并断言隔离后，重新做同配置、同 3 人 22 舰对照：`browser-baseline-isolated`（仅关闭直通）客机完整状态中位数 22/22Hz、输入确认 P95 149.503/137.674ms；`browser-3`（默认直通）40–41Hz、71.656/70.796ms。此处才是本阶段有效的隔离路径对照；仍是单次单机受控结果，不能推断 Valve/n2n 或所有硬件。

重连夹具最初误用 4001（身份被另一个页面接管，协议明确不重试），并未保持同一 match 对象。改为可重试的 4000、按 LanApp 保持同局对象后通过。五人夹具最初共用一个本机 helper，触发其四连接安全上限；改为每个客户端独立 DesktopLanBridge，不改变生产连接上限。以上夹具失败记录均保留。

五人 22 舰的软件渲染重载测试仍未通过，不能用五人轻载冒充五人重载验收。完整数据和剩余边界见 `network-authority-io-phase17-2026-09-21.md`。
