## 已实现

- 独立可替换 `cargoGestures` 服务，`OriginalCargoGestures` 默认按原版无费用容器规则：向内先填满、已满可继续超载；向外先移出超额、再次点击可整栈转移。人员共享容量、燃料容量及普通货舱分开计算，保留源码的 int/向下取整和不足1余量整栈分支。**不包含市场短缺/过剩交易分支**。
- 认证只读 `/campaign-api/cargo-preview` 增加可选 `quickTransfer`：先验证世界/控制权、舰队和完整成员版本、保留库存及源栈可用量，再用锁定的 `fleetStats` 和 `cargoGestures` 计算。替换规则可拒绝/返回0，但不得超出源栈。查询不产生指令回执、事件、版本或库存写入。
- `quickCargoTransfer` 只应用报价数量，跨栏合并或放到首空格，不生成手持光标；不可变、数量精度、64商品/4096格保护保持原子性。
- UI Ctrl 操作查询期间锁住转移/确认和离开页面；Esc取消读查询，T可取消读查询及已有草稿，10秒超时可重试。舰队/成员/控制权/库存变化、取消和旧组件迟到响应不能覆盖新状态。已有手持时 Ctrl 按源码落入普通放置，而不是再次发快捷查询。
- 最终抛弃仍需G确认，沿用原指令权限/版本/幂等回执。没有另开表单或改变原旗帜、双容器、左栏汇总和T/G位置。
- 规则档案升级为 `reference.cooperative 0.12.0`（新增 `reference.cargo-gestures 0.1.0`）。锁定规则不静默漂移；旧开发档若使用旧锁仍须显式迁移/旧规则支持。本轮未删除、重建或迁移任何用户存档，仅使用内存QA世界。
