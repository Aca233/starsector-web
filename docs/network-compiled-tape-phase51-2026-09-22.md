# Phase51：实际编译五人对照复现过载，不能启用新异步路径

2026-09-22。**补齐了可复用的隔离编译验证路径；没有新的默认联机优化上线，也没有降低验收门槛。新直接tape辅助编码仍不能证明解决重负载。**

## 本轮改动

- 扩展现有`build-local-battle`：默认dist行为保留；显式隔离输出只允许仓库artifacts内新目录，拒绝替换已有目录。主线程及嵌套Worker均使用同一份冻结战斗源图，记录源码与编译JS/CSS哈希，禁止campaign模块进入入口图。
- 扩展现有`check-compiled-multiplayer`：可验证并运行隔离构建；默认仍检查原有效dist。保留真实UI建房/入房/配装/准备/开局、输入、800ms阻塞发布、同局reload、清理的原断言。可指定初始seed，服务器match对象在广播前统一赋值；不修改已运行的模拟。
- 修正被冻结源加载器的`?raw`语义：返回JS字符串模块，而非直接把JSON当JS解析；URL/Worker包装仍交给Vite。首次构建因此失败的日志保留，定向修正后才重建。
- TypeScript通过；改动脚本lint通过；既有构建审计测试扩展到3项，全部通过。两份battle-only隔离编译通过，均记录2430个主/Worker导入源、591源文件冻结图；全部10份输出CSS逐字节相同。主机/辅助Worker实际被编译，不是只测Vite源代码。

本块没有玩法/UI代码改动，没有生涯、提交、推送、安装或发布。

## 实际编译运行结果

5个独立headless Chromium，1280×720，D3D11；22舰、seed917，相同源码图、真实编译UI。模拟不在tick1暂停，解决了上一轮测试入口无法完成启动的障碍。两次均成功加载并开始推进。

|运行|原始断言结果|服务器最后完整tick|实际观察|
|---|---|---:|---|
|当前默认同步对照|测量期间战局结束，失败|1988|完整发布退到约10Hz；房主画面仍约60FPS；最终worker-runtime持续过载/恢复失败|
|新直接tape辅助编码定向复查|预热期间战局结束，失败|612|辅助线程确实启用，至少391个作业完成、fallback0；初期完整发布达到约51–55Hz，随后模拟与发布一起下降并过载|

原A/B计划在对照失败后停止，`comparison.json.passed=false`。根据新复现的过载，只做了一次候选故障定向复查，不重新跑对照挑成功。**没有构成完整正反顺序性能对照，不用上述tick或早期Hz宣称严格的加速/回退百分比。** 两次进程均终止、浏览器和服务器清理完成。

对照失败前最后一个HUD样本：完整9Hz、画面60.002FPS，模拟16.872ms、capture6.508ms、encode4.699ms。候选最后仍active的辅助数据示例：prepare约3.245ms、worker约2.412ms，capture约7.565ms；这些是独立平滑指标，不能相加冒充同一帧实际耗时。

报出的最终backlog约282ms（对照）/272ms（候选）包含终止后才落入HUD的尾值；故障摘要把`battle-failed`之前的样本另列，不混入停机后冻结指标。候选退出后serializer显示inactive，不代表它从未启用，也不是已发现编解码异常。

## 结论与后续方向

1. 在这个同机负载中，确实复现“客机画面60FPS，但完整状态低Hz、最终断线”。不能只修HUD或插值，也不能把降低编码局部成本当作整局已经完成。
2. Phase50辅助线程的“重建世界再编码”已去除，但权威仍先capture生成整棵投影，再遍历该投影提取tape；准备成本仍在权威线程，辅助结果也仍需回到权威后发布。**现在没有证据支持默认打开它。**
3. 下一块需要消除权威侧的第二遍投影提取/中间对象工作，并审查跨线程发布等待。保留当前同步路径和完整精度/信用/恢复预算，不再仅仅调整Worker开关。
4. 测量为单机五浏览器，不是远程Steam/n2n或5台独立机器。运行结束后读到16逻辑CPU、约63.8GiB内存；这只是容量，不是运行期间CPU负载，不能据此把失败归咎于外部进程。两次壁钟输入/完整轨迹也未证明逐位相同。
