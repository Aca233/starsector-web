# 联机房主操控预测与快照打包（2026-09-18）

## 状态

优先处理联机。修复房主本舰缺少展示预测的操控延迟，并减少快照打包开销；**不是大舰队过载已经修复的声明**。3005 服务（PID 18988）保持不动，构建和双端验证都使用独立临时端口。

未改变固定物理 dt、舰船/特效数量、AI/伤害规则、恢复次数、快照格式、安全校验或协议 v22。权威仍是房主的 Worker，服务端转发/校验，不在其他客户端重复跑权威战斗。

## 本轮定位

基于上一轮已落地源码和生产构建 2026-09-18T05:23:28.237Z 重新采样，没有继续凭旧 drawStrip 热点修改渲染：

- 真实双端 32 舰主线程 profile：房主约 10.75 秒 idle，客机约 9.89 秒 idle（约 14.8 秒采样）；GPU 为 RTX 5060 / ANGLE D3D11，不是软件渲染。不能把问题归结为渲染线程占满或显卡太差。
- 随后采样真实双端 Worker：32 舰两次恢复后在 tick687 报过载；100 舰在 tick43 报过载。热点仍包括武器控制、威胁评估、角度运算、快照遍历等。
- 排查中发现 LanBattle 的 record/receive/render 三个预测入口都排除了 seat0。房主实际也使用展示副本，权威在后台 Worker；因此同步频率下降时，房主按键响应要等快照。

## 改动

### 房主和加入者使用同一套本舰展示预测

移除三个仅允许客机进入预测的条件。仍只记录成功发送的输入，用本席位 acknowledged 清理已确认输入；预测不发射武器、不运算伤害、不修改权威位置。原有近距离碰撞、失焦/菜单、死亡/撤退、断线/重新同步和过期帧回退全部保留。

正式改动：src/network/LanBattle.tsx。没有更改 MotionPrediction/SnapshotPlayback 的算法或预测时间上限。

### 快照标量打包

对象字段仍先筛选键、再按相同顺序读取值，保持两次 getter 读取及 SKIP 规则。第二遍直接拷贝有限数值、字符串、布尔和 null，结构化字段、undefined、非有限数继续走原递归路径；去掉每个对象的 filter/map 回调。没有跨帧缓存，没有删状态字段或降低精度。

正式改动：src/network/CombatSnapshot.ts。

## 验证

### 一致性

- 4,001 组随机/边界打包差分：非有限数、负零、undefined、函数、循环与共享引用、Vector2、Map/Set、typed array、稀疏数组、危险键及副作用 getter；逐值/键序相同，getter 都读取两次。
- 32 舰600tick、100舰240tick、40阵营240tick；每30tick对原/新 capture 输出比较，两轮均一致。原/新状态哈希检查点各36个（两轮共72次同帧打包比较）。
- 这里的完整战斗循环时间不用于证明模拟加速：改动只涉及打包，两轮模拟计时有明显共享机器波动。

### 真实双端操控

独立生产验证构建，仅在展示循环加只读诊断引用；实际服务器建房、加入、准备和开战。强制2Hz同步以放大等待快照的差异：

- 房主和客机按 W 后，首次按键绘制样本均已产生本舰预测位姿；该帧权威位置尚未改变。一次房主样本约6.3ms后出现预测，而首次展示权威位置变化在约163ms后；这不是 RTT 或所有设备延迟承诺。
- 每次预测 render 前后核对位置、速度、角度、输入字段、瞄准点、生命与开火标志，没有改写展示中的权威字段。无页面异常。
- 菜单打开：预测停用并清除展示位姿；返回后恢复。
- 近碰撞：仅在展示副本注入临近主舰作为夹具，确认停用/清除，之后还原。没有更改真实 Worker 世界。
- 房主真实 WebSocket 断开：停止预测、清空旧输入；自动续接完成最新帧握手后恢复，无旧按键残留。

类型检查、lint、无诊断钩子的生产构建均通过。

### 预测自身开销隔离

同一带只读诊断引用的候选构建分别保留/禁用房主 prediction.render：启用场景共298帧、204帧允许预测，预测累计25.3ms，均值约0.085ms/绘制帧（单次最大1.4ms）；两场均约12.3～12.4秒后过载，快照墙钟倍率均约0.905。此有界实验不支持“新增房主预测是主要过载来源”的判断，也不证明全场无回退。禁用仅存在于验证页面内，正式源码不含该开关。

验证最后发现并行工作修改了 AutofireController 的固定炮射控分支；保留该修改。本报告的原/新性能和状态差分使用冻结源码隔离本轮两处改动，不冒充已经验证了随后改变的 AI 行为。当前工作区另外进行类型检查与隔离构建。
