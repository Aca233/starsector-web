# 私有显示类记录布局复用：性能验收（2026-09-26）

## 结论：否决，候选已完整撤回

本轮不是旧seal方案的原样恢复：不seal输出、不freeze键数组，只在三个私有类记录构造点登记一次来源；零原型组件和任意外来对象不纳入缓存。即便如此，唯一正式配对仍显示编码均值+5.04%，六个连续区间全部变慢；Host交付均值+0.65%，四段变慢。交付P95确实下降3.59%，如实披露，但不足以抵消相关路径平均耗时退化并满足预先写入的多指标保留条件。

已按本轮修改前原字节恢复Encoder、RenderShipProjection和既有render测试入口；专项helper归档，完整320模块重新核对与baseline一致。上一有效避碰优化等保持原状，本轮未留下新的生产性能改动。没有通过重复测试择优保留结果，也不能未经剖析将结果归因于JIT/GC/seal。

## 来源和方案边界

见render-record-layouts-source-notes-2026-09-26.md。本机0.98a-RC8 WeaponAPI.java:158/185/262的动态角度/位置/规格接口已检查；Web图传输没有原版算法对应，不改玩法/UI/频率/精度/字段/实体，也没有原版实机或视觉验收。

只在既有封闭数据命令Worker内对本Encoder的私有ProjectedRenderShip/System/Weapon完整输出缓存首次Object.keys。每帧所有字段值仍重新读取、比较并编码，保留原类型、prototype、forbidden、simulation、元数据、身份及预算校验。所有权证明以三个输出构造点无条件写入固定字段集合、不逃逸为边界；公开引擎/UI/外来同原型对象及可变零原型组件仍完整枚举。它不是same-realm脚本沙箱，也不授权给Worker加可执行插件后继续沿用。

缓存数组不直接共享到snapshot或packet。每个changed行（包括ObjectPatch）产生独立snapshot.keys，unchanged保留原别名。这保留旧包外部修改shape.keys、首次shape节点共享和补丁切断历史数组别名的既有语义。源Ship、武器规格、vector、数组均不封闭、不冻结，不缓存字段值。
