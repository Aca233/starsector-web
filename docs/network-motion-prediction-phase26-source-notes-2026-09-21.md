# Phase26：本机运动预测校正（实现前边界，2026-09-21）

## 证据与范围
- 本轮是 LAN/Steam 共用显示端修正，不改变原版移动、碰撞、伤害、武器或 UI 规则。
- `MotionPrediction.render` 已复用 `PlayerControls.applyPlayerControls` 与 `ShipMotion.advanceShipMotion`，仅创建自有 pos/vel/input 字段的 detached replica，写入 `ShipPresentation` WeakMap。
- 当前差异：校正拿上一帧的显示位置与本帧的重放位置直接相减，把两帧之间正常前进的位移也当成误差，以 90ms 衰减；频繁回包可以不断重新施加这种滞后。
- 当前差异：ACK 丢弃所有已确认输入后，从 blankInput 开始重放，不能保持已确认的持续推力/转向；只有最后约一帧使用 live 输入。
- 当前差异：LanBattle 在 fresh motion 存在但 inactive/nearCollision 时跳过整个预测调用，没有显式清理预测内部旧显示状态，重新启用可能带入旧校正。
- 不更改原版方程和资源，因此不重做玩法移植；原版实机视觉验收仍待许可，本轮不得启动可见窗口或操作桌面。近碰撞停预测、500ms 超时、250ms 重放上限保留，不放宽保护来伪造覆盖率。

## 预期修正
1. 在同一显示时刻比较：把上一预测状态用相同运动方程推进到当前帧，再与新权威基线重放的结果比较，只平滑真正差值。
2. 保存最后已确认的 held 输入作为重放初值；不重放 actions，不把未确认指令标成 ACK。
3. 暂停/近碰撞时显式丢弃过时的预测历史，但保留 MotionReplica 提供的权威显示姿态。等新权威数据后重新预测。
4. 加入预测实际生效、退出原因、重放时长、校正距离等结构化诊断。不改网络 Hz/RTT。

## 验证
- 固定 10/20/60Hz 基线、60FPS 的无损匀速轨迹，对比修改前后的额外表现位置滞后，保留旧实现副本；不能称为真实公网延迟测试。
- ACK 后持续推力、转向、真实小误差平滑、大误差/传送立即恢复、焦点/碰撞/陈旧数据暂停与恢复。
- 真实引擎预测前后完整快照/RNG不变；有界输入历史与重放步数。
- 共用 LAN/Steam 链路测试、日志白名单、类型检查、无头多客机实连。持续开火扩展不在本轮：不为提高覆盖率而猜弹药/幅能/冷却。

实现时追加：连续操控回归进一步确认不能从新输入的采样时刻截断自上次基线以来的时间；并删除会越过输入时间边界的 0.001ms 最小子步。两者均仅修正预测重放，不改权威物理方程。失败记录保留，精度断言未放宽。
