# 默认 LAN v1 定义重复与所有权审计（2026-09-26）

## 结论

**有结构性重复，但本轮没有生产提速补丁，也没有新性能通过结论。** 在固定的 onslaught/hammerhead 阵容中，武器定义约占舰船恢复普通数据字段的一半；接收器已经复用挂载点的定义根，单纯再加一层对象池不能省掉这些字段恢复和校验。

这与此前真实 LAN 恢复阶段诊断方向一致，但本轮是结构/身份审计，不能把字段数量当耗时占比，不能把重复比例直接当理论加速比，也不能宣称火控或 GPU 渲染不再是其他场景的瓶颈。

## 场景与可复现方法

- Node v24.13.1，无头 CPU 场景；2 玩家，seed 917，22/64 舰，battleSize 3200。
- 两个玩家 onslaught，其余 hammerhead；逐 tick 执行 1/60 fixedUpdate，各 480 tick，每 12 tick 用实际默认 captureLanDisplayCombat → binary encode/decode → applyLanDisplaySnapshot。
- 结构采样点为 tick 240/300/360/480，各规模四份；没有采样所有帧的定义变化。
- 明确断言 displayVersion=1、没有 displayDefinitions；不打开 Worker/v2，不改变模拟/发送策略。
- 328 个构建依赖保存在 sourcemap/source-hash 清单中；复查实际运行读取的资产清单字节未变。内容 catalog 的编译依赖由源码冻结图覆盖，不是额外的运行时文件读取。
- 运行无渲染、IPC、联机或输入到画面测量；不计时、不输出 Hz/延迟改善。

各规模四个采样点的武器定义根数、内容种数和定义字段数相同，后三次同绑定的内容签名均未变化。**不推出这些定义永远不变，也不覆盖混编舰队、战机、伤亡/新生成实体或所有模组。**

统计定义：
- “恢复字段”统计 plain/record 对象的属性，不把协议包装键算成目标字段，不把数组元素算成 assertDataField 字段。向量、typed block 等专用 envelope 保持不透明，未计数的专用工作不代表没有 CPU 成本。
- “校验树访问单位”按实际已恢复定义树计数，包括数组及标量，等同该数据树的 visit 节点数，不是实际计时/分配次数。
- 内容签名区分 undefined、-0、非有限数、数组空洞和属性顺序；不是 JSON.stringify 的宽松等价。
- 只统计武器/系统 metadata；已有 craftSpecs 舰体定义缓存不是本轮要重新实现的功能。

## 对象池为什么不是这里的主要解法

跨三个相邻采样点：
- 22 舰：558/558 次同绑定武器定义根保持原身份，0 次替换。
- 64 舰：1,566/1,566 次同绑定武器定义根保持原身份，0 次替换。

这直接证明本场景并非每帧为每个武器重新分配根对象。不过它不统计所有嵌套分配，不能声称没有 GC 或对象池完全无用。

离线接收端重放合同在两种规模均通过：
1. 同内容的两个挂载点有独立根；改其中一个不影响另一个。
2. 改写接收端 damagePerShot，下一次应用快照恢复权威值，根身份不变。
3. 接收端添加的本地扩展字段保留，不能用换根或清空对象悄悄删除。
4. 将 damagePerShot 改成 accessor 后，恢复在读取 getter 前拒绝，调用次数为零。

所以内容相等不能授权跨挂载点共享可变根，也不能按“wire 内容没变”跳过目标恢复/验证。GPU 不会自动消除 JavaScript descriptor、对象所有权及协议校验成本。

## 下一候选的选择

1. 优先减少**武器定义**重复处理，而不是先优化较小的系统 alias 或再改 validator 的标量分支。源端 system 读数去重已经存在。
2. 既有 v2 的不可变定义表方向与本轮证据相符，但它已有捕获变慢、权威端 P95 和可写兼容限制，本轮不重写旧门槛、不默认开启。
3. 先细分 v2 的额外捕获成本（准入 descriptor 扫描、内容编码、回退等），寻找能真正取消重复遍历的结构性设计；不是原样重跑 v2 选择好数据。
4. 新方案必须明确 source 更新契约和 receiver 所有权，保留原始可变目标/本地扩展路径，或明确声明隔离的只读能力边界。不能假定模组永不修改 metadata。
5. 只有形成实质不同的候选，才另写完整权威成本、恢复成本、真实 ACK→draw 尾部和正确性门槛并实现。不把本表 95%/98%重复量包装成可兑现的性能收益。

## 失败、工具修正与验收边界

- 首次运行完成 22 舰结构采样后，测试夹具误用了不存在的 damage 字段，assert.ok(first) 失败；run-1 全部保留。没有生产失败，也没有冒称两种规模通过。
- 定向改为现有 damagePerShot 后，run-2 两种规模全部完成。冻结生产依赖未变。
- 后续审阅修正纯诊断 helper：普通自定义 `$custom` 属性不能一概认作协议 envelope；另补跨样本根身份统计。final 定向重放完成；八个 wire SHA 和普通字段计数均与 run-2 一致。
- 新增 3 项小型工具合同通过：record/批记录展开计数、严格内容签名和 accessor 拒绝、内容重复/身份独立/跨帧变化。
- 改动三份工具 lint 最初有一项未用解构变量警告，定向修正后无警告。冻结 esbuild 编译及场景执行通过；没有生产修改，未运行或声称全项目 typecheck。
- 当前工作区有并行变更：与冻结图相比 HyperionPack、HyperionSystems、ModManager、DesignModel 四个文件有漂移，均未覆盖。这是冻结版本的结构证据，不冒称当前全部源码验收。
- LAN 接收/发送/呈现相关九个生产文件与此前保留版本 SHA 完全相同；本轮只新增诊断脚本、合同和文档。
- 没有子代理、桌面输入、可见窗口、暂存/提交/推送/打包/发布。没有运行中的测试进程；优化总目标仍未完成。
