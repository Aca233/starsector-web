# 在原规则 AI 上训练残差策略（2026-09-18）

## 这次训练什么

不是替换原 AI。原有舰队计划、站位候选、拦截解算、在途火力预算、碰撞规避和开火安全门禁仍然工作。学习层每个模拟秒为己方各艘存活舰选择一个模式：

| 动作 | 原规则 AI 收到的建议 |
|---|---|
| BALANCED | 不改变原规则偏好 |
| PRESSURE | 更积极接近、提高压盾目标权重 |
| FINISH | 略缩短距离、提高残血/过载目标权重 |
| CAUTIOUS | 保持更大距离、降低进攻机会权重 |

距离仍被舰种、碰撞净空及紧急幅能储备限制，动作不能直接授权开火、排能或违背玩家命令。当前学习的是接敌及**各武器目标偏好**，不是新的舰队总指挥器，也不是端到端神经网络。

算法为共享表格 Q-learning，学习值由真实战斗回报更新，不是把四个手写模式随机切换。固定动作空间是安全执行接口，模式选择才是被学习的部分。

## 观测 v2 与运行开销

模型升级为 schema version 2，观测版本 `flux-hull-window-mobility-target-pressure-v2`，最多 324 个离散状态：

- 自身幅能 3 档、自身船体 2 档。
- 可见主目标的幅能/过载/排能窗口 3 档、船体健康 2 档。
- 舰体基础速度比 3 档。
- 基于可见舰船的舰级、距离、剩余船体估计局部兵力压力 3 档。

不读取隐形敌舰或未来状态。兵力压力只是粗略特征，不声称是精确 DPS。模型停用时直接走 BALANCED，不在每门武器/每帧额外扫描舰队。v1 权重不能直接套入新状态编号，校验会拒绝。

默认动作与候选动作都至少采样 8 次、Q 值优势至少 .03，推理才会使用候选动作。这个门槛是保守回退机制，不是统计上的强度保证。生产 JSON 仍 `enabled: false`；实验模型只存在本地 artifacts 中。

## 真正的对手和场景划分

`FleetCombatLab.ts` 直接运行当前 `CombatEngine` 和 `CapitalShipAI`，60 Hz 物理、每秒一组舰船级动作。

- 一方是“原 AI + 学习动作”，另一方所有舰船保持 BALANCED。不是把双方同时换成新策略再比较。
- 每个场景/种子交换学习方阵营，另外跑同条件 BALANCED 对 BALANCED，控制阵营和阵容偏差。
- 训练：3 种 2v2 组合，使用 wolf / lasher / hammerhead / sunder。
- 验证：不同组合/阵型的 2v2、3v3，只用于选检查点。
- 最终留出测试：另外的 2v2、3v3 组合与阵型，包含训练未使用的 shrike、vigilance，种子流也与训练/验证分开。
- 最终模型先写入 `selection.json` 冻结，再运行 holdout；holdout 不更新 Q 表、不用于回头挑检查点。

训练对手只有当前规则 AI，**不等于**对人类玩家、不同版本 AI、自博弈联赛或所有舰种均有效。

## 回报和正确性

- 回报来自全队归一化船体损失差、全队胜负、己方过载时间和微小时间成本。
- 不奖励开枪次数，不将超时算胜利；超时在对照评分中记 .5，同时单独报告。
- 舰队尚有成员存活时，旗舰被毁不结束实验；死亡舰船不会从原始全队船体分母中消失。
- 同一步中处于同一 state/action 的友舰对 TD 目标取平均，只更新一次，避免把同一团队回报当成多个独立样本重复加权。
- 本轮长对局检查发现旧实验调用 `suppressDestructionSideEffects` 会跳过真正的击毁标记和处理，而不只是特效。已取消该选项，使用原生销毁/殉爆流程，并加入回归检查。早期试跑目录 `fleet-2026-09-18` 已明确标记 INVALIDATED，不得使用其结果证明性能。

## 命令与产物

```powershell
npm run ai:check
npm run ai:fleet-train -- --episodes 64 --seconds 75 --test-seconds 120 --checkpoint-every 32 --validation-pairs 3 --holdout-pairs 12 --seed 20260918 --output artifacts/ai/fleet-2026-09-18-native-deaths
```

训练默认同样为 64 局；每局最多 75 秒，最终测试最多 120 秒。每 32 局保存检查点。需要 Node 22+，不需要 GPU、Python 或新训练依赖。

评估一个已保存模型（不会继续训练）：

```powershell
npm run ai:fleet-evaluate -- --model artifacts/ai/fleet-2026-09-18-native-deaths/candidate-policy.json --test-seconds 120 --holdout-pairs 12 --seed 20260918 --output artifacts/ai/fleet-evaluation-repeat
```

产物包括：

- `run.json`：阶段、参数与状态。
- `training-episodes.jsonl`：每局结果、动作计数、回报与确定性状态摘要。
- `checkpoints/`：各检查点模型及独立验证结果。
- `selection.json`：在接触 holdout 前冻结的选择及模型摘要。
- `candidate-policy.json`：真实训练得到的候选 Q 表，不覆盖生产 JSON。
- `evaluation.json`：逐场对照、交换阵营结果、各场景汇总、模型/模拟器摘要和筛选门槛。

置信区间按“相同种子和场景、两个阵营合成的一对”重采样，而不是把相关的每舰动作误当独立样本。筛选要求至少 12 个镜像对、12 场真正结束的候选对局、实际使用了非基线动作、配对得分差区间下界大于零，并检查整体船体平衡及逐场景退化。即便通过，该脚本也**不会自动部署**。

## 验证范围

现有 24 项 AI/火控检查继续运行；新增 10 项舰队学习检查涵盖观测版本、隐蔽信息隔离、默认关闭的快速回退、场景/种子隔离、owner 快照观测一致性、对手控制权隔离、真实击毁流程、两阵营各场景可运行、确定性复现、超时统计和筛选门槛。

未覆盖航母/相位/主力舰课程、多人联机压力、所有 Mod 或模型启用后的完整浏览器 Worker 压测。短实验中的正收益也不能直接推广为全面胜率提升。

## 本轮实际结果（有效原生击毁流程）

有效产物目录：`artifacts/ai/fleet-2026-09-18-native-deaths/`。固定种子 `20260918`，训练 64 局，完成 7,060 次表格更新、覆盖 200/324 个状态。仅根据验证集选择第 64 局检查点，再冻结模型进行最终测试。完整训练/评估用时约 219 秒（本机，不代表游戏运行开销）。

最终测试为 12 个镜像场景/种子对，即 24 场候选策略对局，另有同条件的 24 场原 AI 对照：

| 指标 | 原 AI + 学习层 | 原 AI 对照 |
|---|---:|---:|
| 胜 | 11 | 12 |
| 负 | 12 | 12 |
| 超时 | 1 | 0 |
| 得分（胜 1、超时 .5、负 0） | 47.92% | 50.00% |

- 配对平均得分差：**-2.08 个百分点**；按镜像对 bootstrap 的 95% 区间为 **[-12.50, +10.42] 个百分点**，不能证明提升，也不足以断言总体必然更差。
- 全队归一化剩余船体差的平均改善为 +0.0297，不能当作胜率提升；平均回报差为 -0.00664。
- 实际执行了 795 次非 BALANCED 决策，说明测试确实使用了学习动作，而不是全部回退到原 AI。
- 每种留出场景只有 8 场候选对局：shrike 双舰场景得分差 +12.50 个百分点；混合三舰场景 -18.75 个百分点；vigilance 三舰场景 0。样本较少，逐场景数值只能作为问题线索，不能据此挑场景部署。
- 筛选结果 **未通过**：总体得分区间跨零，且混合三舰场景退化超过预设阈值。状态为 `NOT_DEPLOYED`，生产策略继续 `enabled: false`，没有替换原 AI。

结论：训练、冻结、对照和拒绝退化模型的流程已经跑通，**这一版候选策略尚未证明能增强原 AI**。这不是强化学习不能增强原 AI，而是当前小规模状态/动作设计、训练量及共享团队回报尚不足以支持这样的结论。

后续可在训练/验证集上扩充多舰课程、改进团队信用分配与观测，并比较多个训练种子；本次 holdout 已经看过，若据其结果修改算法，应另行预留新的最终测试集，不能反复在这批数据上调参后声称独立提升。

最终工程验证：34 项 AI/舰队学习检查、ESLint、生产构建通过（构建仍提示大 chunk）。两次独立的 2 局短流程试验在模型、模拟器 bundle 摘要、训练日志和留出结果上完全一致；这只验证可复现性，不作为强度证据。
