# 模拟战友敌部署与完整目录（2026-09-17）

## 修复原因

旧面板分别保存友军/敌军选择，但确认时只提交当前页并立刻关闭，另一边的选择被丢弃。目录仅使用 sim_opponents.csv 的30个预设（28种舰体）；不是所有可改装舰船。

## 操作

1. 在友军和敌军页分别选择舰船；Q/W切换，两边选择互不覆盖。
2. 两边都有选择时按钮显示“部署双方”，一次提交两边。单边选择仍可独立部署。
3. 分别显示两边已用/本次新增/上限；友军占用包括测试旗舰。任意一边超额或装配无效，整个批次不入场。
4. 成功部署后关闭面板和战术地图，不请求暂停；取消仅关闭面板。后续 Tab → G 仍可追加任意一边。
5. 默认完整目录，支持舰名/舰体ID/装配搜索、舰级筛选、分页；可切换回原版模拟预设。筛选、翻页、切换目录都不会清空已选舰船。

## 内容与费用

- 完整目录来自可改装运行时舰体和已导入原版装配，而非硬编码清单。当前175种舰体、351项装配，171种舰体的346项装配通过注册校验。
- 没有独立原版方案的舰体明确标为“舰体默认装配”，不伪装成某个原版战斗预设。
- 四种舰体（gargoyle、merlon、ravelin、shuttlepod）缺少独立部署费用；legion_xiv_Automated 在当前装配规则下超出40 OP。这些条目显示原因并拒绝部署，不猜费用、不自动删装备凑数。
- 采用原版目录解析后的 supplies/rec，保留 .skin 继承和覆盖。例如攻势XIV=40、执行官=50、军团XIV=40、狮心卫队斗士=5 DP。
- 新增 deployment-costs.json 和 simulation-variants.json 轻量投影；import-native-catalog.mjs 同步生成。此次仅从已有目录生成数据，没有运行全量资源导入，也没有验证资源哈希或大小。
- 原版有同variantId、不同源文件/武装的方案；通过源路径的无损十六进制编码隔离运行时身份，保留原始 sourceVariantId，不覆盖另一套装配。
- 目录只读取元数据；查看或选择时才编译装配，并缓存本次面板解析结果。编译不修改测试旗舰的 studio-prototype。

## 部署实现

CombatEngine.deploySimulationFleet 统一处理两边批次：先校验全部费用、方案及双方总额度，再构造待入场舰船，最后更新活动名册。原 deploySimulationShips 单方接口保留为适配器。

双方开场编队使用同一初始化阶段；确认后先建立真实主敌舰，再挂接友军AI和航母。后续增援从相应战场边缘入场。舰船费用、航母飞行甲板、可见性更新与既有战场逻辑共用。

## 验证

未新增测试源码/测试运行器。使用 esbuild write:false、Node stdin 和隔离浏览器上下文。

- 351项身份唯一，保留30项原版预设；346项可用装配全部完成内容注册校验。
- 混合友敌部署、双方独立额度、伪造费用/任一侧超额不入场、航母生成舰载机、开场间距、后续边缘入场、唯一舰船ID及旧单方接口通过。
- 浏览器组件实测：跨页/跨筛选保留双方选择；超额时战场仍只有旗舰；成功后双方同时出现并关闭地图；390px窄屏无页面横向溢出、确认按钮可见。
- 生产页面完整链路：改装 → 模拟战斗 → 敌军攻势XIV + 友军莫拉 → 部署双方。入口有地图，部署后地图和弹窗都关闭；再次 Tab/G 显示友军80/200、敌军40/200，再追加5DP敌舰后为80/200、45/200；取消后地图仍开启。
- 最终类型检查、lint、目录脚本语法、生产构建通过。构建仍有既有大分包提示。
- 开发版隔离验收页出现Vite热更新WebSocket连接超时；以上完整链路使用生产预览验证，不依赖热更新。没有把该开发连接提示当作游戏运行错误或宣称修复它。
- 没有宣称所有特殊原版效果1:1复刻，也未做长期大舰队性能验收。
