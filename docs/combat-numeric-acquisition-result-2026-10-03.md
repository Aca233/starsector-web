# 数值火控替换结果（2026-10-03）

## 结论

完成了一个真实计算块：武器寻敌、常速截获、射界判定和船体/护盾射线检测已切换到纯数值算法，并接上实际联机主机 Worker。不是 getter 包装或永久影子状态。**整体战斗性能目标仍未完成，模拟速度限制没有解除。**

仅在已有私有数据指令 Worker 所拥有的实际引擎中默认启用。通用内联世界继续使用旧路径；`VITE_COMBAT_NUMERIC_ACQUISITION=false` 可关闭新算法。之前失败的 canonical state core 和 copied numeric motion 仍默认关闭。没有更改固定步长、瞄准频率、参战/目标上限、暂停、玩法或 UI。

## 测量与正确性

同一既有场景：2 玩家 +20 AI，seed917，22 根舰、初始176实体/734挂点；双方均使用原有 Worker 所有权约定；每臂150步预热+120步计时，ABBA。最终均为170实体/90弹体。

| 项目 | 旧路径 | 数值路径 | 本次降低 |
|---|---:|---:|---:|
| 完整一步平均 | 59.259 ms | 57.568 ms | 2.85% |
| 火控查询阶段平均 | 16.205 ms | 15.437 ms | 4.74% |

这是一次配对测量的小幅正向结果，不能当作所有舰队/设备上的稳定收益。57.568 ms仍远超60Hz所需16.667 ms；不能把小型浏览器场景的约60Hz外推到重载场景。standard和large-battle-v3的逐步快照、随机状态、异步权威与同步执行、网络运动帧对照通过；四臂270步最终完整快照/RNG一致。1536例精确几何、每挂点完整preAim、真实范围权限、未知回调、关闭帧和默认准入边界验证保留在既有检查脚本中。

第一次实验的“12.6%整体改善”伴随火控自身退步，不再用作结论。通用内联修复臂整体反而慢7.8%，没有默认推广。CPU剖析定位每帧重复审核全部组件和武器规格的开销后，才复用实际主机已有的私有指令边界；原始失败数据全部保留。

## 实际联机验收

后台、无头、单机loopback；2玩家+4 AI，全部AI仍按原预设装备。玩家既有三个中型挂点通过正常配装协议显式换装现有单发质量校准炮，以覆盖本地确认后重复开火；没有修改武器规则或降低舰队数量。10.001秒推进602步；实际主机数值寻敌/扫描/接触计数增长；两端确认重复开火、800ms主机页面阻塞期间客机ACK前进、同一比赛重连、权威/控制台无错误及资源清理全部通过。该浏览器运行与数值计时的玩家配装不同，**不是性能对照**。

前两个浏览器夹具因空的第4组、蓄力/连发武器不支持单发确认重复而失败；第二次诊断还发现我漏读了单发限制。未删断言、未隐藏失败，也未改生产预测规则。
