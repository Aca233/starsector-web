# 私有Worker预瞄范围：最终验收（2026-09-25）

## 决定及限制

保留**小幅模拟阶段优化**。最终16目标门槛的真实200 Onslaught配对：模拟均值45.908→44.926ms（−2.14%，约省0.98ms），p95 57.935→55.195ms（−4.73%）。Worker往返+解码均值78.876→78.498ms，**只降0.48%**；不能称为大幅端到端延迟改善，更不是GPU或多核加速。44.93ms仍远高于60Hz的16.67ms预算，继续优化目标未完成。

这是一轮固定规模/种子的先导，不声明统计显著性、跨机器/混编/模组或所有长局均相同。六个连续区间中4个模拟改善、1个近乎不变、1个较慢；保留依据是主目标模拟平均及p95改善、已证实的实际工作量减少和行为对照，而不是把交付均值的不到半个百分点当作强证据。

## 保留的生产实现

- 新增`PreAimRangeIndex.ts`，只对已登记的Worker、已通过现有完整逐舰资格门槛的发射前batch生效。没有取消/简化hasOwnedFireControlReadHooks扫描，没有ArmorGrid资格修正，没有跨舰/跨tick缓存。
- `FireControlQueryBatch.ts`传递私有Worker所有权，重复preAim后备查询且可见敌舰>=16才建立索引；首查询与小名单保持原路径。batch结束即释放，普通/公开可变引擎不获得新索引权限。
- `AutofireController.ts`只替换preAim后备名单来源。指定目标仍先执行原track；正式aim扫描、角色/可见性/射界/精确碰撞/目标排序/RNG/发射决定保持原流程。
- 不是旧层次范围树：只保存位置/原序号，以跨度大的一轴排序，二分保守窗口，恢复原名单顺序。半径与相对速度全名单上界、充能/beam时间和向外padding确保包含旧outsideAcquisition允许的所有候选；不确定数值/密集窗口回退。包括active但arc尚未展开的偏置护盾。

## 激活失败修正，而非择优重测

首候选设>=32目标才建索引。无profiler200舰结果为模拟均值−0.13%、交付+0.91%。冷启动3tick探针显示build/query为0；补充150预热+3tick计数发现298043次Worker preAim调用的可见敌舰数全部为16–31，最大27，因此候选根本未实际启用。

据此将门槛改16，增加真实100舰资格下15/16/27可见目标的阈值合同。短探针先确认激活，再重做修改后精确源码的完整配对。首候选源码、失败激活、原始性能都保留，未覆盖或反复跑同一源码挑最好数字。

最终3tick独立插桩：594次建索引，5295次查询，进入索引的候选142965→51300（−64.12%）。这不包含594次首查询，且只是早期工作量计数，**不是完整战斗提速64%**。生产源码无计数探针；最终性能没有开启这些计数。
