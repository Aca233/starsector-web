# 战斗热路径优化：优先保持体验

## 约束与实现范围

本轮不降低渲染分辨率、画质、粒子数、舰船数或弹药数，不调整 AI/物理更新频率，也不修改武器射程、伤害、目标选择策略或战斗规则。修改范围只有三个 AI 文件：

- `src/engine/ai/ThreatAssessment.ts`：同一次同步威胁评估中，每个有效敌舰只计算一次机动参数；复用 DPS；避免方向/相对速度计算的部分临时向量；用保持原顺序的循环代替护盾扇区评分的临时数组，以及结果汇总的多次过滤。
- `src/engine/ai/ShipCombatProfile.ts`：保持候选射界、评分累加顺序和同分判定，移除每个候选方向的 `filter` 数组。
- `src/engine/ai/FireControlGeometry.ts`：在舰体多边形求交前增加保守的局部包围盒筛选。可能命中的查询仍使用原精确算法；护盾单独处理，不随舰体包围盒一起剔除。

机动参数不会跨 AI 调用或模拟步缓存：后续 AI 可能改变系统/幅能状态。几何缓存只接受外层数组与每个顶点均冻结的舰体边界；可变边界每次重新计算，新边界对象自然失效。包围盒取全部实际顶点，不把 `collisionRadius` 当作完整舰体边界，并保留边界接触和数值余量。

## 诊断

50 艘攻势战列舰预热 60 步后，使用 Node inspector 对随后 40 个实际模拟步采样。累计样本占比：威胁评估约 28.7%，`shipSegmentEntry` 约 32.7%，有效武器射程约 12.1%。这些调用链相互包含，不能相加为独立预算。

此前已有弹丸/舰船空间索引和 TS/WASM 碰撞通路；本轮不是重建该系统，也没有移除原有精确碰撞检测。

## 校验方法

遵循项目不恢复测试文件/测试运行器的约定，使用临时内联 Node/Vite SSR 对照，不增加测试套件，不审计资产哈希/大小。

- 60,000 次原版/优化版 `shipSegmentEntry` 数值对照：包括旋转舰体、凹多边形、超出碰撞半径的顶点、起点在舰内、零长度线段、顶点接触、偏心护盾、不同护盾类型/弧度、无有效多边形，以及只冻结外层数组但仍原地修改顶点的情况；结果相同。
- 800 组威胁评估及火力概况的完整字段/顺序对照：覆盖直射弹、制导弹、光束、来源缺失、过载/排幅、相位、推进器失效、系统不同阶段、禁用武器和空弹药；结果相同。
- 战斗对照加载同一份内存冻结源码依赖，仅替换本轮三个文件；使用相同随机种子和编队，每步交替原版/优化版的执行顺序。
- 比較可枚举战斗/AI 状态、引用结构、随机流、位置、幅能、装甲、武器、弹丸和特效等检查点数据。仅排除实际墙钟计时 `RuntimeCollisionKernel.telemetry.kernelMs`；不能要求两次执行耗时本身相同。闭包/WeakMap 内部状态不能直接序列化，其影响由后续战斗演化间接检查。
- 这些是限定场景的等价性证据，不是对所有未来模组/输入的形式化证明。

## 压测条件与解读

机器：Intel i5-13490F，RTX 5060，2560×1440 / 180 Hz 显示器。此处只测 Node 中的实际 CPU 战斗模拟，不包括浏览器渲染、GPU、音频解码或显示器呈现，不能换算为已实现的画面 FPS。

每组创建 10/50/100 艘攻势（双方各半），保留默认 18 个小行星；种子 `0x51180`。第 i 艘的 `pair=floor(i/2)`、`side=i%2`，位置为 `((pair%5)*3200+side*1500, floor(pair/5)*850)`，双方相向，初始目标为相邻敌舰。每步按原逻辑执行玩家 AI 与 `fixedUpdate(1/60)`，共 360 步，前 60 步预热，统计后 300 步；不减少战斗工作量。

原始采样和对照结果保存在被 Git 忽略的 `artifacts/capital-stress/`。

以下为一次配对运行的统计，不是多次运行的稳定上限；桌面后台负载、JIT 和 GC 会带来波动。表内比较使用本轮配对基线，而非上一轮独立采样。

| 50 | 132.57 | 81.74 | 38.3% | 163.86 → 108.94 | 1623 |

### 构建和浏览器检查

- `npm run build -- --outDir artifacts/combat-performance-after` 成功（包含 TypeScript 检查），不覆盖正在被其他工作使用的默认 dist。
- `npm run lint` 退出码为 0；当前工作区 `src/ui/tactical/TacticalMap.tsx:109` 仍有两条不可变性警告，非本轮修改位置。生产构建也仍提示现有大分块警告。
- 对独立生产构建的 `?view=combat` 入口做浏览器冒烟检查：2560×1440、DPR 1、实际 RTX 5060 D3D11 WebGL2，战斗画面可加载，未收集到页面异常或失败请求。浏览器已关闭，临时预览服务已停止。
- 冒烟检查没有测量 100 艘同屏 FPS，也没有证明 headless 浏览器能够按显示器 180 Hz 实际呈现。

### 距离目标

100 艘的 CPU 模拟负担明显下降，但平均约 410 ms/步仍远超 60 Hz 模拟的 16.67 ms/步预算；180 FPS 的呈现预算更只有 5.56 ms/帧。不能据此宣称已经实现 100 艘 / 180 FPS。

本轮保持体验的路线有效，但还需要继续处理全舰队火控/威胁重复工作、弹丸与导弹候选查询，以及射程/舰体插件解析等热路径，并持续校验状态与顺序。渲染和 GPU 优化应另行实测；不以减少效果、跳过 AI 更新或放慢模拟作为默认补偿。
