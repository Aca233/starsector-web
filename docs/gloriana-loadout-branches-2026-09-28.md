# 女王号：两条预设分支与新默认军械闭合

日期：2026-09-28；承接Skill复审C和D中的默认武器依赖部分。不是独立安装包交付。

## 先看原版：证据 → 差异 → 实现 → 验证

本机0.98a-RC8的 `starsector-core/data/variants/conquest/conquest_Standard.variant` 与 `conquest_Elite.variant` 在武器、插件、幅能容量及武器组上不同；`heron_Attack.variant` 与 `heron_Strike.variant` 则真实改变机载联队、主炮、耗散和插件。这里借鉴“配装改变职责和操作”的原则，不复制原版参数。当前Web女王两预设除了4点容器和名字基本一致。本轮保留已有方案选择/预览/确认/取消/撤消结构，不重排原版式界面；原版桌面实机仍待许可，未新增官方战锤考据。

## 本轮规则（Web原创适配）

- **战列齐射 II**：舰艏2光矛+2重鱼雷；六炮廊显式购买现有12OP联锁供弹机。插件常态实弹射速×0.8；选中舷敕令满强度×2.1（相对无插件常态），对舷叠加原敕令减速。玩家需要挑舷、挑窗口，非永续增益。保留当前联队的既有约定；若自选联队过贵，照常报预算错误，不偷偷裁装备。
- **盾矛协同 II**：保留六甲板与48槽，安装现有18OP近域整备线；2狂怒联队+1雷鹰+3星鹰，共8截击机、1炮艇、6轰炸机。核心两个通用中槽鱼雷换同档攻城炮，核心20耗散、0容器。放弃舰艏有限重鱼雷爆发和六炮廊供弹增益，换可返航补弹的航空持续打击。战损补充时间×0.7、补充率恢复+50%，代价是联队出击范围×0.75；**不缩短存活轰炸机12秒装弹**，不提高武器伤害。
- **新默认舰体**：3个跨舰武器引用替换为本舰既有专武（M12/M13鱼雷，M14攻城炮），修正默认核心分组。使用正式已有素材，槽位/档位/射界不变；仍保留用户可改装权。
- **旧存档**：不在decode/load迁移中替换武器、联队、插件或组；旧存档显式保存的竹鸢武器仍可读。修改预设函数只影响新建/主动确认的预设；用“II”区分新模板，内容稳定ID不变。
- **选择提示**：沿用已有预设警告区域，明确哪个保留联队、哪个更换联队及其代价，纠正旧航空方案也声称“保留当前联队”的错误文案。

## 验证计划

一次类型检查、改动文件lint及既有军械脚本的定向场景：预算/48槽同档/依赖闭合、旧存档不变、两套模块与机库真实差异、实弹常态与敕令窗口的实际射击/幅能/退出、战损补员与返航重装、预设选择取消/确认/撤消以及真实Worker读回。测量使用生产Ship/FighterSystem/Worker，不为示例增加假战斗逻辑。不把功能探针当自然混战平衡，也不宣称完整舰船包已安装验证。

## 验证结果

### 类型、逻辑与实际行为

- `npm run typecheck`及改动文件oxlint通过。既有军械入口 `node scripts/check-gloriana-armory.mjs --loadouts-only --logic-only` 的**6项分支检查＋9项航空回归，共15项通过**。报告：`artifacts/gloriana/armory/verification-loadouts.json`。
- 新默认核心230/260 OP；两个新预设核心均260/260。战列的六炮廊各实付12OP供弹机，模块预算分别146/200、154/200、138/200（左右相同）；航空核心实付18OP近域整备线，六炮廊不装供弹机。两套整舰仍9段/48个兼容同档挂点，无漏槽或白送插件。
- 在仅含女王舰体/模块/飞机/武器记录的临时内容注册表中，新默认与两预设均可构造真实整舰和六甲板，不需要注册竹鸢武器。随后还原测试注册表。**这只证明舰船/武器数据闭合**：仍使用宿主已注册行为与原版公共素材，不证明可独立安装。
- 旧配装模拟快照含三门竹鸢专武、自选联队、武器组与旧模块装配，保存/读回保持这些内容及身份不变。自选六星鹰联队的战列方案超28OP，保留装备并返回预算错误，不静默削减。

#### 受控单宏炮实测（不是整舰DPS或自然命中率）

生产Ship左前炮廊；仅启用一门既有宏炮、固定射向、手动触发，无碰撞目标。初始幅能为0；敕令测试先经过0.8秒启动，再统计6秒窗口；观察实际发射与幅能付款，不只比较面板倍率。

| --- | ---: | ---: |
| 常态30秒实际出弹 | 28 | 35 |

#### 航空

- 战列默认14机（8狂怒、2雷鹰、4星鹰）；航空15机（8狂怒、1雷鹰、6星鹰），均六联队。

- 新航空方案重新通过固定炮口、拦截/压盾/护盾窗口、双雷出射、返航装弹、友舰/小行星遮挡与丢失目标等既有场景。

`runGlorianaLoadoutCheck()`（既有军械入口的loadouts分支）在隔离headless Chromium/SwiftShader和5197临时服务中通过，两方案各独立新配置：

1. 新默认没有跨舰武器；预览显示260/260和准确的换装/代价提示。
2. 预览后取消不改草稿；确认实际改装；撤消恢复原有武器/联队/插件/模块/分组/幅能配置；应用保留原船ID和名称。

5. 两方案无pageerror或HTTP失败资源；自己的浏览器和Vite服务已关闭，不影响用户5173/5174。
