# 操作边沿需求驱动的回执前重试：预注册（2026-09-26）

## 依据和实质差异

上一轮空队列回执前重试（lan-pre-receipt-retry）已否决且精确回退：发送/ACK目标全部通过，但第一对忙时control→submit +3.540039ms，超过3ms门槛。已有数据表明忙时接受输入26.7→45.7、27.4→43.4包/秒；后段等待不能归因于这些包、GPU或GC，同mask也不证明完整输入重复。本轮不改其判定、不原样重跑。

新候选改变**重试需求的来源**，不是微调旧回执额度或时钟：

- DOM按键、松键、开火、动作、显式清零调用sendInput默认edge=true，失败后保留一个需求位。
- 原60Hz定时器调用sendInput(false)，照常采样/发送；若此前没有操作边沿需求，它失败时不会新建需求位。
- 有待发送边沿时，定时器失败不能擦除它；任何一次成功发送最新输入都满足需求并清除。
- 原回执前空队列机会只服务这一需求，重试以edge=false调用。不会自我制造新的需求。
- 未launch/sync/ready等原早退清除需求；焦点/权限仍走原resetInput。所有input字段及原动作清空/序号提交语义不变。

共享上一候选已验证的有界单所有者回执前机会组件，但不恢复“所有失败采样都重试”的策略。对比合同必须证明相同周期失败序列，旧候选会额外发送、本候选不会；相同操作边沿本候选仍会及时重试。此区别是本轮核心机制，不以更宽门槛换通过。
