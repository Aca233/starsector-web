# 轻量舰队战术与配装角色 · 2026-09-17

## 范围与结论

在既有逐炮火控、局部驾驶、防御与系统决策上，新增一个**每 AI 阶段共享的轻量舰队计划**。用于正常单机、玩家自动驾驶和 LAN 权威引擎中的普通 AI；不取代玩家战术命令，不接管远端或手动驾驶的舰船。

这是明确标注的 Web 启发式策略，不是原版 BasicShipAI/FleetAI 的完整移植，也不是学习模型。没有修改舰船机动、武器伤害/射程、物理步长、AI 频率或画质。

## 行为

### 1. 目标选择

- 综合进入有效射程的时间、目标剩余结构与幅能、过载/排幅机会、局部敌我支援和已分配火力评分。
- 保持当前目标有额外奖励；已有目标的火力承诺先计入，再逐舰移除自己的承诺并重新分配，避免所有舰船同帧换到同一目标。
- 近处可击杀目标更有吸引力，但不会仅因远处目标残血就无视接敌时间。
- 指定交战/避开目标优先；防守和护航还会按任务位置调整选敌偏好。
- 敌方候选与敌方支援只来自本队可见单位；死亡、离场、停泊目标不参加。使用 teamId 而非把 isPlayer 当成唯一阵营标识。
- 每门炮的独立选敌/射击安全仍由 AutofireController 决定，不强迫全部挂点朝舰队目标空射。

### 2. 火力分配与接敌方向

- 手动舰船与显式交战任务的已知目标计入承诺，但不会被重写。
- 对目标的可承受火力使用结构、装甲与火力的粗略需求估计；过多舰船集中于同一目标会降低该目标后续得分。
- 同队、同目标、无显式命令的攻击舰按当前空间位置分配不同接敌方向，驾驶只施加有上限的切向修正，不沿直线穿过敌舰。
- 新计划每阶段建立，不保存跨战斗的舰船引用；部署、死亡、配装失效和新命令会在下一次决策反映。

### 3. 配装角色

角色由可用武器、实际有效射程、运动速度和可出击机翼规格推导，不根据舰船 ID 写打法分支：

| 角色 | 当前行为 |
| --- | --- |
| LINE | 沿现有主炮距离施压，并错开接敌方向 |
| BRAWLER | 在主炮距离内稍微压近，不改变武器真实射程 |
| ARTILLERY | 保持按主炮配装计算的远距离，不因副炮强迫贴脸 |
| SKIRMISHER | 对残血/支援型目标增加偏好，使用更宽的接敌方向和更强的切向修正 |
| CARRIER | 主炮较弱、机翼主导时，以机翼可用交战范围保持距离；无主炮不再自动当成完全无武装而无限后撤 |
| UNARMED | 武器暂时全部失效或耗尽时寻求友舰掩护，原有武器恢复后重新分类 |

高压或低结构舰船只有找到合适掩护时才自主 regroup：靠向友舰背敌一侧，而不是永远直线倒车。等强、同样暴露的邻舰不能互相作为掩护。显式航点、防守、护航、避开命令以及 doNotBackOff/系统强制战术模式仍优先。

## 模块与兼容性

- `src/engine/ai/FleetTactics.ts`：纯计划函数、评分、火力承诺、掩护与接敌方向；参数集中在 fleetPolicy。
- `src/engine/ai/FleetNavigation.ts`：角色交战距离、切向接敌与掩护站位。
- `CapitalShipAI.ts`：消费计划，然后继续原有威胁、防御、避碰、系统流程。
- `CombatEngine.ts`：普通舰船 AI 阶段只计算一份计划。旗舰自动驾驶保留现有前置更新顺序，因此会独立计算一份前置计划；不能将其描述成整个 tick 只有一次计划调用。
- 四 owner 协议发送相同的标量/ID 计划。权威阶段重新生成并逐字段比较计划，任何变化使预测失效；串行回算消费同一阶段计划。覆盖 planFleetAI 的自定义实现禁用推测入口，避免执行未知副作用。
- `ship.tacticalAI` 新增 fleetRole、fleetTask、targetScore、pressureRatio、assignedPower 诊断字段；assignedPower 是本舰本次承诺的有效火力估值，不是全队目标总量。手动接管沿用现有清理流程。

## 验证

遵循现有项目约定，没有恢复测试 runner 或新增测试脚本文件。通过 Node 内存加载真实源码执行断言，保留结果 JSON：

- 首轮 **25 项行为检查**：弱目标/失能目标偏好、接敌代价、目标保持、迷雾及隐藏支援隔离、死亡/离场/停泊排除、空战场、手动控制、多队伍、显式/舰队命令、火力分配和接敌方向、120 次静态计划稳定性、残血掩护、航点优先、无主炮航母、弹药失效、未知舰型配装复用、纯函数与计划变更校验。
- 最终掩护规则 **7 项补充检查**：避免互相掩护循环、保留有效残血掩护、doNotBackOff、防守/护航/避开驾驶优先、己方撤退舰不分配任务。
- 最终六舰混战：攻势/典范/厄运/野狼/攻势/星体，种子 222，固定 1/60 秒。两次各 3600 步，记录状态一致；全程检查位置、速度、朝向和幅能为有限值。峰值 89 个弹丸加光束、23 架舰载机；观察到施压、掩护、游击、航母支援、收割与武器失效角色变化。60 秒未结算，不把它写成胜率或打法最优的证据。
- 四线程等价检查：50 艘默认攻势，真实生产 owner.worker.ts 经仅内存的 Node worker_threads 适配器在四个线程执行，与正常串行引擎逐步对照 180 步的舰船/目标/战术/控制/武器/弹丸/光束关键状态。不是所有闭包、隐藏状态的形式等价证明，也不是浏览器吞吐基准。
- 浏览器开发入口实际交战至结算；重开后 U 切换 AI → MANUAL → AI。手动模式 tacticalAI 清空、aiHoldOffensiveFire=false，恢复后重新产生角色和任务。观察期间没有捕获到页面 console error/warn。

最终 `npm run typecheck`、`npm run lint`、`npm run build` 均通过；Vite 仍提示部分分块大于 500kB，不影响构建成功。

证据：`artifacts/fleet-tactics-2026-09-17/behavior.json`、`final-behavior.json`、`owners.json`、`browser-smoke.json`、`gates.json`。

## 开销与边界

100 舰静态 Node 场景，40 次预热、200 次测量，**单次计划**均值约 2.058ms、中位 2.009ms、P95 2.327ms。计划是新增开销；旗舰前置更新、owner 发布/校验可能带来额外调用。这不是整步时间、屏幕 FPS、跨机器性能承诺或性能提升。

武器汇总为 O(挂点数)，支援与评分为 O(队伍数 × 舰船数²)，不对每个目标重新扫描最强重叠火力弧。没有降低 AI 频率来掩盖开销。

仍然不包含全局寻路、战略包围、复杂阵型重构、完整舰长性格、逐弹伤害饱和、装甲格收益、鱼雷同步齐射或舰载机完整战术重写。火力需求和机翼战力是估值；机翼暂时损失/再整备不是完整的未来可用战力预测。接敌方向与友舰掩护是局部建议，不保证密集封闭地图无死锁，也没有证明相对旧版或原版的胜率提升。
