# 原生AI阶段导航索引：验收与性能（2026-09-25）

## 结论

保留候选，继续减少大规模战斗中的重复扫描。**修复后的精确源码**在本轮200 Onslaught配对中，模拟均值52.557→45.847ms（−12.77%），模拟p95 65.160→57.445ms（−11.84%）；Worker往返+显示解码均值87.294→79.054ms（−9.44%）。不是调低频率、减少舰船、降低精度或放松火控审计，也没有GPU迁移。

这是本地默认真实Worker的一次固定场景先导；不等于实际FPS、网络RTT或输入到屏幕延迟。45.85ms模拟步仍约为60Hz预算16.67ms的2.75倍，总优化目标未完成。

## 为什么选择这一块

当前源码重新剖析发现：火控资格检查仍贵，但直接跳过它不安全；`TacticalNavigation.obstacles`及其add/距离计算也在每艘舰的避碰、冲刺路径检查中重复扫描全名单。即使绝大部分舰船非常远，也要重复读取相位/舰级/护盾/运动并执行筛选。

新`NavigationObstacleIndex`只在私有数据命令Worker、既有原生AI阶段门槛通过且≥64舰时创建。阶段内按X位置排序，借助所有舰船半径上界和L1速度上界，保守排除不可能进入原避碰范围的舰船；候选恢复原名单顺序后，仍执行旧过滤和完整精确风险计算。

- 不缓存死亡、相位、友敌或可见性；护盾半径上界包含未激活/PHASE护盾。原来的lookahead、8段积分、候选速度顺序与评分公式不变。
- 每舰AI后刷新保守上界；若发现位置变化，整个索引立即失效，不保留旧排序。finally关闭，名单/长度失配回退。
- 数值异常、负视界、范围溢出、候选过密均回退原扫描；小行星保持原扫描。
- 普通/inline引擎、未知钩子、owner依赖观察器、不满足原生读者的调用均保留旧路径。没有取消火控逐舰hasOwnedFireControlReadHooks检查。
- 只增加内部所有权查询，复用已存在的Worker登记；未添加用户DTO权限位或默认开启此前的实验呈现Worker。

本地local-combat.worker和LAN host.worker都会登记共用CombatEngine，源码上该路径覆盖这两种受控宿主；本轮性能仅测本地Worker，没有对LAN relay/真实客机/网络延迟作新收益声明。

## 真实失败与复查

首次候选完整状态/初始合同通过，模拟均值52.204→45.365ms。收尾补上普通调用的distanceTo访问器读取次数后，发现未提供索引时仍多检查一次原生数学方法（113次而非112次）。失败保存在`generic-reader-failure.log`。

修复为先确认受控索引存在，再读取数学方法；另将半径保守上界显式纳入0，覆盖未激活护盾分支及异常负数。修复后2194合同通过，并对精确最终源码定向复跑同一场景；本文只引用较后的52.557→45.847ms结果，未选择首轮较快数字。首次源码和样本保留，首轮不视为最终验收。该修复没有放宽观察器/外部回调的兼容要求。
