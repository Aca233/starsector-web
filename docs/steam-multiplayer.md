# Steam 浏览器联机（协议 v17 / Spacewar 开发联调）

## 已实现的运行方式

仍然是浏览器游戏，没有 Electron 窗口。每台电脑的轻量 Node 启动器调用原生 Steamworks，监听本机 HTTP/WebSocket；浏览器只连接自己的启动器。房主的浏览器 Worker 运行权威模拟，启动器复用局域网房间核心处理权限、准备、配装、分队、输入与快照，再通过 Steam P2P 转发给客机启动器。没有部署到 Valve 的战斗计算服务器。

局域网版保留：它与 Steam 共用房间和战斗逻辑，但连接入口、身份和房间命名空间隔离。Steam 玩家不能拿六位房间码从 LAN socket 绕过 Steam 大厅身份；恢复凭证还绑定 SteamID 和 Steam 大厅 ID。

## 源码运行

- Windows x64，Node.js 22+（便携打包要求）和 Steam 客户端；每名玩家须登录自己的 Steam 账号。
- 首次执行 npm install，之后执行 npm run steam（构建并启动）。已有同一构建时可执行 npm run steam:serve。
- 默认 Spacewar AppID 480。自己的 AppID 可通过 STARSECTOR_STEAM_APP_ID 或 --app-id 参数设置。480 是官方示例 / 联调身份，不是正式发行许可。
- 默认只监听 127.0.0.1:32102；冲突时尝试 32103–32111，不终止其他程序。重复启动匹配版本时复用已有启动器，不抢占已经连接的浏览器页面。
- 浏览器访问启动器给出的 ?view=steam 地址。网页不能独立替代本机原生接口；Steam 不在线时保留网页排错与重试入口。

## 玩家操作

1. 每个人拿同一份包，打开 Steam 并登录，再双击「启动 Steam 联机.cmd」。本机组件隐藏运行，浏览器自动打开。
2. 房主创建好友房间或公开测试房间。进去后仍是原来的房间侧栏和中央改装台。
3. 房间 → 邀请朋友 → 复制完整 Steam 房间号；朋友在自己的入口粘贴并加入，有密码时另外填写。
4. 不发送本机 127.0.0.1 地址，也不发送侧栏的六位 LAN 编号。房间列表只显示相同游戏标识和构建的公开房间；480 共享环境下列表可能不完整，优先使用房间号。
5. Steam 邀请回调会预填房间号，玩家确认后才加入；不自动退出正在玩的房间。普通浏览器不支持 Steam 覆盖层，使用复制房间号。Electron 桌面版已接入窗口主进程浮层与真实可用状态检测，见 [桌面邀请说明](electron-desktop.md#steam-好友邀请)。
6. Steam 大厅最多 10 人；游戏房间可以设置 2–10 席位，实际容量由房间核心校验。AI 不占真人席位。
7. 离开房间后可点击「退出启动器」。仅关闭浏览器不会自动关闭本机组件。运行中的其他 LAN 房间也会阻止无意停止启动器。
8. 可在 Steam 入口或主菜单明确选择局域网，此时才启动可供其他电脑访问的 LAN 监听。不会自动修改防火墙、登录账号、注册开机启动或修改 Steam 安装文件。

## 分发

npm run package:steam 生成新的 Windows x64 ZIP，默认启动项为隐藏的 Steam 浏览器启动器；也包含「局域网联机.cmd」「单机试玩.cmd」「诊断 Steam 联机.cmd」。无需另装 Node/npm/Electron，需自行安装并登录 Steam。普通 npm run package:windows 仍输出原来的 LAN 便携包。

源文件由 esbuild 依赖图收集后原样复制，原生 steamworks.js 模块和 Steam API DLL 随包放置。不会带入个人浏览器资料、Steam 凭证或游戏存档。游戏资源与 Steamworks 的授权要求仍由各权利人决定，不因生成 ZIP 获得商业发布权。

## 传输与安全边界

- 当前原生绑定是 steamworks.js 0.4 的 ISteamNetworking P2P 可靠消息接口，不是声称已接入 ISteamNetworkingSockets / 专用 SDR Hosted Server。Steam 处理连接及可用中继，不保证具体路由、低延迟或所有网络一定可达。以后替换现代 Steam Networking 接口时，可以保留房间核心和浏览器 UI。
- 不发送超过 SDK 限额的单个消息：按 32 KiB 分片，较大数据使用 deflate level 1 压缩；同一广播快照共用压缩结果。每个客机最多一份未确认快照，之后的新快照跳过，慢玩家不拖慢所有人的分发。
- 每条消息遵守原有 16 MiB 展示快照预算（传输封套另留少量余量）；重组总内存最多约 32 MiB，限制并发消息数、分片元数据、解压输出及 8 秒超时。恶意分片不会按声明长度无限分配。可靠传输仍可能队头阻塞，不等同于 UDP 回滚网络码。
- 只有当前大厅中被 Steam 标识的成员才能触发游戏消息；客机只能连接固定房主。namespace / build / protocol / owner 必须一致，所有权变化明确结束而非悄悄转移模拟。第三方 Steam 测试大厅不会被当作本游戏房间。
- 原生操作只接受本机同源、带专用请求头的 POST；WebSocket 校验 Host、Origin、大厅标识与单个活跃网页约束。不给网页任意原生调用能力，也不读取 Steam 登录凭证。
- 延用最新完整帧确认后再恢复控制的弱网门禁。普通浏览器断线可在 30 秒内续接，房主刷新导致 Worker 丢失仍不能恢复。Steam 退出登录、大厅被移除、原生组件退出或真正换主机不能保证续局。

## 验证与未验收项

已用临时 stdin 验证：分片乱序重组、压缩、超限元数据、缓存超时、邀请 AppID；模拟 Steam SDK 下的真实本机 WebSocket 大厅、房间权限、Steam/LAN 隔离、恢复身份绑定、分片快照/ACK、操作和续接。没有创建测试文件或测试运行器。

双独立 Edge 浏览器使用模拟 Steam 传输完成了：创建/加入 → 选择野狼级并应用配装 → 准备/开战 → 客机刷新恢复 → 房主结束 → 双方返回房间 → 离房/重建。确认房主创建 1 个战斗 Worker，客机不创建；邀请框使用完整 Steam Lobby ID，重复控制页面受限，非法号码不锁死操作；390px 入口无横向溢出。返回主菜单、未启动组件时返回、Steam 切换 LAN 及重复 LAN 启动合并均通过。页面未出现未捕获错误。

这些是流程验证，不是性能基准。默认无头渲染的双战列舰检查曾触发既有主机过载保护；改用 D3D11 无头渲染、1000×720 双护卫舰完成上述流程，不能据此承诺百舰流畅度。

TypeScript 类型检查、lint、生产构建和服务端语法检查通过（Vite 仍有既有大分块提醒）。已生成包含便携 Node、原生模块及 DLL 的 Windows x64 启动包。未运行 Steam 时，本机网页仍可访问，建房按钮禁用，重试显示真实错误，确认退出可停止组件。

原生 DLL 已实际加载。验证中有一次 SDK 短暂初始化成功，但随后本机接口未持续响应；重新探测时 Steam 未运行，返回“Cannot create IPC pipe to Steam client process”。已加入 Steam 断开/恢复事件的状态处理，并停止无大厅时的 P2P 轮询，但尚不能认定上述原生异常已在真实连接下修复。

**真实 Steam 建房、两个账号间 P2P、跨网络及 Valve 中继均未验收。** 当前包是开发联调包，不应把模拟通过当作实际 Steam 成功；下一步需保持两台电脑的 Steam 登录和启动器运行，实测邀请、准备、开战与断线恢复。
