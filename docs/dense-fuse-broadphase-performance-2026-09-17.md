# 密集百舰近炸引信优化（2026-09-17）

## 结论

保留保守的近炸引信船体距离粗筛。相对于已经包含弹丸威胁 BVH 和武器阶段缓存的本轮基线，密集百舰完整工作均值在两轮配对测量中减少 **19.3% / 20.6%**，完整 P95 也下降。

**常规布局并没有普遍变快，百舰常规完整均值反而增加 3.13% / 0.94%。** 不隐藏这个结果，也不能断言它已经被证明只是测量噪声。保留理由是当前最拥挤场景有显著、重复的收益且不减少画质或模拟精度，不是所有场景都达到了性能目标。

百舰 180 FPS 尚未实现。新增真实 rAF 驱动的压力诊断仍显示严重卡顿，见后文；不能将脚本完整工作耗时取倒数当作 FPS。

## 热点依据与改动

本轮先对当前基线做密集场景诊断，再选择优化，不继续针对常规布局的微小热点试错：

- 生产浏览器 CPU 采样中，`checkProximityFuse` 含子调用约 26.05 秒，`distanceToShipHull` 含子调用约 17.51 秒；后者 self 约 9.78 秒，点内多边形判断 self 约 6.00 秒。父子时间重叠，不能相加。
- 独立 SSR 阶段计时中，12,000 次威胁评估的护盾选向约 216 ms，不是当前最大的密集场景开销。计时插桩和 CPU 采样只用于定位，不与无插桩配对时间混算收益。

过去每颗近炸弹与每艘可能的敌舰都执行精确船体多边形距离，即使舰船明显很远。本轮新增 `mayBeWithinShipHullDistance`：

1. 只缓存深度冻结的作者船体轮廓的 L1 最大半径，包住任意旋转；不把 `collisionRadius` 当作真实船体边界。
2. 每次读取实时舰船位置和查询点，按引信原有距离阈值扩张保守范围，并保留坐标尺度相关的浮点裕量。
3. 护盾距离仍先执行原精确计算。只有护盾距离已超过引信阈值，且船体保守边界也确定不可达，才跳过船体多边形计算。
4. 其余情况保留原来的 `Math.min(护盾距离, 船体距离)` 和比较，不因护盾已经很近就改变 NaN 传播语义。
5. 可变/部分冻结几何、缺失轮廓、负/非有限阈值、非有限姿态或坐标、极端尺度回退。轮廓替换按数组身份自动重新计算，不缓存跨帧位置或舰船状态。

没有缩小近炸范围，没有改变护盾弧、伤害/爆炸、弹丸/敌舰顺序、特效数量、AI 更新频率、模拟步长或预测时长。没有恢复之前撤回的渲染实验。

本轮生产源码仅两个文件：

- `src/engine/simulation/collision/HullGeometry.ts`
- `src/engine/simulation/systems/weapon/ProjectileCollisionHandler.ts`

## 精度、回退及快路径执行验证

- **120,000 次数值查询**：30,000 种轮廓/位置/尺度条件，分别检查随机阈值、精确接触距离及其上下邻近阈值。覆盖正常、极小、极大尺度，退化/凹形轮廓、深度冻结与可变几何。4,958 次粗筛排除都满足原精确距离大于阈值；60,384 次原判定接触均未被排除。
- 10 个非有限/异常点、姿态和距离回退检查。
- **1,200 次完整近炸入口前后对照**，包括实际护盾弧、护盾半径 NaN、异常阈值、默认/显式舰船列表、航程耗尽触发；共 102 次触发，返回值与爆炸/视觉事件记录一致。
- 密集百舰完整模拟 180 步，6 个全状态检查点一致，仅排除墙钟 `kernelMs`。
- 密集 180 步影子验证：实际执行 **1,918,781** 次新边界查询，排除 **1,896,147（98.82%）**；每个被排除的实际查询都额外调用原精确船体距离验证，全部确实大于阈值。这些额外计算仅在诊断中存在，不进入计时构建。
- 常规布局前 180 步的同类诊断查询数为 0；这不是全部 360 步的覆盖证明，更不能凭此抹掉上表的计时回退。
- 另 14 项检查覆盖冻结外数组但可变顶点、修改顶点、替换轮廓、非有限几何、旋转后远超 `collisionRadius` 的细长船体。
- 缓存约定针对作者数值几何，不声称任意带副作用的 JavaScript accessor/猴子补丁都已全面认证。

## 真实 rAF 帧节奏诊断：目标仍很远

候选生产构建中，由 Chromium 的真实 `requestAnimationFrame` 回调驱动生产 60 Hz 调度器、`CombatSession.fixedUpdate` 和插值渲染，不调用 `gl.finish()`，不启用 CPU profiler。密集百舰预推进 180 步，预热 5 个回调，记录后 20 个：

- 回调间隔窗口 19.249 秒，观察到约 **1.04 个回调/秒**。
- 间隔中位数约 966.6 ms，P95 约 1316.6 ms。
- 窗口内完成 120 个模拟步，约 6.23 TPS；每个测量回调运行了 6 个模拟步才渲染。
- 100 艘仍存活，页面/GL 无错误。

这是无头 Chromium、脚本自动驾驶/相机下的核心循环压力诊断，**不包含完整输入、音频和 UI 循环，不是物理 180 Hz 显示器验收，也不是配对 FPS 加速测量**。它直接表明当前工作负载仍严重卡顿，不能靠将单步耗时倒数来宣传帧率。

原调度器的 100 ms 墙钟差值上限未修改；`droppedSimulationSeconds=0` 只表示未触发积压裁剪，不表示墙钟时间从未被该 100 ms 上限截断。180 Hz 展示预算 5.56 ms、60 Hz 模拟预算 16.67 ms，当前两个主要部分仍远超预算。
