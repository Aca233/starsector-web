本轮由主代理直接完成，未使用子代理。目标仍是整个生涯模式；本轮只补齐普通整组货物操作与资源 HUD 的联动，不把这一小块冒充完整生涯。

编码前记录见 `campaign-cargo-ui-native-audit-2026-09-20.md` 的 HUD 对照小节。原版 0.98a-RC8 拿起/暂存机械 16 导致货舱占用 16→0、撤销恢复的实机观察来自上轮；本轮重新查看用户货舱截图并核对 CargoData/LogisticsModule 源码，没有再次运行原版交互或原版 Java 探针。

## 已实现

- `CargoTransferRetained`（导出名 `cargoTransferRetained`）汇总 hold，不包括手持和 discard。
- `CargoPanel` 发出有组件生命周期、世界/权威实例/玩家/舰队/回执范围的事务预览，保留旧的撤销、确认、关闭和过期草稿规则。
- HUD 即时显示本地剩余补给、燃料、船员。空间/容量/消耗来自认证只读 `/campaign-api/cargo-preview`，不把参考公式抄进 React。
- `CargoPreview` 复用当前锁定的 fleetStats.resolve/logistics.quote。shadow fleet 与 shadow world 内同一舰队是同一个不可变对象；未修改的世界集合复用 Repository 的深只读快照。
- 查询验证控制权、世界、权威实例、完整成员版本和舰队版本；库存只能是实际库存的子集，拒绝凭空新增/超过现有/非有限/负数/危险键。
- 查询不走 execute，不产生 command receipt、事件或版本，也不写 pending command storage。查询失败不阻止本地撤销。
- 客户端去重依赖实际舰队/成员上下文，不因 session 每 350ms 返回新对象或另一个玩家改变世界 revision 就清空预览。60ms 合并快速操作，取消/新操作/回执/卸载后忽略旧响应；成员维修状态变化会重新计算。
- 当前库存改变时预览显示未知、保留草稿并禁止确认，T 撤销后恢复最新权威 HUD。沿用原有联机并发策略，不暗中改成自动重基。
