# 模拟战初始部署与“无贴图”显示修复

## 复现和根因

1. 模拟战首次选择舰船与后续增援都调用 `CombatDeployment.entryPosition`。该方法把舰船放在 ±6000 战场边界之外，因此首次敌军也从约 y=-6300 入场。
2. 初始试验舰位于约 y=600，通常视野半径 3000；首次敌舰被放到 6900 之外，超出视野。
3. 船体绘制正确使用 `isVisibleTo`，浮动血条却只排除死亡，移动镜头后出现“只有血条没有船”的错觉。
4. 实测缺失外观的锤头贴图已 decoded（108×164）、在资源预加载列表中，WebGL error=0；并非素材文件丢失。

## 修正

- **初始编队与后续增援分开**：首批敌军部署前，恢复模拟器原先的相对试验舰编队位置；后续部署仍从边缘入场。初始可先部署盟军，再部署首批敌军。
- 初始阶段使用已有首批敌舰部署标志，不使用 `combatTime === 0`。部署菜单期间模拟时钟仍可前进，等待、取消、重新打开不应把首次部署误判为中途增援。
- 初始多舰保留原先编队间距与防重叠处理。这是恢复现有 Web 模拟器位置，不声称坐标已逐项对齐原版。
- 部署完成立即计算可见性，暂停时也不需要等待下一次 tick。
- HUD 阵营及显示使用实际观察队伍；每帧隐藏失去视野、死亡、返航入库或撤退舰的血条。血条遵循与船体绘制相同的接触状态。
- 不取消战争迷雾，不给敌人额外视野；远处盟军继续保持可见。

## 回归方式

`node scripts/check-simulation-visibility.mjs`（Vite 开发服务器、Playwright 可通过 NODE_PATH 提供，COMBAT_TEST_URL / BROWSER_PATH 同既有浏览器回归脚本）。隔离浏览器挂载真实设计试飞和部署窗口，不使用用户存档。

验证：30 个模拟装配的舰体贴图可解码；首次敌军近场且可见；真实 Tab → 增援后敌军边缘入场；船体和血条随接触同步出现/隐藏；远处盟军贴图正常；先盟军后敌军、多舰无重叠、菜单等待和重开均保持正确阶段。

本次浏览器回归：8 组检查通过，页面异常 0。类型检查通过。
Lint 无错误或警告。常规构建曾在清理已有 dist/game-assets 时遇到 ENOTEMPTY；未手动删除资源，使用 Vite `build({ build: { emptyOutDir: false } })` 完成生产构建，更新 dist/index.html 与引用的资源包。保留已有大分块提示。
