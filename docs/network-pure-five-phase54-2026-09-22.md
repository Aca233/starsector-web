# Phase54：纯五人、五舰实际编译联机测试

2026-09-22。按用户要求，把“纯5人”从此前“5人+17艘AI”的负载场景中独立出来。本轮没有改游戏模拟/网络实现，没有启用新优化；改动为既有测试入口、证据和文档。

## 实际配置

- 5个独立无头Chromium进程，各控制1艘 Onslaught，3对2。
- aiHulls 明确为 `[[],[]]`；所有测量席位样本实际 ships=5，无额外AI或待命舰。
- 通过真实编译UI建房、加入、应用配装、准备、开始；使用正常验证的房间设置命令。
- 五端注入浏览器内部前进/持火输入，服务端确认收到并接受每个席位的 firing=true、keys=1 输入。测量中弹体16–72枚，不是五个客户端停在空场景。
- 额外预热20秒，测量30.001秒；关闭CPU采样器，避免其额外负载。
- 同机回环LAN，**不是5台电脑、远程Steam/n2n或真人对战**。没有可见窗口或操作系统键鼠输入。

输入确认是HUD平滑指标的样本中位数，不是原始包RTT或端到端P95。五端服务器往返中位数6.68–8.54ms只代表本机回环加软件调度，不可作为互联网延迟承诺。客机FPS最低样本46.45–54.20，仍有短时抖动。

主机模拟速率样本59.517–60.710Hz，完整生产中位58.448Hz，上传中位58.196Hz；backlog最大样本15.475ms。发布blocked指标中位6.991、最大65.942次/秒，表示发布尝试受信用门控，不等于丢包率。**本场景不再呈现22舰时的持续模拟过载，应继续定位短时完整帧生产/信用等待和接收端突刺，而不是仅依据22舰结果重写五人场景AI。**

这次只证明在该脚本输入、舰船和测量窗口中，纯五人可接近60Hz且功能正常。最低样本说明尚未全程稳定60Hz；也不宣称这是一项代码优化带来的提升。
