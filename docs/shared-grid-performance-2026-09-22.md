# 共享空间网格性能实验（2026-09-22）

**结论：候选未达到性能验收，默认接入已撤回。当前生产代码与本轮开始时一致；此文记录实验，不是已上线的加速声明。**

## 方法与限制
先核实本机0.98a-RC8反编译源码并记录source-audit；只更换本轮三个生产模块，其它源码冻结于before-sources.json，避免并行修改污染A/B。无头Chromium/D3D11，真实CombatSession和默认4 Workers；对照两侧相同seed、同实体数量、同输入与固定步数。24舰沿用默认串行路径。没有降低模拟频率、火控扫描频率、画质或调度预算。

固定步表中的ms是模拟+视觉更新时间，不是FPS；不包含单列渲染的gl.finish。60步预热后计时；每30步比较完整引擎、playerAI、炮塔tracker的规范化状态，排除已有空间访问标记和计时字段。rAF使用生产调度器，FPS与TPS单列；是独立战斗页面，不覆盖React HUD/音频。桌面与原版实机未操作。

## 最终取舍

- final-r1的100舰127.02→128.09ms；200舰379.77→366.78ms只在该轮改善。交换iframe布局与执行次序的final-r2，100舰96.95→96.98ms，200舰275.94→277.51ms，无稳定收益。
- 额外100舰奥德赛/典范混编：301.05→327.74ms，120步、4次完整状态相同，但耗时回退约8.9%。没有通过只展示Onslaught或调高舰数门槛来掩盖此结果。
- 百舰真实rAF两轮：ABBA平均FPS7.95→8.01、TPS7.45→7.35；BAAB平均FPS9.03→8.27、TPS8.86→8.14。第一轮多画帧并没有更多模拟步，第二轮两项都退步。
- 因此恢复AutofireController.ts与FireControlQueryBatch.ts的本轮初始字节；仅本轮新增的生产AcquisitionSpatialGrid与测试入口已移入ignored实验记录。既有火控批次/友军BVH/在途预算/默认4 Workers均保留。未暂存、提交、推送或发布。

## 已验证与未完成

候选具备300单位分类网格、同火控阶段跨船复用、逐批惰性刷新、按轴运动包围、矩形成员缓存和原序恢复。preAim、aim舰船选择、PD导弹获取、友军射线/在途阻挡均接入过并测试；全船体边界包含在阻挡包围内，精确几何/开火安全/扫描频率未改变。小场景、非原生扩展/读取器和异常数值回退。**这些只是被撤回候选的能力，不是当前启用功能。**

- 最终候选24/100/200舰各240步、每30步完整状态一致；反序再测100/200舰一致；100混编120步一致。
- 随机拦截/走廊完整性、数值边界、原序/重复对象、移动/换格/引用替换/关闭/自定义读取器、实际aim接线计数均通过。稀疏合成用例的候选比例不是实战帧率。
- 候选24项combat AI与12项system intent回归、应用TypeScript与范围lint通过。
- 独立无头战斗页面通过驾驶/护盾回执、战术图打开关闭、暂停不走tick、dispose归零；Worker数与实际提交检查通过，WebGL错误0。候选corridor-r1同一步两侧截图已人工查看，战斗呈现相符，不声称像素完全一致。
- 没有改UI；没有原版桌面实机验收，独立战斗页也不等于完整React入口/HUD/音频验收。
- 共享导航网格、小行星火控网格、250–500ms阻挡缓存均未在本轮实现。多船卡顿未解决。

现有目标保留、扫描节拍、批次过滤和廉价运动判定已经消除了部分全场重算；此次新增网格仍要同步可变位置/半径并维护缓存，减少候选不必然减少总耗时。后续应先建立明确的运动/护盾/成员增量失效协议，再按采样火焰图处理逐舰/逐炮热点，不能仅继续加空间索引或减少模拟步数。
