# Phase 16：客户端首发预测（2026-09-21）

## 完成了哪一步

这是“客户端立即响应、房主保持权威”的第一步，不是整场战斗预测/回滚完成。没有让客机运行完整 AI、伤害或碰撞，也没有把网络 HUD 的 10/20Hz 改成假 60Hz。

在 `LanBattle` 的共同输入路径中，本地输入发送被实际接受后，为支持的手动编组预测第一次按下扳机的首发弹丸。LAN 与 Steam 走同一调用，没有新增实验开关。后续从实际应用的完整世界取得 ACK，撤销预测或与权威弹丸交接；仅收到 motion/socket 回执不能确认开火。

## 支持与回退

- 支持 LINKED 手动组中的无蓄力 BALLISTIC / BALLISTIC_AS_BEAM / PLASMA；连射武器只预测第一发，按原本完整 burst 的幅能预留条件判断。
- 原生 hammerhead 默认第一组两门 heavymortar 实测产生 **2 个首发预测**。默认 harpoon、railgun、pdlaser 组仍回退，见 `stock-coverage.json`；没有把“代码启用”冒充“所有武器都使用”。
- 暂不预测：蓄力炮、光束、导弹、交替编组、持续长按的后续轮次、自定义每帧武器插件、混合不支持武器的编组、独立实验弹丸流。
- 原版规则保持：弹药、冷却、瘫痪、过载、排散、相位、系统禁火、编组选择和幅能预算。只读检查，不把本地估计提交为伤害结果。
- 源码对照先于实现：`network-local-fire-prediction-source-notes-2026-09-21.md`。原版实机同场景视觉比较仍待用户允许；无可见窗口、桌面切换或桌面输入。

## 安全与纠偏

`LocalFirePrediction` 使用独立 `PredictedProjectileLayer` WeakMap，真实 WebGL 弹丸通道读取它。预测对象不加入 `engine.projectiles`，不被捕获回网络，不可被选中/碰撞/拦截；伤害和 EMP 为零，不消耗世界 RNG、弹药或幅能。复用原生资源与 `SourceProjectileLifecycle` 运动/寿命公式，不提前播放声音或枪口事件，避免与权威回包双播。

- 最多 32 发，最多 250ms，旧/不支持状态回退，不无限猜测。
- 同一按住动作不重复生成，重复输入与同基线连点不能叠加同一挂点的预测。
- 只有已应用的完整世界 ACK 才解决待确认记录。同源/挂点/规格且不属于预测前基线的单一弹丸可以交接；小偏差最多 80ms 平滑，大偏差立即回到权威结果。
- 没有活着的权威弹丸时，仅记 `resolvedWithoutProjectile`，不推断“命中”或“拒绝”。预览也可能被撤销，不承诺所有按下都成功击发。
- 切组/系统等未确认命令会阻止后续首发预测，直到相应完整世界 ACK；不能拿旧武器状态预测新组。
- 暂停/失焦/断线/失同步/死亡/换舰清理；清理不能伪造已消费输入，也不能因清空显示层再次使用未确认的旧就绪状态。
- 已由权威移除的弹丸不能被显示纠偏延长寿命。

## 日志：是否真的使用

现有会话日志的 `hud.input.firePrediction` 记录：
`predicted / matched / resolvedWithoutProjectile / expired / cancelled / suppressed / pending / lastResponseMs`。

这些是本地预测计数，不是网络包速率。`lastResponseMs` 是成功本地发送到首次显示层呈现的间隔，不是 RTT、伤害生效延迟或显示器 input-to-photon；未真正呈现前是 null。允许列表不保留舰船身份、指令内容或弹丸实体，过期 HUD 不继续报告为新数据。

## 验证证据

输出目录：`artifacts/network-stream-20260921/phase16/`。

- 原生世界测试：预测前后完整快照、世界 RNG、音频调用、弹药/幅能/冷却不变；真实武器控制器发射后由真实完整世界恢复完成 ACK 交接。
- 10/20Hz 与 50/100/200ms 的确定性时钟用例：本地首发不等权威回包，超时/空结果正确撤销。这是模拟条件，不是真实 Steam/n2n 性能测量。
- 无头 Chromium 使用真实 WebGL2 渲染器和 97 个原生纹理，模拟时间推进到 16.67ms 时确实绘出首发（386 个变化像素），而权威弹丸数组仍为空；ACK 空结果撤销后像素完全回到原画面，零 GL/page 错误。
- `first-round.png` 是 Web 无头实渲染截图，不是原版实机对照；没有用截图里的数字代替网络性能。
- 两种 transport 的实际 `LanBattle.sendInput` 代码及 `LanConnection` 离线执行测试：阻塞/抛错发送不触发预测，成功发送保留原始 action/焦点信息再调用，健康输入节奏不变。
- 首轮全网络回归暴露旧输入测试夹具缺少新依赖（`firePrediction is not defined`）。已补调用观察器及上述两条路径的断言，而不是删除测试或移除生产预测。初始日志保留。
- 测试仅生成隔离的战斗测试 bundle，不含生涯模块；浏览器关闭自身 worker/server，未触碰用户浏览器。

## 尚未完成、不能声称

没有减少完整世界带宽、减少房主模拟量、实现全战场 rollback、保证客机模拟 60Hz，或修复此前多人弱网下数秒的整世界陈旧问题。声音/枪口反馈仍等待权威，预测弹丸散布是中心线估计，需接受后续权威纠正。后续需要带可靠关联的持续射击/事件同步和更小的关键状态传输，不能只扩大猜测窗口。

本轮未提交、推送、打包或发布；没有生涯更改进入发布物。源码默认路径不等于已安装 0.2.6 自动得到更新。
