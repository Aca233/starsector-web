## 试点合同
- 只做普通已知舰船网络视图，不接通默认LAN/Steam、不改传输、不安装框架。
- 明确字段表覆盖本舰/舰队的运动、船体、生命周期标志与动态幅能字段。其余武器、护盾、装甲、系统等仍走当前P1递归捕获和应用，成本计入，不把一个运动小包冒充完整舰船。
- 字段由网络视图采样后登记变化，不改模拟写入点，也不声称消除了采样轮询；登记写入点是另一项尚未完成的改造。
- 候选A：字段级float64增量，客机直接写回对应原生字段；同一份捕获/字段包复用到多个接收端。剩余字段仍按现有二进制+字节增量对照。基准为当前P1完整舰船捕获+相同可靠字节增量路径。
- 局部实验不能证明整场弹丸/特效/战术数据开销已下降。新spec/跨通道新舰船实例创建不在试点；预先构造的同版本舰船注册表必须先存在，未知ID拒绝。
- 显式协议版本/epoch/sequence/base/generation，创建全字段、更新掩码、删除、CRC、缺失基准拒绝与完整恢复；可靠有序链路已接受才推进发送基准，不改其它可靠性合同。
- 原生产源码不加功能开关或发布入口。测试适配器仅导出当前P1私有捕获/还原，候选剩余视图的构造/拷贝必须计入生产端成本。

## 事前验收门槛
1. 字段精确一致，包含负零；不修改权威图/RNG，原生对象/引用身份保留；异常包不部分更新字段视图。边界：重复、乱序、丢包/丢基准、CRC/版本/掩码/数值异常、删除/重建、回压未提交、重连、新epoch和资源上限。
2. 同一预记录原生战斗轨迹，同一字段集合/同一采样tick，先预热，A/B与B/A交替至少3轮；分别报告capture/encode/byte-delta/decode/apply、收发CPU总和P50/P95、原始及压缩载荷。不要把回环耗时称网络RTT。
3. 只有每种负载下总CPU中位至少降低10%，总CPU P95不恶化超过5%，线上候选载荷（未含真实socket/TLS头）不增加超过5%，正确性全部通过，才考虑下一步接入试验。位置每帧变化可能不省；负结果也保留。
4. 不能用不同字段、降低Hz、较小渲染画布、调高超时或漏算剩余P1字段“过关”。本轮离线纵向测量没有整场WebGL/跨机真实路由验收，不能默认上线。
