# 定义捕获扫描优化（2026-09-24）

## 决策

保留本轮小幅优化：相比上一轮已经修复挂载点身份的 **display-v2**，64 舰快照捕获均值下降 **7.15%**（7.82 → 7.26 ms），捕获 P95 从 10.20 → 9.55 ms。此次比较不是旧 v1 与 v2，也不能把两轮百分比直接相加。

新定义表仍保持 `VITE_LAN_DISPLAY_DEFINITIONS` **默认关闭**。这一步只是削减新增捕获成本，未证明整个 v2 已消除相对 v1 的捕获回退；未测真实联机输入延迟或渲染尾部，不晋升默认路径。

## 原因与改动

同场景旧 v2 的一次 CPU profile（只定位，不用于收益统计）中，定义 inspect 自身约 372 ms/240 个测量 tick，描述符读取是主要采样点；另外重复分配 values 数组、检查子对象资格，再运行 keys.every 比较。

只修改 DisplayDefinitionCapture 的检查循环：

- 每次仍检查原型、枚举当前键、逐个读取自身数据描述符并比较真实值；访问器不会被执行。没有全帧“见过就跳过”或可变根的身份缓存。
- 已验证的键与值在本次扫描中逐个确认相同后，复用旧值记录，不再次检查该不可变子数据的准入资格，也不再运行第二次 every 比较。
- 只有首次差异才复制已经核实的前缀并分配新值数组，继续检查/采集后缀。途中遇到不支持的数据，直接回退，不覆盖之前的缓存状态。
- 仍保留精确内容去重、帧内字典、预算、原有采样时机及可变对象回退。没有新增全局强引用缓存、没有修改房间协议/接收器、没有改 AI/物理频率或模拟规则。

原版可变定义 API 与本次最低对照追加在 `display-definitions-source-notes-2026-09-24.md`。没有操作桌面或可见浏览器，没有原版实机/画面对照的新结论。
