# 联机服务端转发与重连优化（2026-09-18）

## 范围

本轮只改 `server/lan-server.mjs`，新增生产模块 `server/lan-state.mjs`。保留其他任务已存在的 UI、后台恢复、Steam 和便携启动改动。不修改模拟 dt、伤害、AI、舰船/特效数量、播放插值和恢复预算。协议仍为 20。

## 改动

1. **复用已校验的状态文本。** 房主本来已经把快照编码为 JSON；服务端此前解析、校验后又完整 stringify 一次。现在在房主权限、对局、序号和帧校验通过后，标准四字段消息直接复用文本。额外顶层字段、空白前缀或字段顺序不匹配时，仍惰性生成标准消息，避免转发额外顶层属性。保持字符串发送，以及 Steam 识别状态所需的 `{"type":"state",` 前缀。
2. **只保留验证摘要。** 房间长期持有的帧现在仅包含 tick、舰船 ID/阵营、部署 ID/阵营。世界特效、投射物、武器与舰船完整状态仍原样转发，但不再存入房间缓存。结算、部署校验保持需要的全部字段；重连原本就等待下一张新帧，不依赖旧缓存。摘要用新对象复制，不引用大型输入对象。
3. **资源未就绪时不推状态。** 重连连接在 `assetsLoaded=false` 时不接收大快照，避免和资源加载争抢解析/网络。不能用 `loaded` 过滤：资源准备好但尚未应用新帧的客户端必须收到状态，才能完成 sync-ready、恢复控制。控制/房间/结算消息不受过滤影响。
4. **校验一次性完成再提交。** 舰船和动态战机共用一组 ID 去重；空行、非法 ID/阵营、冲突部署行等会被拒绝。校验失败不推进 lastSeq/lastTick 或替换缓存。

现有 Steam 房间扩展只读取房间元信息，不依赖完整帧；便携打包使用依赖图，已确认新模块同时进入 LAN 和 Steam 启动器的依赖集合。

## 同帧服务端微基准

输入来自本轮真实双端 8 舰交火，tick 1804，813,127 B 的完整 state 消息。比较本轮修改前的解析/校验/重新编码路径，与新解析/校验/摘要/复用路径。每轮预热 70 次，200 次交替执行、交换先后顺序，共三轮，每版本 600 个样本。

| 范围 | 原路径均值 | 新路径均值 |
| --- | ---: | ---: |
| 第 1 轮 | 8.784 ms | 4.299 ms |
| 第 2 轮 | 9.683 ms | 4.809 ms |
| 第 3 轮 | 9.866 ms | 4.906 ms |
| 合并 | 9.444 ms | 4.671 ms |

该帧的服务端处理均值下降 **50.54%**。两路径输出字节相等。这里包含 Buffer 转文本、JSON.parse、帧校验、必要的转发编码，**不包括 socket 传输、物理模拟和客户端绘制，不能解释为游戏 FPS 或整机 CPU 提升 50%**。原广播本来也是每次 stringify 一次，不是每位接收者一次。

原保留帧的 JSON 等价大小 813,043 B，新摘要为 577 B。这是保留数据的序列化体积，不是进程 RSS 测量；服务端仍需临时解析完整快照，网络与 Steam 压缩缓存也仍有开销。快照线上字节数没有因本轮改变。

证据：`artifacts/lan-relay-benchmark.json`、`artifacts/lan-relay-frame.json`。

## 验证

使用 stdin 临时脚本和 Playwright，没有新增测试文件或运行器。

### 协议/传输验证

- 标准状态文本复用；额外顶层属性剔除；空白/乱序格式走兼容回退。
- 非房主、旧对局、旧序号、重复舰船 ID、跨舰船/战机 ID 冲突、非法部署信息拒绝，且房间状态不半提交。
- 客机断线后恢复：资源就绪前无大帧；就绪后能拿到新基线；确认前输入不生效，确认后输入到达房主。
- 本队部署许可、敌队部署拒绝，结算验证正常。
- 一个积压接收者不会阻止健康接收者拿到最新状态。
- SteamPacketCodec 压缩缓存复用、分片往返通过；**这是模拟协议检查，不是双 Steam 账号或跨网实测**。
- 摘要不保留输入的可变对象引用。

证据：`artifacts/lan-relay-validation.json`。

- 0 pageerror、0 Worker error、0 recovered。
- 本轮开战仍通过 start 协议触发，不作为工具栏按钮全流程验收。

证据：`artifacts/lan-relay-live.json`、`artifacts/lan-relay-live-log.txt`。

### 十连接/百舰数据通路

10 个真实 WebSocket 客户端，使用从实际 8 舰状态扩展的**合成 100 舰数据**，单帧 3,764,501 B；9 位接收者收到转发。第 10 位连接重连时不接收未就绪快照，完成资源准备后收到新状态并进入 controls-ready。摘要等价大小 7,825 B，无服务端错误。

这是数据通路/容量验证，不运行 100 舰物理，也不是 10 台机器、持续 20 Hz 或跨网性能保证。大型快照的实际带宽仍是问题。

证据：`artifacts/lan-relay-ten-peer.json`。
