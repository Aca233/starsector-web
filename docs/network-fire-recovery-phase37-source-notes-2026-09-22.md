# Phase37：完整权威确认后的持续开火预测恢复（实现前）

上一轮是进展：修正实际对照，3/5人A/B、B/A轨迹一致，拒绝整体收益不稳定的恢复器候选。本轮解决实际已复现的预测覆盖缺口；不把视觉响应改善冒充网络RTT下降或完整同步60Hz。

## 原版证据 → 保留行为

- 本机0.98a API `../decompiled/starfarer_api_source/com/fs/starfarer/api/combat/WeaponAPI.java:158–200`：朝向/炮口、弹药、冷却、禁用及开火状态独立；恢复预测不能改这些权威值。
- `../starsector-core/data/weapons/tpc.wpn`：原生炮口偏移、autocharge、投射物资源；本轮继续使用既有原生弹体呈现，不新增伤害/RNG/声音/枪口粒子。
- Web `ShipWeaponControlSystem` 的弹体ID来自RNG，不是单调计数，不能用最大ID当作新弹体证据；`WeaponSimulationSystem:103`每物理步推进elapsedTime，结合相邻完整世界combatTime可排除非新生成弹体。
- 原版同场景实机和截图未核实（用户禁止桌面/可见窗口）。本次只修联网客户端显示预测，不改变原版HUD布局、武器操控或权威玩法；原版未提供本项目联机预测规则，不声称此规则是原版实现。

## 现有差异

LocalFirePrediction的rising被命令屏障拒绝后，held=true且cycles为空；持续开火没有重新按下，就没有首发也没有repeat信用。Phase36 baseline-2三台真实客户端全部predicted/repeated=0，屏障后释放重按/分开选组再按则恢复。已有测试只测试重新按键，遗漏持续按住。

## 最小安全修正

仅在本地**已发送成功、仍持续按住**的当前扳机内观察：先等完整世界ACK超过该扳机/最后命令，建立完整自身弹体基准；再由后续完整世界的一枚唯一新同舰/同挂点/同规格弹体取得一个下一轮信用。不重画已确认弹体，不根据运动ACK、计时器或未确认输入凭空授权。旧ID、时间/ACK倒退、过旧输入/观察窗、重复/歧义/超限、切舰/组/瞬移/暂停/松手、AI/系统禁火/实验弹体流均保守回退。

沿用32待确认、512基准ID、250ms寿命/完整状态时效，以及原有支持武器/单轮/正常时速与射速、弹药/幅能/冷却/装填检查。不放开命令屏障；不修改世界/弹体数组/伤害/音频/RNG。回收接收侧自身弹体列表，避免每个pending重复扫全战场；未到期的60Hz输入仍不扫描战场。
