# 亚顿之矛：原作结构与舰载武器考据

日期：2026-09-27。范围：先研究原作，再决定固定武器/活动炮塔/舰体系统；本轮没有生图、修改运行数值或改动现有槽位。

## 结论先行

1. 官方定位是可维持星灵文明的自持方舟与阿塔尼斯旗舰，不能只按放大的普通炮舰设计。
2. 原作战役的轨道轰炸、太阳射线、护盾超载、净化光束等是不同的能力契约，不能用四档常规舰炮的名字替代。
3. 目前 Web 26 个挂点全为 TURRET，是本项目自行设置；原作依据不足。不能反过来一口气把它们全改成固定炮。
4. 原作精确炮数、实体发射口位置、关节、射界及转动角度尚未核实。本轮只建立可追溯边界，不编造一张“官方炮位图”。

## 二、原作能力：已核实什么

行号均为上述固定提交的 `campaigns/voidstory.sc2campaign/enus.sc2data/LocalizedData/GameStrings.txt`。

| 项目 | 证据 | 对 Web 设计的约束 |
|---|---|---|
| 方舟/旗舰与人员承载 | 官方文字；游戏文本 388、399 行记述逃离艾尔和无家可归的星灵居于方舟 | 船的特色不能仅用大装甲、高伤害、更多炮塔表达 |
| 太阳能碎片 Solarite | 316 行任务奖励；638–640、656 行可重新分配系统中的 Solarite | 战前/战役配置预算与战斗施放 Energy 不是同一个资源，不应混作每发扣除的弹药 |
| 折跃援军 | 1239–1240 行：可见地点折跃水晶塔、2 近战与2 远程战士 | 这是折跃部署机制；改成太空战机或限时援军须明确属于 Web 改编 |
| 轨道轰炸 | 1241–1243 行：5 次可选目标区域的轨道激光打击 | 5 次射击不等于舰体上有5座炮，不应画成5根炮管证明考据 |
| 太阳射线 Solar Lance | 1247–1250 行：指定起点、指定扫射方向，释放3道扫射光束 | 应保留路径规划与扫射语义；目前 XL 单发弹体不是它的原作行为 |
| 群体召回 Mass Recall | 1257–1258 行：目标区域友军传回主基地，并获得屏障 | 战役里确有此能力；但召回终点不是任意位置，改成舰队救援必须另立规则 |
| 护盾超载 | 1259–1260 行：友军单位与建筑获得限时屏障 | 不是给母舰加一个普通360°盾，也不是荣光女王的虚空盾；改成局部范围是平衡改编，不是原作原范围 |
| 重构光束 | 1269–1270 行：自动修复机械单位/建筑，最多3目标 | 支援和多目标资源分配也是方舟特色，不必全部转换为伤害武器 |
| 净化光束 | 1271–1273 行：可控制持续光束，未手控时自动选敌 | 要区分持续控制与太阳射线的定向扫射，不能都变成蓝色高速弹丸 |

辅助 XML 交叉验证：
- `void/AbilData.xml` 的 `SOAThermalLanceActivate` / `SOAThermalLanceExecute`，配合 `void/EffectData.xml` 的 `SOAThermalLanceCP` / `SOAThermalLanceDamage`，与文本的激活、瞄准、路径伤害对应。
- `SoASuperShield` 有独立能量/冷却定义；`SOASuperShieldSearch` 有区域搜索和阵营过滤。数据是地面战役单位尺度，数值不得直接换算成远行星号舰体伤害。
- `SOARecall` 等通过 `SoACaster` 施法单位注册；施法单位的450生命、不可旋转/无敌等标记不等于剧情方舟的生命值、机动性或无敌规则。

## 三、外形与炮塔：看到什么，不知道什么

### 官方影像能支持的视觉观察

- 6s/9s 外部镜头表现的是纵向延伸、层层包覆的装甲构件与明显的前后遮挡，不是单块金色平板上开一个洞。
- 装甲有较大的安静表面、深色内构和局部蓝色发光开口；不是每一条金边都同样亮，也不是每一个发光面都是可识别炮口。
- 内部静滞设施、舰桥等镜头与官方方舟定位一致。内部设施不能拿来当舰外炮座样式或炮口位置。
- 早期宣传视频与社区模型只能共同约束大体形体。相机绕行造成的相对位置变化，不算独立炮塔转动证据。

### 数据中的两个重要陷阱

1. `voidstory/ModelData.xml:5371–5376` 引用 `...Hologram_SmallWeapon` / `...Hologram_BigWeapon`。这是太阳核心界面的全息模型分类，不等于原舰只有两档武器，也不能映射为 Web 的 S/L 槽数量。
2. `SMX2_Spear_OrbitalStrike00..19` 的 Unit/Actor/Model 定义属于 `SMSET` / `Storymode` 场景资产。20 个资源 ID 不等于20座实体炮。

### 仍然待核实

- 每个可见发射结构的准确位置、数量、上/下/侧安装面。
- 是固定发射器、内部可偏转晶体、活动炮头，还是完全非武器的构件。
- 转轴方向与角度、舱盖动作、发射期间运动、待机/关闭状态。
- 与舰体尺度一致的俯视图，避免将侧面或腹部结构随意搬上背部。

这些信息缺失时，不能因为一个区域“空”就加炮；也不能因为它“像炮”就给360°射界。

## 四、现有26槽如何处理

本轮只记录，不改变现有配装、保存数据和运行资源。完整坐标与射界已存 `artifacts/spear-of-adun/canon-research/current-mount-audit.json`。

| 当前组 | 当前配置 | 原作证据状态 | 当前结论 |
|---|---|---|---|
| XL01–02 | 2座、TURRET、100°；新双轨炮体 | 肩部位置、双轨形体和旋转均未有原作对应证明 | 保留为安装技术样板，暂停推广；不能称原作太阳射线炮塔 |
| L01–04 | 4座、TURRET、220°/260° | 位置/数量/活动方式未核实 | 不继续据此画更多炮，也不先改为固定炮 |
| M01–08 | 8座、TURRET、200°–260°（含280°侧向槽） | 同上 | “离子连射器”是 Web 自拟武器，并非已确认原作炮型 |
| S01–12 | 12座、TURRET、300° | 原舰近防配置未核实 | 可作为未来 Web 补足项，但必须标注改编，不能说原作就是12座 |

安装规范应包含两个独立维度：
- **尺寸档位**：S/M/L/XL，保留用户要求的严格同档换装。
- **运动方式**：固定发射器 / 独立活动炮头 / 舰体内置系统。不能用档位推导是否旋转。

同档换装仍需满足合法安装接口。固定版本与炮塔版本的外形、枢轴和枪口要分别标定；不能把一个旋转炮塔贴图硬塞进固定井，也不能让固定护罩随瞄准转动。这里是后续设计要求，不宣称已经完成该接口兼容实现。

## 五、后续开发门槛

1. **原作结构门槛**：找到可对应的原作外形/模型/动作证据，标出已知与未知；无依据的部分明确为 Web 适配，不捏造数量与射界。
2. **二维适配门槛**：先确定俯视叠层、固定构件、活动构件和枪口，再生图；不再从生成图反推武器机构。
3. **行为门槛**：固定炮、活动炮和舰体系统各自有明确瞄准与命中规则；太阳射线不再只是普通大炮改名。
4. **数值门槛**：先决定原作能力怎样适配太空战斗，再按实际齐射扇区、持续幅能收支、弹药恢复、转向追踪与目标类型验证。不能把所有炮DPS相加当成同一目标的实际输出。
5. **审美门槛**：一处原作有依据的安装点，在真实舰体上检查空座、待机、瞄准/固定朝向、发射、受损；不因代码能运行就标“美术合格”。

当前最重要的决定不是“再加一种技能”，而是停止把现有26个旋转挂点当作亚顿之矛的原作蓝图。
