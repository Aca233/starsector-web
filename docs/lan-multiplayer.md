## v14 AI 按配装编组

- AI 窗口仍然点舰船直接添加建议配装；同舰体折叠在一起，展开后各实际配装有独立数量。也可一键复制当前真人改装草稿、选择本地址已存方案、导入 JSON，或新建 AI 配装。不会覆盖真人舰船或本机方案。
- 分组依据实际配置，不是名称 / 方案库 ID / 修改时间。武器挂点、武器组及自动开火、插件、S-mod、舰载机、幅能配置和战斗技能参与区分；原生方案身份也保留（例如手性舰配对系统依赖它）。同配置的异名导入自动合并，沿用已存在的方案名称。
- 「整组改装」只改该队该方案组；「拆出一艘改装」只替换一个名单位置，其余舰船仍用原配置。改成已有配置后会合并数量，不增加 / 删除舰船。个人战的归组仅为显示；改装不合并敌对阵营。
- AI 编辑复用原生改装台；真人编辑器暂停显示但保留其草稿、基线和撤销历史。AI 草稿收到关联的服务器确认后才返回编成；取消不会修改房间。返回保留目标队、搜索和批量数量。AI 方案名称和装备使用同一草稿 / 另存 / 撤销路径。
- 全员可只读查看配装，只有房主可改；应用后取消全员准备。编辑目标带编成版本，若期间数量 / 分队已改变，则拒绝过期应用并保留草稿，不会悄悄改错另一组。连接中断、房间关闭、回执超时也不会把草稿标为已同步。加载 / 战斗期间不能修改。
- 传输只保存一份每种配装（aiLoadouts），编成使用引用（aiHulls 字段延续原协议名），不用为每艘船重复完整设计。服务端验证声明式设计格式、舰体、权限、版本和总字节预算；主机 / 客机载入前仍执行完整游戏内容校验。方案字典由专用 AI 命令管理，普通房间规则不能直接覆盖。
- 战斗按每种实际配装分别编译、缓存舰船规格，不能因同舰体而共用错误武器 / 插件；开局冻结完整字典，客机重连使用同一份。DP 仍取舰体成本，后备部署保留原方案。
- 验证：内存检查异名同配装去重、不同配置分组、整组 / 单艘替换与合并、跨队隔离、过期提交、字节预算和真实引擎多方案实例；真实 WebSocket 检查权限、确认、准备取消、个人战、客机重连和开局冻结；双浏览器操作验证导入、只读详情、真人草稿保留、取消草稿、390px 布局，以及两名真人 + 两种 AI 配装短时开战至 tick 63。不是大舰队性能验收。

## v13 战斗规模与房主规则

- 主菜单「游戏设置」及单机战斗设置可保存默认战斗规模。默认 400 DP，200–400 为原版范围，400 以上到 3200 为 Web 扩展（步进 20），不是舰船艘数上限。
- 本作按实际参战阵营均分全战场 DP（向下取整，空队不占额度，大厅至少按两队预估），不是原版战役的非对称额度。400 DP 的双队战各 200；三队战各 133。个人战每个真人 / 每艘 AI 都是独立阵营。
- 创建房间带入房主当前偏好；从开发 / 预览端口切换到 3001 时通过浏览器 fragment 携带。访客自己的默认值不上传、不覆盖房间，也不被房主数值覆盖本机保存。
- 房间侧栏显示总规模与每队额度；「房间设置」中所有人可查看，只有房主能在大厅 / 结算后修改，服务端校验并广播。修改取消全员准备，不影响已保存的本机默认值；加入新玩家同样需要重新确认。加载开始时冻结规则，战斗中不能改，客机重连使用原局规则。
- 真人旗舰必须首发且计入本队 DP。AI 默认按编成顺序填充空余预算，其余保留后备，不删除编成。高级首发目标可设「自动」或更低值；真人与各队旗舰仍必须首发。队伍全灭自动调后备，有真人的队伍也可在 Tab → G 手动部署；纯 AI 队按空额度自动增援。
- 开局前双方用同一舰体 DP 目录检查真人首发总额和最高单舰成本，预算不够直接提示需提高规模或调整分队 / 舰船，不把必然失败的编成送入加载阶段。低规模不会削减 AI 名单，但不能让单舰成本大于整个阵营额度的舰船入场。
- 单机模拟及舰队出击使用保存值作为新战斗默认；模拟部署窗口可即时调整本局规模但不能低于已占用的 DP，不覆盖全局默认。正在进行的其他战斗不受设置页修改影响。
- 协议 v12 新增后备舰队部署状态与命令；v13 明确总 DP 语义、房主参数携带和权威预算，旧页面需刷新。扩展规模不是流畅度承诺。

## v11 大舰队边界

- 移除 4 艘 AI、14 队与 512 动态舰船的固定配额；保留已适配舰体、数据结构、权限、准备和开局冻结校验。
- AI 编成窗口设置每次添加数量，点舰船图直接加入，自由分队整批加入所选队，个人战每艘独立成队。卡片显示原生舰船缩略图；同队同舰体归组为 × 数量，个人战仅按舰体合并显示，不合并实际阵营。可增减一艘、整组改数量 / 换船、确认移除编组。列表滚动仅限制显示，不影响出战；真人席位仍为 2–10。
- 不接受无限大/非法数量造成分配崩溃：分配前检查编成的 1 MiB 字节预算（预留个人战分队和后续真人加入的开销）。全量战斗快照不超过 16 MiB；这是通信安全边界，不是无限性能承诺。
- 主舰总数超过 32 时同步 5Hz，超过 128 时 2Hz；其他情况沿用按人数 20/10Hz。拥塞时丢弃过期快照而非排队或立即结束对局，下一张完整快照覆盖旧状态；控制命令不按快照丢弃。
- 同舰体 AI 复用编译后的建议配装，多舰编队按近似方阵展开；队伍名超过 Z 后使用 AA、AB 等。雷达配色循环使用，标签保持唯一；超过 31 队的视野不再发生位掩码别名。
- 计算仍由房主浏览器承担。大舰队可编入不等于任意船型/弹幕规模下百舰流畅；降低同步频率也不会降低房主物理与 AI 计算量。

## 玩家操作顺序

流程为 **创建 / 加入房间 → 房间内选船、改装与分队 → 应用修改 → 准备 / 开始**，不拆分对战 / 合作模式。入房前只填写一次玩家名称，选择创建或加入；不显示大船预览、舰船参数、选船改装或方案导入按钮。直接打开服务器页面时，创建 / 加入会自动完成连接握手，不需额外点击「连接服务器」。邀请链接的房间码与已有携带配装仍保留，所有选船和改装操作统一放在房间中。

- 连接阶段：房主点击创建才启动后台；加入者填地址只连接一次。粘贴邀请链接会保留房间码，密码仍在加入表单填写。
- 配装阶段：左侧常驻真人成员、队伍、准备状态和已应用舰船缩略图，中间直接编辑自己的船。点击自己的缩略图 / “更换舰船”打开选船弹窗；点击他人缩略图只读查看，不替换自己的草稿。底部固定显示同步状态与唯一主操作；人数、密码、成员管理、聊天和邀请仍用次级工具。
- AI 编成：房间成员栏只显示真人；房主在独立的“AI 舰船”中按队手动添加舰船（个人混战中每艘 AI 独立成队），默认没有 AI，不占玩家席位。可点图批量添加，可搜索选择 171 个已适配舰体并使用建议配装。
- 准备阶段：其他真人确认配装和队伍后准备，房主直接点击“开始战斗”，不再要求房主先准备。只有房主时给对面添加 AI 也能开局；至少两个敌对阵营有舰船；空队不参战，掉线或未准备的客机会显示名字并阻止开局。产生未应用修改时取消自己的准备；任何真人仍在编辑都会阻止开局。应用配装、更改队伍、AI 或容量会清除全员准备，不能在加载或战斗中改装。
- 离开房间先确认；房主离开会关闭整个房间，普通成员只离开自己。正常结束本局与故障退出使用不同提示。

## 三队互打与个人战

- 三队互打：入房 → 左侧 **编队规则** → **增加 C 队** → 返回，成员卡选择 A / B / C；房主可调整全部成员。队伍槽位不再限制为 14 个，默认仍是 2 队。末尾空队可移除，有真人的队伍不能直接移除。
- 个人战：同一个窗口点击 **每人独立一队**。所有真人及每艘已添加 AI 都互相敌对；新加入真人 / 新添加 AI 也会独立成队，不会自动成为队友。此时成员卡禁用手动合队，切回 **自由分队** 才可合队。
- AI 始终手动添加、默认空，不占真人席位。自由分队中按队管理，个人战中直接点击舰船图；支持填写一次添加数量，每批逐舰独立成队；真人仍最多 10 人，百舰持续流畅度未保证。
- 编队变化取消准备，但不替换配装或本地草稿。仍需应用修改并收到确认；客机准备、房主直接开始。空队不阻止开始，只要求至少两个有舰船的敌对阵营、全部真人在线、没有未应用编辑且客机已准备。
- 每队从不同方向入场。AI 选敌、防空、导弹 / 水雷、武器碰撞、舰载机 / 系统无人机、舰体效果、队伍视野及雷达按 teamId 判断，B / C 不再被合并为一个“敌方”。雷达和战斗顶部用同一套阵营颜色；只读配装与原生改装流程不变。
- 以存活的主舰阵营判定淘汰；最后一个阵营获胜，个人战显示赢家姓名，所有主舰阵亡为平局。房主旗舰先阵亡仍继续模拟，直到剩余阵营决出胜负；房主退出 / 刷新导致模拟丢失的限制不变。离场客机仍由 AI 接管原队舰船，战斗中不重排阵营。
- 多方电子战只接受同队导航 / ECM 支援，受最强敌对队伍的 ECM 惩罚；这是明确的 Web 多队规则，不声称原版存在相同的多队玩法。

## 使用舰船设计

1. 入房直接显示原生改装台，连接和左侧真人列表保持可见。“更换舰船”弹窗可搜索、按舰级和势力筛选 175 个舰体，其中 171 个可选；4 个核心系统尚未适配的舰体禁用并显示原因（fabricator_unit、hive_unit、shrouded_eye、shrouded_maelstrom）。选船带入建议配装，先停留在本地草稿。独立 AI 选择器使用同一舰体范围和建议配装，暂不支持 AI 自定义改装。
2. “应用修改”才提交草稿，不再离开房间或“应用并返回”。未提交时其他玩家看到上次已应用的配装。收到对应 requestId、房间码和新版本的服务器确认才显示“已同步”，主按钮随即变为准备 / 开始；仅收到房间广播不算确认。初始建议配装若尚未提交也需应用。拒绝、掉线或 10 秒超时显示失败并保留草稿，不自动重试或自动准备；可重试、放弃本地修改或另存 / 导出。房间关闭时保留改装台供备份。保存只追加本机副本，不覆盖单机草稿、基线或已有方案；导入不写存档。导入文件上限 2 MB，传输方案上限 64,000 字符，方案库最多 100 项。
3. 每人一艘旗舰，使用当前构建的已适配舰体和装备。同步武器、插件、S-mod、幅能电容 / 耗散、武器组、已支持战斗技能和舰载机联队；不传人物姓名 / 头像，也不上传可执行插件或任意 ShipSpec。未知装备、非法挂点 / 分组、超 OP 等按设计器同一规则拒绝。
4. 本地 preview、localhost、局域网 IP 和不同端口各有独立方案库。从联机入口连接到房主时，只通过浏览器 URL 片段携带主动选中的方案，落地读取后移除片段；片段不发往 HTTP 服务。也可通过 JSON 手动带入。不会自动搬运整个方案库或覆盖任何原有存档。
5. 开局冻结每个控制席位的配装，房主 Worker 与各客户端分别注册独立的联机舰体实例，不覆盖原舰体或设计器的 studio-prototype。客机刷新从房间中的冻结配装重建展示；房主刷新仍不能恢复模拟。

注意：服务端只做有界数据结构 / 身份 / 生命周期校验，不加载战斗引擎；完整装备与 OP 语义校验在客户端准备确认及全员加载时执行。非法手写客户端不能靠发送 ready 绕过主机的开局加载校验，但这不是独立服务器战斗审计或公网反作弊。

## 从主菜单自动启动（房主）

用本项目的本地开发或预览入口打开游戏，按 **局域网联机 → 创建房间**。进入联机页不会启动后台；点击创建才会由本地游戏服务启动独立、隐藏的 Node 后台，随后自动连接并建房。已有匹配的后台会直接复用，不重复启动。

加入者点击 **连接房主**、输入房主 IP:端口，或直接打开房主分享的链接，再输入房间码。加入者不调用启动接口，也不需要运行自己的联机服务器。

- 默认自动启动监听 0.0.0.0:3001。缺少构建或源码比构建新时会自动构建；不会扫描原版资源来生成哈希或做大小审计。正在运行的后台优先复用，不热更新或中断对局。外部重新构建使版本不匹配时，会提示先停止旧后台。
- 开发与预览通过仅允许本机、同源 POST 的 /lan/start 接口启动；浏览器不能凭空启动 Node，普通静态托管页不具有此能力。远程访客不能替你启动进程。
- 后台启动/构建日志位于 artifacts/lan-server.log 与 artifacts/lan-build.log。后台启动失败或端口冲突会直接显示错误；不会结束未知进程，不改防火墙，不注册开机自启。后台独立于网页，关闭网页不会停止服务；日志记录其 PID，需要停止时可在任务管理器中按 PID 结束对应进程，这会结束所有对局。
- 多次点击共用一个启动过程，独立开发/预览进程也有启动锁。若整个启动进程被强制终止而留下锁，确认无构建运行后可移除 artifacts/lan-launch.lock 再试。

## 手动启动 / 独立服务器

在 starsector-web 项目目录，使用 Node.js 22+（本机验证 Node 24.13.1）：

```powershell
npm ci
npm run lan
```

这会构建游戏，再启动静态资源和 WebSocket 房间服务。默认监听 0.0.0.0:3001，终端列出本机与局域网地址。不修改系统防火墙或路由器，不使用云服务。

已经构建且未修改源代码时可直接运行：

```powershell
npm run lan:serve
```

端口被占用或需要指定监听网卡时：

```powershell
$env:PORT = '3002'
$env:HOST = '192.168.1.20'  # 示例，替换为服务端电脑实际的局域网 IP
npm run lan:serve
```

终端可能列出虚拟网卡/VPN 地址，请选择与其他玩家处于同一局域网的地址。主机最好使用有线网络；Windows 仅允许服务端程序在可信的专用网络上通信。访客 Wi-Fi 或 AP 隔离可能阻止连接。无需公网 IP、域名或端口转发。

所有玩家必须打开同一服务端提供的页面，不能在一个服务提供的网页中跨域连接另一个服务。默认主页保留舰船设计，并新增“局域网联机”；也可直接使用 /?view=lan。

开发服务和本项目 preview 不直接运行对局，但支持上述“创建房间”自动启动流程。任意第三方静态服务不能启动后台。每次重新构建后，应停止旧服务并重新启动，所有玩家刷新页面；构建版本不同会拒绝握手。

## n2n / Radmin VPN 虚拟局域网

原理上支持：本项目通过 HTTP/WebSocket（TCP 3001）通信，不依赖局域网广播发现。同一虚拟网络内只要能访问房主的虚拟 IP:3001，就可沿用局域网流程。

1. 所有玩家先连接同一个 n2n 网络或 Radmin VPN 网络。
2. 房主从游戏中创建房间，自动启动后台。
3. 房主分享联机说明中的虚拟网卡地址及房间码（例如 Radmin 分配的 26.x.x.x 地址，使用软件实际显示的 IP）。
4. 其他玩家打开该地址加入，不启动自己的服务。访问不通时检查虚拟网络是否连通，以及系统/安全软件是否允许来自该虚拟网络的 TCP 3001；不要为方便而关闭整个防火墙。

服务端按当前本机网卡地址验证 Host，也接受启动之后出现的虚拟网卡，仍保留同源 WebSocket 验证。新增虚拟网卡后刷新联机页面可更新地址列表。这里验证了普通局域网 IP，未实测本机不存在的 n2n/Radmin 网络。异地延迟、抖动、直连/中继与上传带宽会影响体验；它不增加人数上限，当前房间最多十位玩家；虚拟网络性能需要实测。

## 两种部署

- 同机局域网：房间创建者的电脑同时运行 Node 服务、浏览器和计算 Worker。
- 独立中转：另一台局域网电脑运行同一 Node 服务，所有玩家通过该电脑的 IP 打开页面。

协议相同。Node 服务只提供已构建的游戏资源、校验控制身份、管理房间并转发输入/状态，不导入或运行 CombatEngine。战斗始终由房间创建者的浏览器 Worker 计算。首版暂不能指定其他成员接替计算主机。

## 游玩流程

1. 玩家打开同一个局域网地址，填写名称并连接服务器。
2. 一人创建房间，在大厅 A / B 两队名单中安排成员。玩家可以自己选队，房主可调整任何玩家的队伍。成员名单仅显示真人；房主在独立“AI 舰船”中向任意队伍添加、换船或移除 AI，不设固定数量配额，支持批量添加和列表滚动，默认不添加。AI 可从 171 个已适配舰体中选择，自动带建议配装。房间默认四人，房主可在“房间设置”调整为 2–10 人，不能低于当前成员数（含断线保留席位）。容量、分队或 AI 编成变化会取消所有人的准备。
3. “邀请朋友”可选择实际 / 虚拟网卡地址并生成含房间码的链接。可设密码（最多 32 字，另行告知朋友），各自点击自己的舰船进入同页选船 / 改装，也可读取已存方案。房间聊天保留最近 40 条、每条最多 200 字；大厅和结算后房主可移出任意非房主成员。
4. A/B 两队都必须有玩家或 AI 舰船，所有真人在线且其他成员准备后，房主直接开始，无需自己先准备或坐满房间。只有房主一人时，可手动为对面添加 AI 开局。前后端共用同一开局校验，显示具体阻塞原因。所有成员资源加载及主机 Worker 就绪后统一进入战斗。同队协作、异队交战，都使用同一种房间。开局冻结本局玩家与 AI 名单，控制席位独立且不会因其他成员离开而重编号；不允许加载中或战斗中加入新成员。
5. 每人控制自己的舰船。视角、武器控制台、装甲投影、雷达及舰体/幅能标牌跟随各自舰船；HUD 的敌我颜色以当前玩家为准。
6. 主机判定伤害、死亡与胜负；结果显示“A 队获胜 / B 队获胜 / 同归于尽”。房主身份不绑定 A 队；移动队伍不会改变谁运行 Worker、谁控制哪艘船。返回房间可换队、调整 AI、重新准备并开局。

操作：W/S 推进，A/D 转向，Q/E 平移，Shift 鼠标转向，X 制动，左键开火，右键护盾，V 排能，F 舰船系统，1–7 或点击武器控制台选择武器组，滚轮缩放。Esc/空格打开联机菜单，H 打开操纵说明。打开菜单、离开窗口都会清除持续输入，主机对超过 500ms 未更新的输入进行清零。

武器组选择、射击模式与自动开火均经服务器转交主机，不直接修改本地展示数据。点击控制台相应按钮，或使用 Shift+1–7 切换齐射 / 交替、Ctrl+1–7 切换自动开火。动作有编号和去重，客机刷新后接续服务端序号。

联机不能单独暂停，菜单打开时战斗仍继续。房主“结束本局”会结束全场并保留房间；房主离开房间则关闭房间。客机在战斗中“离开对局”仅退出自己，舰船留在本局由 AI 接管，其他人继续；主动退出不是断线重连，不能中途重新加入。加载阶段有玩家离开或加载失败仍会取消本次开局，需要重新准备。断网期间退出按钮等待连接恢复，避免本地退出后服务器仍保留运行中的对局。

## 断线与恢复

- 服务端察觉断线后保留席位 30 秒；半开连接先经心跳检测（最长约 15 秒）。客户端自动重试，首次握手有 5 秒超时。
- 客机短时断线：清除持续操作，主机 Worker 临时使用 AI 接管。重连且资源加载完毕后交还控制。不会因断线立即踢出，也不会新增第二个成员。
- 客机刷新页面：同一标签页的 sessionStorage 保存随机重连凭证；仍打开原服务器地址时自动恢复房间、当前完整展示快照与输入编号。不保证关闭标签页后能恢复身份。
- 房主仅网络短断线：保留原页面中的同一个 Worker，连接恢复后继续分发状态。不要刷新页面来解决短断线。
- 房主刷新 / 页面崩溃：原权威模拟已经丢失，不能用展示快照重建。本局明确结束，房间仍可准备再开一局。没有主机迁移。
- 客机席位超过 30 秒保留期：移出房间，战斗继续，舰船持续由 AI 接管；本局结束前不能重新加入。客机运行失败也仅退出自己；加载阶段失败仍取消开局。房主席位过期则关闭房间。
- 版本不符或服务端进程重启：需要重新连接 / 加入；服务端不持久化房间。Worker 短暂停顿可有限恢复：保持 60Hz 固定物理步，丢弃墙钟积压与旧输入，重新同步。暂停超过 10 秒，或一分钟内出现第三次调度 / 严重积压恢复，会明确停止；不能把网络重连当作任意后台挂起恢复。
- 单方阵营仍有存活舰船时战斗继续；本人沉没后镜头跟随存活友舰。全部敌方 / 友方主力舰被击毁才判胜负。

## 当前同步实现

- 一个主机 Worker 运行固定 60Hz 战斗，普通客户端不执行 fixedUpdate。
- 展示快照额外包含舰载机 / 无人机和仍被残骸、弹丸等引用的离场实体，完整同步生成、战损、回收与补充。每帧同种动态舰船规格只传一份；客机验证规格所需资源属于本地构建后创建展示对象，不运行第二套 AI。动态实体安全上限 512 是报错保护，不是可玩容量承诺。
- 每位玩家以约 30Hz 发送操作，所有操作（包括主机自己的操作）经服务端绑定席位后转交 Worker。每个席位独立维护输入序号、动作去重、输入超时与在线状态。
- 按用户要求，主机快照目标固定为 60Hz；不再按舰队规模、采集耗时、CPU 预算或拥堵反馈主动下调到 20/10/5/2Hz。服务器对就绪且发送缓冲为空的客机逐帧转发，不另设 20Hz 上限。主机 credits、解码队列、socket 背压与原有过载保护保留；真实负载高时仍可能低于 60Hz，界面分开显示目标与实际接收频率，不重发旧快照来凑数。物理步长仍为 1/60，AI 多 Worker 默认关闭。
- 远端舰船使用以权威 tick 为轴的有界播放缓冲。房主和客机都只对自己的船做最多 250 ms 的近期未确认运动输入展示预测，随后平滑校正；房主的权威同样在后台 Worker，不在展示线程。接近主舰碰撞、死亡、失焦、断线和同步期间停用，超过 500 ms 没有新应用帧不再预测。展示位姿存在 WeakMap，不写入权威位置、配装或快照；展示线程不运行完整 fixedUpdate，不预测伤害或胜负，也未对所有弹丸 / 效果实现完整时间插值。参见 [房主操控修复与快照打包验证](lan-host-input-and-snapshot-2026-09-18.md)。
- 一次性战斗音效以有编号的事件转发，客户端去重并本地播放；浏览器可能要求先点击战场以允许声音。持续循环音效和完整音频表现尚未接入。
- 目前仍发送部分视觉粒子及环境数据，尚未做差量、量化或二进制优化。不要以首版完整快照协议估算十人百舰带宽。
- 这个快照只是展示投影，不含可恢复的完整 AI/随机源状态，不能用于主机迁移。
- 现有碰撞内核的自动 Wasm 加载以 window 为前提，主机 Worker 当前走正确性的 TypeScript 路径；后续规模优化时再接入 Worker 可用的 Wasm 加载。

## 连接与安全边界

- 校验相同协议和构建版本；版本信息随构建产生，不检查或导出原版资源。
- 校验 Host/Origin，只接受本机、选定监听主机及本地网卡地址；只提供 dist 内明确可访问的文件，拒绝私有路径和跨目录/符号链接逃逸。
- 玩家身份来自连接，不能通过消息字段冒充另一个席位；只有计算主机可发布快照和结果。
- 输入序号与离散动作编号用于拒绝重复；验证整批动作后才推进编号，旧对局消息不会作用于新对局。
- 256 位随机凭证绑定原成员；替换连接会废弃旧 socket 的事件处理权。房间密码使用带随机盐的摘要，只用于朋友间限制误入，不替代 HTTPS 或抗暴力破解认证。
- 限制连接/房间数量、消息体积、频率和发送积压。一次广播只序列化一次；对发送积压超过 512KB 的客机跳过可替换状态帧，不无限排队旧快照，保留关键房间 / 结果消息及更高的硬背压断开保护。
- 资源准备超时、主机长时间无状态、Worker 长暂停或无法跟上模拟时明确终止对局，不制造第二个权威。
- 适合互相信任的朋友局域网。HTTP/WS 不加密，计算主机可以作弊；不适合不可信公网竞技。

- 战斗顶栏显示服务器 RTT 与主机计算是否偏慢。菜单 → 操纵与联机说明 → 网络诊断分别显示 RTT、抖动、输入确认耗时、快照接收频率 / 年龄、模拟步和快照采集耗时。RTT 只到转发服务器；输入确认还包括房主处理及快照返回，不能混为网络 ping。
- 浏览器每秒发一个应用心跳，10 秒无 pong 主动进入重连；服务器仍保留 WebSocket 心跳与 30 秒会话窗口。浏览器计时器本身被系统冻结时，检测也会延迟。
- loaded 仅代表资源就绪，不再直接交还控制。每次开局 / 续接 / 重同步获得新的 syncId，等待比同步门槛更新的完整帧实际应用，发送 sync-ready，收到 controls-ready 后才接受输入和部署。重连凭证、席位、队伍不变；旧 epoch 的操作包不再可用。同步中的客机在旧协议中由 AI 托管；v22 起改为在线同步保持手动、中立输入，只有真正断线或离房才由 AI 接管（见下方控制权更新）。
- 超过 1.5 秒无状态、2 秒无输入确认进展或输入确认耗时超过 2 秒，先停操控并重同步；清除本地按键、开火和未发送动作。输入上行积压超过 64 KiB 时不再追加操作，未发边沿动作被放弃。不会把断线期间的点击在恢复后补发。
- 主机 Worker 遇到短暂停顿或严重积压会清空旧控制、丢弃过大的墙钟积压并要求所有人重新同步，而非用巨大 dt 追赶。每分钟最多两次，单次调度暂停最多 10 秒。服务器连续 12 秒无状态且房主仍在线会结束本局；房主同实例网络续接有受总恢复期限约束的短上传宽限。没有任意长卡顿保障。
- 拥塞降频只减少新快照入队；已经进入 WebSocket/TCP 队列的字节不能撤回，仍存在队头阻塞。大快照仍受 16 MiB 安全预算约束。服务器不承担战斗模拟，不持久化房间；房主刷新、崩溃或服务器退出仍不可恢复。

本轮使用 stdin / 内存打包验证（未创建测试文件）：预测前后权威快照逐字相同；真实 Worker 暂停 2 秒可恢复、旧输入不重放、重复过载有界停止；真实 WebSocket 验证开局门禁、最新帧确认、客机续接、旧 epoch 拒绝、房主恢复屏障与 12 秒看门狗。实际跨设备 / VPN 弱网仍需继续验证。

追加双浏览器验证：约 500 ms 注入往返延迟下操控及独立诊断可用；客机约 2 秒断线后自动续接，收到新 epoch 确认后恢复控制，恢复首批按键 / 动作均为空；房主 Worker 暂停 2 秒后双方恢复；房主短断网保持同一个 Worker；390px 视口无横向溢出，未见页面脚本异常。修正了单个小操作包排队误触同步降频，正常双人开局为 20Hz。截图见 artifacts/weak-network-diagnostics.png 与 artifacts/weak-network-recovered.png。


## 后台暂停豁免（2026-09-17）

上述 v16 心跳与房主暂停限制已增加后台可见状态处理：隐藏页面不触发应用层 10 秒心跳断线，回到前台先探测并重新同步；连接仍在线的后台房主最多允许 5 分钟无有效状态更新。底层连接检测、30 秒断线重连、前台过载及页面刷新不可恢复等限制不变。详见 [后台暂停行为、边界与回归测试](background-heartbeat-2026-09-17.md)。

## 房间操作更新（2026-09-18）

房间左侧现在直接列出开战准备进度与阻塞原因；缺对手可一键打开敌对队伍的 AI 编成。客机可以「应用并准备」或「仅应用配装」；房主满足条件时可以「应用并开始」，有客机需要重新确认时只应用配装，不会自动开战。队伍卡片提供添加 AI / 加入此队 / 更换舰船的明确入口。准备与开始均等待服务器确认，详情及验收记录见 [房间流程优化](lan-room-workflow-2026-09-18.md)。

## 同步控制权更新（协议 v22，2026-09-18）

在线但尚未同步完成的真人舰现在保持手动归属，清空旧操作并暂不接受新输入；只有真正断线或离房才由 AI 接管。续接连接成功即撤销 AI，仍须最新完整帧确认后才能操控和部署。舰船不冻结物理，也不会获得无敌。房间状态提示区分「同步中」与「离线」。前后端须使用同一版本。

真实双端已验证开局、在线重同步、断线续接、客机刷新、房主 Worker 暂停恢复和主动离房；32/100 舰过载仍未解决。详见 [控制权调整、验证与性能边界](lan-control-presence-2026-09-18.md)。

## 房主重复扫描优化（2026-09-18）

原生 AI 阶段现在共享友军阻塞射线候选名单和按 ID 的目标名单，仍实时检查目标/护盾/相位及几何，阶段结束即释放。没有降低舰船数量或改动决策规则；局部避让计算下降，但真实32/100舰双端仍触发过载，尚不能宣称流畅。详见 [实现、差分验证及失败边界](lan-fire-lane-index-2026-09-18.md)。


## 本地表现层（协议 v24，2026-09-18）
