# 爆炸纹理粒子配方同步：LAN / Steam 共用内容层（2026-09-19）

## 状态与边界

已在房主生产快照路径默认启用第一步：把原生爆炸的静态纹理粒子数组替换成版本化生成配方，客机本地重建。LAN 二进制和 Steam 现有可靠快照路径共用此内容层。

**这不是整个特效系统事件化，也不是完整的对象级增量。** 配方仍随自包含快照重复发送；没有“只发一次、确认后不再发送”的事件协议。爆炸位置、寿命、半径、结束/清除仍由原来的完整权威快照决定。重连首帧和跳帧不依赖上一帧的粒子基准。

没有降低模拟/目标快照的 60 Hz，没有修改伤害、碰撞、舰船数量或增加超时。房主仍执行原始粒子生成循环，消耗相同的 RNG，保存相同对象。单机默认不登记配方。没有改 LAN/Steam 的底层协议选择或 Steam 默认 Reliable 传输模式。

当前是源码与独立构建验证，不是双机实战验收，也没有安装/替换用户正在运行的桌面端。不能把这里的字节或 CPU 降幅换算成 RTT 降幅，更不能据此承诺解决“客机只有十几 Hz”。

## 实现

- `src/engine/visual/ExplosionPuffRecipe.ts`：只在启用的房主视觉 RNG 上记录 `[1, diameter, cursor, rings, velocityX, velocityY]`；`reserveSamples(0)` 只读取原生 RNG cursor，不改变随机数消耗。
- `src/engine/visual/ExplosionVisuals.ts`：原始 factory 前后登记，原生成循环不变。
- `src/network/HostSnapshot.ts`：集中生产房主和基准测试的 cosmetic setup/capture；保留已有本地尾迹及 `HostMuzzleEvents`。旧测试没有安装 muzzle sink 的数据不能代表当前生产成本。
- `src/network/CombatSnapshot.ts`：仅在 `world.fxSystem.explosions[].puffs` 的原生路径尝试 `$explosionPuffs`。普通 `captureCombat` 默认仍是原完整路径；共享生产 capture 默认开启。没有改 SWF2 固定键字典。
- `src/network/ExplosionPuffCodec.ts`：每个 viewer 独立、有界的解码缓存。缓存模板冻结；还原时复制到 viewer 自有对象，避免客机修改污染下一帧。

### 回退与限制

房主每次查询会校验登记数组、原成员身份、枚举字段顺序、访问器与原数值。修改、重排、替换、额外字段、非原生 RNG/向量方法均保留普通捕获。验证 getter 时不执行它，原完整路径保持原读取行为；不冻结房主对象。

单配方最多 256 puffs，每帧最多 8192 puffs / 512 配方；超过房主预算的效果转回全量。客机拒绝畸形配方、超预算和过深嵌套；缓存最多 128 配方 / 8192 puffs。RNG cursor 支持超过 `2^53` 的原有重复加法行为，不改为 uint32 或乘法跳步。

新 marker 需要双端同一完整 build；继续依赖现有严格 build 校验，不支持把新房主与旧客户端强行混用。若代码级回退，应同时关闭新房主的 `configureHostCosmetics(engine, false)` 登记与 `captureHostCombat(..., false)` 压缩，避免留下无收益的登记成本。

## 验证环境和统计口径

- 真实 `createLanWorld` / `fixedUpdate(1/60)`，32 舰，seed 1511506142，两玩家中立输入，双方各 15 AI 锤头。
- 使用生产共用 setup/capture，muzzle 事件 sink 已安装，不再使用旧的无 sink 快照。
- 记录 tick 600–720，每模式 121 帧；前 30 帧为预热，剩余 91 帧统计。独立运行三轮，每模式合并 273 个稳态耗时样本。
- 同一 tick 原全量/配方模式交替先后。LAN 用真实 SWF2 + SLD1 sender/receiver，模拟 ACK 延迟 8 tick（约 133 ms）。Steam 用已有 sender/receiver 与 SWSP packet codec。
- LAN 字节为压缩后的消息负载，不包括 WebSocket/IP 头；Steam 字节包括 SWSP 头，不包括 SDK/IP 底层开销。不是端到端测速。
- 合并阶段 P95 由每帧耗时之和计算，不是各阶段 P95 相加。
- 不含渲染、GPU、真实网络、Steam SDK 运行；LAN host CPU 不含 WS 压缩/物理发送，guest CPU 不含网络解压与 SLD 恢复。音频与标量遥测同等省略。

自然场景 host 接近持平，P95 略有增减，不保证任何设备每帧都加速。合成压力的 LAN host 合并均值三轮均下降（10.998→9.645、11.770→10.378、11.931→10.855 ms），合并均值约降 11%；guest 收益较小且其中一轮反而上升。

**额外生成成本不可忽略：** 两种捕获使用同一个已登记的房主，所以以上表格不包含原版与启用版的全部生成差异。另测直径 1400 爆炸、每轮 200 个样本：自然跑次生成均值 0.032→0.166 ms，压力跑次 0.021→0.126 ms。每次大爆炸新增约 0.10–0.13 ms 的登记成本；瞬间大量生成时需要继续观察。不能只看包长。

结论：保留这个有限范围默认开启，依据是压力场景的显著带宽收益和三轮 host 合并耗时改善，而不是常态性能的大幅提升保证。

### 不成功的中间实现

初版逐帧为所有字段分配 descriptor，压力场景 capture 约 4.6→11.7 ms，不能接受。后来限定真实爆炸路径、复用列式解码，再改为捕获原生 getter 查询函数与成员身份校验。最后将 recipe marker 的解码判断放到高频 vector/数组分支之后，避免所有普通向量为少见配方多付一次检查。

失败/中间 JSON 保留在 `artifacts/cosmetic-sync-20260919/`，包括 `production-profile-initial.json`、`burst/production-profile-initial.json`、`burst/production-profile-descriptor-guard.json`、`performance-before-cold-dispatch.json` 及对应 repeat 文件；不是删除较差数据后只留最好一次。最终表格使用最终三轮合并样本。

## 正确性与浏览器边界

新增 8 个测试覆盖原生生成/RNG/ID、单机与自定义回退、字段修改/重排/getter、缓存隔离及预算、100 帧 LAN/Steam 编解码恢复、重连/清空、生产 muzzle 路径、720 tick 双引擎战斗对照（8 舰，采样完整捕获一致）。getter 验证不读取 getter，替换的 Proxy 向量不被提前检查。

Node 同运行时的原全量/重建数据严格一致。跨 Node v24.13.1 / Edge 153.0.4234.46，54 个录制配方、4 遍，共比较 30,912 个粒子：纹理/尺寸/旋转严格一致，部分三角函数衍生坐标有极小差异，最大绝对误差 **5.684341886080802e-14 游戏单位**。因此**不宣称跨 JS 引擎逐位无损**；浏览器测试为视觉向量设置绝对误差上限 1e-10，实际误差远小于该值。没有通过量化改变房主数据，也不把这套重建用于碰撞/伤害。

测试命令与结果位于同目录 `regression.txt`、`recipe-tests.txt`、`edge-recipe.json`。生产录制源为 `scripts/bench-cosmetic-sync.mts`，浏览器验证为 `scripts/check-explosion-puff-browser.mjs`（支持 `PLAYWRIGHT_MODULE` / `CHROMIUM_EXECUTABLE` 环境变量）。
