# 透明紧凑 UI 规范

## 授权与本轮边界

用户明确允许完整重做 UI，并要求统一规范。对本次原创视觉重做，不再以复刻原版皮肤、字体、边框、按钮位置为目标。玩法、数据、存档、联机协议和快捷键不能因此暗改。生涯开发、提交与发布仍遵守 AGENTS.md。

本轮包含三套完整布局提案（主菜单、改装、战斗、设置和选择浮层）；未把任一提案强行接入正式页面。正式项目只提取已认可的局内/局外色值到共享 token，原色值与原布局保持不变。三套提案共用以下行为、尺寸和状态约束；皮肤不是把无关 Uiverse 组件拼贴在一起。

**最新方向（用户反馈“原来那个布局其实就挺不错的”）：保留当前项目原有布局与功能区位置，不继续以全面重排为目标。三套提案降为视觉参考，后续优先统一透明表面、字号、间距、组件状态与交互细节；除非用户重新明确要求，不迁入提案的新布局。**

## 设计原则

- 舰船与战场优先。正文、细线、操作点直接落在背景上；只有必要的选择器和弹窗获得可读底色。
- 不加副标题、口号、装饰性英文、虚构遥测或无意义编号。标注只服务当前操作。
- 功能控件用真实 DOM/CSS；不把按钮、文字、数值烘焙进背景图片。使用现有生图，不重复生成。
- 一个动作区只设一个主操作。危险动作独立确认，保存与返回不互换位置。
- 透明的是底板，不是字。禁止对整块 UI 设置 opacity 导致文字与焦点一起变淡。

## 基础标尺

| 项目 | 规则 |
| --- | --- |
| 字体 | 系统无衬线；普通 400、强调 500；数值 tabular-nums |
| 字号 | 正文 13、说明 12、辅助最小 11、面板标题 16、页面标题 24；主菜单可用 28–38 |
| 间距 | 4 / 8 / 12 / 16 / 24；页面安全边距桌面 24、小屏 16 |
| 控件 | 默认高 32；密集步进/工具按钮 28；触屏有效点击区至少 44×44，不靠缩小字适配 |
| 图标 | 常规 16；关键功能保留文字；图标单独使用必须有可访问名称 |
| 描边 | 1px；不用多重边框、厚阴影、常驻光晕 |
| 圆角 | 默认控件 2、浮层 4；C 方案可用 10–12，必须整套一致 |
| 动效 | 反馈 140ms，浮层最多 180ms；只响应操作；不循环扫光，不弹跳位移 |
| 触达 | 点击、Tab、Enter/Space；不把关键操作藏在 hover 后 |

共享值入口为 `src/ui/core/design-tokens.css`。现有 `--ui-*` / `--combat-*` 是兼容别名，不再分别维护相同角色的基础色值。布局定案后按组件迁移尺寸、间距、动效；不得增加第三层页面专属补丁来覆盖补丁。

## 颜色与表面

- 普通操作冷灰，主操作低饱和浅色；局内幅能蓝、结构绿、警报暖红，不能为了换肤打乱语义。
- 警报与选中态必须同时有文字、边线或标记，不只靠颜色。
- 常态面板透明；A/B 用线划分区域，C 仅局部浮层加少量底色。战斗不铺满屏模糊。
- 模态框用深色实底保证阅读；“透明界面”不等于所有内容都必须透出战场。
- 对比度目标：普通文字至少 4.5:1，较大文字和控件关键边界至少 3:1；必须在明亮战场和亮背景上验收，不能只用纯黑色样例计算。本文不是全项目无障碍合规声明。

## 组件状态与交互

| 组件 | 必须具备的行为 |
| --- | --- |
| 按钮 | default / hover / pressed / focus-visible / disabled；禁用不接收点击；异步操作显示进行中并防重复 |
| 选择列表 | 稳定高亮与 aria-pressed/selected；筛选空态；不以 hover 冒充选中 |
| 输入与搜索 | 常驻可访问名称、输入值、focus、错误；错误就近提示，不只用红线 |
| 数值步进 | 当前值与上下限；到限禁用；单位不随位数抖动；业务层仍须校验 |
| 开关 | 原生 checkbox 与可点击标签；状态与业务值一致，不能只有视觉变化 |
| 弹窗 | 明确标题、一个关闭入口位置；Esc、Tab 焦点闭环、背景 inert、关闭恢复焦点；不连开多层 |
| 保存 | 真实完成后才提示成功；演示必须写“已保存到当前预览”，不得冒充真实存档 |
| 联机 | 未连接 / 连接中 / 成功 / 失败；未做请求不显示成功，不伪造房间或玩家 |
| 提示 | 不遮挡点击；动态结果 aria-live；高频 HUD 数字不逐帧播报 |

快捷键只在当前场景生效，编辑输入时让出字母键；R/改装、C/技能、W/武器、F/系统及数字组只是提案中的演示绑定，接入时以正式游戏已有映射为准。设置尊重 prefers-reduced-motion，不允许界面关闭动效后仍有常驻动画。

## 布局与占位

- A「透视指挥」：左侧方案、中间舰船、右侧参数；战斗左下紧凑读数，右下雷达。推荐默认。
- B「战术工作台」：参数左置，舰船右置，方案在底部横排；战斗操作按横向功能带组织。
- C「轨道浮层」：窄方案轨道，大舰船视区，参数拆成底部三段小浮层；局内保持分离小块，不加整片底板。
- 同一数据与主要功能在三套中一致，切换方案才能比较布局而不是比较信息缺失。
- 小屏允许控件重排、参数纵向展开，不能把桌面整体等比缩小。320/390/1024 宽检查内容边界。
- 正式战斗 HUD 按最新要求全展开：技能、武器组、选中组挂点状态和目标武器详情不折叠、不设内部滚动区、不截断条目；保留透明底板与原有锚点，密集配置优先横向分栏。完整显示优先于此前“底部约 20% 高度”的提案指标；必须以真实战斗和密集数据检查视口边界，不能仅隐藏滚动条。
