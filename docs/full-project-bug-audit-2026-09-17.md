# 全项目缺陷审查与回归（2026-09-17）

## 范围与方式

本轮从输入/联机扩展到内容注册、改装、舰装/S-mod/舰长战斗技能、战斗模拟、碰撞、AI/武器/舰载机、GPU资源生命周期、声音、存档结算、方案库、页面加载及模拟部署流程。保留工作区其他任务的未提交修改。

不新增测试代码文件或测试运行器：断言通过 esbuild write:false + Node stdin 在内存运行，浏览器验证使用隔离上下文。没有进行资源哈希/大小审计，也没有运行全量导入器或修改原游戏资源。资源清单仅用于正常运行时内容校验。

## 已复现并修复

### 1. 派生舰体丢失原生身份
- 原因：部分舰装及相位锚按运行时 spec.id 查原生事实，但改装、联机和模拟会改写该 ID。
- 复现：apex、shepherd、tempest、venture 安装 converted_fighterbay，在改装页合法，改名为 studio-prototype 后被拒绝。doom 的低CR相位锚原舰体会战沉，改名后却能免费紧急下潜。
- 修复：注册中心为原始内容建立 sourceHullId，派生规格保留；原生事实消费者改用稳定身份，内容验证接受并校验此字段。不按四艘舰船特判，也不修改原生相位锚进度公式。
- 回归：5944 个可安装组合 × 改装/联机/模拟三种运行时身份；原舰体及三种派生ID分别测试低CR/正常CR，共8个相位锚伤害场景。

### 2. 完全重叠的舰船和小行星无法分离
- 原因：距离小于0.001直接忽略碰撞，出生、传送或同位置部署时持续穿叠。
- 修复：有实际方向时归一化；零距离舰船对使用稳定ID决定互换对称的退化法线。小行星使用稳定遍历方向，不消耗随机数。
- 保留原有护盾精确接触、碰撞广相筛选及质量加权响应。
- 回归：12组舰体/极小距离及参数互换对称性，小行星—舰船、小行星—小行星；原0距离复现修复后均可分离。

### 3. 纹理上传失败破坏缓存并泄漏GPU对象
- 原因：替换canvas纹理时先删除旧纹理；新上传失败后缓存仍指向失效对象。上传和构造中途失败也未清理已分配对象。
- 修复：新纹理完整创建后才交换并释放旧对象；分配后任何同步异常均回收新对象；第二张基础纹理创建失败时清理第一张。
- 回归：分配失败、图像上传异常、采样配置异常、mipmap异常、两种构造失败；失败保留旧纹理、重试成功、重复dispose不重复删除，最终无遗留对象。
- 限制：这是异常路径及资源生命周期修复，不代表所有显卡白屏/OOM均已解决。

### 4. AudioContext刚启动时首个节流音效被吞掉
- 原因：缺失的上次播放时刻被当作0，而新音频时钟也为0。
- 修复：只有确实存在上次播放记录时才判断节流。
- 回归：时钟0首次播放、同一时刻重复抑制、间隔后再次播放。

### 5. 陈旧改装页面覆盖其他页面的新方案
- 用实际StudioApp保存函数复现：storage事件送达之前，旧页面会把另一页面新增方案覆盖为0个。
- 修复：读取保留原始已观察值；单机及联机统一写入辅助，在写入前检测陈旧读。冲突暂停写入、保留内存草稿并明确提示导出；配额错误不假称保存成功。空字符串按坏数据保护，不再当作首次使用。
- 回归：连续正常保存、异页冲突且事件未送达、冲突后的再次保存、三种坏库、配额异常。
- 限制：写前比较是乐观冲突保护，不是跨进程原子事务；浏览器跨标签严格同时提交仍需更强的存储事务设计。

### 6. 懒加载页面失败导致整页空白
- 浏览器实际出现 Failed to fetch dynamically imported module；根节点仅有Suspense，没有处理rejected import的错误边界，React卸载整页。
- 修复：根节点增加RuntimeErrorBoundary，展示加载/运行失败及真实错误信息，提供重新加载和返回主菜单；不自动删除存档或无限刷新。
- 回归：生产页面人为阻断StudioApp模块请求，错误界面可见；解除阻断后点击重新加载恢复改装。

## 新反馈：仍需定位，不能冒称已修好

- “结束模拟恢复初始装配”：当前生产版本中，卸下稳定护盾→模拟→结束模拟没有复现，卸装和本机草稿都保持。尚不能证明原版方案切换、用户本机存储受保护/配额状态或开发热重载下的全部路径无问题。
- “通灵塔打攻势一直闪屏”：最初默认装配未复现；按用户截图还原裂隙闪电等武器后已复现并修复全屏白光，见下方补充。默认装配的检查不能覆盖自定义武器。
- 已确认5173开发服务对engine文件变更执行moduleGraph.invalidateAll + full-reload；并行代码修改会干扰正在进行的游戏。开发页曾发生懒加载失败，固定生产预览同流程正常。尚无证据证明用户报告的所有闪屏都由热更新造成，未盲目削弱正常相位/微光效果。

## 补充：截图中的扩散全屏白光（已复现、已修复）

### 根因与范围

- 用户截图为4175生产预览：HUD/识别框仍正常，战场从命中位置向外刷白。这次不是懒加载失败或开发热重载。
- 截图装配：2深渊耀光、4死神鱼雷、2伪粒子射流、2裂隙闪电、2恶性放射流。原先默认通灵塔配置不含裂隙闪电，无法触发此路径。
- 原生 rift_lightning_shot.proj 的 length=1000000、hitGlowRadius=-1；导入器错误地把负数改为0，内置武器数据也存成了0。
- 原版 MovingRay.notifyDealtDamage 仅在半径为0时从弹丸长度推导光晕，负值不生成普通命中光晕。Web视觉层原本也区分这两种语义，但导入阶段丢失了禁用标记。
- 修复前：真实WebGL2探针在战斗0.7167秒复现，最大命中光晕直径1,328,258.67世界单位；960×540画布按固定像素采样，99.941%为高亮白色（RGB各通道>220）。

### 修改

1. 源导入保留有限负半径，不再把合法原版哨兵当作近似功能或转成0。
2. 内容校验允许负命中光晕半径，仍拒绝NaN、正负Infinity及非数值；其余非负尺寸字段规则不变。
3. 精确修正裂隙闪电、伪粒子射流两条内置记录为-1，同步移除两份导入报告中的过时警告；未运行全量导入器，未改原游戏资源。
4. 类型/视觉层注明负值、0和正值的区别。未添加武器ID特判、尺寸硬上限，也没有全局调暗/删掉正常光效。光束的非正半径仍按宽度计算。

### 回归

- 内存脚本检查严格源导入、两份实际原游戏武器导入、非法数值拒绝、正半径与自动半径尺寸、负值禁用、光束尺寸，以及舰船能力发射路径的哨兵传递。
- 全142种内置武器：116种弹丸生成命中光晕、26种光束计算半径；各字段及生成尺寸均有限。负哨兵武器不生成普通光晕，其余弹丸最大命中光晕直径900。该上限只是检查结果，不是代码裁剪阈值。
- 真实挂点持续射击检查弹丸上的-1未丢失；独立WebGL2渲染探针如下。为稳定触发命中，诊断中强制前进/持续射击、关闭玩家相位并清除软幅能，不是原版平衡或AI手感基准。
