# 万有引力号 · v9 玩法重做草案

2026-09-30。**状态：玩法提案，待用户确认核心方向；未修改生产规则。**

用户本轮要求“重做万有引力号”，随后澄清“我指的是玩法”。本轮不换舰体、不生图、不调整炮塔素材；保持 `web_gravity` 和所有安装位稳定 ID，不覆盖用户配装，不发布或改动生涯内容。

## 1. 当前玩法对照与重做目标

这是原创 Web 舰，不是原版舰船复刻。现有 v8 源码核实：

| 生产入口 | 现有行为 | 本轮准备改变的决策 |
| --- | --- | --- |
| `src/engine/content/GravityArmory.ts`、`src/engine/simulation/systems/GravityDamage.ts` | 左键保持连接时固定 1200 能量伤害/秒；最长牵引 5 秒 | 从持续扣血改为主动建立压力、选择释放时机的主攻击 |
| `src/engine/extensions/ship-systems/GravitySystems.ts` | F 固定井，G 消费井，中心/边缘固定 3200/800 伤害 | 井的建立和维持应影响坍缩收益，不能刚建立就获得同一完整攻击 |
| 同上，`GravityTractor.ts` | 右键成功释放连接，但保留 F；排斥不附加伤害 | 紧急自保应与维持攻势有明确取舍，不能永远全部同时保留 |
| `src/engine/simulation/GravityTractorState.ts`、`GravityFieldState.ts` | 实体目标、锚点、场序号和逐波命中记录是权威状态 | 复用真实对象/碰撞与盾甲结算；新增状态需要完整 Worker/快照支持 |

以上是源码事实，不是玩家实战平衡结论。现有 v8 检查和录屏不算新玩法的验证。

**一句话定位：操纵敌舰位置，蓄积潮汐压力，再主动撕裂目标的实验战列舰。**

不是换成重炮舰，也不是增加另一套自动伤害。核心循环：

**布井切割战场 → 牵住关键目标并蓄压 → 松手撕裂或等待井成形后坍缩 → 在自保和维持攻势之间选择。**

## 2. 操作规则草案

### 左键：潮汐牵引 / 松手撕裂

- 捕获仍需短暂建立，目标仍按真实质量和动量被拉动，不能被鼠标直接摆放。
- 对敌舰，不再连接后固定扣 1200 DPS。按住时建立局部潮汐应力，正常蓄压约 1.2 秒；提前释放可打弱攻击，完整释放打一次明显的重击。
- 有限最长保持时间。不能无限蓄能、无限挂住；超时只释放当前已获得的强度，不产生额外倍率。
- 敵舰相位、遮挡、脱离射程、投射器故障、舰体过载/排散/撤退均打断；强制打断不偷算一次满蓄力攻击。更换目标不继承上一目标压力。
- 只有有效主攻输入的正常释放才结算攻击。切武器组、失焦、暂停、切换控制舰、系统打断不是主动开火。
- 盾弧覆盖先承受实际盾幅能，未覆盖才经过装甲/船体；不默认穿盾、无视装甲或制造船内必中伤害。
- 友舰、弹体、残骸和小行星仍可主动操纵，但不获得敌舰专用撕裂伤害；放手保留实际动量，不补充寿命/伤害、不自动返航。实体碰撞仍受原有上限约束。

### F：重力锚 / 成形中的势阱

- 准星位置部署一个固定井，不跟随鼠标或敌舰。再次 F 收回；重新布井重新付出建立时间和费用。
- 建立后约 2 秒达到完整相干状态；持续牵引进入有效内区的敌舰可加快成形，但总强度封顶，不能叠层刷无限倍率。
- 场本身控制动量，不自动打另一份范围伤害。重舰靠质量/推进抵抗，轻舰可以抢先脱离，普通友舰/友弹豁免。
- 成形状态仅属于这个井的实例；收回、失效或重布不继承。维持有时限、距离及幅能费用。

### G：潮汐坍缩 / 兑现场的准备

- 消费已建立的那个井，固定其位置和成形状态，经过可见预警后结算一次范围潮汐攻击。
- 早按：快速但弱；完整成形：强但给敌人更多离场机会。不是靠隐藏随机数或已收取的伤害储存能量。
- 消费后井消失，不追踪准星、不转移到新井、不继续免费控场。
- 保留合法左键连接，因此可选择把目标牵入内区再兑现；不能强制保证命中。
- 同一装配根每次只结算一次，真实盾甲、相位和遮挡有效，普通友军不受直接伤害。

### 右键：紧急排斥 / 放弃攻势换脱身

- 本舰周围一次有限冲量，仍不是护盾、光束免疫或删弹按钮；每个对象每波最多一次。
- **仅在激活成功后**，取消当前左键蓄压、终止本舰未消费的井，并中断尚未兑现的坍缩。无取消攻击附赠伤害，也不返还已付费用。
- 启动失败不销毁合法连接或井。主动抓过的对象可以作为反投例外，普通友舰仍不被无条件推出。
- 使用后进入恢复窗口；这是需要保留的救命牌，不是另一项无代价输出。

## 3. 资源与配装边界

- 不新增一条独立资源槽。沿用幅能；主攻蓄压期间降低/暂停被动耗散，使长期持续攻势确实积累负荷。具体比例及费用待受控场景测量，不先承诺数字平衡。
- 移动、转向、装甲及主动排散仍可正常使用；排散会放弃连接/井。不能偷偷取消舰体原有运动能力。
- 暂保留 60 DP / 280 OP、1 内置 XL / 0L / 4M / 6S、无盾无相位无航空；玩法确定后再评估舰体强度，不预先以加血解决一切。
- 两套配装作为初始基线保留：潮汐攻坚（2 偏转 + 4 近防，强调单目标完整释放）、引力控场（4 偏转 + 2 近防，强调布井和坍缩）。4M 仍为可换自卫炮，不把普通炮升为主输出。
- 当前 v8 的 174/280、180/280 OP 仅为历史基线。新规则及内置成本落地后须重跑生产配装编译器；四档同档规则不变。

## 4. 工程接入与未完成项

- 主攻需要 `CAPTURE → CHARGE → RELEASE/INTERRUPT → RECOVERY` 权威状态；不能只在画面上演出蓄力，实际继续旧 DoT。
- 蓄压进度、攻击序号、松键事件和目标引用均需要通过实际 Worker/显示恢复；每次释放去重，避免快照重放多打一次。
- 井的相干度需要显式实例状态，并由模拟推进；暂停不增长，重新建立清零。G 捕获旧井序号/位置/强度，不能读到新井。
- `SystemModifiers.dissipationMultiplier` 已有系统侧能力；主武器蓄压要进入真实聚合路径并在取消/死亡/重置后恢复，不能直接改基础耗散值后遗漏复原。
- AI 不再一直按住左键。需要按蓄压、命中机会、敌舰离场趋势和本舰危险释放；危险时右键明确放弃进攻，不能机械地同时开完所有能力。
- 反馈沿用现有场畸变技术；反馈必须读取权威压力/相干度/实际结算，不画静态蓝环冒充新规则。不修改舰体资产。

## 5. 验证顺序与批准门槛

1. 用户确认本草案的核心循环，尤其“左键松手重击”和“右键放弃当前攻势”。确认前不替换 v8 生产玩法。
2. 完整实现一块后集中做一次类型检查、改动文件 lint 和相关既有引力场景；不逐项反复跑全套。
3. 专项覆盖：短/满/超时释放、强制中断无偷伤、换目标不继承、井成形/重布、G 固定实例及去重、右键成功/失败的事务边界、友军豁免、盾甲/模块、暂停/死亡/撤退清理。
4. 真正 Dedicated Worker、旧自定义配装兼容、AI 自然实战分别验证。长期真人强度、多人端到端及单舰包安装另行报告，不因窄测试通过而宣布全部完成。
