# 差量解码的只读补丁覆盖层：来源与边界

上一轮几何Map缓存已因真实Host均值变差撤回，不重试。本轮针对已接受ObjectPatch接收路径：每条稀疏变更先previous.row.slice整行（往往几十字段），再写少量差量，之后完整验证并完整写显示记录。初始候选显式保留了这种简单但可能冗余的复制。

候选不动Encoder、Wire或协议15，只改Decoder内部：非重入apply借用已接受标量历史为只读base，单独存有序index/tag/value三元组；完整遍历有效合并值重建所有refs/metadata，保留展开预算、根、可达图、类型等校验。显示写入也从合并值读取，并仍写每个字段。直到所有分配/显示写入/typed替换重绑成功后，才将已验证的小补丁写回内部历史并提交索引。历史不来自可被消费者修改的显示对象。

异常边界：无效包、写显示字段抛错、保留父节点重绑抛错都不能提前修改已接受历史/版本。解码重入时不能修改外层借用的base，所以嵌套apply保留完整行复制回退；常规Host非重入路径才省去slice。内部数组/索引是Decoder私有数据，不是公开不可变历史API；不声称支持消费者直接改写其private字段或全局内建集合。

新/重入节点及布局变化仍走完整行。String是实际值，-0/NaN保持，schema keys继续拷贝，不复活失败的Entry/keys共享组合。字段写入、引用解析、消费者未变字段覆盖和typed-array重绑不变。UI仍原格式。

使用既有render-projection合同并加入冻结旧Decoder对照，特别覆盖根/view本身为补丁、畸形后部字段、写入/重绑失败和嵌套apply；一次集中typecheck、改动文件lint、相关场景。然后一轮200舰150+180tick真实Host未插桩对照，317左右模块按当前源冻结两臂。少复制不是提速证据，若查补丁/分支成本抵消则撤回，不择优重测。

这只改Web传输内部，不改原版玩法或UI，无新增原版画面/实机结论。不启动子代理/桌面/可见窗口，不提交/发布，保留并发改动。

## 实现后验收补充

候选只改Decoder一个生产模块；完整行/新节点继续独立row，常规补丁借用base+小三元组overlay，根/view读取overlay，两次完整字段线性合并，最终提交才推进内部历史。activeApplications用try/finally维护，嵌套解码复制base保护外层读取。

集中typecheck通过（9631ms）、三处改动oxlint通过（125ms）。既有ObjectPatch合同先通过，新增边界测试初次在“重绑失败后重试应恢复所有显示别名”断言失败：这是冻结旧Decoder自身不保证的语义（旧显示对象已部分重绑，索引/历史仍未提交）。本轮不扩展失败原子性；只将该过强断言改成新旧完整显示图/别名结构相同、已接受历史不变、重试值一致。保留原失败日志，仅定向复跑新增边界组，不重跑typecheck和既有组；改动测试文件lint及边界组通过：82379 checks、13次双Decoder成功应用、12次拒绝（含重入后抛错）、4次嵌套调用。已有ObjectPatch组仍覆盖正常typed replacement的别名恢复、消费者字段覆盖、特殊数值和完整校验。

注：所述“历史/版本不提前提交”不是显示记录的完全事务回滚。无效包在写显示前拒绝；setter在实际写入阶段抛错可留下与旧版相同的部分显示更新。若setter自己成功嵌套apply，内层提交按旧版保留，外层抛错不撤销内层。
