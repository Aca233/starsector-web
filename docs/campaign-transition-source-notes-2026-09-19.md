# 原版跳跃与缺油漂移：来源核对 — 2026-09-19

**本文件记录来源核对，不等同于完整还原声明。** 后续0.6.0已实现本次有限切片，实际能力与明确偏离见 [跳跃实现进度](campaign-transitions-progress-2026-09-19.md)。世界生涯总体仍未完成。

## 来源与直接证据

- `starfarer_obf/com/fs/starfarer/campaign/CampaignEngine.java`：`doHyperspaceTransition`（1548起）；模拟先推进各 location，再推进 engine-level scripts（1085起）。
- `starfarer_obf/com/fs/starfarer/campaign/fleet/NoFuelDriftScript.java`：对超空间无燃料、非AI、未跳跃舰队选择最近重力井，覆盖移动目标；靠近到舰队半径后随机选一个目的地并进入原版过渡。
- `starfarer_api_source/com/fs/starfarer/api/impl/campaign/JumpPointInteractionDialogPluginImpl.java`：init的跳跃燃料报价、optionSelected的启动及扣费。
- `starfarer_api_source/com/fs/starfarer/api/campaign/JumpPointAPI.java`：JumpDestination引用目标实体，保存最小/最大抵达半径，不只是地点坐标。
- `CampaignFleet.getSelectionSize/updateFleetSizeCount` 与 settings：半径=min(100,22+1.8×sizeCount)，护卫/驱逐/巡洋/主力权重1/2/3/4，空间站主力有25的特殊分支。不能根据船数随便设固定半径。
- `CampaignFleetMemberView.setJitter/advance`：跃入/跃出阶段等待单舰抖动淡入淡出完成，证明原版阶段时长与表现对象相关，不能只拷贝一个固定秒数。
- `MutableFleetStats.advance`：临时加速度倍率的计时来自天数；跳跃START添加0.1游戏天的10倍加速度，而非0.1现实秒。

## 费用：不能统一收一个虚构“跳跃油费”

1. 普通星系出口：先取有效每光年燃料费用，Math.round；正数若四舍五入为0则最低1。
2. 非虫洞的超空间入口：费用置0。
3. 虫洞：上述整数费用×5；还存在稳定、扫描器等交互前置条件，不能只套倍率就宣称虫洞可用。
4. 玩家交互是先启动过渡，然后扣油；在接近入口阶段中止并不自动退费。
5. NoFuelDriftScript直接调用engine过渡，不走玩家对话报价/扣费路径。NPC也不能简单照搬玩家对话规则。

## 原版过渡的结构

`START → MOVING_TO_POINT → WARPING_OUT → [玩家FADE_OUT] → SWITCHING_LOCATIONS → [玩家FADE_IN] → WARPING_IN → FINISH`，接近入口还可进入ABORT。

- 入口非空则覆盖移动目标靠近入口；到达判据是距离减入口半径的一半，再比较舰队半径。非当前location和快速推进另有500/1000的宽判据；共享世界应明确选择全精度联机策略，不使用“谁正在看地图”影响权威结果。
- 未在约2秒（加显式启动延迟）内接近会ABORT；快速推进有30秒上限分支。不能从地图任意处直接切换location。
- 逐舰跃迁间隔随机0.05–0.2秒，每加入一舰推进倍率×1.1。全部舰船开始后还等待抖动结束，阶段有5秒退出兜底。
- 玩家全屏淡出/淡入各0.25秒；NPC没有这两段。多人须明确映射每位人类舰队，而非沿用唯一playerFleet指针。
- 切换location时，抵达位置为目标实体位置加随机极角/半径偏移。**源码只重设位置和目的地，并不清空移动模块速度**；不能随手把速度归零。
- 跃入逐舰启动期间反复以当前坐标作为停止目标，通过原版移动积分器制动；全部舰船已启动后等待抖动期间不再重设目标。
- 过渡过程中设置禁止接战时段，完成后保留1秒。未实现此门禁前不能允许过渡舰队同时进入战斗锁。
- 引擎脚本在位置/后勤推进之后执行。单纯在tick开头换地点会把该tick油耗计在错误空间里。

## 缺油漂移

- 仅当前处于超空间、fuel==0、非AI、非过渡舰队适用。
- 只选星体或气态巨行星的重力井，目的地非空，排除目的地系统有`system_abyssal`标签的井；最近距离严格比较，列表顺序决定完全相同距离的先后。
- 覆盖目的地后继续使用正常移动积分，不是立即传送。
- 到井中心距离不超过舰队半径时，从有效destination列表随机取一项启动过渡。
- 若确实没有合格重力井，源码不覆盖目标；但“拓扑未加载/未知”不能冒充“已确认没有重力井”。

## 来源核对时列出的接入工作（实现边界见进度文档）

1. 持久空间实体与跳跃目标引用，包含位置、半径、地点、标签及destination落点半径；后续须考虑轨道更新，而非长期缓存目标坐标。
2. 版本化过渡状态、已付费用、目标引用、阶段与逐舰进度；在同一世界事务中推进，重试和重开不能重复扣费/换落点。
3. 持久可重现的随机流；默认不能调用Math.random后在提交失败时丢失随机状态。源随机分布与Web可重播策略应分别记录。
4. 将脚本阶段放到已移动/扣费之后，再将结果提交；和参战暂停、编队、行进命令、接战保护统一处理。
5. 在server选择确定的逐舰/淡入淡出策略后，使表现层订阅阶段，而非由某个客户端“动画播完”决定世界存档能否前进。原版观察视口对阶段的影响属于必须说明的多人适配，不应暗藏成原版规则。
6. 测试两舰队独立跳跃、不改另一舰队位置、跨批次/重开/回执失败一致性、缺油到井、无合格井、ABORT费用以及过渡期操作门禁；之后做实际地图和联机验证。
