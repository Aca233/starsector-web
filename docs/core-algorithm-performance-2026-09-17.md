# 核心算法第二轮优化 · 2026-09-17

## 本轮取舍

用户允许在收益明显、体验影响很小时降级；本轮采样仍指向 CPU 重复计算，因此没有降低分辨率、特效数、舰船数、AI/物理频率，也没有修改武器伤害、射程规则或模拟时间速度。不要把 CPU 压测当成已实现 100 艘同屏 180 FPS。

50 艘场景预热 60 步后采样 40 步：威胁评估约占累计样本 36.8%，有效射程约 18.8%，导弹拦截约 12.1%。调用链有重叠，比例不能相加。上一轮新增的舰体包围盒筛选保留。

## 修改

### 1. 可验证的静态射程缓存

涉及 `src/engine/extensions/Immutable.ts`、`src/engine/extensions/HullMods.ts`、`src/engine/simulation/WeaponRange.ts`。

- `immutableCopy` 用 WeakSet 标记自身递归复制并冻结的元数据；不把任意浅冻结对象当作深度不可变对象。
- 对这些舰体配置缓存已解析的插件列表。定义注册表不允许覆盖既有定义，未知定义抛错不缓存；公开 `installedHullMods` 仍返回调用者可修改的新数组。
- 仅对已核对过依赖字段的本文件内置插件缓存最终射程。外部自定义回调、不明来源的冻结对象、可变改装配置继续实时计算。
- 挂载后的武器 spec 仍允许修改。缓存命中前核对基础射程、武器类别、尺寸、挂载类别覆盖、点防标志、光束标志，以及 rangefinder 所用 PD hint（包含数组原地修改）。舰体配置更换对象则自然失效。
- 后续新增内置射程钩子若读取更多武器字段，必须同步扩展 `WeaponRange` 的依赖键。没有以“冻结的函数不会变化”为由缓存任意自定义回调的结果。
- 不缓存伤害、幅能、冷却、系统阶段等战斗动态状态。

### 2. 威胁预测的精确下界剪枝

`src/engine/ai/ThreatAssessment.ts` 保持原 ETA 公式、预测时域、候选顺序和护盾评分。原 ETA 为各准备时间的最大值加非负飞行时间：恢复时间或接近时间已经大于 horizon 时，后续转向/弹道计算不可能再产生有效威胁，直接跳过。当前已发射的弹丸/光束仍照常评估，不是缩小感知范围或降低评估频率。

### 3. 导弹拦截的惰性遮挡查询

`src/engine/simulation/systems/weapon/ProjectileCollisionHandler.ts` 先找原顺序中最近的真实弹道/导弹接触，再查询舰船、小行星和残骸遮挡。若弹道根本不触及导弹，则无需昂贵的遮挡计算；若最近接触已位于遮挡后，更晚的接触也不可能先命中。严格的 `<` 判定、同距离候选顺序、穿透逻辑和伤害流程保留。

仍然扫描当前弹丸数组；没有引入可能漏掉当步移动、增删或诱饵切换的陈旧空间索引，也没有为了扩大批处理而移动碰撞结算边界。

## 对照与隔离

- 临时内联断言/忽略目录中的性能脚本，不恢复项目已移除的测试套件和运行器，不执行资产哈希/大小审计。
- 59,842 次射程数值对照：含首次计算/缓存命中、内置插件组合、逐字段与原地 PD hint 变更、可变及浅冻结配置、插件公开数组被修改、自定义动态回调、未知定义失败后补注册；结果一致。
- 1,000 组完整威胁评估对照，含不同 horizon、恢复时间、相位、死舰、光束、制导弹、禁用/空弹药武器；结果一致。
- 600 组导弹拦截结果/状态/特效调用对照，含同距离候选、阵营、已伤害列表、遮挡先后、零长度路径与穿透；结果一致，其中 204 次不再需要查询遮挡。
- 初始 10 艘战斗 120 个逐步状态对照通过。
- 隔离后的正式压测从同一份内存源码快照加载两个独立运行时，仅撤销/应用本轮五个模块的优化。同一碰撞文件同期新增的诱饵分支同时保留在前后两份中，不计作本轮收益。
- 比较可枚举的模拟/AI 状态、引用关系、随机流、舰体、装甲、幅能、武器、弹丸、光束与特效。排除碰撞空间索引、内核工作缓存和诊断计数/墙钟计时等派生数据；本轮主动减少查询，不能要求这些工作计数保持一致。闭包/WeakMap 的内部状态不能直接序列化，其效果由后续战斗演化间接校验。
- 限定场景一致不等于对所有未来插件、输入和运行后端的形式化证明。

## 压测方法

Intel i5-13490F / RTX 5060。Node/Vite SSR 执行实际模拟代码，无渲染、GPU 或音频解码。10/50/100 艘攻势、双方各半、默认 18 个小行星、随机种子 `0x51180`。编队及初始目标沿用上一轮：`pair=floor(i/2)`，`side=i%2`，位置 `((pair%5)*3200+side*1500, floor(pair/5)*850)`，双方相向，初始目标为相邻敌舰。

每组 360 步，每步依次执行玩家 AI 与 `fixedUpdate(1/60)`；前 60 步预热，统计后 300 步。每步交替原版/优化版的执行先后顺序，每 60 步核对状态。桌面背景负载、JIT 和 GC 会影响绝对耗时，不能将不同轮次的独立采样直接串起来计算累计收益。

原始采样、隔离基线、对照数据与临时性能脚本位于被 Git 忽略的 `artifacts/core-algorithms/`。

## 正式配对结果

| 战列舰数 | 优化前平均 ms/步 | 优化后平均 ms/步 | 耗时减少 | P95 ms/步（前 → 后） |
|---:|---:|---:|---:|---:|
| 10 | 6.42 | 5.01 | 21.9% | 8.83 → 6.96 |
| 50 | 98.95 | 67.19 | 32.1% | 168.15 → 124.18 |
| 100 | 466.05 | 332.96 | 28.6% | 716.54 → 574.70 |

三组各 6 个状态检查点一致，结束时所有参战主力舰存活；峰值弹丸数分别为 324 / 1,623 / 3,216。100 艘的 TypeScript 碰撞查询批次数从 1,143,651 降到 738,290（约少 35.4%），这是模拟查询计数，不是渲染 draw call。

另跑 6 艘奥德赛/典范及其舰载机混战 360 步，每 30 步的 12 个状态检查点一致，峰值 18 条光束、36 枚制导弹，结束时共 14 艘主力舰/小型机体。

优化后再次按 50 艘、60 步预热 + 40 步采样检查调用链：有效射程占比约 1.9%（之前约 18.8%）；威胁评估约 24.3%，导弹拦截约 12.0%，碰撞批处理刷新约 7.8%，舰体射线查询约 9.9%。这是相对采样占比，剩余任务占比上升不代表其绝对耗时必然变慢。

### 工作区并行更新与最终集成

正式压测运行中，实时工作区的 HullMods 另行加入相位时间增益字段和四个内置插件，因此原始记录的 `sourceUnchanged` 为 false。运行时使用内存冻结快照，性能前后两侧并未中途换代码；没有覆盖或撤销这些独立更新。

结束后从最新工作区重新构造仅撤销本轮优化的基线，保留新插件、相位字段和诱饵分支，补做：

- 59,356 次当前内容的冷/热射程对照；
- 400 组包含火箭追踪诱饵、熄灭诱饵、同距离接触和遮挡的结果/状态/特效对照；
- 奥德赛/典范混战及毁灭/攻势场景，共 240 个逐步完整状态对照。

全部一致，该轮结束检查五个目标模块均未再次变化。正式性能表描述冻结快照的配对结果，不声称是所有后续独立功能更新后的帧率保证。

## 构建与目标差距

`npm run build -- --outDir artifacts/core-algorithms/build`（含 TypeScript）和 `npm run lint` 均以 0 退出；构建仍保留现有大分块提醒。独立构建不覆盖默认 dist。

100 艘平均约 333 ms/步仍远超 60 Hz 模拟的 16.67 ms/步预算。尚未实现或验证 100 艘同屏 180 FPS。本轮未动渲染质量或模拟频率；下一步优先考虑弹丸全表扫描/批处理刷新，以及威胁候选的精确空间预筛。若考虑有损模式，应单独量化收益和体验差异，不把降低模拟速度伪装成性能达标。

独立生产构建另通过浏览器冒烟检查：2560×1440 / DPR 1，RTX 5060 D3D11 WebGL2，战斗 HUD 正常加载，页面异常与失败请求均为 0。浏览器和临时预览服务已关闭。该检查不是 100 艘渲染帧率测试，headless 运行也不证明显示器按 180 Hz 呈现。
