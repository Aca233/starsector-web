## 当前差异与预期

`combatProfile` 与舰队 readiness 仅读当前实体的武器。方舟核心因此被当成 UNARMED；有友军时被安排 REGROUP 到友军背后，单舰也会被无武器后撤条件拦住。局部站位还把自身附属模块当成遮挡、火力线与碰撞体。

驾驶整舰的根实体应依据存活模块的真实火炮、射程、挂点姿态和机库作出决策；模块保留独立火控与幅能，不重复算成独立舰队驾驶员；自己的模块不作为需要让路的友舰。真实碰撞避让、高幅能撤退和显式命令保留。

## 验证方法与边界

在现有 `check-adun-ark.mjs` 中加入方舟带友舰场景，检查角色、前进控制、实际固定步位移与模块全毁后的判断。复现使用现有 CombatLab；其打包器补齐与生产 Vite 相同的原始配装 JSON 文本加载，避免把 `?raw` 导入当 JSON 对象。

## 本轮结果

- 修复前：默认方舟 CORE 有 0 件武器，存活模块合计 13 件；有友舰时 `UNARMED / REGROUP / WITHDRAW`，推进输入 -1。
- 修复后：同场景 `ARTILLERY / PRESSURE / ENGAGE`，推进输入 +1；射程与朝向使用武器所属模块的修正值、偏移和姿态。
- 舰队规划只为根舰分配驾驶任务，火炮与机库合并贡献；存活模块继续独立火控、幅能及损毁，不重复分配编队航路。自身模块不再算作局部遮挡、掩体或需要让出火力线的友舰。
- 定向运行现有方舟检查，4 项模块 AI 场景、既有五模块/13武器/4甲板检查及资源闭包检查通过。无友舰/左右友舰均立即交战；高幅能和模块全毁仍撤离；左右镜像各跑真实权威引擎 45 秒，前进 1129.83 单位，首次主武器射击约 0.77 秒，后撤时间 0 秒。
