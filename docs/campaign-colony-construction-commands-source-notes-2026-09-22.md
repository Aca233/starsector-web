## Implementation / integration contract

New files only: `OriginalColonyConstructionCommands.mjs` and `.d.mts`. Existing queue engine, Runtime, server/client and captures remain untouched. Preserve the live queue/array/record and credit object references, saved cost pairing and Java float/int conversions. Services are synchronous, market/player-bound, and provide real candidate construction, specs, existing industry objects, getters, lifecycle cancellation/removal, and economy refresh. There is no discount formula.

All admission and confirmations precede ledger mutation. A local ledger guard restores credit/queue mutations on throw; **it cannot undo arbitrary candidate, cargo, lifecycle or economy side effects**. The caller must abort its entire authoritative revision transaction on any thrown error. Receipt/UI notifications must be published only after successful transaction commit.

Confirmation cancellation must be presented using an authoritative refund quote at the same revision; execution recomputes and requires the expected refund to match. This avoids accepting client-invented refunds or silently confirming a changed price. Queue targets include native objectRef, expected industry ID and saved cost, so a payload swap cannot turn a stale selected slot into cancellation of another industry.

Unknown modes/commands, unresolved grouped choices, ambiguous queue identities and stale targets explicitly reject. Actual getBuildCost/progress/availability must come from live services; no historical fallback or assumed zero.

Source and native UI-call-site inspection only; **no original live UI/screenshot evidence** was available (desktop interaction prohibited). Native selected/disabled/confirmation branches are source-verified, visuals/key/mouse behavior remain unverified. No tests, typecheck, lint, build, or runtime validation run in this task. Main task performs unified validation. Suggested cases: insufficient funds/full display slots/industry cap/hidden choices; queued saved-cost refund and identity-preserving swaps; head-only economy refresh; started vs disrupted cancellation; downgrade-chain float accumulation; stale confirmation; service-failure transaction abort; and idle queue start with saved-cost override and correctly bound refunds.

## Final exported interface

- `ORIGINAL_COLONY_CONSTRUCTION`: immutable `industries[id]` directory (`name`, `imageName`, `tags`, `costMult`, loaded `cost`, `buildTime`, links, plugin, description/order/data); `industryIds` preserves native source insertion order. Main can bind `getSpec(id)` to its actual loaded spec using this reference.
- `inspectOriginalColonyConstructionBuildOptions(market, credits, runtime)` → ordinary live options (`cost`, current name/image, eligibility flags/reasons) plus explicitly unsupported choices. Run only in the host's explicit inspect mutation revision.
- `quoteOriginalColonyConstructionCommand(market, credits, request, runtime)` → authoritative cost/refund. Real constructors may have side effects; this is not a read-only GET operation either.
- `executeOriginalColonyConstructionCommand(market, credits, command, runtime)` → mutated shared state plus a UI receipt. Types: `build`, `cancel-queued`, `swap-queued`, `cancel-construction`, `cancel-upgrade`. Build requires `confirmed:true, expectedCost`; active cancellation requires `confirmed:true, expectedRefund`. Queue targets require `{objectRef, industryId, cost}`; industry targets `{objectRef, industryId}`. Construction removal additionally requires `interactionMode:'LOCAL'|'REMOTE'`.
- `startOriginalColonyConstructionIfIdle(market, credits, runtime)` → started actual industry's objectRef or null. Separate native market-advance phase; uses the existing queue engine, never a global fleet or eager start from purchase.

The helpers enforce basic shared-state cancellation/start postconditions but do not replace full service-side unapply, cargo return, notification staging or world-transaction rollback. No validation commands were run; ready for the main task's unified integration and checks.
