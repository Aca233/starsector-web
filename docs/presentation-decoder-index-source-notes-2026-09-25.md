# 本地显示解码索引：修改前契约（2026-09-25）

## 证据 / 范围
CombatPresentationDecoder.apply 每帧用 new Map(this.objects) 复制完整对象索引两次：candidate 用于验证，next 用于发布，未变化的节点也重复插入。此前 render-projection 的真实 Worker 报告已记录主线程解码成本，但那是旧版本，不拿旧毫秒数当本轮性能基线。当前需同源图实测。

此处只优化 Web 本地显示协议的内部索引，不修改原版玩法/UI、字段、精度、频率或舰船数量。原版没有该 Worker 协议，以当前编码/解码契约、冻结旧解码器为等价依据。没有桌面/原版实机或画面变化，不能把测试当新增原版还原验收。

## 方案与不可放宽项
1. candidate 改为只读覆盖查找：本包 plans 覆盖已有 objects，removed 视作不存在；精确计算候选节点数。仍完整遍历全部可达节点/边及元数据，不缓存或省略图验证。
2. 在所有现有格式、类型、预算、根、引用、可达性检查通过后，给每个 Plan 暂存新 Entry，先完成全部对象/typed-array 分配，再写显示字段。
3. 旧 Entry 保留到字段应用和长度变化的引用重新绑定完成。最后才删除/替换 objects 的索引项，避免再复制全量 next Map。保留私有索引的历史插入顺序和公开对象身份。
4. 不修改 header/epoch/revision/tick、元数据字典、危险属性/模拟原型拒绝、liveUnits/metadataUnits、refs 图扫描、可变 keys 复制、typed array 的保留父引用重绑定、视觉包校验。
5. 坏包不得在验证前修改上一帧对象/私有索引，也不能消耗 revision；可以随后应用同 revision 的完整合法包。不宣称防住消费者擅自冻结/安装 setter 导致的写入异常（原实现亦非该类任意异常回滚）。

## 验证计划
扩展既有 render-projection 场景，同一个当前 encoder 包流给冻结旧/新 decoder：比较完整解码图，并检查坏包的拒绝/原子性、删除/重入、字段变化、metadata、typed 长度变化及不变父节点重绑定、身份数量和索引复用。
扩展既有 benchmark-real-workers 的可选 --decode：真实生产 Worker 产生包，浏览器主线程测 apply，与 Worker 往返/模拟/编码分开计时；旧/新源图、固定种子与实体数量，逐帧完整图和值/别名对照。沿用既有交替测量及完整权威/隐藏状态审计。无显著可用收益或有错误则撤回/修复，不以减少 Map 数量宣称总体提速。
集中 typecheck、改动文件 lint、既有合同场景；只对具体失败定向复查。不发布、不提交、保留上一轮编码器和其它任务改动。
