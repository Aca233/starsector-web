# 联机完整快照的无损字段去重（第三轮）

用户认可 3005 的运动平滑，本轮不改 SnapshotPlayback / MotionPrediction，不减少舰船、特效或数值精度；保留用户正在运行的 3005。

## 实现

- CombatSnapshot 增加每帧自带的 layouts 字段表。嵌套的重复对象（武器、弹丸、尾迹点、粒子等）用布局编号和顺序值表示；world 和每艘船 state 的顶层仍保留字段名，满足服务器队伍/结算检查及连续显示时钟读取。
- 不删除任何原本投影出的数据，也不量化坐标/浮点数。Vector2、typed arrays、Map、Set、Ship 引用、undefined 和非有限数的现有语义不变。字典只在一帧内共享，没有依赖上一帧，因此中途重连、跳帧或丢弃旧帧不需要增量基线。
- 采集期间按首字段、字段数筛选候选布局，再逐字段比较；不为每个弹丸/粒子重复 JSON 编码字段名。布局上限 1024，字段上限 2048，超出写入条件退回普通对象。读取时拒绝越界编号、长度不匹配、重复或危险字段名。
- 同一帧中共享同一 ShipSpec 对象的战机只计算一次规格签名；按值相等的不同规格对象仍保持原去重语义。战机分类改为 Set 查询。
- Worker 添加不依赖大快照的一秒级性能消息，以及恢复/错误时的诊断信息（实际 tick、回调间隔、单步耗时、积压、采集和编码成本）。这样不能再把“只收到 tick 0 快照”直接解释为“物理从未推进”。此消息不负责物理或胜负判定。
- 协议升级至 19：本轮开始时工作区另有版本 18 的后台可见性/恢复相关改动，保留其字段与逻辑；本轮不修改恢复次数、宽限时间或物理 dt。现有版本/构建号门禁阻止旧客户端把紧凑记录误读为普通对象。

## 同帧测量（不是整场 FPS 对照）

8 艘守护者的同一帧，先预热 20 轮，再交替旧/新顺序测量 60 轮：

| 项目 | 原格式 | 紧凑格式 |
| --- | ---: | ---: |
| UTF-8 消息体 | 659,341 B | 440,744 B |
| 采集 | 1.63 ms | 1.86 ms |
| JSON 编码 | 3.09 ms | 2.04 ms |
| JSON 解析 | 1.78 ms | 1.55 ms |
| 显示还原 | 1.68 ms | 1.37 ms |
| 上述阶段合计 | 8.17 ms | 6.81 ms |

该样本体积减少约 33%，处理链减少约 17%；字典构建会增加少量采集成本，但编码/解析/还原抵消了它。并非承诺所有场景都有该幅度，更不能换算为 FPS 提升 17%。测量文件：artifacts/lan-compact-microbenchmark.json。

单独浏览器 Worker、手工构造的 8 艘守护者（不含真实 UI 玩家完整配装）运行至 tick 3601，约 60.4 秒墙钟，交付 1178 份快照，没有恢复或错误。此验证不包含两个完整画面的争用，不能替代双端实战。最大快照仍约 1.26 MB，说明大量尾迹/特效时带宽瓶颈尚未消失。日志：artifacts/lan-compact-worker-60s.json。最初探针使用了不含 Vite 环境初始化的 Worker 入口，加载失败；改用 Vite worker_file 入口后才进行此统计。

## 独立诊断面板

- SnapshotPolicy 共享 HostPerformance 类型；Worker 性能消息及 error/recovered 诊断结构受类型检查。
- LanBattle 读取每秒独立性能消息。主机模拟成本/推进倍率优先使用步数更近的诊断或快照，不再强制依赖大快照交付。
- 明确区分“显示状态步”与“主机实际计算步”；展示最近一步、采样窗口最慢一步、回调间隔、待补计算和诊断年龄。
- 超过 2.5 秒未更新的独立诊断明确标为已过期；诊断与快照都过期时不继续展示旧的推进倍率。这里的计时是墙钟耗时，可能包含线程等待，不宣称为 CPU 净耗时。
- 本地房主对 AI 的真实小场景能够显示性能消息。随后只在测试页注入模拟诊断并停止测试 Worker，验证显示 tick 与计算 tick 分离、独立成本/倍率更新、过期提示；零 pageerror。该注入仅检验 UI，不是性能基准。记录：artifacts/lan-compact-diagnostics-ui.json。
- 最新 typecheck 与隔离生产构建通过。lint 无 error，工作区其他 UI 文件有 5 条 warning（LanRoomTools、LanRefit 两条、LanTeamControls、LanAiFleet）；构建保留既有大 chunk 提示。

结论：无损编码的同帧体积/处理链收益已验证；诊断链已补全。8 舰完整双端的持续过载原因尚未定位完成，不能宣称长期联机稳定性已经修复，也没有替换用户认可的 3005。
