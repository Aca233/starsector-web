# Phase26：修正客机运动预测自身引入的滞后（2026-09-21）

## 结论与启用状态
本轮不是再加一个默认关闭的实验开关。修改直接进入 `LanBattle` 的既有本舰预测路径，LAN/Steam 共用；房主自己的显示副本也使用它。只写显示姿态，不改变房主战斗权威、网络协议、发送频率、碰撞判定或伤害。**源码已启用，尚未打包、推送、发布或替换用户安装的游戏。** 生涯模式未改动。

## 找到并修掉的问题
1. **错时刻校正。** 原先把上一显示帧的位置与当前帧权威重放的位置相减，把正常前进也当作误差，反复施加 90ms 指数平滑。现在把上一次预测用同一运动方程推进到当前显示时刻，再比较，保留真实偏差的平滑。
2. **ACK 后持续输入丢失。** 原来确认输入从队列移除后，以 `blankInput` 重放，到最后约一帧才使用实时按键。现在保留最后确认的 held 输入，不保存/重放离散 actions。
3. **新采样截断时间。** 新输入在本帧采到，不能把上次权威基线到本帧之间的时间直接跳过。重放起点覆盖这段间隔，并仍受 250ms 上限约束。
4. **暂停后沿用旧校正。** 近碰撞/失焦/不可用时，原来可能跳过整个预测函数。现在显式清理预测历史和校正，保留已存在的关键运动显示层，收到新权威基线再恢复。
5. 50ms 以上本地帧停顿不继续拖动旧校正；传送、大位置误差以及超过 45° 的角度突变直接回到新结果，不慢慢旋转追赶。

保留：近舰碰撞保护、死亡/撤退保护、500ms 权威超时、最多 60 条/1 秒输入历史、250ms 重放上限。本轮没有取消这些保护来制造“预测一直生效”的假象。持续射击、导弹、光束等没有扩展预测，保留既有首发预测的安全边界。

## 默认路径无头实连验收
独立 headless Chromium/D3D11，真实 LanBattle/Worker/桌面 LAN helper/局域网服务器。固定 seed917、共 22 艘舰船，顺序运行，每组测量 20 秒；通过测试页内部 DOM 事件切换推力、横移、制动，不操作用户桌面或键鼠。随后阻塞房主显示主线程 800ms，检查输入确认继续推进，同战斗重连、清理完成。

- 两次均无 authority failure/页面错误；输入 ACK 在停顿内推进；同战斗重连及清理成功。
- 所有显示端实际记录了非零预测帧和校正计数，不是只验证构造函数存在。5 人末次测量采样中客机累计预测 666–1026 帧、校正 566–843 次、hardSnaps=0。
- 近碰撞等条件仍会暂停预测；计数是实例生命周期累计值，不能当作测量期间 Hz 或覆盖率。

## 日志新增
会话日志的 `hud.input.motionPrediction` 已接入白名单：
- `active`、`reason`：当前是否生效，以及 active/reset/inactive/collision/unavailable/stale。
- `renderedFrames`、`suspendedFrames`、`reconciliations`、`hardSnaps`：真实累计执行次数。
- `correctionDistance`、`correctionAngleDeg`：最近一次同时间校正的差值，不是 RTT。
- `replayMs`、`pendingInputs`：本帧重放时间跨度和保留输入数。
不写舰船对象、原始按键或任意错误字符串，不改现有网络 Hz/ACK 指标。
