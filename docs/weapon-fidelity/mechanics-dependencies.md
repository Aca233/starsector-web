## Guardrail

`visualSpawnType` is not a second simulation spawn type. It may only select renderer treatment and visual-family defaults. Likewise, `beamVisualMode`, `hitGlowBrightenDuration`, deterministic Beam contact cadence, launcher smoke, missile engine/trail fields, `missileExplosionVisualSpec`, independent hit-glow state, and impact presentation profiles do not change simulation ownership. In particular, missile top-level visual explosion radius/color must never overwrite `.proj explosionSpec.radius/coreRadius`, proximity-fuse values, collision radius or damage radius. Simulation, collision, damage, range, fuse behavior, guidance/turning, charge/refire timing, and entity lifetime continue to use the existing gameplay fields until a separately authorized mechanics change is reviewed. Reaper must not be made guided merely to satisfy a visual scenario title, Heavy Blaster is not converted to RAY collision merely because its source rendering style is beam-like, and Sabot's current Web stage logic is not silently rewritten into source MIRV behavior.
