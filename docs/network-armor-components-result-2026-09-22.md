# 装甲组件变更驱动同步：第一块改造结果（2026-09-22）

## 结论与范围

已保留此前 protocol 26 / SWF3 数值块优化，并在实际主机捕获、客机原生还原路径接入装甲单元格的变更驱动复用。不是对整张战场架构重构目标的完成声明，也不是已经测得网络 RTT/FPS 改善。

| 目标 | 本次交付 |
| --- | --- |
| 写入时标记组件 | ArmorGrid 私有写入版本；setCell、批量写入、接收端替换均覆盖，抛错后的部分写入也失效缓存 |
| 不重复处理未变化数据 | 主机未变化装甲不再逐格捕获/打包；解码器按完全相同字节复用不可变块；客机同一块且本地未修改时不再写回单元格 |
| 生命周期内缓存 | 捕获与还原缓存按真实 ArmorGrid 对象弱引用绑定，不按可复用的 ship ID 绑定；并非已经实现舰船静态定义的生命周期协议 |
| 运动与可靠事件分开 | 复用既有设计，本次未改传输、启用实验通道或新增伤害事件协议 |

## 正确性和恢复边界

- 数值仍为原生 Float32，无量化、伤害公式、RNG、模拟顺序或 public dirtyVersion 策略变化。
- public cells 的可变数组接口继续可用；一旦引用外泄、替换或自定义，立即退出可信复用，走旧路径。只看 dirtyVersion 不足以保证正确性。
- 所有发出的 SWF3 快照依旧自包含。冷加入、跳过帧、reset、相同舰船 ID 的新对象不依赖漏收的组件差量。
- 解码缓存最多 128 项 / 4 MiB 数值存储（大端平台按双份存储计费）；哈希只选槽，命中必须完整比较字节。哈希冲突、淘汰、冷缓存只影响命中率，不影响还原。
- 数值块私有存储不通过 inspector 或 copy target 的自定义 set 方法泄露；检查器返回副本，拷贝使用 TypedArray 内建方法。
- HUD 投影复制数组，不读取原始可变 cells；UI 仍读取显示 DTO 原有数组，未改变绘图/布局。共享工作区同时出现的 ArmorReadView/TacticalMapView 修改已保留，非本任务独立交付成果。
- 保留 60Hz 模拟及全量状态目标、逐客机 delta 基线、ACK/credit、队列上限、重同步逻辑。

## 集中验证和定向修复

1. 初次 typecheck 发现 HUD/战术 DTO 不具备 getCell，撤回 UI 方法替换，改在投影边界复制数据。
2. 定向检查期间另一个工作区任务改变 TacticalMapView 的装甲来源，产生一次 copyCells 类型错误；保留其 ArmorReadCache 和 DTO 数组接口。最终 typecheck 通过。
3. 改动文件 oxlint 通过；并发整合后的相关投影/UI 文件复查也通过。
4. 既有 codec + relay + motion 场景 **29/29** 通过；不可变 copy target 加固后的 codec 定向复查 **10/10** 通过。
5. 既有 native-capture 中三个相关场景 **3/3** 通过，覆盖完整状态对照、HUD 真实投影、局部写入、批量写入、抛错部分写入、可变别名、冷加入、跳帧、reset、本地改写后的纠正和同 ID 新对象。
6. 20 tick 对照场景（主机及 viewer 捕获合计）计数增量：**16 次新捕获、64 次捕获复用、11 次实际还原、15 次还原跳过**。这仅证明路径启用和等价性，不是生产比例或耗时/RTT收益测量。

日志、运行退出码、改造前备份与源文件哈希保存在 artifacts/network-armor-components-20260922。最终 typecheck-final.log 和 lint-final.log 无错误输出。
