# 弹丸帧内字段共享优化 — 2026-09-19

## 做了什么

本轮不是再增加诊断。已经在 `captureHostCombat` 默认启用弹丸帧内字段共享，供 **LAN 与 Steam 共用**：

- 同一帧中，按字段布局和 `specId` 分组；完全相同的字段只编码一次，其余字段按弹丸保留。
- 对比的是本帧真实捕获值，不假定颜色、伤害、导弹配置等字段永远不变。任一弹丸字段变化都会保留。
- 接收端按模板直接写回各弹丸，不先展开成完整世界或完整记录数组；各弹丸仍拥有自己的可变嵌套对象。
- 每个快照带齐自己的模板，**不依赖上一帧**，因此发送跳过、恢复连接和新观战副本无需新增基准握手。
- 没有改成不可靠传输，没有修改目标 60Hz、窗口/超时、伤害、碰撞、弹丸数量或数值精度。

这是**帧内共享字段**，不是完整的跨帧对象级增量架构。为保留模组 getter/Proxy 的读取、异常和 Ship 引用发现，房主的通用捕获遍历仍在执行；不能把此项宣传成“已消除完整捕获”。客机还原也仍按原顺序写入所有传输字段，没有假定旧副本不可变。

## 实现位置

- `src/network/ProjectileColumns.ts`：帧内分组、严格等值比较、解码结构与展开预算验证。
- `src/network/CombatSnapshot.ts`：在捕获后、二进制/JSON 编码前共享字段；直接逐字段还原。优化路径在同一帧内复用不可变的 undefined wire 标记，减少短命对象。
- `src/network/HostSnapshot.ts`：共享房主入口默认启用，最后一个参数可关闭以做同代码路径 A/B。
- `scripts/check-projectile-columns.mts/.mjs`：状态、兼容、安全与传输测试。
- `scripts/bench-projectile-columns.mts/.mjs`：32 舰生产路径离线交替对照。
- `scripts/check-projectile-columns-browser.mjs`：真实 Edge 二进制解析与还原一致性检查。

普通 `captureCombat` 默认仍为旧表示；少量、异构/自定义映射、无合适共享字段或超预算的弹丸数据回退旧格式，不删除任何弹丸或字段。

## 对照结果

同一个 32 舰自然战斗，保留生产 `HostMuzzleEvents` 和爆炸配方；每 tick 在同一引擎状态上交替先后捕获两种表示。三轮各采集 121 帧，剔除前 30 帧预热，共 **273 对稳态样本**。客机走 native target retention 还原路径。

| 指标（均值） | 关闭字段共享 | 开启字段共享 | 变化 |
| --- | ---: | ---: | ---: |
| 完整二进制状态 | 300,033 字节 | 232,783 字节 | **-22.4%** |
| LAN 既有增量再压缩后的应用字节 | 45,438 字节 | 44,141 字节 | **-2.9%** |
| Steam 既有可靠编码、含 SWSP 头应用字节 | 99,597 字节 | 94,291 字节 | **-5.3%** |
| 房主捕获（含分组） | 6.99ms | 8.11ms | **+16.1%，变慢** |
| LAN 二进制编码 | 5.55ms | 4.00ms | -28.0% |
| LAN 二进制解析 | 3.36ms | 2.45ms | -27.1% |
| 客机还原 | 5.13ms | 5.22ms | +1.8%，未提速 |
| 房主捕获 + 二进制编码 | 12.54ms | 12.11ms | **-3.4%** |
| LAN 客机解析 + 还原 | 8.49ms | 7.67ms | **-9.7%** |

**限制与取舍：**

- 分组有额外捕获成本，净收益主要来自更小的编码/解析工作量，不是所有阶段都变快。
- 三轮客机解析+还原均值分别减少约 11.5%、13.7%、4.9%。绝对耗时波动明显，第三轮该项 P95 从 14.61ms 变为 16.18ms；没有证明尾延迟稳定改善。
- 原有压缩/增量本来已经去掉很多重复字节，所以不能把完整快照减少 22.4% 宣传成链路带宽也减少 22.4%。
- LAN ACK 延迟为离线 8 tick 模型；Steam 使用实际编码/分包代码回放，没有登录真实 Steam。数据不是实网抓包，也不是端到端延迟或 FPS。
- 二进制解析时延仅对应 LAN 路径，不冒充 Steam JSON 解析测速。
- 没有证明用户朋友的 10–20Hz 已恢复，也不能按这些百分比线性推算最终 Hz。

原始逐帧数据及汇总保存在 `artifacts/projectile-columns-20260919/repeat-{1,2,3}/production-profile.json` 与 `summary.json`。

## 一致性与防护

- 保留字段和弹丸顺序，包括混合布局、常量变动态、出生/删除、重排、ID 重用、清空、跳帧和重连。
- 不量化坐标或配置值；非有限数、undefined、typed array、Map、Set、Ship 引用使用现有还原语义。
- 共享值不直接赋给客机作为可变模板；修改一枚弹丸不会污染另一枚、下一帧或房主源数据。
- 校验模板/布局索引、排序且不重复的字段索引、每行宽度和额外字段。布局仍经过现有原型污染 denylist。
- 最多 4,096 行、128 模板、每布局 256 字段、262,144 顶层字段单元；重复共享子树累计节点也最多 262,144，防止小包触发巨大恢复工作量。
- 预算超限时房主退回完整表示；接收端对超限紧凑包拒绝恢复。预算限制不改变模拟中的实体数量。
