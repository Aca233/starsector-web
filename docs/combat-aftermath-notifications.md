# 战后观察与舰船损失通报修复

## 原因
- `CombatEngine.fixedUpdate` 在已有战果时只更新 FX/尾迹，舰船、弹丸、光束、小行星保持结算时的状态。
- 结算窗口关闭只切换 React 显示状态，没有明确恢复观察/画布焦点；镜头仍然跟随旗舰，包括旗舰残骸。
- 原有 radioMessages 没有 HUD 消费者；死亡通报还只针对双方旗舰，不是全舰队事件。

## 修改
- 独立 `BattleAftermath`：幸存舰船惯性移动、小行星漂移、残骸和特效继续，已有弹丸滑行并退出、光束结束；不运行 AI、开火、命中、伤害或扩展回调。
- 战斗时间、伤害统计、结构/装甲/弹药/CR、战斗 RNG 和已保存战果保持不变；观察时间独立推进。
- 点击“观察战场”或 Esc 关闭结算窗口会恢复观察并聚焦画布。WASD/方向键自由移动镜头，滚轮缩放，空格暂停/继续；可重新打开战果。旗舰战沉但友军仍在作战时同样支持自由观察。
- 原版 `decompiled/starfarer_obf/com/fs/starfarer/class/C.java` 的 `shipDisabled` / `shipDestroyed` 提供通报样式参考：舰名、舰级、阵营颜色、状态，排除战机，15 秒保持 + 5 秒淡出。
- 实际死亡处理边界生成一次事件，覆盖增援舰而不依赖 UI 轮询识别死亡；重开清空。消息以战斗/观察时间计龄，暂停时不消失。

## 边界
- 目前死亡状态统一为 destroyed；不伪造原版“停机/可回收”分类。
- 战后惯性观察、光束最多 1 秒及残留弹丸最多 5 秒的退出是 Web 展示策略，不声称是原版战后仿真的逐行移植。
- 本次界面修复作用于使用“观察战场”结算窗口的本地战斗/设计试飞，不宣称联机 HUD 已接入这些通报。

## 回归
`npm run typecheck`、`npm run build` 和 `scripts/check-combat-aftermath.mjs`。

浏览器回归需要运行中的 Vite 开发服务器和可解析的 Playwright 包（可通过 NODE_PATH 指向桌面依赖包目录）。
- `COMBAT_TEST_URL`：开发服务器地址，默认 http://127.0.0.1:5173。
- `BROWSER_PATH`：可选 Chromium / Edge 可执行文件。
- `node scripts/check-combat-aftermath.mjs`：隔离浏览器上下文，不读取或覆盖用户浏览器存档。

涵盖：旗舰/敌舰/增援损失、战机排除、战后运动与弹药退出、保存和统计不变、一次结算、消息淡出/暂停/重开、无伤实验室、自由镜头，以及真实 React 结算按钮、Esc、空格和焦点恢复。

验证时同时修正了舰队面板出击按钮现有的一处多余右括号，否则 JSX 无法编译；没有调整该面板的编成逻辑。

本次验证：类型检查、生产构建、25 项浏览器/引擎回归全部通过，页面运行异常 0。Lint 无错误，联机界面已有 2 条 React 可变状态警告；构建保留原有的大分块提示。
