# 底层改造与后续开发成本路线图

日期：2026-10-08。状态：本轮七项工程改造已实现并完成集中专项验收；native 全存档验证保留现有参考数据阻塞，性能未证明提速。用户已明确要求“全部完成”，授权落实本文全部工程改造项；不包含本文明确另行策划的多人包分发、新玩法和持久性策略变更，不授予提交、打包或发布生涯内容的权限。当前结果见 [交付记录](foundation-development-results-2026-10-08.md)、[架构索引](architecture-current.md) 和 [开发指南](foundation-development-guide.md)。

## 本轮实施合同（2026-10-08，编码前补充）

沿上述授权落实以下完整工程块，不将“全部”解释成全仓语言重写或未来机制已全部实现：

1. 本地战斗协议脱离具体 Kernel，生产者/消费者使用同一公共契约；新增可独立运行的严格类型入口。对本轮需要调整的 JS/声明边界减少双份定义；不批量迁移未触及的 309 对文件。
2. 新增依赖边界及循环检查，精确登记当前例外，禁止新增违规；支持类型依赖和运行时依赖分别报告，并接入日常检查。
3. 梳理全部内置舰船包及兼容目录，统一能力事实和准入；完成可在现有机制下迁入的包元数据/目录接线，保留数值、ID、资源、操作和多人限制。
4. 增加可复用的显式逐版本迁移入口，接入真实持久化数据族；以已有旧版本升级需求为准，无历史版本时只登记当前版本，不虚构升级规则。失败保留原始数据、并发冲突和已有存档回执保证。
5. 将数值阶段的纯读取接口与对象桥接/提交接口分开，接入实际 AI/fire/contact 消费者和阶段失效检查；在原完整场景中核对行为及整步成本，不改变原有顺序/频率。
6. 建立覆盖已有检查入口的机器可读目录和按改动预览/执行工具，提供兼容现有回放的隔离复现命令；权限、并发、存档检查按相关领域保留。
7. 新增当前架构索引、按领域的本地开发构建/类型入口；复用现有 UI 公共契约，检查并处理本轮相关入口的重复关闭/键盘逻辑，不作无依据的全界面视觉重写。

实施顺序：协议/迁移、内容能力、阶段接口按独立写集推进；主任务负责工具、入口、整合及最终验收。完整工程块完成后集中运行一次类型、改动文件 lint 和相关既有场景；具体失败定向复查。所有变更保留为工作区改动，桌面操作、提交及发布不在本轮范围。

玩家流程、失败及取消：界面布局与快捷键保持现状；内容预检失败不落盘、安装取消不改配置；迁移在副本完成，未知版本/失败不覆盖原档；阶段关闭/过期不能继续读旧观测；验证工具默认预览，执行需显式参数。新架构检查失败报告可定位的文件/边，不自动删除代码或重建例外基线。

## 目标与判断

目标是让后续增加舰船、技能、界面和联机功能时，少改无关模块、少维护重复定义、少发生旧存档和跨端行为回归。玩家收益是更新兼容性、操作一致性和故障可恢复性；帧率改善必须另用完整场景证明。

最接近“一劳永逸”的投入，是把已经约定的边界变成自动检查，把重复维护的数据变成单一来源，并给版本变化提供迁移入口。没有一种架构能使未来所有新机制都只需填配置。

初始建议第一批先做独立协议契约、对应严格类型、增量依赖门禁和检查入口。随后用户授权“全部完成”，本轮按上方实施合同落实七块完整工程；战斗性能仍独立验收，不把代码整理宣称为提速。

## 优先改造项

### 1. 公共契约独立，类型与校验尽量同源（优先级最高）

以本地 Worker 命令、回执和 telemetry 为首个切片。协议应依赖稳定的数据类型，不从完整引擎类的多层属性推导公共接口。保留本地战斗、联机和生涯各自的时序与语义，不强行合成一个万能消息总线。

对新建或已经修改到的边界采用单一类型来源：优先 TypeScript 源码生成声明；暂时保留 JS 的模块可按实际成本选用带类型的 JSDoc 与实现检查。外部 JSON 的类型和结构校验同源，资源归属、权限、金额、版本等领域约束继续由领域代码校验。已有二进制布局生成器继续使用；不替换成逐帧通用 JSON 校验。

严格模式从依赖可控的协议/纯规则模块开始，逐域扩展。不得用批量 `any`、类型断言或删除约束换取通过，也不把第一批扩大成全项目改名/语言迁移。

长期收益：新增字段能及时暴露遗漏消费者；修改引擎实现不再迫使协议随之变化。

### 2. 把模块职责变成可执行的依赖规则（优先级最高）

明确规则、内容、权威运行、传输、呈现、UI 和持久化的公开入口。协议层不依赖具体宿主实现；纯规则不依赖 React、DOM 或数据库；UI 经命令和呈现视图操作权威状态。已有兼容适配放在明确的边界位置。

先建立当前依赖图和精确例外清单，只禁止新增逆向依赖及新增循环，逐次消除旧例外。检查必须识别类型引用与运行时引用，避免把类型耦合错误描述为打包泄漏。优先整理入口职责，不能仅按文件行数机械拆分。

长期收益：多人或多任务开发时，错误耦合在改动时被发现，不必靠每位开发者记住全部文档。

### 3. 完成内容包与能力声明，缩小新增内容的改动范围（高优先级）

沿用 `ShipPack` / `ContentRegistry` / 已有扩展注册表。逐艘把尚在兼容工厂中的目录、配装、素材和能力要求迁入现有包入口。为实际需要的新机制补充宿主能力版本、支持范围和依赖关系，并让改装预检与运行时准入消费同一份能力事实。

对于战斗效果，逐机制明确生命周期、需要读取的阶段数据、可能改变的实体/属性，以及何时刷新观测。已有原生行为通过适配接入；原版允许可变回调，不能擅自宣称所有回调已纯化。未知写入保持显式保守失效，不能漏刷新。

开发流程目标：选用已实现能力 → 填包定义及素材 → 预检 → 隔离加载 → 进入既有改装/真实 Worker 场景。预检失败不写入；取消安装不改变配置；刷新激活和升级行为沿用当前约定。新底层机制仍需宿主实现，多人包传输/协商另行策划。

长期收益：普通新舰、新武器通常集中修改包自身；核心只因出现新机制而变化。

### 4. 存档和内容版本的显式迁移机制（高优先级、敏感）

为确有升级需求的存档族定义逐版本迁移函数、兼容范围和旧样本。文件 schema、数据库 schema、规则版本、内容包版本、网络协议与回放 build 是不同维度，分别演进；不合并成一个全局版本号。

迁移先在副本中完成并校验，再按对应存储的事务/原子写能力提交；保留旧数据恢复路径。失败或未知未来版本继续拒绝加载并保留原数据。内容缺失不自动替换默认舰船；跨槽位/ID 迁移必须显式映射。多人事务、幂等回执、revision 冲突检查不变。

不为尚不存在的 v2 虚构迁移规则，也不对战斗回放自动跨 build 重放。备份保留数量、保存频率和崩溃后允许丢失的进度若需变化，属于单独产品取舍。

长期收益：以后升级数据结构时有固定入口与可验证的恢复路径。

### 5. 继续收紧数值阶段和效果写入边界（性能主线，单独验收）

沿当前 `StageProtocol` / `StageProducer` 前进。区分只读数值查询接口与提交所需对象映射；规定每个阶段哪些数据有效、谁可修改、效果发生后刷新哪部分。复用存储和稳定规格，避免每个系统再创建一份世界或重复派生属性。

不能无条件跨 AI/fire/contact 阶段缓存同一份结果，不能更改资源扣除、命中、护盾过载、死亡或随机流顺序来制造提速。保留已确认需要的有序提交。只在完整生产路径中移除已被替代的重复查询后，决定是否进一步并行或更换语言。

历史驻留方案记录整步均值约 34.56 → 100.52 ms，已被拒绝；这是历史特定场景，不是当前性能基线。它说明只增加 Worker 和缓存容器不能保证收益。本轮阶段整理后的 ABBA 完整步约 33.82 → 34.03 ms，状态/RNG 一致但未证明提速，详见 [阶段验收](foundation-stage-boundaries-source-notes-2026-10-08.md)。

### 6. 按改动选择必要检查，复用现有回放（中高优先级）

给现有检查建立机器可读目录：所属领域、入口、需要的环境、是否涉及存档/权限/并发、是否昂贵。提供先列出将运行哪些检查的入口，再按改动领域运行最小必要集合。初期用明确映射与依赖关系，不猜测任意动态影响。

无法可靠确定影响时，扩大到该领域必要检查并说明原因；不把权限、并发、存档安全检查当作可省项。发布门禁保留。一个完整功能块只集中验证一次，除非出现失败或新变化。

复用已有回放的 build、protocol、配置、已确认输入和 witness，组织成可在隔离环境复现问题的开发入口。当前日志有长度/内存上限且只支持相容 build，需保留这些真实限制；不另建默认永久录制系统。

长期收益：减少反复研究“该跑什么”和手工重现问题的时间。

### 7. 保持一份当前架构索引，按开发领域拆分构建入口（随后推进）

建立简短当前索引，列每个领域的状态所有者、公开 API、正在使用的后端、已接受方案、被拒绝方案、最低验证入口。历史 source-notes 保留为证据，当前索引指向它们，避免复制大段历史。索引应标记“已接线”和“已验收”的区别。

在需要时拆分普通应用、Worker/服务端与生涯开发的类型/构建入口，使日常工作可以只处理相关领域。先做本地开发目标，不改变生涯发布限制，不放宽现有 `check-release-scope`。不要为了开发速度引入远程微服务或强制全项目搬迁到新仓库。

UI 沿已有组件契约完成剩余迁移，业务数据仍归领域；新增可见交互需另行策划。这一项排在契约、依赖边界与存档演进之后。
