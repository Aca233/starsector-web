# AI 资格检查候选验收（拒绝）— 2026-10-03

## 结论
没有解决剩余高 ms。本轮候选逻辑等价，但没有性能收益，已撤回所有四个生产文件中的本轮修改。`rollback-source-check.json` 证明与开工前冻结源码逐字节相同；上轮已接受的固定模块职责分流及其他已有改动保留。拒绝源码、bundle、测试与结果留作证据，不进入生产。

## 候选做了什么、没做到什么
将小组件的整个原型键逐项 hasOwn，改为实际 own 属性与原型名字集合求交；保留不可枚举覆盖与每次动态失效检查。原生 producer 创建冻结纯数据 world，两处 bind 可复用“容器 own 数据描述符”的事实，其它 owner/read-plane/回调检查不变。这不是把173个实体的资格检查变成一次常量检查，更不是已经重写真实 Worker 的封闭执行边界。

原设想“只在阶段入口检查”未直接实施：公开 CombatAIPhase.plan 允许两次 plan 间任意方法/组件替换。没有实际独占封闭调用图或可靠的变更 revision，跨 plan 信任可变对象会错误持有 neutral controls。不能用布尔标记、DTO、普通原型或永久 WeakSet 伪造该权限。

## 性能：不接受
第一组ABBA与静态检查重叠，作废，不算收益或退化。逻辑验证结束后独立运行计时；两个 bundle 各额外150预热，再做四臂ABBA，每臂150warm+120sampled，包含全部producer准备/资格/整步成本。

| 指标 | 当前接受基线 | 本轮拒绝候选 | 变化 |
|---|---:|---:|---:|
| 整步均值 | 34.077 ms | 38.845 ms | +13.99% |
| AI（planning+controls+effects） | 11.998 ms | 12.620 ms | +5.19% |

样本四臂存在波动，不据此声称某条具体语句稳定导致4.77ms退化；但两臂候选均未达到收益，因此足以拒绝作为性能优化。更少 hasOwn、完整逻辑通过，都不能替代整步收益。

## 根因与后续边界
上一轮实测的约2.238ms资格路径、229.442次nativeMember/步没有被本轮解决。它把通用可替换对象 API 的安全证明混进每个模块的热路径；换一种反射算法仍在做重复结构证明，冻结再复制world也增加producer工作。

真正的执行边界重写需要把实际Worker的同步、无未知回调的原生root/module计划调用图，与支持任意调用方world/方法替换的通用API分开；在真实入口证明、未知入口撤销，不依靠消费端猜测对象资格。是否能减少全roster资格成本，仍须实现并实测，不能冒充已经做到。

其它已实测根因仍未处理：有序权限mask 94.337%重复scope、输入元数据缺revision、preAim先建BVH再命中current、递归关系getter、精确防御索引与旧门禁耦合。本轮没有悄悄扩大更改范围。
