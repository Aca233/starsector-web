# 掩护会合航速实验：行为指标改善，但对抗未改善，已撤回

日期：2026-09-18。结论：**REJECTED_AND_RESTORED**。本轮没有继续训练 RL，没有采用新的运行时 AI 规则；上一轮的 REGROUP / DISENGAGE 撤离条件修复保留。

## 调查与假设

检查撤离、掩护会合和重新接战时，观察到 `regroupVelocity` 会将掩护舰的完整速度叠加到位置修正速度。混合双舰固定回放中，残血 sunder 距掩护点仍有约 400–500 单位，掩护舰朝该方向的速度投影约为 −100 至 −109，自身最高航速为 90，合成请求可以指向当前掩护点的反方向。部分帧没有碰撞避让。

候选假设是：远处先驶向掩护点，仅在进入制动/到达区间后逐渐匹配掩护舰航速。改动只有 `FleetNavigation.ts` 中的 `regroupVelocity`，没有修改选敌、撤离意图、武器、损伤、物理频率或学习策略。

**需要纠正最初对现象的解释：世界坐标中的反向速度，不等于相对移动掩护点在远离。** 例如掩护点向本舰移动 150，本舰同向移动 60，二者仍以 90 的速度接近；强行让本舰反向移动 90，会将接近速度提高到 240，改变原来的会合与制动过程。仅凭“反向请求”减少，不能认定导航或实战一定改善。这里的运动学例子用于解释指标局限，不是已证明对抗退步的唯一原因。

## 冻结的前后行为回放

三种编成 × 三个种子（211、307、419），各最多 60 秒：

- hammerhead 对 hammerhead，LINE。
- hammerhead + wolf 对 sunder + lasher，STAGGER。
- hammerhead + lasher + wolf 对 sunder + hammerhead + lasher，WIDE。

每组前后各跑一次带观察钩子的回放，并分别做不带钩子的复演；36 次模拟对应 **9 组场景比较**，不算 36 个独立效果样本。每次观察版本与无观察版本的完整权威摘要（结局、船体、幅能、位置校验值、弹药等）一致。

“远处可移动”限定为：到掩护点距离 > 60 + 制动距离，且最高航速 > 10，避免把发动机近乎失效混算为导航失误。下列航速请求在碰撞避让前统计，单位为累计舰秒，不是舰船实际倒行时间。

| 指标 | 原规则 | 候选 |
|---|---:|---:|
| 远处掩护导航决策时间 | 130.27 | 108.33 |
| 请求朝当前掩护点反方向移动 | 22.60 | 0 |
| 其中未触发碰撞避让的时间 | 19.82 | 0 |

这些局中双方均使用同一版本，因此结局变化不能当作新版对旧版的胜率。双驱逐的三局完全没有 REGROUP，前后摘要一致；混合和三舰样本的生存/输出变化并不一致，不能仅凭上表采用候选。

## 真正的新版对旧版对抗

在查看对抗结果前保存 `head-to-head-plan.json`，冻结候选与四个新种子 **617、829、1061、1297**。同样三个编成，各交换新版所在阵营，最多 90 秒：**12 个镜像组合，24 场直接对抗**。没有借用此前 RL 留出结果，没有训练，也没有根据本轮结果挑种子或调参。

对抗 bundle 从同一份冻结模拟器生成，只在掩护导航函数入口按 teamId 分派：被测试阵营用候选，另一阵营用原函数。选敌、目标分配、火控、物理和随机源完全相同。

- 24 个函数分派探针检查了两种阵营选择、双方舰船以及多组位置/速度；选择结果逐项等于相应原函数或候选函数。
- 将所有阵营都分派回原函数后，三个编成、双方视角的短回放与未修改基线的权威摘要完全一致，共 12 次中性校验模拟。
- 逐场保存原函数/候选函数的实际调用次数，避免把根本没有使用新规则的对局误认为有效暴露。

### 对抗结果

| 场景 | 新版胜 / 负 / 超时 | 平均得分 |
|---|---|---:|
| 双驱逐（无掩护导航调用，对照） | 3 / 3 / 2 | 50.00% |
| 混合双舰 | 1 / 3 / 4 | 37.50% |
| 三舰 | 4 / 4 / 0 | 50.00% |
| **合计** | **8 / 10 / 6** | **45.83%** |

胜计 1、负计 0、超时/同归于尽计 0.5。**45.83% 是得分，不是胜率**；实际胜率为 8/24 = 33.33%。相对五五开的得分差为 −4.17 个百分点。以镜像组为单位的 5,000 次描述性 bootstrap 范围为 39.58%–50.00%，对应差值 −10.42–0 个百分点。只有少量编成和种子，不能将该范围当作普遍战力结论；24 场也不是 24 个独立样本。

三舰的胜负随阵营/编成优势变化，有些胜局中新版函数根本没有被调用，不能宣称这些胜利由候选带来。混合双舰样本反而退步。上述结果不支持启用候选，因此**保守撤回，而不是继续修改参数并重复使用这批结果直到过线**。

## 回退与工程验证

- 候选的 10 项契约检查通过：远处航速、到达跟随、连续过渡、静止掩护、旋转不变性、不修改输入、无目标、碰撞避让、命令/幅能保护、Worker owner 与串行控制一致。它们证明实现符合候选设定，**不证明设定让 AI 更强**。
- 旧版本按该候选契约检查会在第一项失败，记录为 `baseline-red-check.txt`；这不是旧生产版本不能工作的证明。
- 新契约已从生产 `ai:check` 移除。`scripts/check-cover-navigation.mjs` 要求显式传入冻结候选 bundle，以免将被拒绝的行为要求误用为生产回归标准。
- 仅撤回本轮加入的掩护航速混合代码；`FleetNavigation.ts` 与本轮开始的源文件逐字一致。上一轮 `FleetTactics.ts`、`CapitalShipAI.ts` 的撤离条件修复没有撤回。
- 回退后生产 **72 项 AI 检查、lint、构建通过**，仍有原有大分块警告。没有启用 RL 权重。
- 工作区同时有其他火控/武器轮廓修改。没有回滚那些修改，也没有假称最终整个 bundle 与本轮开始完全相同；`decision.json` 单独核对掩护函数精确恢复和之前撤离规则保留，并记录其他模块变化。
