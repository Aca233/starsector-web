# Phase19：权威快照叶节点分派（实现前，2026-09-21）

- 边界：本轮只改联机快照捕获，不改正在开发的火控批处理/CombatEngine/Ship，也不改生涯、模拟频率、AI、伤害、网络信用或恢复预算。所有旧WIP保留。
- 原版证据：本地0.98a来源，`CombatEngineAPI`的舰船/弹丸集合和`CombatEntityAPI`的位置、速度、朝向接口是活状态；数据投影只用于Web联机呈现，不是原版网络协议，也不是可恢复模拟存档。之前对照与标记类型沿用`CombatSnapshot`约定；不能用省略动态值伪装加速。原版实机UI未复验，本轮无UI变动且不占用桌面。
- 基线：固定seed917、5艘玩家攻势+17艘AI锤头、预热240步后600步，所有来源已冻结到bundle+sourcemap+SHA清单；每步均执行完整捕获/编码，不是压低发送Hz。初次CPU profile的pack self约4472ms，普通记录每次会重复做Ship/Vector2/typed-view/Map/Set判定。火控资格检查也有成本，但那部分存在独立WIP，本轮不覆盖。
- 候选：仅显式nativeCapture、原生叶类型判定未被替换时，一次取得普通对象的直接prototype；Object.prototype/null对象不可能是这些特殊叶类型，因此跳过重复instanceof/isView。数组原优化不变；其它实例/子类和generic/custom捕获照旧。每帧做资格检查，构造器自有Symbol.hasInstance（包括getter）或原生判定变化时回退。所有字段、引用发现、循环标记、排列顺序、布局字典和字节内容必须不变。
- 验证：冻结旧源图与只覆盖CombatSnapshot的新源图，逐帧输出hash/字节数相等；同场景无Profiler交替多次计时，分别列固定步/捕获/编码，不把CPU循环吞吐当作网络Hz。真实原生/自定义数据、特殊叶节点和回退/异常回归；有收益才保留，否则撤回。节点CPU和浏览器游戏仍须分别验证。

## 对象分派候选撤回

600帧网络字节总数/逐帧累计SHA一致，6项叶节点及回退契约通过。但单独进程的CPU环境变化极大（未改模拟代码也从21.57降到8.42ms），不能把它归功于捕获改动。改为同一冻结22舰/169弹丸世界交替120对采样后，旧捕获均值3.0462ms、新3.1067ms，未见净收益，已撤回生产改动并保存候选/测试。

## 下一个候选：同一完成tick的显示/网络捕获复用（实现前）

Phase17分离了房主显示与网络信用，但两个信用异步归还时，同一物理tick可能先捕获一次给网络、随后再次捕获给显示，源世界没有推进却重复遍历。拟只在直通模式、另一通道尚未消费同tick时保留一个最新投影；不缓存多tick、不额外发包，不绕过现有信用，发给两条通道后立即释放。下一固定步、部署/撤退、presence清除控制、恢复、启停、换局/回退均失效。输入入队不直接修改引擎或ack，仅在实际固定步应用；音效与性能头每次发送分别生成，不重放缓存的声音。检验两个信用顺序、声音有界/终局、同tick外部变更、释放与停机；记录实际命中/捕获次数而非开关宣称生效。

## 同tick捕获复用：实现及证据

- 默认在已经建立的直通权威双消费者路径启用（LAN/Steam共用）；Node/旧协议单消费者不保留缓存。只保留一个尚待另一通道消费的完成tick。不会抬高或压低Hz、跳步、追加网络积压或改变ACK信用。
- 发布头和声音始终重新生成；下一固定步及部署/撤退、presence、换局、恢复、启停、通道回退使缓存失效。编码/转移前先消费保留引用，异常也不会把旧投影钉在内存中。
- 同一冻结22舰、169弹丸、tick600世界，实际旧/新snapshot函数，120对交替顺序，并覆盖显示先/网络先，真实ArrayBuffer转移：首次均值11.2030→7.3961ms；最终实现复测21.1101→13.7325ms。捕获240→120、命中120；字节逐一一致、世界hash不变。计时包含两次发布，不包含物理推进、真实网络、渲染；墙钟诊断字段在配对夹具内固定，不能解读成用户ping降幅。环境绝对耗时变化很大，不用跨进程数字比较。
- 实际3人/3舰浏览器运行的8秒测量区间推进481tick，authority日志相邻区间捕获增加413次、复用增加72次，证明不是只写了开关。该次后续主线程阻塞/重连未通过，不能算整项通过。
- 22舰3人及5人当前WIP浏览器重载均在测量前发生authority过载，原始失败保留。没有同条件冻结浏览器A/B，不能归因给缓存，也不能宣称缓存已经解决重载。火控另一批WIP没有修改；当前本地多浏览器也不能代替真实多机Steam/n2n测量。
