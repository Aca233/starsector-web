# 联机入口玩家名称持久化核查（2026-09-20）

## 用户确认的范围
用户进一步明确：是 **进入房间时填写的玩家名称/昵称**，不是角色技能页的舰长档案。撤回本轮误解导致的舰长档案持久化试改，保留此前换船技能与一键准备的修复。

## 原版证据与最小对照（编码前）
- 本机原版为 0.98a-RC8。`PersonAPI.getName/setName`、`FullName` 是游戏角色姓名，不等于此处 Web 联机入口玩家昵称；原版没有这个 Web 房间入口。此次不改原版角色、技能或档案 UI。
- 当前 Web 源码：`LanStart.tsx` 的 `lan-player-name` 与 `SteamStart.tsx` 的 `steam-player-name` 都只更新 `LanApp` 内存。`LanApp.tsx` 初始化只读 URL fragment、`connection.saved.name` 和默认「玩家」。
- `protocol.ts` 仅将昵称与重连令牌一起存在 `sessionStorage` 的 `starsector.lan.session.v5[.steam]` 中，并要求 build 一致；`forget()` / 主动关闭会删除整份会话。因而关闭标签页、退出连接或更新版本后，昵称不能可靠恢复。
- `server/lan-server.mjs` hello 校验名称非空、最多 24 字符、无控制字符，随后 `p.name = m.name.trim()`；无须更改服务端身份与重连逻辑。
- 预期：单独持久化输入的有效玩家昵称，创建/加入房间、普通刷新、新标签页、返回菜单、版本/连接变化均能恢复；独立于临时会话、令牌、舰长名与配装。保留现有输入框和按钮，无额外“保存”点击。
- 显式跳转携带的昵称优先，其次本机昵称，其次兼容旧会话，最后默认「玩家」。Steam 默认账号名不得覆盖用户明确输入的昵称。仅持久化名称，不把重连凭据放入 localStorage。
- 验证：纯存储校验、失败回退和优先级；浏览器真实创建/加入、刷新/新页面、主动退出后恢复、URL 自动连接、昵称发送值与 UI 一致、Steam 默认名保护，以及既有一键准备回归。
- 原版实机界面验证不适用此 Web 扩展；不声称原版等价。保存范围为当前浏览器和当前站点，不跨设备/域名自动同步。

## 实现与验收
- `PlayerName.ts` 只持久化版本和昵称；读写异常安全回退，坏值不自动删除；迁移旧会话仅取名字，不存/恢复令牌。
- `LanApp.tsx` 在用户输入时保存，自动连接也使用同一份已恢复名称，创建/加入再重试保存；提示存储失败。原输入框布局和进房按钮保留。
- 撤回误解产生的舰长持久化试改，`CaptainSkillsScreen` 未改；此前换船保留角色技能、统一准备操作、列表本地预览均保留。
- `check-lan-player-name-storage.mjs`：5 项通过，覆盖名称有效性、优先级、损坏与拒绝写入、隔离存储、旧版本会话只迁移姓名。
- 浏览器已通过真实服务创建/加入、刷新、新标签页、主动退出、URL 自动创建、跳转带昵称、存储失败警告，以及模拟 Steam 状态轮询不覆盖明确昵称。Steam 测试仅验证入口与状态刷新，不代表实机 Steam 联网验收。
- Web 1440×1000 截图检查：新增存储失败警告可见，输入框/创建加入/底部按钮未被遮挡；`artifacts/lan-player-name-storage-warning.png`。
