# 通用舰炮安装系统 v0.2：样板驱动的 2.5D 装配方案

初版：2026-09-26；安装/生图/挂点细化：2026-09-27。用户允许修改游戏，要求比单舰补底座更好的方案。
状态：设计提案。2026-09-27本轮仅细化原舰炮安装方案，不重写整套造船流程，不调用生图、不修改运行代码和现有槽位。下述承座、作者工具和安装契约未实装；四档尺寸的已有代码不等于安装系统完成。

> 2026-09-27后续决定：用户暂不继续此大型安装系统，先实施四档严格同尺寸换装。下文为保留的美术安装提案，不代表已实装；所有跨尺寸下装需求取消。详见 [最新规则](strict-weapon-slot-sizes-source-notes.md)。

> **2026-09-27 实施更新：** 用户随后指定亚顿之矛验证新架构。已落地安装 v1 最小链路：槽位固定座、武器世界尺寸/归一化枢轴、严格同档换装、改装/战斗/Worker同源、空座资源闭包与残骸归属。下文完整 2.5D 方案中的任意接口适配、甲板前景遮挡、作者工具与ZIP安装器仍待实现；并未把旧舰批量迁移。实际字段、验收与差异见 [亚顿之矛实装记录](spear-of-adun-source-notes.md)。

## 1. 决策

推荐扩展宿主的“挂点装配与渲染契约”，保留二维舰船素材和现有战斗规则。
不把所有内容换成3D，也不继续只对休伯利安ID做特判。以休伯利安验证现有三档安装，再用独立超大型夹具验证第四档；其他舰船包按同一规范接入。

三个层级：
- 仅修贴图：成本低但无法解决固定承座随炮塔转、自由换装后再次不贴合的问题。
- 2.5D安装系统（推荐）：固定安装结构、旋转组件、接触暗部与甲板遮挡分层；以数据驱动兼容关系和表现。
- 全3D：需要重新制作舰体/武器模型、材质和大量旧内容，且偏离当前二维远行星号美术，不作为本问题前置条件。

## 2. 来源与当前差异

- 本机0.98a-RC8：starsector-core/data/weapons/hellbore.wpn，已有turretSprite/turretGunSprite、visualRecoil、RENDER_BARREL_BELOW和枪口offset；autopulse.wpn已有独立glow、turret/hardpoint差异。原版逐帧实机未补验。
- 宿主src/engine/content/ShipSpec.ts：WeaponMountSlotConfig有位置、尺寸类别、类型、射界；没有安装平面、承座、基座占地或局部遮挡声明。
- src/engine/render/webgl/passes/WebGLShipPass.ts：支持body/gun/glow及后座，已有可复用能力；不应声称必须重写整个渲染器。
- src/studio/ShipStage.tsx：改装页另行读取图片自然尺寸并排布，与战斗渲染存在两条表现路径。
- src/engine/content/HyperionArmory.ts：清除独立gun层并设置visualRecoil=0，整套炮塔以单张body旋转。原图含外部支撑/大轮廓基座，与舰体安装过渡未分开。
- 实际观察舰体、炮塔图集和Web实战/改装截图：风格接近但边缘粗细、细节尺度及机械连接不一致。运行图片有有效alpha；平均灰度接近，不能把问题直接归因于“没透明”或“只需调暗”。

预期：未安装时看得见合理空座；装炮后有固定/旋转分工；多方向转动仍贴合；不依赖发光掩盖接缝。验证以关闭特效的实际缩放截图为主。

## 3. 三方责任，不为每个舰炮组合重新绘图

### 舰体拥有安装环境

舰体/模块声明固定甲板位置、朝向、承座类型、可容纳的基座轮廓、局部前景遮挡、接触暗部接收区域。
承座类型可逐步提供平甲板、嵌入式、舷侧悬臂；升降/收纳不是首版必做项。
可选局部安装高度只用于显示分层和接触暗部，不自动成为弹道高度或新增碰撞维度。

### 武器拥有机械组件

武器声明旋转轴、基座接触轮廓、炮身、可选独立炮管、发光遮罩和枪口。
不要用整张PNG的矩形尺寸替代基座占地；炮管允许伸出基座。不同尺寸武器也不默认按同一比例缩放。
激光器不必为了“动起来”强加机械后座；只有实际设计需要时拆出并驱动动作。

### 适配器负责安装匹配

适配器连接承座与武器接口，优先使用武器作者声明的安装变体，然后使用同规格通用转接环/支撑。
小/中/大/超大型槽决定尺寸兼容性，另须满足武器类型约束，物理基座轮廓解决美术适配，二者不是同一个字段。
禁止为了塞进去任意拉伸武器或移动真实枪口；超出已声明适配范围给作者检查提示。首版不因此静默拒绝原本合法的玩家配装。
原版武器/舰体未声明新元数据时保持原路径，不强加统一巨型圆盘。

## 4. 统一装配结果

建立一个共享的、只读的安装解析结果，供改装、战斗和作者预览消费，不再各写一套尺寸和枢轴计算。

概念输入：舰体槽位 + 武器定义 + 安装变体 + 当前炮塔方向/动作。
概念输出：固定承座、接触阴影、旋转部件、可选炮管、前景遮挡、发光层的姿态及资源引用。

这是拟议契约，不是已有JSON字段。实际字段名和版本随实现冻结。

要点：
- 固定层跟随舰体/模块，旋转层跟随炮塔；局部遮挡只裁需要藏入甲板的区域，不把整根炮管截断。
- 枢轴/枪口的作者数据保持同源；显示预测不得回写权威瞄准或伤害。
- 如果新增安装变体会改变枪口几何，应在配装编译阶段生成权威几何，不能只在shader里缩放显示。
- 后座/蓄能/禁用读已有状态；不在每个页面新增私有计时器。
- Worker投影、快照与内容注册验证必须覆盖新增元数据；不能只让改装页显示新效果。
- 空座、停火、射击、转向、禁用与残骸有明确回退规则。

## 5. 视觉融合：先解决结构，再加材质

第一层：固定安装圈、承重连接、炮身接触甲板的暗部、局部前景遮挡。
第二层：同一像素/世界比例、材质边缘宽度、粗糙度观感和细节密度。
第三层：仅在材质遮罩允许的区域应用同系列配色/磨损，保留识别色、军徽和自发光；不把整张炮塔一键染成舰体平均颜色。

接触暗部是贴近物体的AO/高度近似，不等于虚构一个随旋转灯光乱跑的大黑椭圆。裁在合法甲板接收区域内，不投到太空中。

完整法线贴图/实时主光仅作为后续可选能力。单张AI图片不能可靠自动恢复法线或材质；未经校准的伪法线可能使炮塔更像塑料。首版不依赖它。

## 6. 作者工具与单舰包

在现有开发/改装预览中增加安装检查模式，而不是另做一套成品游戏UI：
- 显示基座占地、枢轴、枪口和旋转包络；提供0/45/90/180度方向检查。
- 分别预览空座、四档炮塔、各档同尺寸不同武器、换装原版兼容武器、禁用/开火。
- 检查基座悬空、遮挡反了、缺资源、变体枢轴漂移、枪口与弹体不一致。
- 旋转包络检查是作者警告，不自动引入炮管互撞或开火封锁。

单舰包收齐所需承座/组件/遮罩/安装定义，并声明宿主最低能力版本。基础通用能力由宿主提供；不能让第二艘船要求玩家手改引擎或先装休伯利安。
注册/安装应完整验证引用和能力；必需能力缺失明确拒绝，只有声明为可选的美术效果才允许降级。完整ZIP安装器仍未实现，不借本提案冒充完成。

## 7. 实施顺序与边界

1. 安装契约和共用解析：只读、可验证、旧内容零默认变化；同时覆盖改装与战斗/Worker。
2. 休伯利安结构适配：选前部大炮、中段中炮、尾部小炮作为三类样本，验过转向与换装后推广至24槽；不改槽数、伤害、OP和技能。
3. 通用接触暗部/遮挡：缓存静态结果，动态只变换；保证模块和残骸不重复绘制整套炮座。
4. 材质一致性与作者检查工具：结构验收通过才做风格修整，不靠强光遮丑。
5. 舰船包契约接入：原版回归、跨舰换装、重新开战与快照恢复；再决定是否扩展到荣光女王。

全局性能：禁止每帧读取PNG/扫描像素/生成canvas；按安装组合缓存，尽量图集合批，远距离简化。接触阴影可以降级关闭，固定/旋转正确性不能降级。以当前多舰战斗作前后对照，不凭空承诺帧率。

不在首版改变炮管碰撞、自舰遮挡弹道、炮塔生命值或武器射界。那些会改变AI、平衡和权威战斗规则，需要作为独立玩法设计决定，不能借美术修复悄悄加入。

## 8. 验收条件

- 无发光/无射击时已经自然，常用与近距离缩放均成立。
- 原有合法配装仍合法；固定承座不随炮塔转；同向/侧向/后向无飘移或不合理基座悬空。
- 改装、Worker实战、重进战斗及快照恢复使用一致的安装数据。
- 枪口和实际发射位置一致，毁坏/禁用/模块脱落后无遗留浮空层。
- 原版未启用新契约的舰船和武器外观/玩法保持原样。
- 在代表性舰队规模下测量新增渲染开销；不只验证单舰静态截图。

## 9. 四档尺寸对安装系统的约束

用户已确认第四档是**超大型（EXTRA_LARGE / IV）**，不是强化等级。统一规则位于 `src/engine/content/WeaponSizes.ts`：四档严格相等匹配，不允许上装或下装；同档可换不同武器，类型限制照常执行。四档标识不变，旧跨尺寸存档不自动替换或清空。

尺寸兼容不等于物理贴合：同尺寸武器也可能有不同占地，固定承座/转接结构可负责过渡，但不得用转接件绕过尺寸限制，也不放大图片或移动真实枪口。真实素材使用作者尺寸与枢轴，尺寸表只提供缺失贴图时的占位兜底。伤害/射程/幅能/OP不从尺寸乘倍率，正式XL武器需单独设计。

四档规则代码与改装入口已接入；2026-09-26的四档专项验收记录曾被其它工作区变动阻塞，见 `four-tier-weapons-source-notes.md`。这是当时记录，本轮未重跑四档专项验收，不把历史阻塞描述当作当前全项目状态。本提案的承座、共享安装解析、遮挡和作者工具仍未实现；不能用第四档接口代替炮座融合验收。


## 10. v0.2 核心：一份安装样板同时约束图和数据

### 10.1 本次补查的实际依据

- 原版0.98a-RC8 `starsector-core/data/weapons/hellbore.wpn`：独立turretSprite/turretGunSprite，visualRecoil=10、RENDER_BARREL_BELOW、炮塔枪口[35,0]和固定枪口[50,0]。它证明炮身/炮管与两种安装形态可分开，不证明新增“固定承座层”已有。
- 当前 `WebGLShipPass.ts` 以mountFacing旋转body和gun，按真实图片尺寸绘制；因此**turretSprite里的base通常仍是旋转组件，不能直接当固定甲板底座**。
- 当前 `ShipStage.tsx` 用图片naturalWidth与translate(-50%,-50%)定位；战斗亦有以纹理中心为基准的武器路径。只有槽点准确，不代表非居中炮塔轴也准确。新枢轴必须两端共同支持，不能只在改装里加CSS偏移。
- 当前休伯利安源图实际1122×1402，源枢轴(561,820)，运行缩放0.5；`hyperionPoint(u,v)=[(820-v)*0.5,(u-561)*0.5]`。不得把请求的生图尺寸、缩略图坐标或裁剪后坐标直接填入挂点。
- 这些是本轮代码/本机资源核对，不是原版实机操作或新方案的运行验收。

### 10.2 一个槽位不是一个点：必须分清五件事

| 数据 | 含义 | 不能混用为 |
| --- | --- | --- |
| 逻辑槽 | 稳定slotId、四档尺寸、武器类型、射界、默认配装 | 不直接决定贴图放多大 |
| 安装锚点 | 武器转轴落在舰体/模块局部坐标的哪里 | 不是PNG矩形中心、枪口或UI按钮中心 |
| 承重区 | 甲板真正可承载固定承座的区域 | 不是整个非透明舰体，天线/机库/结构空洞不一定可用 |
| 接口占地 | 武器与转接件相接的实际底部轮廓 | 不是包括长炮管的整张图外框 |
| 动作包络 | 炮塔在有效射界内旋转、炮管后座时扫过的区域 | 不是伤害碰撞体，不自动限制玩家合法配装 |

**逻辑尺寸、物理占地、图像分辨率三者分离。** S/M/L/XL是游戏兼容档；同档不同武器可以有不同长宽与底部轮廓。不能规定“大槽图必须是小槽图的两倍”，也不能靠把小炮放大填满XL承座。

### 10.3 安装样板的交付形态

每种“尺寸×机械接口族”先做一张可量测样板，而非每个挂点各生一张不一致的炮座。

样板包括：固定承座外轮廓、转轴十字、可接受的武器接口轮廓、方向基准、炮管/后座净空、统一世界单位尺、所属材质系列。至少有平甲板旋转座、嵌入座、舷侧支撑/固定架三种形态；只制作舰船实际用到的组合。

- 彩色框/十字/尺寸文字只在作者工具和生成参考图中显示，不能烧进运行PNG。
- 原作武器外观不是安装规格；先定样板，再用它约束候选炮塔尺寸。
- 接口族负责机械匹配，材质系列负责外观。不要为同一接口的不同涂装重复做几何。
- 自动转接只在作者声明的有效占地范围内成立。不能声称一个通用圆环可以适配所有异形炮座。
- 旧内容缺元数据时保持旧外观/合法性；新方案中的“未适配”给作者提示，不偷偷变成玩家装不上的新规则。

## 11. 生图优化：先验结构，再生成表面，不靠提示词精确定位

### 11.1 固定使用四件交接材料

1. **舰体局部环境图**：真实甲板材质、边缘宽度和光照，另给一个全舰小图交代尺度；不要只给一张孤立炮塔参考。
2. **安装样板图**：确定转轴/接口/轮廓，和气氛图严格区分。
3. **已认可的武器家族样本**：明确哪些是固定支撑，哪些随炮塔转；不同尺寸独立设计细节密度，不只是缩放同图。
4. **目标尺寸卡**：运行世界尺寸、实际导出像素比例、朝向和禁止项。输入图/生成图/导出图各自的尺寸和裁剪信息都保留。

正交灰模/结构线稿用于控制形体，俯视舰体局部用于控制材质。单张好看的透视炮塔图不适合作为唯一输入。

### 11.2 生产拆分，不要求AI一次交付可直接使用的分层图集

| 资产 | 推荐交付 | 不能画进去 |
| --- | --- | --- |
| 舰体安装区 | 与船体相连的加强甲板、装甲过渡、供能接口 | 可换装炮管、旋转炮塔、槽位编号、大型泛光圆盘 |
| 固定承座 | 薄转接环/装甲楔/支撑架，必要时空座盖板 | 随瞄准转动的炮身、喷焰、夸张地面投影 |
| 旋转炮身 | 带真实转轴的炮塔和旋转下座 | 固定在船壳上的支撑脚、大片甲板、不可旋转外框 |
| 可动炮管 | 确有后座/开合需求时分出，基准与炮身一致 | 自己画一套不对齐的底座 |
| 光照/遮挡信息 | 作者校准的发光mask、局部甲板前沿、接触区域 | 从单张图片“自动恢复准确高度/法线”的未经验证承诺 |

先认可一套组装候选，再在相同基准下生产/整理组件；优先单个部件一张，避免模型把多个尺寸、俯视和透视混在一张展示板里。AI输出是候选，不保证层间精确配准。不能让三次独立生成的随机形状直接拼装。

先看**无发光、无后座、灰背景上的舰体+承座+炮塔**，确认不悬浮之后才加入充能和特效。空槽也应像真实安装位置，但不是每个挂点都变成醒目的大圆洞；小槽可以只露细小接口或低矮甲板加强。

### 11.3 两段可以直接填参数的提示词结构

**固定承座候选（不是武器成品）**

> 用于二维俯视舰船游戏的独立固定安装承座。严格正交俯视，无透视，图像上方为参考舰艏方向。遵循所附安装样板的外轮廓、中心转轴和接口尺度；参考舰体局部的装甲厚度、磨损密度、偏暗金属材质和克制高光。形态为【平甲板薄座/嵌入式座/舷侧支撑】，承重连接朝【指定甲板方向】，让它像舰体结构的一部分而不是摆在甲板上的圆盘。只画固定支撑和接口，不画旋转炮塔、炮管、弹药、发光、武器槽符号、尺寸文字、环境或额外舰体。交付单个部件，完整轮廓不裁边；背景按已验证的输出能力处理。

**旋转炮塔候选（不含固定承座）**

> 用于同一舰船的【小/中/大/超大型】【能量/实弹/导弹】旋转武器组件。严格正交俯视，炮口朝图像上方。以安装样板的转轴和接口轮廓为结构基准，以已认可武器家族为造型基准；配合所附舰体局部的像素尺度、金属边缘和明暗层次。武器特征为【炮管数量/供能结构/装甲外形】，保留清楚的旋转下座与实际枪口，不加入固定甲板支撑脚、不把整块装甲平台带入炮塔。无固定承座、无背景舰体、无火焰/光束/能量球、无外发光、无标签、无透视厚侧面、无强烈落地长投影。不要求用巨型底盘表示等级。交付一个组件，留出完整轮廓及后座空间；最终枢轴/枪口由作者标定，不把模型输出当精确坐标保证。

这不是可脱离样板的万能提示词。每次明确是整套外形探索还是单部件候选，不能把二者混为“生成一张就实装”。具体数值、接口图和材质图由该舰的作者数据生成交接材料。

### 11.4 本机生图能力边界

2026-09-27读取用户配置：默认本地代理`http://localhost:54654/v1`、模型`gpt-image-2.5`；仅文生图已标为验证通过，编辑/参考图控制/透明背景尚未验证。正式执行时重新读配置，不在方案中写死请求能力。

- 能用文生图先探索形态，但**没有验证图像输入能力时，不得声称模型会遵循所附样板**。
- 图像编辑/参考条件经验证后，才进入“样板+舰体局部→候选”的自动化；局部编辑不保证严格保护未编辑区域，仍要做轮廓与锚点差异检查。
- 尚不支持时保留完整提示词和样板，采用作者已有素材/人工制图完成精确装配，不静默换提供方。若要另行生图，默认一张，不把默认质量固定成low。
- 每张检查实际格式、宽高、alpha；棋盘格不等于透明。请求尺寸不是结果尺寸，生成图不可直接充当坐标真值。
- 原始生成图不覆盖；后续获准的切图/缩放须确定性导出并保留变换，不能借后处理悄悄重绘或拉伸。

## 12. 槽位怎么放：几何编辑器为主，自动建议为辅

### 12.1 编辑器必须展示“安装得下”，而不只是能点到

在现有改装视图上增设**作者安装模式**，保持玩家原改装交互不变。普通玩家不必看到所有工程覆盖层。

作者同时看到：实际舰体、固定承座、实际炮塔、转轴、底部占地、旋转包络、枪口和射界。点选实际武器可实时预览，不用只有统一大小的圆形占位符。支持平移/镜像/吸附/数值精调/撤销；调整一个挂点不能自动移动所有对称挂点。

两种吸附要区分：几何对齐吸附可到中心线/参考线；自动落在可承载甲板区域只是候选。透明度只能发现船外空白，不能理解机库门、发动机、天线或结构空洞，因此还要有人工确认的“可装区/禁装区/前景甲板”标注。

自动建议只做三件事：
1. 过滤明显悬空、越出承重区或挡住机库/喷口的候选。
2. 按已批准的槽位数量/四档预算、接口占地、左右分工和射界给候选排列。
3. 显示冲突原因并允许作者调整，不直接重写主舰JSON、删除槽位或改配装。

先布局主武器和航空/喷口禁区，再补中型交叉火力与小型近防，最后检查舰艏/主干/舰艉。顺序不是固定配比；用户批准多少槽就逐个登记，不把“看着空”当加大槽的理由，也不为了视觉清爽擅自减槽。

### 12.2 兼顾玩法，不把所有射界开成360度

- 火力覆盖图按候选武器的射程/安装方向/射界给几何估计，并分别显示前向、侧向、后向的可参与武器。它不是实际DPS、命中率或近防拦截率保证。
- 主炮排布体现舰船定位；舷侧炮应有侧向使用动机，近防应照顾引擎/机库附近。对已有船的射界或数量调整属于玩法修改，需单独批准，不伴随炮座美术修复偷偷改。
- 密集小槽不是等间距图钉阵列：把近防点做进装甲肩台、机库侧壁或尾部甲板，炮座和结构相连；但不得编造原作没有的可见武器来填空。
- 扫掠包络碰到舰桥、邻炮或前景甲板给作者警告。首版不新增炮管实体碰撞、不禁止旧合法开火、不改变自舰弹道规则。

### 12.3 坐标要闭合，而不是看图填一组数字

源PNG像素 → 已记录的裁剪/等比缩放 → 模块局部坐标 → 舰体装配坐标 → 运行世界坐标。

每次导出记录实际输入宽高、裁剪原点、枢轴、缩放和朝向基准；模块变换另行保存。以本机休伯利安为例（不是所有图片通用公式）：

`forward=(820-v)*0.5; right=(u-561)*0.5`。

反算并画回同一张实际源图核对，再导出稳定slotId的增量变更。换图/裁边/改运行尺度后必须重新验证基准，禁止沿用缩略图点击的裸坐标。槽位移动不重编号；导出展示新增/删除/移动/射界变化的差异，作者确认后才应用。

## 13. 宿主实现收敛：先做小而完整的路径

### 13.1 作者源与运行数据分开

以下是拟议字段语义，不是宿主已支持的JSON schema：

| 层 | 应有内容 | 持久化/传递规则 |
| --- | --- | --- |
| 作者工程 | 原图版本/实际尺寸、变换链、参考来源、甲板标注、安装样板、候选对比 | 不随战斗每帧传送 |
| 舰体安装定义 | 以slotId关联固定承座、安装方向、承重区/局部遮挡、接口族 | 作为版本化内容，缺失时走旧路径 |
| 武器组件定义 | body/gun/glow、各层枢轴、接口占地、枪口、后座轴 | 不能仅把PNG尺寸当武器几何 |
| 编译装配结果 | 资源引用、固定/旋转/后座变换、绘制顺序与遮挡目标 | 改装与战斗消费同一结果；资源按内容版本缓存 |
| 动态状态 | 炮塔角、后座/蓄能、禁用/摧毁、模块归属 | 优先读取已有权威状态，不另建UI私有动作计时 |

纯美术变体不得移动实际枪口；如果作者确实改变枪口或安装几何，要在配装编译阶段产生权威几何并同步给Worker，不能只在渲染器中改。

### 13.2 明确绘制规则

基础顺序是舰体→固定承座/转接件→接触暗部→旋转炮身与炮管→局部甲板前沿/装甲唇→发光；炮管在炮身上/下由组件声明，而不是全局硬编码。多个炮位需按共同层序处理，不能画完一个炮位所有层再让下个炮位的底座压住它的炮管。

遮挡必须声明作用于哪些组件：嵌入座装甲唇可以压住旋转下座，但默认不裁伸向外侧的炮管。基础版优先用明确的固定装甲前沿和小范围接触暗部；任意复杂遮罩/法线/高度场不作为首版依赖。接触暗部在已确认的甲板接收区内，不投到太空；不能把炮塔原图的强方向投影当作随炮转的接触阴影。

共用的是**装配几何和绘制清单**，不是重写整个改装UI。ShipStage保留槽位按钮与键盘交互，舰炮视觉层消费同一装配结果；战斗WebGL读取同一层序/枢轴。不同后端仍要截图核对，不能以“共用代码”代替视觉验收。

静态装配缓存键包含舰体/模块/武器/安装定义的内容版本，换装、资源更新、模块脱落和舰体换图会失效；选择/瞄准只更新动态变换。旧内容不强加底座，远距可减少阴影细节，但不能把固定座改成随炮旋转。

### 13.3 本次建议的开发顺序（细化第7节）

1. **安装样板与作者覆盖层**：先能画出锚点/占地/炮管包络、叠实际武器，镜像/撤销并导出增量。尚未需要生新图。
2. **共享安装解析+第一套接口**：选休伯利安L01、M05、S12做大中小样本；各有空座、原配炮、同档替换炮，先不改24槽数量与位置。
3. **小批美术适配**：上一步确定缺哪些固定支撑/组件，再按能力验证结果生成所需候选；不先批量重生成整舰或24个底座。
4. **改装—本地Worker战斗—残骸闭合**：旋转/后座、真实枪口、禁用与模块/残骸归属一致后再推广全舰。
5. **跨系列和XL**：用另一种材质/接口武器验证通用性；XL用独立测试夹具，不能顺便升级休伯利安大和技能或加新大槽。
6. **单舰包能力声明与完整安装**：纳入包资源/能力预检；只有依赖安装和真实运行验收后才称完整可安装包。

第一批可交付结果应是“一大一中一小，空着像座、装上像船的一部分、转动不漂、换炮不突兀”，而不是又一张不能装进游戏的美术概念图。

## 14. 新增验收门槛与返工定位

| 观察到的问题 | 先修哪里 | 不接受的掩盖办法 |
| --- | --- | --- |
| 船/炮根本不像目标，俯视体块不对 | 参考/正交结构样板 | 加细节/加辉光 |
| 转动后支撑架也一起转 | 固定/旋转组件归属 | 调暗整张图 |
| 炮塔随角度绕槽点打圈 | 枢轴与变换链 | 每个朝向单独手调偏移 |
| 炮座太大，小炮像大圆盘上的小零件 | 接口占地与转接件 | 放大武器贴图填满 |
| 预览正常，开战漂移 | 共用几何/绘制清单、模块变换 | 只修CSS |
| 枪口亮点和弹体起点分开 | 作者枪口与权威编译几何 | 把闪光图拉长 |
| 一换炮就穿模或没有机械连接 | 接口族与同档占地适配 | 为每对舰炮组合单独重画 |

每种接口至少验：空座；同档两种不同占地；跨尺寸拒装；前/左右/后或该槽射界允许的极限角；后座极值；禁用；实际1:1和正常战斗缩放。1:1指1世界单位对应1渲染像素，不是AI源图原尺寸。

记录配装与资源版本。数字变换往返应在浮点容差内一致（建议1e-6世界单位）；1:1视觉锚点与实际枪口需在约1渲染像素内对齐，低缩放另外检查是否消失/糊边。这是拟议项目验收标准，不是假称原版规定。

需有改装/战斗/重新开战与快照恢复的对应截图，模块拆落不留浮空炮座；与旧内容的基线对比确认没有强加渲染或兼容变化。性能在代表性多舰战场测前后差值，不凭空承诺特定FPS。

**本轮交付仅为方案v0.2；以上安装工具、运行接口和美术适配默认待实现，不因文档写全就标为已完成。**
