# 护盾状态切换与齐射结算缺陷修复（2026-09-17）

## 范围

本轮按“找 bug、修 bug”执行，不继续多线程实验，不更改线程配置、LAN 协议或存档格式。只修改三个运行时文件，保留正常碰撞批处理。工作区原有其他改动不回退。

## 1. 齐射中的旧护盾命中吞掉后续伤害

**问题**：`ProjectileCollisionHandler.checkShipCollisionsBatch` 先批量计算几何命中，再逐发应用伤害。第一发导致过载时，护盾已经失效，但后面的 `SHIELD` 命中仍沿用批处理前的结果。原有失效检查只处理舰船死亡或失去碰撞，不处理护盾消失。

**复现**：攻势结构 20,000，装甲格清零，护盾完全展开，硬幅能距容量仅差 1；两发伤害为 1,000 的高爆弹沿相同路径穿过护盾与舰体。

| 指标 | 修复前批处理 | 逐发参考 / 修复后批处理 |
|---|---:|---:|
| 第二发命中位置 X | 272（旧护盾） | 225（舰体） |
| 实际结构伤害 | 0 | 958.083880 |
| 剩余结构 | 20,000 | 19,041.916120 |

这是固定复现场景的伤害数据，不是所有武器的统一伤害，也不是性能提升数据。

**修复**：消费批量结果前检查护盾碰撞是否仍然有效。若旧护盾失效，用原始弹道与仍可碰撞的候选舰船重新求交。不能简单把护盾命中改成舰体命中：后续炮弹可能尚未到达舰体、擦过舰体，或应命中后方舰船。未失效的命中继续使用批处理结果。

## 2. 强制 / 指定时长过载没有立即通知关盾

**问题**：`FluxTracker.triggerOverload` 会触发 `onOverloadStarted`，但 `forceOverload` 和 `overloadFor` 不会。后两者被战备故障、Acausal Disruptor、Energy Lash 和部分舰装使用，导致已经进入过载的舰船仍可能保留开盾状态，直到后续舰船更新。

**修复**：两条入口在成功进入过载并设置时长后同样触发通知。已有过载不重复通知、不重置计时；排幅期间仍拒绝过载；强制过载不额外播放普通命中过载音效。

**验证**：三个入口均立即关盾，通知恰好一次；指定时长和过载时间倍率保持原语义，非法指定时长仍被拒绝。

## 3. 排队开盾请求绕过禁盾状态检查

**问题**：快速关盾再开盾会排队等待 0.35 秒收拢。舰船的禁盾检查只看 `isActive`，漏掉尚未生效的请求。此时启动 Burn Drive，实测第 21 步会错误将护盾状态重新置为开启，下一步才被关闭。该帧展开弧度为 0，因此本轮证据不能证明它提供了有效碰撞防护。

**修复**：禁盾系统、战备防御禁用、过载 / 排幅检查使用 `isRaiseRequested`，同时取消当前开盾和排队请求。保留正常收盾视觉与没有禁用条件时的延迟开盾行为。

**验证**：正常排队开盾仍成功；系统禁盾、CR=0、排幅、过载四种场景连续 40 步均无残留开盾请求或错误开启帧。
