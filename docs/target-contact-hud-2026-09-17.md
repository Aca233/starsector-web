# R 目标检查与悬停简报（2026-09-17）

## 用户要求

参照用户提供的原版战斗截图，补齐局内 R 目标检查；舰船幅能、结构、战备简报仅在鼠标悬停时显示，不再对全舰队常显。

## 实装行为

- 鼠标移到可见、存活、未撤退 / 停靠的舰船上，仅显示该接触的幅能、结构与战备。友舰为绿色，敌舰为橙色。移到空白、离开画布、失焦、打开菜单或战术地图时撤销悬停。
- R 锁定鼠标下可见敌舰，显示橙色菱形框、武器组 / 伤害类型 / 射击模式 / 自动开火 / 状态与有限弹药、舰名和舰型、幅能 / 结构 / 战备、距离、航速及装甲纸娃娃。所有数值来自实时舰船对象，不伪造敌舰信息。
- 鼠标移开后锁定详情仍然保留。同一目标再次按 R 取消；指向其他敌舰按 R 切换；在空白处按 R 清除。无有效鼠标位置时不再使用陈旧的瞄准坐标选目标。
- 目标详情只读，没有敌舰武器组按钮。锁定目标不重复显示另一份悬停简报；可以同时悬停另一艘舰船。
- 目标死亡、退出实时舰船列表或不可见时隐藏详情。菜单和战术地图暂时隐藏详情；关闭后仍可恢复有效锁定。
- 初始暂停 / 新舰部署后，R 使用最新世界名单，而不是等下一逻辑帧更新 `combatShips`。
- 移除了渲染器原先自动对最近敌舰绘制的红色“锁定”方框；射击提前量提示现在只使用明确的 R 锁定目标。普通敌我识别菱形不是信息简报，仍保留。
- 单机和 LAN 共用接触 HUD。LAN 仍由现有主机命令执行与快照同步，不新增协议字段。

## 实现约束

全舰队使用一个鼠标 / 名单观察循环，最多挂载一份悬停简报和一份目标详情。位置随渲染帧更新，文本按 10Hz 刷新；没有给每艘舰船增加 React 更新循环。

继续复用既有装甲纸娃娃和仪表组件。保持当前项目的可读字体，不声称已做到原版逐像素一致。目标武器表最多显示 12 项分类记录，超过时明确标出剩余数量；常规挂点通常会按同型武器合并。距离为舰船中心距，航速为当前世界速度。

窄屏下详情采用左右顶栏布局，并将雷达移到右下方避免遮住目标摘要。坐标计算区分 Canvas backing pixels 与 CSS pixels。

## 验证

- 独立真实浏览器、实际鼠标与 R / Space / Escape / Tab 按键，19 项交互场景通过。
- 100 艘舰船的暂停诊断名单：没有全舰队常亮标牌，悬停仅一份，另一个目标锁定时最多两份。此项不是 100 艘同屏战斗性能认证。
- 验证锁定、取消、切换、空白清除、友舰悬停、无重复简报、只读面板、菜单、战术地图、不可见目标、目标死亡、滚轮缩放、660px 窄屏与离开画布；无浏览器运行时错误。
- 33 项模型断言通过，包含首次逻辑帧之前的 R、陈旧 / 非有限瞄准拒绝、友敌与状态过滤、重叠目标选择、31 以上阵营可见性、9 组缩放 / 插值坐标往返、渲染提前量只认明确锁定、LAN 快照投影恢复目标。
- 没有进行多台设备联机验证；联机结论限于共用 UI 接线、类型检查和快照模型检查。
- `npm run typecheck`、`npm run lint`、`npm run build` 均通过；生产构建仅保留大分块警告。

诊断中一次 Vite 开发热重载打断了页面；最终浏览器运行在独立页面阻断开发热重载 WebSocket 后通过，不改变用户服务器或正常页面。诊断文件、结果与桌面 / 窄屏截图位于忽略目录 `artifacts/target-contact-hud-2026-09-17/`。未恢复项目测试运行器，未进行游戏资产哈希 / 大小审计。
