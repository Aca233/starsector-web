# 联机房间操作流程优化（2026-09-18）

## 面向玩家的变化
- 左侧增加开战准备进度：配装确认、敌对阵营、真人准备。显示具体等待的玩家，不必猜测开始按钮为何不可用。
- 缺少敌人时可直接「添加 AI 对手」，自动打开空的敌对队伍；各队卡片也能直接添加 AI 或加入此队。队伍标题同时显示真人与 AI 数量。
- 自己的成员卡增加明确的「更换舰船」按钮，不再要求发现可点击的缩略图。
- 客机有草稿时提供「应用并准备」，同时保留「仅应用配装」。已准备时明确提示等待房主，仍可取消准备。
- 房主独自对战 AI 且其他条件满足时提供「应用并开始」。有客机或其他阻塞条件时仅应用配装，明确说明下一步；应用会重置客机准备，不自动替其他人确认。
- 战斗规模不足时可直达房间设置。邀请、设置、聊天集中在底部，窄屏自由换行；底栏按实际高度给改装台让位，不遮住底部控件。

## 正确性与兼容
- 配装仍是本地草稿，收到匹配的 configure 回执才标记同步。另存方案仍是独立操作。
- 应用后使用最新房间广播重新检查开战条件，避免旧 React 渲染中的准备状态导致误开始。
- 准备 / 开始等待实际房间状态确认，失败不自动重试；动作失败不把已同步的配装误标为失败。
- 客机只校验自己的配装；其他人的未应用草稿不会阻止自己准备。房主开战仍校验所有参战配装。
- 连续点击保护包含快速回执后的双击，防止第一下准备、第二下立即变成取消准备。
- ready/start 的错误回传保留 requestId，以便立即把服务端拒绝反馈给发起者；无协议版本变更，但应与服务端一起更新。
- AI 编辑返回时保留目标队伍与选择；外部打开请求不会覆盖返回状态。

- `npm run typecheck`
- 对涉及文件运行 `oxlint`
- `node scripts/check-lan-room-workflow.mjs`：10 项，包含真实隔离 WebSocket 服务的权限/改装中准备拒绝、准备/取消确认、监听清理、应用后准备重置和 DP 阻塞。
- 隔离构建：`npx vite build --outDir artifacts/room-workflow-build`，保留原 dist 和现有服务。
- 独立浏览器 / 房间：客机应用并准备、取消准备、房主应用后等待客机再次准备、缺对手直达 B 队、断线保留草稿与锁定提交。

没有修改用户存档、重启现有联机服务或中断正在进行的房间。正式使用前请在没有对局时构建并重启服务，让所有玩家使用同一版本。
- 最终浏览器补充验收：80ms 间隔双击只发送 1 次 configure 和 1 次 ready；AI 修改队伍后进入改装再取消，返回仍为该队且方案保留；双人准备后实际进入战斗；独自对战 AI 的「应用并开始」实际进入战斗。
- 390×844 窄屏：底栏上缘 684.6px，改装区底部 672px，互不遮挡。1440×900 桌面与 1280×740 小屏均检查；测试过程中无 pageerror。
