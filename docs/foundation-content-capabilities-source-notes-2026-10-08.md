# 底层内容目录与能力准入

日期：2026-10-08。对应 [底层改造路线图](foundation-development-roadmap-2026-10-08.md) 第 3 项；本项实现和专项检查完成，整体类型与 Worker 验收归主任务记录。

## 目标与范围

将现有七个内置单舰包的配装都迁入同一数据目录，移除改装目录按舰体 ID 分派的兼容入口；让包预检、启动和 Worker 使用同一宿主能力判定。保留全部配装 ID、名称、武器组、投入、警告、取消/确认和启停流程。不新增技能、调整战斗数值、分发多人包，也不重写既有可信行为。

## 依据与当前差异

- 本机原版来源：Starsector 0.98a-RC8（环境版本依据见主路线图）。`../decompiled/starfarer_api_source/com/fs/starfarer/api/plugins/ShipSystemStatsScript.java` 的 `State`、`apply`、`unapply`；`../decompiled/starfarer_api_source/com/fs/starfarer/api/combat/EveryFrameCombatPlugin.java` 的 `advance`/绘制接口。它们证明既有生命周期/效果接口，不能证明 Web 包格式或我们的版本策略属于原版。
- 现有 `ShipPackValidation` 使用 `BundledShipPacks` 判断可信行为；系统、武器效果和舰装状态已分别由扩展注册表持有。能力事实应从这些注册表读取，不建立第二份“已支持技能名单”。未知能力不得仅凭包内声明获得支持。
- 七个包中荣光女王、罗西南特已有 `variants`；另五个包的配装仍在 `ExtensionVariantCatalog` 和 UI 工厂。迁移以这些工厂的实际输出为对照，不凭印象重建配装。
- 原版截图/实机此次未查看；此次不改变 UI 布局和玩家操作，不声称新增原版等价验证。

## 接口和流程

1. 七个包均在包定义提供完整配装。旧公开工厂保留为目录转接，改装与模拟器仅查询包目录。
2. 包可显式要求能力 ID、最低版本和使用范围；ABI 1 旧包未声明时从真实舰体、模块、配装、武器引用推导。能力声明只增加要求，不能抹去实际数据依赖。
3. 宿主能力版本表示该能力契约版本；来源是已编译宿主行为、系统/效果/舰装注册事实。区分战斗支持、战役未模拟和未知能力，不宣称任意 Java 插件兼容。
4. 安装预检失败不持久化；启动或 Worker 准入失败不发布新包目录。目录发布先构建完整索引，再一次替换并递增 revision。保留现有 IndexedDB revision CAS、刷新激活与多人自选包限制。
5. 不改存档结构或 ID。启停/卸载的存档引用检查、取消安装行为保持。
6. 实际旧配装证明烛渊五门近防使用 `web_sc2_hyperion_pd`。本次显式声明 `foundry.zhuyuan → foundry.hyperion >= 1.0.0`；只允许已声明且启用的依赖满足武器引用，不复制武器或改变现有配装。停用/卸载依赖包将使用已有错误区说明未满足依赖，保存前拒绝，避免刷新后出现缺武器目录。该舰目前不是无需其它包的自包含舰。

## 实施与验收

依次记录旧工厂配装输出、迁移包数据、接入共用能力准入、替换目录分支并索引查询。集中核对七包全部预检、旧新配装逐字段相等、未来/未知/缺失能力拒绝且目录 revision 不变、能力声明不能绕过实际依赖；根任务统一类型/lint 及真实 Worker 场景。未执行的检查如实记录，不包装或发布产物。

无待用户决定的玩法取舍。新能力 ABI 升级、多人包协商仍需对应后续方案。

## 实际交付与验证

- 七包 13 套配装均由 `ShipPack.variants` 驱动。五个旧 UI 工厂只保留公开兼容调用，`ExtensionVariantCatalog` 不再按舰体 ID 分派。迁移前后台记录真实工厂输出，迁移后比较全部嵌套配装；仅剔除随机设计 ID 和时间戳，其余名称、装备、投入、航空、系统、模块、组及警告逐字段相等。
- `ShipPackCapabilities` 是包预检、启动、目录发布及 Worker 准入的公共入口。系统/舰装/效果的能力版本由 `DefinitionRegistry.register(definition, capabilityVersion)` 提供；注册默认 1，显式版本用于后续受审升级。未知、未实现、未来版本及未声明支持的战役范围均拒绝。
- `ShipPackCatalog` 在 revision 变化时构造舰体、基线、配装和改装元数据索引，后续查询不再遍历所有包；只读数据冻结，失败不替换旧目录。此项减少重复查询/分配，没有帧率测量或提速倍率声明。
- 显式依赖包含最低三段版本、循环及启用检查。素材预检临时挂载尚未刷新激活的已保存依赖，成功/失败均逆序撤销；启动则按依赖顺序挂载再提交。
- 已通过 `node scripts/check-ship-pack-catalog.mjs tmp/foundation-content-before.json`：七包独立声明闭包预检、13 套旧新比较、真实编译、未知/未来/范围能力、隐藏依赖、缺失/循环依赖、失败 revision 保留；另经实际 `preflightShipPackFile` 验证依赖素材挂载成功/哈希失败均清除临时 manifest 与 blob URL，不发布运行内容。
- 日常入口：`node scripts/check-ship-pack-catalog.mjs`；迁移前快照仅为本次核对证据，日常检查不依赖该文件。首次检查因另一个工程块正在添加阶段模块而暂缺引用；模块完成后本项全部通过。
- 无桌面操作、原版实机或页面截图；包文件未打包、未提交、未发布。IndexedDB CAS 未改，本项内存预检不能替代主任务的实际浏览器/Worker 验收。
