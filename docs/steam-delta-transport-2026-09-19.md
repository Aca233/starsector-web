# Steam 无损状态差分与断线恢复（2026-09-19）

## 范围与原因

用户反馈桌面 Steam 联机延迟大后断开连接，未取得当时两端日志，不能认定这次断线只有一个原因。本轮针对已测量的真实战斗状态带宽：双野狼护卫舰状态约 31–46 KiB JSON，普通 deflate 后约 8–12 KiB。即使自适应窗口能提高帧数，64 KiB 在途字节预算仍会限制高 RTT 链路的同步率。**不加大积压、不放宽超时、不改变物理或浮点精度。**

## 传输设计

- `server/steam/snapshot-delta.mjs` 在桌面辅助进程对完整展示状态做 JSON 树差分；浏览器继续收到原有完整 `state`，物理模拟、状态采样频率、输入语义不变。
- SWSP 分片头不变；`data` 内部增加带版本的 `steam-state` 包。保存 token、基准 token、目标 UTF-8 长度及 SHA-256；严格校验重建的完整规范化 JSON。
- 可靠有序通道的“上一条成功提交给原生接口的状态”是基准；窗口跳过、字节预算拒绝、原生发送失败或部分分片发送失败均不提交基准。不同客机保持独立进度，共享同一目标状态的解析／哈希／压缩结果。
- 可发送时距上一完整帧达到 1 秒便优先发送完整关键帧；新对局、连接切换及恢复请求也强制完整状态。若差分不比完整包节省 128 字节以上则发完整包。差分封装的压缩门槛为 512 字节（只在压缩确实变小时使用），控制／输入仍使用原 4096 字节门槛。
- 差分适用上限为 512 KiB 规范化状态、65536 节点、深度 96；补丁本身也需满足解码器检查。超限原始状态走旧完整状态路径，补丁超限走完整关键帧，避免发送会被接收端拒绝的数据。
- 丢失基准时不向网页转发、也不刷新状态存活计时；回收该条消息的 ACK 信用并附加 `needsFull`。主机只接受当前连接中仍在途的对应 ACK。下一次可发送状态改为完整状态，之后恢复差分。
- 对象键顺序、删除、数组伸缩、Unicode、数值、null 均无损。`__proto__` 等字段作为普通 JSON 自有数据处理，不触发原型 setter。拒绝重复或无序数组索引、稀疏扩张、重复键列表、巨长数组、非法补丁及错误哈希。
- 各客机只保留最后一帧基准，共享编码器只保留当前准备；没有保存每一条在途消息的完整世界状态历史。既有 64 KiB 状态在途预算、8 秒保护、可靠输入队列和限流保持。

## 持久化验证

`npm run steam:check`：30 项 node:test，以及真实 gateway／codec 虚拟链路测试的 1470 条断言。新增测试无 artifacts 固件依赖，包括：

- 1200 组确定性随机树、逐字 JSON 比对、500 条演化状态的真实 SWSP 编解码、多分片完整状态；
- 基准隔离／共享准备、跳帧不提交、周期关键帧、对局切换、旧状态回退、补丁节点／深度超限回退；
- 缺失基准不转发或续命，精确释放信用，再发完整帧恢复；错误 nonce、重复和未知 `needsFull` ACK 不影响当前流；
- 状态数窗口及字节预算分别拒绝时，下一条状态仍使用最后成功发送的基准，跳帧可直接还原；
- 原生发送中途失败不得提交部分帧；恶意补丁、安全预算及原型污染回归；
- 原有浮层、输入动作 FIFO、短时停顿、自适应状态窗口、低带宽长时间模型回归全部保留。

源码 lint、TypeScript 检查通过。隔离构建保持 v0.2.1 基线，只带既有 v2 联机修复与本轮 Steam 改动；不混入工作区同时开发的舰船系统／LAN 二进制优化。

## 实际战斗录制离线回放

80 条真实游戏生成的合成双护卫舰开火状态，跨度 5268ms，经**生产版本**编码器、SWSP 分片、解码器和接收器全部精确还原：

- 原始完整包线速合计 937152 字节，新传输 272801 字节，包含分片头及 6 个周期完整帧，减少 **70.89%**；74 条使用差分。
- 本机这次回放平均编码 1.52ms、平均分片接收＋还原校验 0.81ms，非性能承诺。
- 不把研究原型的 78% 节省或小状态模型的 60Hz 直接当作发布包实战结果。
- 采集脚本后续因一方被击败而未通过其重连阶段；这里仅使用有效录制帧作带宽证据，完整生命周期另行测试。
- 报告：`artifacts/steam-delta-production-replay.json`；采样文件包含合成测试身份，不含真实用户账号。
