# 单舰自包含包规范 v0.3

初版：2026-09-26；规范更新：2026-09-28。用户澄清：**舰船包是最小可交付单位，使用一个包即可完整使用这一艘船。**

本定义替代此前“主题多舰合集优先”的规划。多舰合集可以以后组合这些包，但不是当前包的含义或前置要求。

**状态边界：2026-09-26的核查未完成完整安装/升级链路；2026-09-28本轮仅更新生产/交付规范，没有重新验收安装器，也没有生成可安装ZIP。是否可独立安装，以对应版本的实际记录为准。**

配套：[舰船生产手册](ship-creation-production-playbook.md) · [单舰任务书](ship-creation-brief-template.md) · [当前内容扩展契约](content-extension-contract.md)。

## 1. 最小单位的精确定义

> 一个单舰包 = 一艘可用整舰 + 使用它所必需的全部内容、行为、资源、合法配装及安装信息。

这里的“最小”指**完整可用的交付边界**，不是体积最小、只有一张PNG，或者每个模块都单独分包。

用户只需要兼容的游戏宿主和这个包：
- 安装后能在游戏里找到整舰。
- 能选择合法配装，正常改装、保存、撤销并进入战斗。
- 武器、模块、系统、舰装、航空与特效按包声明完整工作。
- AI和实际Worker运行正常，而不是只在主页面或静态预览中存在。
- 不需要额外寻找未声明的武器包/航空包，不手改配置或源码，不从开发者Temp目录取文件。

一包可以含很多内部实体。例如荣光女王的核心、8个模块、3种飞机都属于同一主舰的完整依赖；这不意味着它是12艘独立主力舰的合集。

## 2. 包里必须收齐什么

只包含本舰需要的内容，没有航空的船不强制附带飞机，没有模块的船不强制做模块系统。

| 内容 | 完整交付要求 |
| --- | --- |
| 舰体与模块 | 规格、结构关系、碰撞/中心、挂点、引擎、盾几何、身份文本 |
| 武器 | 默认/承诺配装所需的定义、素材、效果与真实弹药行为 |
| 舰船系统 | 规则、生命周期、AI策略、反馈以及受支持的行为实现 |
| 舰装 | 实际内置、可选改造、适用性、成本、互斥和恢复规则 |
| 航空（若有） | 每型机体/可辨改装、炮口/喷口标定、对应攻击与推进资源、机载武器、LPC/OP、角色AI、返航/装填/战损流程 |
| 配装与目录 | 至少一个可直接作战的合法默认方案、改装元数据、承诺的分支方案 |
| 运行资源 | 舰体/模块/安装层/武器/航空、必要姿态与匹配战损层、图标/声音/效果资源及校验清单 |
| 接入信息 | 内容索引、行为/引擎兼容要求、文本、资源路径、版本与稳定ID |
| 交付资料 | 操作说明、已知限制、来源/许可、升级策略、对应验收记录 |

可编辑原图、几何标定源、导出脚本和行为源码另保留在开发源包中。运行包不必带开发工具、测试bundle或整个游戏。

每艘船的开发记录先包含 P0-R 原作查图档案：作品/版本、来源页面与图片索引、实际看图记录、玩家确认的多图参考组及各图用途、识别特征与未知项。开发源包附记录；只在许可允许时附参考图本身。运行包只带获准分发的运行资产及必要署名，不因“自包含”把未获授权的官方/同人参考图片也装进去。图像生成或风格转换本身不等于获得原作 IP 的分发许可。

## 3. 自包含与宿主的边界

“自包含”不等于把游戏引擎也塞进每艘船里。

- 游戏宿主提供通用战斗、物理、改装、渲染、Worker、注册及受支持的扩展接口。
- 本舰特有的数据、素材和行为实现随包提供，并通过宿主认可的机制加载。
- 如依赖宿主已有的原版武器/资源或公共能力，必须声明准确的兼容范围并在安装前检查；这不是让用户再找一个未知包。
- 首版目标是不要求用户手动安装其它舰船内容包。作者侧可以复用共享源码/工具，但应由构建与安装流程闭合运行依赖。
- 新机制超出现有扩展能力时，先补宿主接口并明确最低支持版本。不能让安装者手改引擎，也不能在缺能力时静默降级成另一种玩法。
- 新行为不能通过不受信任的JSON字符串eval执行。包内行为需要宿主支持的可信构建/审核/加载路径；在这条路径完成前只能标为开发集成包。

“完整可用”的承诺限定在**声明兼容的宿主版本与验收过的运行模式**，不承诺任意旧版本、任意其它模组组合都绝无故障。

## 4. 荣光女王首包应收齐的范围

- 主舰核心＋8个附属模块，作为一艘整舰部署。
- 6种专属舰载武器及其分层/弹药显示。
- 狂怒、雷鹰、星鹰3种机体、3种机载武器和3种LPC。
- 战列敕令，以及真实AI选舷和生命周期。
- 虚空盾、军械统合、封舱3项内置规则。
- 圣域重整、敕令供弹、近域整备3项可选舰装，保持成本与适用性。
- 既有默认、军械、航空方案；对引用的宿主原版内容明确声明。
- 所有相关运行资源、目录信息、文本与Worker/显示所需行为。

保留当前web_gloriana等内容ID和玩家旧配装。不能为了做包而重命名全部内容或强制替换用户的默认装备。

## 5. 安装必须是一个完整动作

目标流程：

**选中单舰包 → 检查版本/能力/冲突/许可与资源 → 完整激活 → 舰船出现在目录 → 选择配装开战。**

安装过程中自动处理的是包内数据、资源、行为接入和目录登记，不是让用户按README逐个编辑源码。

必须满足：
- 预检所有依赖与内容，不先装一半再发现缺飞机或技能。
- 失败不留下半艘船、占用错误ID或污染已有目录。
- 重复安装、ID冲突和不兼容给明确说明，不静默覆盖已有内容。
- 新建战斗的权威端/Worker获得同一套有效内容与行为。
- 升级保留配装；禁用/卸载遇到在用方案或活跃战斗要保护引用并明确提示。
- 如使用ZIP，检查解压路径、大小、数量与危险入口；不把压缩格式本身当执行授权。

具体清单schema与文件后缀由安装实现决定，本规范不伪造当前引擎已支持的字段。

## 6. 当前代码距离这个目标还差什么

以下为2026-09-26的核查基线，后续实现应逐项用新的验收记录更新，不把此次文档修订当作重测：
- `ModPackage`目前主要承载ships/weapons/i18n及基本身份信息。
- `installContentPack`只等待宿主资源清单并注册数据，不等于解压和挂载一个完整独立包。
- `ContentRegistry.registerPack`有舰体/武器的整体校验注册，但没有据此证明资产、行为、LPC、配装目录等跨层安装已经闭合。
- 荣光女王当前依靠项目内的内容、扩展、资源和改装接线；这些需要收敛为受支持的包接入路径。

因此不能把现有文件直接压成ZIP后声称“一个包即可完美使用”。

## 7. 实施顺序

1. **收齐单舰依赖**：以荣光女王为第一份完整样本，列清包内内容与宿主依赖。
2. **建立唯一包入口**：完整接入规格、行为、资源、改装与配装，保留当前ID和玩法。
3. **实现完整安装动作**：检查、资源挂载、行为加载、激活与失败不留半成品。
4. **接通实际运行**：新战斗、Worker、保存和声明支持的显示/联机路径。
5. **在干净兼容宿主验收**：只安装此包，完成找船→改装→保存→战斗→重开。
6. **生成单舰交付物**：完整通过才标“可安装单舰包”；开发源包与运行包区分，公开发布需另获授权。
7. **第二艘复用同一包规范**：独立成为另一个完整最小单位；共享开发工具不等于用户必须先装第一艘。

多舰合集只是在这些独立包之上的可选组合层，本轮不先开发主题舰队合集或工坊界面。

## 8. 单舰包完成清单

以下默认未完成，不因源码中的船可玩而自动通过。

- [ ] 包身份、版本、主舰ID及全部内容/资源依赖明确。
- [ ] 干净的兼容宿主，仅安装本包即可找到主舰。
- [ ] 无需额外手动找武器/飞机/技能包，无需修改源码。
- [ ] 模块、武器、技能、舰装、航空和特效完整可用。
- [ ] 默认合法配装、改装、保存/撤销、新战斗与重开正常。
- [ ] 真实AI与Worker通过，不只数据导入或静态预览通过。
- [ ] 错误包、缺依赖、冲突、重复安装不留下半成品。
- [ ] 升级/禁用/卸载保护现有配装与在用引用。
- [ ] 多人、性能、长期平衡分别有明确支持/未验证范围。
- [ ] 来源、许可、使用说明、开发源与运行内容的交付边界清楚。
- [ ] 若要公开分发，获得相应发布授权。

## 补充约定：四档武器尺寸

2026-09-26：用户确认尺寸扩为小/中/大/超大型，序列化值为 `SMALL` / `MEDIUM` / `LARGE` / `EXTRA_LARGE`，第四档标记IV。单舰包中的舰体槽位和武器尺寸须匹配统一规则，2026-09-27更新为严格同尺寸安装、同档可换不同武器，仍受类型限制；不得把尺寸当强化等级或自动加伤害倍率。非技能专用XL武器须显式声明有限且至少为1的OP。

包含XL内容的包必须在最终能力协商方案中声明需要第四档宿主支持；未知尺寸应拒绝，不可降成小型或悄悄转为大型。能力字段和安装器尚未冻结，此处不虚构已存在的manifest字段。新档不迁移旧配装，不把休伯利安大和技能自动改成可换装武器。

第四档历史验收见 [四档尺寸来源与验收记录](four-tier-weapons-source-notes.md)，2026-09-27新规则及本轮验证以 [严格尺寸记录](strict-weapon-slot-sizes-source-notes.md) 为准；尺寸通路验收不等于舰船包安装器交付。下一艘船如采用XL，仍需完成武器数值、美术/安装结构、默认配装、保存读回、真实战斗和包依赖验收。

## v0.3 制作闭包与交付门槛（2026-09-28）

配套生产以[手册v1.2](ship-creation-production-playbook.md)及[每舰任务书16–20节](ship-creation-brief-template.md)为准。下表是清点/验收要求，**不是新增的包schema或已完成的加载功能**。

| 制作内容 | 必须闭合的运行引用 | 对应硬门槛 |
| --- | --- | --- |
| 四档安装档案 | S/M/L/XL、类型、固定/旋转、可换/绑定、承座/前景、炮口 | 同档换装；内置位可识别，不允许借“隐藏”漏掉真武器或动画 |
| 动态舰体/模块 | 当前姿态、层所有者、深度、挂点、战损、相关状态 | 正常/旋转/受损/失段不漂移；若宿主不支持动态物理挂点，明确拒绝该声明 |
| 推进 | 每个主/辅喷口，或无外喷的原生场推进声明及所需资源 | 不强制喷气，不烘焙尾焰，不叠重复拖尾；实际推力与失效可观察 |
| 武器反馈 | 蓄能/发射/飞行/命中、图标、声音、真实事件与坐标 | 弹体不随发射后的母舰移动；束端不伪造命中；机载与舰载按实际尺寸区分 |
| 系统/插件 | 主动状态与消耗，内置/可选规则、OP、互斥、图标及反馈 | 不是说明文本或效果演示；准备、退出、失效、卸下清理均成立 |
| 航空 | 每型外观/标定、LPC、武器、弹药、AI、返航与补机、效果 | 不因同名模板共用一切；母舰未预加载或机体重建后也不缺图 |
| 原版/公共能力 | 准确的宿主资源与行为依赖、兼容范围、许可 | 不把原版素材冒称原创；不能静默替换；不能让玩家先装另一艘船才能生效 |

资源清单记录真实文件尺寸、格式、字节数/校验值与路径，并验证被真实执行的预加载路径消费；仅有清单不等于宿主已经强制验证hash。开发源包保留模型/原图/提示词/标定/导出脚本，运行包只带必要且可合法分发的资源。密钥、个人绝对路径、未授权参考图、浏览器测试脚本和高分辨率开发母版不因“自包含”自动进运行包。

追加完成项（默认未验证）：
- [ ] 关闭效果后，舰体、承座、炮头/飞机在正常缩放下仍协调；不是临时占位。
- [ ] 旋转、活动部件、模块受损与单段消失的当前姿态正确。
- [ ] 实际发射/推进位置、状态时序、命中及退出检查通过。
- [ ] 航空按每型而非仅整舰汇总检查；独立资源闭包、返航重装和失库处理通过。
- [ ] 包内每个引用明确属于本包或已声明宿主，无跨舰隐性预载依赖。
- [ ] 干净兼容宿主从安装到真实Worker新战斗、保存重开完整通过；缺能力不降级成另一种玩法。
- [ ] 证据区分受控搭景、真实Worker、自然实战、原版实机和多人；不能以截图或压缩包存在代替验证。

未完成最后的独立安装验证时，可以交付有明确范围的**工程集成版及开发源档案**，但不能承诺“下载一个包便能完美使用”。多舰合集继续是独立单舰包之上的组合，不改变最小交付单位。
