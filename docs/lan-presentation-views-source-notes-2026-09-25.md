# LAN 呈现视图边界：修改前记录（2026-09-25）

## 范围与依据
这是一项默认 LAN 接收端的所有权/分配优化，不改玩法、布局、按键、回执、播放频率或画面精度。沿用已经核实的 HUD/战术地图/部署视图和 `applyTacticalViewCommand` 的观察者权限：只允许关闭地图、选择友舰，不允许下达权威战术命令。原版源码/界面依据沿用相关功能原有 source-notes；本轮没有新的原版实机证据，不声称新增原版等价性。

当前 `LanBattle.tsx` 的 React state 直接保存 `LanDisplayWorld`，HUD、地图、部署、席位计数、暂停菜单都可接触完整战场。完整接收/渲染 Worker 尚不能安全接管该依赖。新边界只公开现有 HUD/map/deployment 视图以及观察者命令，不伪造 Ship，也不把整份恢复世界发回主线程。主线程仍拥有默认渲染，这一阶段不能当作完整 Worker 切换完成。

## 等价与所有权
- React 只持有明确的呈现端口；显示世界仍留在原有 imperative 生命周期内。端口在退出时关闭，旧的 UI 命令不能操作失效战场。
- HUD 维持原先每微任务快照、RAF 按需读取的频率，不改成 100ms 定时快照。
- 只针对 LAN 自有、同步、无扩展回调的 display records，在一次 HUD capture 内去重同一 ship 的投影；不跨 capture 缓存状态。通用 CombatHudProjector 默认保持逐次读取，authority/扩展对象行为不变。
- 所有独特 ship/target、武器、系统、装甲、声效环、部署与阵营计数保留；重复数组槽位仍保留，身份别名不变。元数据保持原引用，不称作跨线程可变元数据 codec。
- 接收、输入 ACK、镜头跟随、播放与特效阶段顺序完全不动；不开启输入事件测试夹具。

## 验证计划
扩展既有 Offscreen 场景验证新旧 HUD 完整值/别名、地图/部署/阵营输出、观察者命令与生命周期；HUD 分配工作用同一真实 LAN display world 交替配对计时，结果不等于端到端输入延迟。集中 typecheck、改动文件 lint、既有真实双端 LAN + 重连场景。保留原始 JSON，不以接口抽离本身宣称加速或全项目完成。
