# Starsector Web 战斗运行时目标架构与迁移方案

日期：2026-09-21。状态：**目标架构提案；运行时核心已部分实施，整体尚未完成。**

> 实施进度更新：运行时权威/宿主事务、共用 AI 池与借用呈现入口已接入，详见 [实施记录](runtime-architecture-implementation-2026-09-21.md)。LocalWorkerHost / detached 呈现已有后续实现，但默认接入、严格 RenderFrame、StateStore 等目标仍未完成；不能把本提案整体标为已实现。

> 后续进展：已建立真实 LocalWorkerHost 与 detached 呈现兼容链路，并迁移正式玩家输入入口；呈现协议已推进到 Float64 记录级增量（不是严格只读 DTO/StateStore），见 [单机 Worker 纵向迁移记录](local-worker-runtime-2026-09-21.md)。百舰桥接成本仍未过关，普通战斗没有默认切换；StateStore、完整检查点、全部 UI/战役命令写入仍未完成。

## 0. 架构结论

采用 **数据导向的混合状态存储 + 单一权威调度器 + 有序结算 + 通用纯计算任务池 + 分阶段空间查询服务 + 只读呈现投影**。

这不是“所有船一起算、一起写”，不是为每艘船创建一个 Worker，也不是重写成 ECS/WASM 就自动变快。目标是先消除不必要工作和对象搬运，再并行真正独立的工作，最后处理仍占热点的数值内核。

硬约束：

- 不减少实体、特效、分辨率或模拟/AI 更新频率来伪装优化。
- 默认兼容现有战斗的更新顺序、数值、随机流与存档边界；修正原版还原差异另立任务，不与性能重构混在一起。
- 主机/服务端保持唯一伤害、弹药、生成、销毁、终局权威。
- 不能把 render FPS、实际模拟 TPS、网络接收 Hz、输入执行确认和状态年龄混为一个“60”。
- 保留现有多核、空间索引、网络直通、渲染上传及生涯工作；用适配器逐步迁移，而不是并行维护第二套完整引擎。
- 不保证任意硬件、无限舰船、任意模组、任意网络都能满帧；必须定义可验收的性能范围。

## 2. 目标拓扑

```text
React / GameSession / 输入 / UI / 战斗结算入口
           │ 有序命令                         ↑ RenderFrame + HudState
           ▼                                  │
    CombatHost 适配层 ─────────────────────────┤
      LocalWorkerHost / RemoteAuthorityHost / InlineFallbackHost
           │                                  │
           ▼                                  │
    CombatAuthority（唯一权威写者）─────────────┘
      ├─ Fixed-step clock / 命令边界 / Semantic schedule
      ├─ StateStore + 内容注册表 + 版本/变更日志
      ├─ QueryWorld / 分阶段空间索引与派生数据
      ├─ JobGraph / 纯计算任务调度
      │       └─ 常驻计算 Worker 池（读已发布状态，写独占结果区）
      ├─ OrderedCommit / RNG / 伤害 / 生成 / 销毁 / 终局
      └─ 投影：RenderFrame / ReplicationFrame / ReplayCheckpoint
                         │
                         ├─ 浏览器呈现：先保留主线程 WebGL2
                         │                └─ 可选 OffscreenCanvas Worker
                         └─ I/O/Codec Worker → LAN / Steam / 服务端传输
```

- 浏览器单机：目标是 CombatAuthority 在专用 Worker，UI 不执行战斗热循环。
- 联机：浏览器房主或 Node authority 是唯一权威；客机运行显示/受约束预测，不偷偷运行第二套伤害权威。
- 同一 CombatKernel 被不同 Host 使用；环境适配只提供时钟、通信、资源句柄和诊断，不复制规则实现。内核不依赖 DOM、Canvas、AudioContext、React 或浏览器存储；现有声音/视觉回调逐步改为提交后的事件端口。声音与事件必须带身份/游标，防重放、丢帧与切局误播，不能靠每份显示快照重复触发。
- 先复用现有 renderer，再按测量决定是否独立 Render Worker。模拟挪出 UI 能减少卡界面，但**不会自动缩短每个模拟步**；必须同时报告状态年龄和真实 TPS。
- 不支持 Worker 时用相同内核内联执行；无 SAB 但有 Worker 时使用可转移缓冲协议，是否净赚由测量决定。

## 3. 状态所有权与数据布局

### 3.1 混合存储，不是宗教式“全 ECS”

| 数据 | 目标存储 | 理由 |
| --- | --- | --- |
| 坐标、速度、朝向、护盾/幅能热点标量、挂点计时、弹丸运动 | 分块 TypedArray，兼容路径使用 Float64 | 连续遍历、可复用缓冲、跨线程协议清晰，避免偷降 JS Number 精度 |
| 实体/组件引用 | 稳定 handle：slot + generation；另有逻辑 ID 与原始顺序号 | 防止销毁复用后的旧结果写入新实体；物理紧凑排列不能改变处理顺序 |
| 船体定义、武器定义、几何和资源元数据 | 版本化、审计后的不可变内容表 | 各 realm 初始化/变更时发布，不每步传递整个 ShipSpec |
| 装配、技能与派生属性 | 编译后的只读配置 + 明确版本依赖 | 把可缓存的计算移出重复调用链，而非无条件冻结现有可变 WeaponSpec |
| 脚本、低频复杂状态、少见系统 | 冷对象区，受权限控制的读写入口 | 不强迫所有功能迁为列存；兼容扩展并限制热路径负担 |
| AI/火控 tracker、各级 RNG、下一次扫描时间 | 显式私有状态 schema | 能重放、比较、迁移，不依赖遍历对象猜测 WeakMap 内部状态 |

保留 `Ship` 等外观 API 作为迁移期 façade，但同一字段只能有一个真值来源：已迁字段由 StateStore 持有，旧对象方法通过适配器读取；不能让对象和列存各自写入后整帧相互覆盖。

内存分块扩容并设置上限和诊断；不用单个超大数组频繁复制，也不以容量上限静默拒绝应生成的实体。swap-remove 只影响物理存储，原迭代/平局/结算顺序由独立 ordinal 保留。

### 3.2 变更与派生缓存

至少区分：content、loadout、behavior、membership/topology、transform、shield、status、team/visibility 等版本域。

例：有效射程的缓存依赖包括装配、技能、ECM/系统等实际输入；亲属模块共享状态须带关系与依赖版本，不能只看本舰字段。绝不把时间函数、外部回调或未知依赖当成纯静态值。

资格审计迁移分两步：

1. 官方行为注册、内容载入/改装、热更新边界建立能力描述与版本；变更只通过可追踪写入口。
2. 审计所有相关写入口后，热路径才可以用整数版本替代深反射和逐字段资格检查。仍允许绕过入口直接修改对象的旧扩展必须保留保守路径。

“模组声明自己是 pure”不是可信证明。第一批并行能力只开放给内置已审计实现；任意 JS 全局副作用仍可能迫使整个相关阶段串行。

## 4. 最重要的约束：先固定语义，再拆任务

### 4.1 不用全帧快照偷偷改变规则

现有逻辑可能让 B 看见 A 刚刚更新的护盾/位置，同时看见 C 尚未更新的状态。这是当前可观察语义，不能用所有船的帧初快照替换。

为每个真实稳定窗口引入 `SemanticCursor`：tick、当前原始阶段、原始 actor ordinal、局部操作序号。它描述旧程序已有顺序，不给旧逻辑重新排序。

QueryWorld 以这个窗口/版本为生命周期。前一艘更新坐标或护盾，相关索引即更新或失效；名单则按原本的捕获时点固定。`fireControlWorld` 在发射前捕获的导弹名单不能因为新统一索引看到新弹丸而悄悄扩大。

原生副作用仍在原来的逻辑点执行：系统激活、排幅、发射、伤害、连锁爆炸及死亡不能统一拖到帧尾。OrderedCommit 并不等于“所有副作用最后才提交”。

### 4.2 三种执行类型

| 类型 | 执行方式 | 例子/限制 |
| --- | --- | --- |
| 已证明独立的纯计算 | 同一已发布只读版本上批量并行 | 保守空间候选、相同窗口内的无副作用几何预计算；仍由原窄相与原顺序判定 |
| 存在有限依赖的推测任务 | 计算结果携带完整依赖证明，在原提交点验证；无效则同步重算 | AI 决策等；必须统计重算率和总耗时，不能只统计 worker kernel |
| 任意副作用/未知依赖/真正有序依赖 | 在权威原位置执行，建立依赖屏障 | 外部模组、跨舰系统、连锁伤害及无法证明独立的随机调用 |

依赖证明包括“没有查到对象”这类否定事实：新生成/进入查询区域的敌舰、阵营/可见性变化，也会使结果失效。只记录最终目标 ID 或命中候选是不完整的。

优先用版本域、查询区域覆盖和结构变更日志表达依赖，避免记录每次普通属性读取生成海量 read-set。证明成本超过计算收益时回串行。

**不把全 AI 推测并行作为唯一加速来源。** 密集战或全球系统效果可能让大部分推测失效，此时应停止浪费推测算力，保留数据布局和索引带来的收益。

### 4.3 随机与数值

- 不改变现有 RNG 的状态、调用次数、调用顺序；不得为方便多核自动改成“每舰按 ID 单独随机”。
- 已有独立实体随机状态可以在独占任务内使用；共享或有副作用的随机调用在权威顺序点完成，或采用经证明完全一致的专用协议。不能预分配一个猜测的随机数量。
- 不因 SIMD、reduce、并行聚合而改变浮点加法顺序。不能把近似误差说成严格等价。
- 阶段版本、实体 generation、内容版本、战局 ID 不匹配时，结果一律拒绝。
- 同一运行时的确定性回放，不代表不同浏览器/JS/WASM/CPU 的 bit-exact lockstep。跨运行时确定性未证明前继续服务端权威复制。

如果未来选择“所有 AI 看统一帧快照”的新规则，可以作为独立、显式授权的 Ruleset V2 研究，不能作为默认性能修复上线。

## 5. 空间查询：统一服务，不是一个万能网格

统一接口和生命周期，保留按用途选择的数据结构：

| 查询对象 | 优先方案 | 正确性要求 |
| --- | --- | --- |
| 小行星/静态地形 | 可复用 BVH 或静态网格 | 变更/销毁更新；保留原几何 |
| 舰体/护盾 | 动态网格或动态 AABB 树；巨型实体单独处理 | 包围真实轮廓及偏移护盾；按当前语义窗口更新 |
| 弹丸/导弹 | 运动包围盒与线段查询、分类型候选 | 连续运动和原碰撞时点，不改碰撞类规则 |
| 友军挡枪 | 带速度范围的运动 BVH/分阶段投影 | 包围完整充能延迟与接触窗口，原窄相兜底 |
| 导航/威胁 | 空间候选 + 有限范围/预测窗口的保守包络 | 覆盖射程修正、炮口偏移、接近速度、制导与全局效果 |

具体规则：

- 一次查询收集实际触及的 ID，用 generation/visit stamp 去重，再按原 roster ordinal 恢复顺序；不要为恢复顺序固定扫描全舰队。稠密候选时可选择线性遍历，比较总成本。
- 长线段可用保守网格遍历减少空格扫描；宽度/巨大 hull 的覆盖必须完整，不能只走中心线。
- 超大实体避免向数千格重复插入；采用独立集合/层级结构并合并有序候选。
- 新旧索引共存期通过适配器共享几何与标识协议，不强迫威胁、碰撞、火控共用一个会过期的查询快照。
- 缓存的是候选、受支持的纯派生量和不可变几何，不是跨阶段的最终“会不会命中”。
- 非有限数据或无法证明边界时保守放行，精确算法作最终决定。

目标是从反复 O(N) 扫描趋向索引查询加候选规模，而不是保证所有情况 O(N)。全舰团在一处互相作用时，真实相互作用仍可能接近 O(N²)。

## 6. 多核：按行为能力与计算批次，不按舰名

### 6.1 能力模型

行为注册项描述 kernel ID/version、读取域、允许写入的局部字段、所需邻域查询和可能副作用。Worker 使用同一受版本约束的实现，不接受随网络传来的可执行函数。

推广顺序：纯几何/候选内核 → 常规舰船 AI 组合 → 相位/护盾等内置系统组合 → 航母/战机依赖组 → 模块舰依赖组 → 自定义扩展。

航母/甲板与模块共享状态不能简单按实体均分。可将强关联组件分成调度组，但“组”只帮助所有权/调度，不自动允许组之间无序更新。

### 6.2 调度与净收益

- 一个宿主统一管理 CPU 预算，避免 AI、编码、资源解码、渲染各自启动一套占满核数的池。
- 持久 worker；粗粒度批次；复用输入、输出、索引和内容表；不每舰每挂点 postMessage，也不每个 worker 构造一份完整世界。
- `hardwareConcurrency` 仅作提示；在真实设备上比较 0/2/4/... worker 的总耗时。少船内联，大场景再派发，调度策略有滞回，避免每帧抖动。
- 按实际任务成本而非船数均分，同时通过结果序号保持提交顺序。
- 并行收益必须扣除 pack/publish、worker sync、等待、验证、merge、重算和额外内存成本。

只让调度策略影响“在哪算”，不能影响“算什么、随机怎么走、按什么顺序生效”。无法保持这一点的负载均衡不属于兼容优化。

成本模型以任务图的关键路径为准：准备/发布 + 不重叠的任务关键路径 + 验证/有序结算 + 重算 + 输出投影。已经与 Worker 重叠的主线程工作不能再加一遍，所有核的 CPU 总时间另列。以 Amdahl 定律举例：若只有 70% 耗时可并行，4 核且零通信开销的理论上限也仅约 2.1 倍；70% 是说明用假设，不是本项目测量结果。这说明达到实时预算必须同时减少总工作量，不能保证加核即达到百舰 60 TPS。

## 7. 线程通信与故障协议

### 7.1 发布状态

- 每个发布页有战局 generation、tick/epoch、内容版本和原子发布序号；未完成写入的页不能被读者看见。
- SAB 只用于协议化的数值页，不代表跨线程共享 JS 对象。
- Float64 值由发布屏障保护，不能在读者仍使用时修改；不假设普通 Float64 并发读写天然安全。
- 输入页/结果页有明确租约或引用状态。两/三缓冲只是容量选择，**没有读者释放协议的“三缓冲”仍有竞态**。
- 无 SAB 时用池化 Transferable ArrayBuffer；转移后原持有者不能继续读。记录真实复制/上传字节，不声称全链路零拷贝。

### 7.2 结果提交与取消

任务标识包含 match、generation、epoch、job ID、kernel version；worker 只写自己的输出分区。权威端按原有语义序号读取并且最多提交一次。

部署、切换战局、暂停、销毁、worker 异常、超时均有显式状态机。超时后同步重算时，旧结果迟到只能丢弃，不能第二次提交。旧 writer 尚未停止前不得复用它正在写的结果页；超时页隔离，必要时终止并重建 worker。

权威端同时拥有未来相关的 AI 私有状态和 RNG 真值。Worker 中的持久镜像只是带版本的缓存：推测修改写入隔离的 delta/临时状态，只有权威接受后才能成为下一任务的基线；被拒绝或取消时丢弃/恢复，并从已提交版本同步。不能让一次未提交推测永久推进 Worker 的扫描计时或随机流。

UI 线程不 Atomics.wait，不忙等。阻塞等待即使放在 authority worker 也不能饿死它的命令入口；使用异步完成协议或明确的专用计算 worker。

### 7.3 背压

- 模拟命令、伤害、生成/销毁、终局等不可丢，必须有界排队、流控与显式失败/恢复，不能无限积累。
- 渲染帧可以 latest-wins：没有空闲页时不发布本次显示投影，**不跳过模拟 tick**。上一帧的视觉事件不能随显示页丢失。
- 输入按 tick/序号进入权威；按键边沿和已接受命令不能因为合并“最新输入”而丢失。任何合并必须符合既有输入采样语义。
- 过载须暴露真实 backlog、state age、时间裁剪和处理能力。窗口失焦/后台节流策略与前台性能分开记录，不擅自改变暂停规则。

## 8. 渲染与模拟真正解耦

### 8.1 三种投影不得混用

1. `RenderFrame`：只读的显示数据、前后变换、资源句柄、显示状态和视觉事件游标；不是完整模拟世界。
2. `ReplicationFrame`：权威协议需要的状态/变更/事件，保留既定精度及确认语义。
3. `ReplayCheckpoint`：恢复未来行为所需的完整权威状态，包括 AI、火控、计时、RNG、模块关系和待执行命令；现有呈现快照不能冒充它。

ICombatRenderer 逐步从 `render(engine, ...)` 迁到 `render(frame, assets, ...)`。renderer 不读取可变 Ship/AI 实例，不参与决定伤害；React 订阅轻量 HudState，不逐帧遍历整个战场对象树。

### 8.2 保画质的优化

- 稳定的资源句柄、批量实例数据、复用几何和 staging buffer；尽量只更新变更区域。
- 视口剔除只用于不会贡献当前图像的显示项，不能剔除其模拟；光照/阴影/屏幕外扩散效果须扩展边界。
- 分材质/纹理批处理必须保持半透明覆盖顺序；不将“所有普通混合后画所有加法混合”当作等价优化。
- 图集/纹理数组必须验证采样、mipmap、边缘 bleed 与颜色空间；不靠降采样制造收益。
- GPU 计时异步取值，生产不 gl.finish。现有离线 gl.finish 配对测试不是生产实现建议。
- Shader 驱动的装饰性粒子运动仅在保留既定视觉时间/随机规则并完成图像验收后采用；不把权威碰撞迁到非确定 GPU 浮点模拟。
- OffscreenCanvas 是可选优化；若多一次数据复制或不同浏览器兼容性抵消收益，就保留主线程 WebGL2。WebGPU 不是首轮重构前提。

渲染可插值，但必须报告呈现的权威状态年龄。显示顺滑不意味着模拟追上实时时钟。

## 9. 单机、联机与服务端统一内核

保留 GameSession / CombatHandoff / 持久状态边界。战斗内核不能自行写生涯存档，终局仍按战局 ID 幂等结算；本提案不将未完成生涯内容变成发布范围。

本地 Host 发命令到本地 Authority；远程 Host 发到房主/服务端 Authority。玩法实现相同，时钟、网络、认证/权限和资源加载由适配层提供。

复用现有 Authority I/O 直通及网络分层工作：

- 输入通道、可靠结构/关键事件、状态/运动投影分开管理背压，但共享战局生命周期与实体 generation。
- 收到、验证接受、执行提交、发送成功、远端消费是不同确认，诊断不得混用。
- 静态定义/装配只在内容版本变化时发送；稳定弹道/视觉事件可按已验证协议精确重建，不能假定所有制导/系统/模组都适用同一预测模型。
- 慢客机不拖住权威固定步；保持有界状态发送及重同步机制，不能通过假 ACK 释放信用。
- 不默降已有网络字段精度或约定发送频率。若希望用更低世界同步 Hz 换更低带宽，必须另列协议与产品决定，不能将显示 60 FPS 冒充 60 个新完整权威状态。
- 跨浏览器确定性未证明，不改成 lockstep。主机权威与客户端视觉预测继续分离。

## 10. 可观察性与性能目标

### 10.1 必须有的真实指标

- 生产完整 tick 的 P50/P95/P99、AI/火控/物理/弹丸/效果/提交分段；实际 TPS 与 sim-seconds / foreground-wall-seconds。
- pack/publish、同步、最慢 worker、等待、验证、merge、重算时间；并行覆盖比例按**串行时间权重**计算，而非只数“支持多少舰种”。
- 各类查询次数、候选数、精确次数、索引更新成本；资格审计成本、缓存命中/失效原因。
- 持久与峰值内存、每 tick 分配量、GC 暂停、复制字节与 worker 重建次数。
- render preparation、CPU 提交、GPU 时间、draw calls、上传字节、实际 rAF 间隔与 state age。
- 输入本地采样→权威执行、执行 ACK、网络状态年龄/Hz/丢包/基线恢复。
- fallback 原因码和占用时间：unsupported kernel、dirty dependency、global effect、worker timeout、no SAB 等。不能仅看 enabled=true。

指标采集使用预分配环形缓冲与可控采样率；详细 trace 为诊断模式，不能让 profiler 本身成为热路径。

### 10.2 建议的目标，不是未经测量的承诺

先指定参考设备、浏览器/图形后端、分辨率、舰种/装配、舰载机/弹丸峰值和运行时长，再谈“百舰 60 帧”。

| 项目 | 建议验收目标 |
| --- | --- |
| 基础实时模拟 | 60 Hz 固定 dt；目标场景持续实际 TPS 接近 60，前台不靠裁剪时间达标 |
| 模拟预算 | 目标场景完整 tick P95 ≤16.67ms，工程争取约 12ms 留余量；P99、积压和长时间平均也必须报告 |
| 基础显示 | 1440p 原画质 60 FPS 的真实生产帧节奏，P95 尽量 ≤16.67ms；CPU/GPU 并行预算分别核算 |
| 输入与显示新鲜度 | 单机目标输入到执行 P95 ≤2 个模拟步，并报告呈现状态年龄；网络目标另按 RTT/抖动制定 |
| 高频显示 | 120/144/180 Hz 是独立等级，分别需要 8.33/6.94/5.56ms 显示预算；不是完成 60 Hz 后自然保证 |
| 内存与稳定性 | 有上限、无持续泄漏、无无界结果/快照队列；30 分钟重载与反复开关局验证 |

当前百舰数据离这些目标还有明显差距。不能从局部查询下降比例推导所需加速已经成立。如果严格有序部分已超过预算，应诚实收窄支持范围或继续减少工作量，不将其藏在插值、时间裁剪或自动降频里。

## 11. 验证矩阵与合入门槛

### 11.1 行为与生命周期

- 默认 Onslaught 不再是唯一基准：标准舰、相位舰、前盾/全向盾、航母与战机、模块站、无人机、导弹/光束/近炸/连锁爆炸、临时 modifiers/自定义回调。
- 10/20/50/100/200 主舰级别另记录实际舰载机/模块/弹丸/挂点总数，避免只用“船数”掩盖负载差别。
- 稀疏/密集、命令切换、暂停/恢复、部署/撤退、销毁/槽复用、终局、重连、热更新与 worker 崩溃/迟到。
- 与冻结基线逐 tick/语义边界比较完整未来相关状态，包含原先 WeakMap 中的 tracker、计时器、RNG；失败定位第一个不同阶段与字段，不只比最终胜负。
- 粗筛随机/边界测试要求保留全部精确接触与原候选顺序；包括延迟、移动、偏移盾、超碰撞半径轮廓、极端数值和负零/非有限输入。
- 原版相关玩法与 UI 如后续发生变化，先补原版源码/资源/实机证据；当前桌面禁操作要求保持。

### 11.2 性能

- 必须包括当前正常 `fixedUpdateScheduled` / 多核 / rAF 生产链路、联机真实权威链路；手动固定步脚本只用于隔离归因。
- 比较旧实现、新布局同内核 0 worker、新布局 N worker，分开布局收益与并行收益。
- 成对重复测试、交替/随机顺序、A/A 噪声校准、预热、长局与冷启动；不在本任务构建/高负载测试同时计时。
- 报告完整时延、总 CPU、GPU、内存、能耗代理指标与 P95/P99；线程数更多而总体更慢的配置淘汰。
- 对效果小于环境噪声的改动，不宣布稳定加速。关键场景回归即阻止默认启用；功能旗标不能变成永久放置失败优化的借口。
- 多人网络需要独立客户端与带宽/RTT/丢包矩阵；同机 loopback 或软件 GPU 结果标注限制。

无 SAB、无 OffscreenCanvas、低核心设备、支持的浏览器/桌面壳均验证正确回退。过载模式必须可观测，不用放宽断言掩盖失败。

## 12. 迁移路线与停止条件

| 阶段 | 具体交付 | 不做什么 | 通过门槛 |
| --- | --- | --- | --- |
| P0：成本与语义地图 | 生产阶段 trace、当前读写/副作用/RNG 顺序清单、混编基准、回退归因 | 不先上 ECS/WASM，不根据旧离线均值分摊当前瓶颈 | 能解释主要完整 tick 成本、回退及 UI 阻塞，建立可复现基线 |
| P1：单线程数据与查询 | 稳定 handle、逐字段 StateStore 试点、派生属性版本、QueryWorld 与有序候选收集 | 不改迭代顺序、不全量镜像世界 | 新旧完整状态一致；真实生产总耗时有超过噪声的净收益，小场景无显著回归 |
| P2：权威与呈现隔离 | CombatHost、RenderFrame/HudState 适配器、本地 Authority Worker、消息代际与缓冲租约 | 不另写 LAN 规则，不先强制 Render Worker | UI 不跑模拟热循环；输入、暂停、切局、终局正确；TPS/state age/复制成本全部合格 |
| P3：通用计算任务池 | 内置行为 kernel 注册；复用 OwnershipPool 的提交/失效原则；纯查询优先、逐类扩展 AI | 不删除安全门槛，不以舰名硬编码为长期方案 | 混编真实覆盖与净收益；旧/new-0/new-N 三方测试；超时/迟到/重算不重复提交 |
| P4：呈现与复制成本 | 批量显示数据、持久几何/上传、只读 renderer；复用现有网络 I/O/codec 边界 | 不改透明排序、不静默降网络精度/频率 | 原画质对照、完整帧和网络端到端收益、资源生命周期验证 |
| P5：剩余热点专项 | 仅将仍占主要成本且数据已连续的数值内核评估 WASM/SIMD；按收益决定 OffscreenCanvas | 不把全引擎移植语言当作绩效，不靠 GPU 权威碰撞冒险 | 包含边界通信的完整净收益、数值兼容与跨平台回退 |

阶段可以局部交错，例如先修索引 O(N) 候选恢复，同时定义呈现契约；但不同时替换内存布局、调度顺序、多线程协议和渲染后端，否则状态差异无法定位。

每阶段都有对应的关闭路径。切换只能在安全语义边界，清理未完成任务代际；不是任意时刻把活跃世界替换成一份过期快照。需要转换权威状态的回退必须先验证迁移协议，不自动丢弃当前战局或重置存档。

## 13. 第一批应实际动的地方

建议从 P0 + P1 的最小纵向切片开始，而不是“先开更多线程”：

1. 在真实 `fixedUpdateScheduled`、现有 pool 和 weapon/fire-control 阶段接低开销阶段计时，补混编与首次不同状态定位。
2. 给现有索引/候选查询统一实体标识、原顺序号和失效窗口，首先验证 `SpatialShipIndex.querySegment` 的候选收集能否摆脱全表回扫。
3. 收拢装配/系统/外部 modifier 相关写入口，给一组高频派生量建立版本依赖；证明完整后才减少 hot-path 资格反射。
4. 定义只读 `RenderFrame/HudState` 适配器，先让现有 renderer 在主线程仅消费投影，通过画面和资源回收检查，再迁移本地权威。
5. 使用这组连续数据和查询契约泛化一个内置混编计算 kernel，比较旧路径/new serial/new workers；以测量决定下一组，而不是一次性扩展所有舰种。

这五项会形成后续重构的基础。若主要收益来自减扫描和数据准备而不是并行，应保留真实有效的部分，不为了“多核架构”强行保留更慢的线程协议。

## 14. 明确不采用的捷径

- 每船一个 Worker；每个 Worker 每步复制完整 CombatEngine。
- 直接移除 Onslaught 资格限制，让不支持的数据模型也进入旧 codec。
- 一帧统一快照 + 任意并行提交，却声称完全保持旧有序语义。
- 用 Float32、改变随机流、降低 AI/物理 Hz、减少弹丸或特效掩盖性能。
- 只看 draw calls / 核数 / 单函数倍数，不测完整生产路径。
- 用 UI 很流畅证明模拟实时；用预测渲染 FPS 证明网络权威 Hz。
- 把 SAB 等同于无竞态，把三缓冲等同于无需租约，把同机回放一致等同于跨浏览器 lockstep。
- 为追求形式统一把全部冷状态塞进 ECS，或在主要成本尚未归因时重写全部 WASM/WebGPU。

**最终推荐：先把单线程必需工作量降下来，再完成权威/呈现隔离，最后扩大可证明独立的并行覆盖。核心价值是可解释、可验证和可回退，而不是名义上使用最多的新技术。**
