# Whole-ship component replication: source notes before implementation

Native evidence remains the local 0.98a ArmorGrid/getGrid API cited by the armor-component notes. This is a replication architecture change, not new damage rules or UI. Preserve exact values, ordering, public array compatibility, simulation RNG, 60Hz, transport credits, and full resync.

Implement an authority-owned write journal over projected native ship components. Observable own data fields retain enumerability/order and values; setters only invalidate cached projections. Poll structural collections and custom/escaped buffers rather than pretending unobservable writes are safe. Generic capture remains available. Cached declarative projection nodes are immutable and carry discovered Ship references; a skipped traversal must not lose detached crafts. Lifetimes use real Ship identity plus a monotonic generation, not IDs alone.

Component payloads are self-contained SWF3 capsules inside existing typed Uint8 numeric blocks, with their own layouts; no dependency on a previous applied frame. Immutable capsule bodies are encoded only on changes and decoded once per validated block identity. Motion vectors/relay metadata remain named and transparent. Critical state components, firing windows, entity lifecycle and static definitions have separate processing paths. Existing reliable LAN/Steam per-peer byte baselines send changed data and references to unchanged bytes, including lifecycle definitions; initial connection/recovery still sends a complete frame. This deliberately does not add a second acknowledgement system or a fragile delta-after-playback dependency.

Receiver applies only changed/locally-invalidated component fields, preserves prototypes, and reconciles generation-aware rosters before component references. Static craft definitions are cached per immutable capsule. Malformed/nested component payloads must be bounded and rejected before unbounded recursive expansion. JSON/tape fallback and diagnostic legacy capture remain valid. Protocol capability revision distinguishes the new semantic marker.

One concentrated validation after coherent implementation: typecheck, changed-file lint, existing codec/relay/motion and native fixture with component mode, dropped presentations, cold/reset, lifecycle, alias writes, and full-state reference equivalence. No desktop, agents, release/install/commit/push. Other tasks' files are not reverted.
