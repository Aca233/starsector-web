# 分层同步底层重构：第一阶段结果（2026-09-21）

## 状态与发布边界

**实验实现，不是“已彻底解决延迟/60Hz”，不应直接成为正式版默认。** 客户端只有在构建环境 `VITE_LAN_LAYERED_SYNC=true` 时才请求新的 `motionState:1` 能力；默认构建仍走既有完整状态路径。服务器需同时确认状态消费额度，桌面桥接还需成功连接独立通道。未协商/普通网页/Steam 不伪装为已使用快通道。

本轮没有提交、推送、打包、发布、更新已安装游戏，也没有修改生涯模式、n2n、网卡或防火墙。没有操作桌面。保留既有无关 UI/Vite 工作。

来源最小对照见 `network-layered-sync-source-notes-2026-09-21.md`；这是一项 Web 联机扩展，不宣称原版具有这样的网络架构或已经原版实机等价。

## 已接入的执行路径

- 权威物理仍按原先固定 1/60 步进。Worker 完成真实步进后独立捕获舰船运动与已执行输入序号；大快照 IPC 消费额度被占用时，小状态仍可发布。两个邮箱各只有一个在途额度，不补发重复帧。
- `SWM1` 独立编码最多 128 艘非预备舰船，位置/速度/朝向/角速度为精确 float64；包含瞬移序号、死亡/撤退标记和 10 个席位的输入确认。11KB 原始预算、16KiB 消息预算、32KiB 在途预算，超界整项回退，不偷偷少传舰船或量化。
- 桌面 LAN 小消息使用认证的一次性独立 WS 通道。关键状态与输入回执不再排在完整世界的同一 TCP 字节流后面；**不同 TCP 仍共享物理出口**，并不自动获得带宽优先级。通道可协商无上下文接管的 level-1 deflate，小型控制消息低于压缩阈值。
- 关键状态使用真实消费 ACK、有界在途窗口。建连时、任何关键负载之前发出的独立通道 ping 提供初始 RTT 基线；应用消费时长不能给自己抬高 RTT/额度。已观测交付率用于拥塞收窗。
- 只有已同步且实际消费过关键状态的接收端才进入 200/500ms 完整状态间隔，并限制为至多一个完整状态在途。ACK 变慢属于拥塞，**不触发恢复全速大包的正反馈**；关键生产停止、独立通道关闭、重同步、隐藏时回到原路径/清理额度。
- 新部署舰船若先于大快照基线到达，小状态等待完整名册，不部分应用或终止专用服务器。全员后台、完整基线故意被保留时，不对无人消费的小状态执行旧基线 tick 检查。专用服务器只在存在已协商、可见的独立通道接收端时启用小状态捕获。
- 客机以渲染专用 WeakMap 保存姿态；一 tick 插值缓冲，外推最多 100ms，250ms 失效，瞬移直接校正。旧完整状态不能把更新的关键姿态倒放。**不改权威 HP、碰撞、AI、世界 tick 或伤害判定。** 本舰沿用有界输入重放。
- HUD/日志分别记录关键状态 Hz、完整状态 Hz、FPS、关键 tick/接收后年龄、在途额度和消费耗时。年龄字段不是已同步时钟测出的网络单程时延；不把预测、渲染或重复包算作新权威帧。

## 真实 socket 的共享带宽回放

命令：

```powershell
node scripts/benchmark-layered-network.mjs artifacts/network-latency-phase5-20260920/frames22 artifacts/network-stream-20260921/layered-replay-final.json
```

22 舰录制、241 帧循环；每个客机是独立 Node 进程；真实 WS/deflate/TCP 经过应用层限速代理。所有客机、关键/完整两条流共用 **一个 FIFO 下行瓶颈**，上行固定 32Mbps；代理按 1500 字节切片，不给关键流额外优先级。每场 10s，排除前 3s。3/4/5 人均测旧完整路径及实验分层路径。

没有模拟丢包，没有真实 Steam/n2n 路由，没有浏览器世界应用/GPU、实时重型 AI。以下状态年龄是**回放发布到客机解码完成**，不包括权威计算/渲染；输入指标是 60Hz 回放采样的合成回执，不是实际游戏输入到像素。不是用户现场链路测速，22 舰也不代表 27–39 舰现场负载。

首次试验中，ACK 陈旧被误当作通道丢失，恢复大包发送，5 人 4Mbps 的关键状态曾低到约 5.7Hz、P95 约 1.46s；已经修掉此反馈错误。该失败试验保留在 `layered-replay.json`，其 `bulk` 汇总字段有覆盖错误，不能作为完整状态 Hz 的依据。第二次 `layered-replay-v2.json` 为中间探索；最终以上 `layered-replay-final.json` 才用于本表。不挑选中间试验较好的数字冒充最终结果。

脚本支持 `--matrix` 的 3/4/5 人 × 1/2/4/32Mbps × 20/60/120ms 矩阵，本轮未跑完该全部矩阵，未测试项不得记为通过。没有上传用户日志或世界状态。

## 仍需完成的架构工作（发布阻塞）

1. **完整世界不再每 200–500ms 整体复制**：拆出实体建立/销毁、静态规格/布局、低频属性与可靠变更；以 revision/epoch 确认和缺失修复替代持续大快照。当前全量编码/首帧/大跨度差分仍会占用共享出口，这是慢链路瓶颈。
2. **弹体/光束/特效事件化**：权威创建/消失事件与有界校正，本地只做显示推进；生成时间、ID 重用、瞬移、命中/死亡顺序和同步修复必须逐项验收。当前小状态只有舰船运动，弹体、护盾/炮塔细节、雷达及读取原始坐标的 UI 还不等同于高频世界。
3. **房间级字节调度**：多客机共享发送预算、避免完整状态突发；基线分片可背压且慢客机不能卡住快客机。两条 TCP 本身不能越过 n2n/路由器共享 FIFO。
4. **Steam 独立适配**：复用编码/epoch/预测规则，但对 native 通道、分片/丢失、队列有界性和实际 SDK 行为单独验证，不将 LAN 成绩套到 Steam。
5. 更大舰队与完整带宽/RTT/丢包矩阵、实体全生命周期、浏览器帧耗时/视觉校正、真实 n2n/Steam 双机复测。

这些验收完成前保留实验开关，不发布成“已根治卡顿”的正式版。
