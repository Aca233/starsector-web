# 原版普通跳跃与缺油漂移接入 — 2026-09-19

## 结论与范围

本切片将普通跳跃和有明确拓扑的缺油漂移接入世界 tick、后勤、持久事务和 Node Worker。默认组合为 **reference.cooperative 0.6.0**，仍是未完成的后端领域链路，**不是完整或可游玩的生涯模式**。未添加地图按钮、网络入口、世界生成、战斗结算、经济、势力外交或殖民玩法。

用户要求仍是：**默认尽量还原原版，能替换整套机制；同一世界内可独立行动，也可自愿合作。** 当前不合并个人舰队、不强制编队成员跟随跳跃，未接入的能力明确拒绝，不用近似规则冒充原版。

## 1. 已接入的链路

- 世界增加持久 spaceEntities：实体身份/版本、location、坐标、半径、标签、重力井锚类型和目的地引用/抵达半径。目标不是缓存下来的另一组坐标。
- fleet.jump 只接收舰队、入口、目的地索引；必须提供舰队与两个端点的预期版本。控制权、战斗锁、环境、有效舰队属性、费用在权威端验证。
- 跳跃费用随请求原子扣除，重放同一请求只返回原回执。接近超时中止不退款。
- 持久阶段：start → approach → warp-out → 人类 fade-out → 换地点 → 人类 fade-in → warp-in → 完成；另有 approach 超时中止。
- 逐舰进度、抖动截止 tick、随机间隔、推进倍率、已付费用、端点所在地点、禁战/加速度截止 tick 都进入存档。
- 顺序固定为：**tick 开头的全世界不可变快照 → 舰队后勤扣费 → 移动 → engine-script 过渡 → 单次世界事务提交**。切换地点当 tick 的燃料仍按旧空间和旧速度计费。
- 切换地点不清空速度；跃入逐舰启动时设置当前位置为制动目标，全部舰船已启动后等待抖动期间保留最后目标；完成时设停止目标。
- 无油、超空间、非 NPC、非过渡舰队选择最近合格重力井。漂移创建的新过渡在**下一 tick**才开始推进，不在创建 tick 直接跃出。
- 编队成员仍独立行动。跳跃期间禁止冲突的航线/维修/编队变更，遭遇准备既检查过渡锁，也检查完成后的禁战时间。

## 2. 原版依据与明确联机约定

| 行为 | 原版来源 / 本切片选择 |
| --- | --- |
| 普通出口费用 | 有效 fuel/ly 四舍五入，正值最低 1；普通超空间入口免费；NPC/漂移不走玩家对话扣费路径 |
| 接近判据 | 距离减入口半径一半，与舰队选择半径比较；半径来自船体权重与 settings，封存船仍属于名单 |
| 临时加速度 | START 添加 10 倍、持续 **0.1 游戏天 = 1 游戏秒**，不是 0.1 秒 |
| 接近超时 | 默认启动延迟为零，超过 2 秒中止，无退款 |
| 逐舰跃迁 | 间隔 0.05–0.2 秒，每舰倍率 ×1.1；等抖动结束，并保留 5 秒阶段兜底 |
| 人类淡入淡出 | 各 0.25 秒；所有非 NPC 控制舰队映射原版玩家分支，NPC 不做这两段 |
| 抵达位置 | 在目标实时位置上，独立均匀抽取极角与半径；不是面积均匀圆环采样 |
| 禁战 | 执行过渡时刷新 30 秒，成功完成改为 1 秒；中止不走成功完成的 1 秒重置 |
| 多人计时 | 所有舰队全精度 60 tick/s；不因某个客户端是否在看地图而使用原版离屏/快进捷径，不等待客户端动画确认 |
| 可重播随机 | 每舰队持久 xorshift32，初始种子由世界/舰队身份确定；不是 Java 全局随机序列，不用于保密奖励或安全令牌 |
| 重力井距离并列 | 按实体 ID 的确定性代码点序打破相等距离，不依赖宿主 locale 或插入顺序 |
| 动态端点 | 抵达时读取实时坐标；过渡中禁止端点换 location。轨道模拟尚未支持，不把静态坐标当已支持轨道 |

来源细节见 [跳跃来源核对](campaign-transition-source-notes-2026-09-19.md)。本地观察到的游戏版本是 0.98a-RC8，不证明安装目录/反编译文件全为未修改同版本。固定 tick 的阶段时序不宣称与 Java 浮点/视口相关动画逐位一致。

## 3. 拓扑缺失与未支持规则

- location.navigation.jumpTopology 必须明确为 complete 才能认定“此处确实没有可用重力井”。缺失或 unavailable 遇到无油漂移，原子拒绝推进；不会假装无油仍可自由超空间航行。
- 确认完整但没有合格井时，按原版保留当前航线。不强行把舰队停住或传送回港。
- 只接受星体/气态巨行星锚与非空目的地；任何目的地为 system_abyssal 的井不参与自动漂移。
- 一个井混有多个目标星系或非星系目的地时，默认规则明确拒绝，不猜测它的“目标星系”。
- 虫洞、轨道端点、地形、航行能力、未知属性修正、未支持船体/船插仍拒绝。没有拿普通油费乘五就声称支持虫洞；空间站/模块舰队、门、横向跳跃、技能和完整交互前提仍未覆盖。
- 航线指令仅提交意图；未知漂移拓扑的错误可以发生在随后权威 tick 中，整个推进事务回滚。在线调度器按既有失败策略停止该世界推进并报告错误。

## 4. 可替换性与兼容性

- travel.advance 从返回舰队改为返回 **{ fleet, events }**；simulation 要求新增 post-movement-events 能力，旧自定义提供者不会被当作兼容版本静默装配。
- 默认 travel 0.3.0；simulation 0.3.0；encounters 0.4.0；cooperation 0.3.0；logistics 0.5.0。规则锁包含新来源证据和联机约定。
- 测试专用大改提供者完全替换 travel 和 fleet.jump：使用瞬时跳跃、不同费用与命名空间扩展状态，沿用相同事务、回执与世界调度，不修改原版提供者，也不加入默认规则组合。它验证机制替换通路，不代表默认规则采用瞬移。
- 需要不同过渡模型的大改可在自己的 extensions 命名空间保存状态，不必使用默认 navigation.transition。根本改变空间、实体或时间模型仍可能需要显式 schema/API 升级。
- 世界 JSON schema 仍为未发布开发版 1，数据库 schema 仍为 2；新增字段/collection 与规则锁有不兼容变化。旧世界不静默补造拓扑、随机或过渡信息，旧规则锁拒绝加载；**没有自动存档迁移**。
- 内核/规则 registry 是可信服务器模块边界，不是不可信 JS 插件沙箱。

新增 scripts/check-campaign-transitions.mjs：**25 项**。包括费用与最小舍入、版本/权限、真实阶段推进、半径/加速度、无退款中止、旧空间计费、保留速度、逐舰随机、分批/重试一致、SQLite 回执失败回滚、文件重开、独立舰队、缺油选择、已知空/未知拓扑、NPC 分支、禁战门禁、合作锁、损坏状态拒绝、真实 Worker 路径和整套机制替换。

六组领域测试共 **124 项**（foundation 20 / encounters 14 / logistics 24 / simulation 20 / travel 21 / transitions 25）。完整验证结果记录于实现账本；这些不是浏览器联机或原版画面对照测试。
