# 后台暂停与心跳豁免（2026-09-17）

## 当前行为

- 以 `document.visibilityState` 判断页面是否在后台；单纯失去键盘焦点不会关闭网络检测。
- 后台页面继续在能够调度时发送心跳，但不因应用层 10 秒未收到 pong 主动关闭连接。最多保留一个未完成探测，避免冻结期间不断积压心跳。
- 回到前台时作废旧探测和 RTT 样本，立即重新探测，给予完整的 10 秒响应时间。若恢复后的首个计时器早于 `visibilitychange` 回调，也会先检查当前可见状态。
- 战斗恢复前清空旧按键、开火和未发送动作，走现有的新快照 / syncId 确认流程，不直接恢复操控。
- 房主通过经过身份验证的连接报告页面可见状态。后台房主最多允许 **5 分钟无有效战场更新**；回到前台时最多再给 12 秒上传新状态，但不得突破上述无更新的 5 分钟总上限。重复可见状态消息不续期，客机状态不能替房主申请豁免。
- 房主 Worker 对不超过 5 分钟的后台调度暂停丢弃墙钟积压、清空控制，并要求重新同步；该暂停不消耗前台过载恢复次数。真实物理积压仍受原来的每分钟两次恢复预算限制。
- 同实例短断线续接保留先前的后台标记，直到页面报告新状态，避免刚切回前台又被旧战场更新时间立即终止。

配置位于 `src/network/protocol.json`：`backgroundGraceMs = 300000`、`hostStateTimeoutMs = 12000`。本次增加了可见状态消息，客户端与服务器必须使用相同版本和构建。

## 没有放宽的保护

- WebSocket 底层 15 秒无 pong 仍断开连接；真正断线后仍只有 **30 秒**重连窗口。
- 房主刷新、浏览器丢弃页面、Worker 崩溃或服务退出仍不可恢复。后台豁免不是后台永不休眠保证，也不意味着房主冻结时战斗还能正常推进。
- 前台主机持续无状态、真实网络故障、持续计算过载仍会停止对局。
- 加载阶段原有 60 秒资源准备超时未修改。

## 回归验证

```powershell
node scripts/check-background-heartbeat.mjs
# 可选：Playwright 可从 NODE_PATH 解析；BROWSER_PATH 可指定 Chromium / Edge
node scripts/check-background-heartbeat.mjs --browser
```

脚本使用隔离的临时目录、随机端口服务和独立浏览器上下文，不访问现有房间、浏览器资料或玩家存档。

验证覆盖：前台断网检测、后台心跳去积压、前台新探测与旧 pong 排除、恢复时事件排序、连接复用的监听器清理、真实断线的重连期限；真实房主引擎 Worker 在模拟两分钟后台调度暂停后继续产出快照、不追赶两分钟物理、不重放旧操作，同时保持过载及五分钟上限；真实 WebSocket 服务的房主 / 客机权限、可见状态校验、有界恢复、短断线续接与会话清理。

可选浏览器检查通过注入隐藏状态后用 CDP **实际冻结页面 JS 20 秒**，恢复后验证仍为同一 WebSocket、没有触发重连，并获得新的 RTT。它不是物理 Alt-Tab、真实系统睡眠或跨设备网络测试。

## 生效方式

生产环境需要重新构建并在对局结束后重启联机服务，所有玩家刷新到同一构建。验收构建写入独立临时目录，不覆盖正在使用的 `dist`，也不主动终止现有游戏服务。


## 2026-09-18 补充修复

连续后台降频还存在独立问题：250–1000 ms 回调会误用前台过载预算，超过一秒则可能反复清零而不推进战斗。现已区分真实计算时间与调度空闲，支持持续后台降频后的有界推进和同步；详见 [复现与修复验证](background-throttle-recovery-2026-09-18.md)。
