# 第二轮多核实验：完整 AI 推测计算（未通过）

日期：2026-09-17。**结论：本次多核原型没有达到额外 +30% 的模拟吞吐量验收，未接入正常战斗。此前单线程算法优化不回滚。**

## 1. 正确基线与验收

- 基线是本轮开始时冻结的当前源码，已包含此前单线程 +32.574% 的算法改进，不是早期失败的 Worker 几何版本。
- 同屏 100 艘 Onslaught，种子 0x51180，固定 1/60 秒。没有降低 AI 频率、跳帧、改变 dt 或浮点精度。
- 验收是**吞吐量 +30%**，即整步耗时降至本轮基线 / 1.3，不是把局部内核加速计为整体提升。
- 本轮基线 57.88 ms/步，对应验收线 **≤44.52 ms/步**。上轮 52.65 ms 是历史冻结版本/测量环境下的数据，不拿它直接除本轮结果。

## 2. 本次做了什么

新 Node CPU 采样：完整舰船 AI 约 43.55%，威胁评估约 23.89%，导航障碍收集约 8.94%。采样均值仅用于定位，不能作为吞吐量基线。

- 持久化 2/4/8 个真实 Web Worker，按舰船划分完整原生 CapitalShipAI.update 计算，而非再分摊旧的小几何内核。
- 每个 Worker 具有独立的原生舰船/AI 副本；在主引擎原有 AI 阶段入口同步数据，独立求出每艘舰的控制、战术与内部 AI 状态变化。
- 主线程按原舰船顺序提交结果。若一次提交改变其他舰船依赖的护盾、幅能或系统状态，后续结果作废，回到原同步 AI 计算，不能用陈旧世界状态硬套结果。
- 从完整对象克隆迭代到共享 Float64/类型标签缓冲区、增量字段同步、小型弹丸数据投影、紧凑 AI 结果。用消息/Promise 等待完整结果，不在渲染线程 Atomics.wait 或忙等。
- 共享输入仅在上一阶段所有 Worker 已返回后重写。序号检查拒绝错帧；重入保护、就绪握手、超时/错误及 dispose 均在隔离原型中。失败会终止实验，不是生产级自动降级承诺。
- SharedArrayBuffer 所需 COOP/COEP **仅设置在诊断 HTTP 服务**；没有改正常应用部署头、Vite 配置或渲染循环。

## 3. 最终重复对照

三轮，每版本每轮 60 步预热 + 180 步计时，共 **540 步/版本**。每步交替/轮换推进各页面，同一时刻只推进一个版本。下表为整步时间加权汇总。

| 版本 | 整步 ms | 模拟步/秒 | P95 ms |
|---|---:|---:|---:|
| 当前单线程原生基线 | 57.88 | 17.28 | 81.97 |
| 同样的副本/推测方案，但串行计算 | 85.04 | 11.76 | 124.79 |
| 4 Worker 完整 AI 推测方案 | 74.40 | 13.44 | 115.59 |

**4 Worker 相对真实基线：吞吐量 -22.21%，整步耗时 28.55%。没有达标，不能算作保留的性能提升。**

4 Worker 相对有额外副本开销的串行推测方案为 14.29%，这个比较只用于拆分并行收益，不能替代与真实原生基线的比较。

### 4 Worker 平均开销拆解

| 阶段 | ms/步 |
|---|---:|
| 主线程准备/打包 | 7.99 |
| 派发到所有 Worker 完成的墙钟等待 | 23.88 |
| 其中：最慢 Worker 的 AI 求解 | 12.34 |
| 其中：最大副本数据应用时间 | 4.41 |
| 主线程结果提交尝试 | 0.06 |

“其中”行是等待区间的子项，**不可相加为总时间**，而不同最大值也不保证来自同一 Worker。主线程准备、同步副本、通信、调度以及剩余串行模拟抵消了内核并行收益。测量区间每步平均提交 68.82 艘 AI，串行回退 30.18 艘，说明此处不能主要归咎于频繁回退。

## 5. 正确性、范围与限制

- 三轮检查点 1/2/3/30/60/90/120/150/180/210/240 的基线、串行推测和 4 Worker 引擎状态哈希均一致。任何不一致会保存差异并终止该轮，而不是继续出有效加速结论。
- 状态序列化覆盖 engine/playerAI 可枚举对象图、Map/Set、引用、TypedArray、特殊数字；函数用占位，碰撞 kernelMs 时钟值标准化。不是所有闭包、隐藏 WeakMap 或 WASM 内存的形式证明。
- 原型是固定原生 Onslaught 场景的阶段副本协议，不是任意舰型、动态部署、订单或自定义回调可用的通用协议。未知状态/扩展不能视为已支持。
- 无渲染、无音频；两个页面碰撞 WASM 均等待 ready；Worker 启动及预热不计入稳态时间。运行时没有本任务同时执行的其他重型验证，用户其他程序保持运行。
- CPU：13th Gen Intel(R) Core(TM) i5-13490F；16 逻辑处理器；Windows / Chromium headless / Node 24。这是**模拟计算吞吐量**，不是前台 UI FPS，也不是已经实现实时 60 TPS。
- 冻结诊断构建成功。没有向生产 src 写入本轮多核代码，因此不借全仓检查来声称本原型获得生产认证；正常工作区其他任务的未提交修改均保留。

## 6. 保留/拒绝决定

**拒绝本次原型进入正常战斗。新增可计入生产的多核净提升为 0，不追加到历史单线程 +32.6% 上。**

本实验否定的是当前“面向对象权威引擎 + 每步副本/推测提交”实现，不是证明多核永远不可能有效。若仍要追求额外 30%，下一条更重的路线是让模拟核心直接维护可共享的数值状态，并明确只读计算/有序提交边界，避免每步转换成 Worker 副本；那是模拟架构改造，不是简单增加 Worker 数量，也仍须实测验收。
