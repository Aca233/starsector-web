# 威胁评估与舰船碰撞优化（2026-09-17，续）

## 保留范围与约束

本轮保留画质、粒子数量、60 Hz 模拟步频、AI 更新频率、命中规则和物理响应顺序。优化针对可重复的几何计算与不会命中的候选，不通过慢放模拟或减少战斗内容实现提速。

修改三个生产模块：

- **FireControlGeometry.ts / weaponMuzzle**：只缓存每个挂载最近一次舰体朝向和炮管朝向的正弦/余弦。每次调用仍读取当前舰体位置、局部挂点、炮管序号及偏移数组，并按原来的浮点运算顺序产生新的 Vector2。Object.is 区分正负零；角度改变即重新计算。没有跨帧的位置快照或外部缓存失效协议。
- **ThreatAssessment.ts**：当前没有穿过目标的活动光束时，不为每个敌方挂载创建 sourceId/slotId 字符串。存在活动光束时继续使用原有排除逻辑，不缩短预测窗口或减少武器/弹丸候选。
- **ShipCollisionSystem.ts**：在精确舰体/护盾查询前加入保守轴向包围范围排除。范围覆盖真实轮廓顶点、回退碰撞半径及当前展开护盾的真实偏移中心。接近、相切、相交的候选继续走原来的轮廓/部分护盾查询与碰撞响应；绝不把包围圆当作新的装甲或护盾表面。

轮廓半径只对 immutableCopy 创建的递归冻结数据缓存；动态数组、浅冻结数组和改装数据不缓存。护盾状态、半径、偏移中心和舰体位置每次重新读取。排除边界使用按坐标量级向外扩张的 1e-7 安全余量，边界附近仍由原精确路径处理。

## 采样依据与被替换方案

优化前对当前实际引擎采样：50 艘、60 步预热后采样 100 步，Profiler 间隔 250 μs。含子调用的占比约为：威胁评估 24.4%、导弹拦截 12.5%、舰体射线查询 12.0%、舰船互撞 7.9%、炮口计算 5.2%。这些调用链重叠，不能相加当作总占比。

另外观察 50 艘前 120 步的 6,000 次评估：平均约 34.8 条预测威胁，1 秒内威胁平均约 10.2 条、最大 16 条。因此没有优先改写护盾方向选择的二次循环，而是处理重复炮口变换与远处舰船的轮廓扫描。

曾尝试缓存完整炮口坐标、每次比较所有输入。该方案的独立重复查询微基准平均仅改善约 2.7%，整场采样也没有清晰支持它优于更简单的实现。因此将它替换为只缓存三角函数，避免完整坐标缓存的多字段检查。相关历史数据归档在 artifacts/threat-algorithms/candidate-point-cache/，不作为最终版本的数据。

最终三角函数方案的独立微基准：800 轮，前 200 轮预热；每轮更新船体位置/角度，再对 13 个原生挂载重复 50 次查询。650 次查询平均从约 0.0491 降到 0.0447 ms，约少 9.0%；这是函数级微基准，不是整场战斗或 FPS 收益。

## 最终配对压测

沿用 i5-13490F / RTX 5060 环境，Node/Vite SSR 执行真实 CombatEngine，没有渲染、GPU 呈现或音频解码。双方各半的 10/50/100 艘攻势，随机种子 0x51180；编队位置为 ((pair % 5) * 3200 + side * 1500, floor(pair / 5) * 850)，双方相向并互设初始目标。

每组 360 步、dt=1/60，前 60 步预热、后 300 步计时，每步交替前后版本执行顺序。两侧使用同一份内存冻结源码，仅本轮三个模块不同。

| 战列舰数 | 优化前平均 ms/步 | 优化后平均 ms/步 | 平均耗时减少 | P95 ms/步（前 → 后） |
|---:|---:|---:|---:|---:|
| 10 | 6.57 | 6.53 | 0.6% | 9.03 → 9.54 |
| 50 | 63.82 | 56.79 | 11.0% | 90.74 → 81.02 |
| 100 | 303.17 | 286.88 | 5.4% | 488.61 → 443.54 |

10 艘约 0.6% 的平均差异应视为基本持平，该组 P95 反而略高，不宣称全场景或所有尾延迟均有改善。100 艘本轮 P95 仍达约 444 ms；负载随战斗演变，测量分布较宽，单次对照不能作为稳定帧率或统计置信区间。共同代码和运行环境会变化，禁止将本轮绝对 ms/步与前几轮直接串联推算累计收益。

三组每 60 步核对一次完整状态，各 6 个检查点全部一致。结束时主力舰全部存活，峰值弹丸 324 / 1,623 / 3,216，峰值导弹 139 / 693 / 1,413。另做 6 艘奥德赛/典范混战 360 步，12 个检查点一致；峰值 18 条光束、36 枚制导弹，结束时 14 个舰船/舰载机实体，该场没有诱饵弹。

最终压测期间共同源码中的战斗视图、输入和 HUD/UI 文件被其他任务更新，但本轮三个模块与核心模拟代码未改变。冻结运行时未中途换码；保留了这些独立更新，生产构建和浏览器检查使用之后的当前工作区。

最终数据：artifacts/threat-algorithms/benchmark-results.json。之前的完整坐标缓存版本另存 candidate-point-cache/，不与最终数据混用。

## 正确性与集成检查

未恢复已按用户要求移除的测试目录或测试运行器，检查使用临时内联 Node 断言和被忽略的性能辅助脚本。

- 最终三角函数版本做 30,000 组炮口对照，每组检查冷/热结果及返回值独立性。覆盖平移、旋转、局部挂点改变、硬点/炮塔切换、炮管序号、原地改变/替换/缩短偏移数组、空/奇数长度数组、正负零、非有限角度和异常炮管序号；坐标逐项 Object.is 一致。修改返回向量不影响下次结果。
- 保守碰撞排除做 6,005 组位置响应对照，覆盖远近距离、旋转、真实多边形、缺省/不足三个顶点的轮廓、超出名义半径的轮廓、可变及浅冻结顶点、偏移护盾、NONE/FRONT/OMNI/PHASE 类型、多种展开弧度与近相切边界。
- 120 组高速舰船配对核对完整状态及特效回调，其中 110 组实际产生撞击伤害；包含不同质量舰体、护盾/装甲/结构承伤、幅能和部件变化，结果一致。
- 最终版本的完整战斗状态对照见上述配对压测。仅排除 kernelMs 墙钟计时，不排除碰撞索引、内核缓存或查询统计。闭包与 WeakMap 内部状态不能直接序列化，其影响由单独函数检查和后续战斗演化验证；不宣称形式化证明所有插件和输入。

## 构建、浏览器与未完成目标

npm run build -- --outDir artifacts/threat-algorithms/build（含 TypeScript）与 npm run lint 均以 0 退出，lint 无警告；构建保留项目现有大分块提醒，不覆盖默认 dist。

独立生产构建通过 2560×1440 / DPR 1 浏览器冒烟检查：RTX 5060 D3D11 WebGL2，战斗画布与 HUD 可见，页面异常与失败请求为 0。浏览器和临时预览服务已关闭。该检查不是 100 艘实际呈现帧率测试。

最终再次采样相同的 50 艘 / 60 步预热 + 100 步采样场景，舰船互撞含子调用占比从 7.88% 降至 0.6%；威胁评估约 25.45%，导弹拦截约 14.51%，舰体射线约 12.5%，仍是后续优化重点。样本占比受其他工作量影响，不能将占比变化直接当作各函数绝对提速。

**总体目标仍未完成：尚未实现或验证 100 艘同屏 180 FPS。** 本轮 100 艘平均约 287 ms/模拟步，仍远超 60 Hz 模拟的 16.67 ms/步预算。CPU 模拟耗时不等于浏览器渲染 FPS，headless 检查也不证明显示器以 180 Hz 呈现。本轮只记录经过对照验证的进展，不把局部优化当作整体达标。
