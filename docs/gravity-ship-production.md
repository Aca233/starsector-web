## 1–3. 定位、决策和弱点

- 在中距离以区域引力改变敌方阵型和弹幕方向，再由质量武器兑现射击窗口的控制支援舰。
- 侧放井：改变敌人横向速度；正面放井：拉近但可能把强敌带到自己面前；收井：保留已经获得的真实运动。
- G：保护近身空间/推开弹幕，但会失去自己的 F，消耗较高幅能并进入冷却；不是无敌帧。
- 重舰按质量抗拉；光束、拉开维持距离、过载与排散空窗是反制。普通推进/转向不被锁死。
- 档位/DP/OP和最终同级强度待整舰实战，不以探针位移直接宣布平衡。

## 4. 已接入规则卡（数值是机制试验基线）

| 项目 | F 区域引力井 | G 全向排斥 |
| --- | --- | --- |
| 指向 | 接受指令时捕获的鼠标世界坐标，固定 | 成功事件执行时本舰位置，不看鼠标 |
| 时序 | 0.35s启动、最多6s有效、0.15s收束、7s冷却 | 0s启动、0.65s波前、0.2s收束、11s冷却 |
| 范围 | 部署/维持距离1400，区域半径520 | 最大半径720 |
| 幅能 | 240启动 + 有效期180/s软幅能 | 800软幅能 |
| 舰船作用 | 240基准加速度，距离柔化、按1000/整舰质量响应 | 210基准一次冲量，距离衰减、按整舰质量响应 |
| 单源预算 | 24舰/96弹每步，合计舰900/弹24000速度变化每秒 | 整个波最多24舰/128弹，合计舰850/弹20000冲量，不逐帧回填 |
| 共享上限 | 舰260/弹1400加速度 | 舰240/弹750同一步合成冲量 |
| 超速 | 只限制新增外力；不突兀抹掉原有超速；宿主推进/制动正常接管 | 同左 |
| 中断 | 收回、距离断开、死亡/撤离、相位、排散/过载、系统离线 | 源失效会停止未传播波前；已获冲量不回滚 |

- F 只拉敌舰及支持的敌方实体弹；友舰和普通友弹不拉。G 支持多艘/多弹，友舰不推，兼容的友方质量弹须显式 `gravityCoupling: MASS_DRIVER`。
- 未知阵营弹丸、光束、moving-ray弹道显示类别、静态空雷、热焰弹及爆炸载荷不受力。moving-ray动能武器的精细分类留待质量炮阶段，不把所有光束外观都包装成已支持。
- 模块归并 assemblyRoot；存活附件质量计入总质量，只给根舰一次速度变化，随后同步附件姿态。已损毁附件不继续提供额外抗性。
- G 校验失败不清 F；成功事件清 F，所有系统事件处理完之后才汇总引力。G/F同帧请求无第二个残留井。
- 波前用扫掠交点检出跨帧高速弹丸，按实际接触侧计算方向；不按“在大圆内”每帧重复推。
- 不改变伤害/发射源/阵营/年龄/寿命；受力的原生实弹按真实弯曲世界路径扣除射程，不受力原生弹保持原规则。
- 没有新增撞船爆炸、隔盾伤害、光束反弹或删除敌弹。

## 5. 权威/显示链路

`GravitySystems.ts` 注册系统定义 → `ShipSystem.activate/dispatchEvents` → `CombatEngine.fixedUpdate` 在系统事件后、弹体运动碰撞前调用 `GravityFieldPhysics.ts` → 统一施力。

场锚点、年龄、波前半径、总预算余额、已命中ID存储于对应 `ShipSystem.gravityField`，不是仅放在 WeakMap 或客户端。真实 Dedicated Worker 使用同一代码。

- RenderShipProjection、LanShipProjection、RenderSystem 按需传出场状态，为后续正式动态素材提供真实驱动。
- 普通船不新增 gravityField 实例字段，不让全部原生系统/弹丸跌出已有固定记录优化路径。
- 新字段采用通用快照记录回退；不能手写或冒充生成的固定schema已更新。
- 旧 authority 快照本来就是显示/诊断协议，**不是可恢复的全引擎存档**；不因此声称支持断线权威迁移。
- 本轮没有绘制临时圆圈、扇形或静态贴纸特效。
